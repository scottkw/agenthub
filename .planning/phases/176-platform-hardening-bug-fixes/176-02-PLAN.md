<objective>
Fix BUG-06 (#123): the `/app/` route — the web-share guest React SPA surface exposed to the public internet via Funnel — serves NO Content-Security-Policy header. Add CSP defense-in-depth by reusing the existing, battle-tested static `cspHeaders` middleware (already on `/dashboard`, `/join`, `/sessions/{id}`) on the `/app/` route registration. Carried over from the Phase 168-02 #123 follow-up (deliberately scoped out then).

Purpose: harden the public guest SPA surface against script/style/connection injection with the same strict policy the sibling routes already enforce.
Output: `/app/` route wrapped in `ws.cspHeaders(...)` + a Go test asserting the header is present on an `/app/` response.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet guest browser → /app/ SPA | Via Tailscale Funnel, an unauthenticated internet client loads the React guest SPA at /app/. Untrusted client, public exposure — the primary boundary this plan hardens. |
| /app/ SPA → daemon APIs (SSE /api/plugin-config/stream, WS relay) | The loaded SPA opens same-origin connect-src channels back to the daemon. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-176-06-01 | Tampering | injected/inline `<script>` on /app/ | high | mitigate | `script-src 'self' 'wasm-unsafe-eval'` (existing policy) blocks inline and third-party script injection; the CSP header now applied to /app/ closes the gap. |
| T-176-06-02 | Info Disclosure | exfiltration to attacker origin | high | mitigate | `connect-src 'self' wss://<base>` restricts fetch/WS/SSE to the daemon origin only; `default-src 'none'` denies everything else. |
| T-176-06-03 | Spoofing/Tampering | clickjacking / framing of /app/ | medium | mitigate | `frame-ancestors 'none'` (existing policy) prevents embedding the guest SPA in a hostile frame. |
| T-176-06-04 | Tampering | overly-strict CSP breaks the SPA (self-DoS) | medium | mitigate | D-06 production-build console sweep verifies the bundle loads; D-07 permits relaxing ONLY for a concrete violation the bundle actually hits. |
| T-176-06-SC | Tampering | package installs | n/a | accept | No npm/pip/cargo installs; existing middleware reused verbatim, no new dependencies. |

ASVS L1, block on high: T-176-06-01 and T-176-06-02 (high) are both mitigated by the reused strict policy. No high threat is left with disposition `accept`. Gate satisfied.
