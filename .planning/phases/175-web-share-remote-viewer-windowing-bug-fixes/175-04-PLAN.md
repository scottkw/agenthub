<objective>
Fix BUG-04's residual bug (#119): a late-joining/reconnecting viewer of a long-running full-screen TUI (Claude, Gemini-CLI, OpenCode) lands in a blank/garbled window because the raw 256 KiB scrollback ring has wrapped PAST the one-time `ESC[?1049h` (alt-screen enter) sequence, so the replayed bytes are alt-screen CONTENT with no mode marker — xterm paints them into the wrong buffer and never self-heals. The fix maintains a live, continuously-fed VT emulator per Hub whose `Render()` output is emitted on connect. Problem 1 (the "MDI window" complaint) is already resolved by Phase 168-03 and is re-verified here, not re-implemented.

Purpose: A guest opening or reopening a shared session must always land in a working view, never a dead empty window with no recovery.
Output: a lazy live per-hub emulator + a `RenderSnapshot()` reconnect preamble wired into both WS handler sites.
</objective>
