<objective>
Fix BUG-02 (#125): when the owner ends/stops a shared session, the remote viewer's terminal just stops updating with zero explanation — a silent dead terminal. Both WS write pumps treat `hub.Done()` as a bare `return` (no close reason), and neither JS client reads the `CloseEvent`. Emit a generic close reason server-side and render a colorblind-safe disconnect banner client-side.

Purpose: A remote viewer must learn when the session has ended. Per the phase's locked decision this is a SINGLE generic notice — do NOT build differentiated "owner ended" vs "network error" messaging, and do NOT add auto-reconnect (RESEARCH anti-patterns).
Output: server sends a fixed close code+reason at both sites; the guest renders one accessible banner.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server WS close handshake → guest browser | The server sets CloseEvent.code/.reason; the guest reads them. The reason is attacker-visible and could be attacker-influenced if derived from user data. |
| guest client → DOM (banner render) | CloseEvent.reason is untrusted text; rendering it as-is would be an injection/info-leak vector. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-175-06-01 | Information Disclosure | WS close reason string (both server sites) | high | mitigate | Send a FIXED generic reason `"session ended"` server-side — never raw Go error text, never a user-set session name (reuse the IN-01 convention at server.go:1574-1579). |
| T-175-06-02 | Tampering | banner rendering CloseEvent.reason | high | mitigate | The banner renders a fixed client-side string only; the CloseEvent.reason is used for logging/branching, never injected into the DOM; no dangerouslySetInnerHTML (HubModal.tsx:67 discipline). |
| T-175-06-03 | Denial of Service | accidental reconnect storm | medium | mitigate | Explicitly NO auto-reconnect added — a same-code "session ended" close means the session is gone; reconnect would be wrong behavior (RESEARCH anti-pattern). |
| T-175-SC | Tampering | npm/go installs | low | accept | No packages installed this phase (RESEARCH: N/A). |
</threat_model>
