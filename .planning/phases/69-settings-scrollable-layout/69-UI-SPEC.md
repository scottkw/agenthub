## Interaction Contract

### Primary Visual Anchor

Primary visual anchor: the "Appearance" section header and theme picker row, as the first element the user sees on scroll into view. This establishes immediate context and reflects the most common reason users open Settings.

### Scroll Behavior
- The `.settings-panel__body` container (`flex: 1; overflow-y: auto; padding: 20px`) is the sole scroll region.
- The `.settings-tab` outer container (`overflow-y: auto`) is a safety fallback — do not add a second scroll indicator.
- No sticky headers. No scroll-to-section anchors. Scroll is native CSS overflow — no JavaScript.

### Tab Switcher Removal
- The `<div className="settings-panel__tabs" role="tablist">` block (SettingsTab.tsx lines 214–239) is fully removed.
- The `activeTab` prop and `onActiveTabChange` prop are removed from `SettingsTabProps`.
- The `settingsActiveTab` state and its prop passes in `App.tsx` are removed.
- All three content groups render unconditionally (no `{activeTab === 'x' && ...}` gating).

### Section Header Rendering
- Each section begins with a bare `<h3>` element inside `.settings-panel__body`.
- The existing CSS stub `.settings-panel__body h3` handles all styling — no new className needed.
- Additive spacing rules: all `h3` elements except the first receive `margin-top: 24px; padding-top: 20px; border-top: 1px solid #292e42`. First `h3` has those reset to 0/none.

### No Interaction Changes
- Theme picker, web server start/stop button, URL copy/QR actions, CT disclosure accordion, port input, CLI path inputs, and Save Paths button all retain their existing event handlers and Wails bindings unchanged.
