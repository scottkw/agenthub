## Component Specification: Behavior Section Toggle

This phase introduces the first toggle/switch control in SettingsTab. The component must be implemented without any third-party library — it is a styled `<input type="checkbox">` with a visually custom track + thumb rendered via CSS.

### HTML Structure

```
<div class="settings-panel__field-group">
  <label class="settings-panel__toggle-row" for="startMinimized">
    <span class="settings-panel__toggle-track">
      <span class="settings-panel__toggle-thumb" />
    </span>
    <span class="settings-panel__toggle-label">Start minimized to system tray</span>
  </label>
  <input
    type="checkbox"
    id="startMinimized"
    class="settings-panel__toggle-input" {/* visually hidden, accessible */}
    checked={startMinimized}
    onChange={handleToggleChange}
  />
  <p class="settings-panel__description">
    When enabled, AgentHub launches with the window hidden. Click the tray icon to open it.
  </p>
</div>
```

### Toggle CSS Spec (new rules to add to style.css)

```css
/* Visually hide the native checkbox while keeping it accessible */
.settings-panel__toggle-input {
  position: absolute;
  width: 1px;
  height: 1px;
  opacity: 0;
  pointer-events: none;
}

/* Clickable row: label wraps track + text */
.settings-panel__toggle-row {
  display: flex;
  align-items: center;
  gap: 10px;
  cursor: pointer;
  min-height: 44px;    /* touch-target minimum */
  user-select: none;
}

/* Track: pill shape */
.settings-panel__toggle-track {
  position: relative;
  width: 36px;
  height: 20px;
  border-radius: 10px;
  background-color: #16161e;    /* off state: input surface */
  border: 1px solid #292e42;
  flex-shrink: 0;
  transition: background-color 0.15s, border-color 0.15s;
}

/* Thumb: circle inside track */
.settings-panel__toggle-thumb {
  position: absolute;
  top: 2px;
  left: 2px;
  width: 14px;
  height: 14px;
  border-radius: 50%;
  background-color: #565f89;    /* off state: muted thumb */
  transition: transform 0.15s, background-color 0.15s;
}

/* On state: applied via React inline class when checked */
.settings-panel__toggle-row--checked .settings-panel__toggle-track {
  background-color: #7aa2f7;    /* accent */
  border-color: #7aa2f7;
}
.settings-panel__toggle-row--checked .settings-panel__toggle-thumb {
  transform: translateX(16px);
  background-color: #1a1b26;    /* dark on accent for contrast */
}

/* Label text beside the track */
.settings-panel__toggle-label {
  font-size: 13px;
  font-weight: 400;
  color: #c0caf5;
  line-height: 1.5;
}
```

### Interaction Contract

| State | Track color | Thumb position | Thumb color |
|-------|------------|----------------|-------------|
| Off (default) | #16161e (input surface) | left (translateX 0) | #565f89 (muted) |
| On (enabled) | #7aa2f7 (accent) | right (translateX 16px) | #1a1b26 (dark) |
| Loading (async) | unchanged | unchanged | opacity 0.5 |

Toggle change is NOT optimistic. Flow:
1. User clicks label
2. Call `SetStartMinimized(newValue)` via Wails binding
3. On success: update local state, reflect new position
4. On error: revert to previous state, show inline error below description (`.settings-panel__error` class)

Loading state: disable the label `pointer-events` and reduce opacity to 0.6 while the Wails call is in flight.

## Settings Tab: Behavior Section Placement

Per D-03 (Claude's discretion), the Behavior section is placed **first** in the Settings tab body, before Appearance. Rationale: startup behavior is a global app preference, not a visual preference, and is more likely to be set once on first use. Placing it first puts it in the area users land on when opening Settings.

### Section Order (after this phase)

1. **Behavior** (new) — Start minimized to system tray toggle
2. **Appearance** — Terminal Theme selector
3. **Web Server** — CT disclosure, port, start/stop, URL/QR
4. **Paths** — CLI path overrides with browse buttons

The Behavior h3 follows the same `.settings-panel__body h3` styling (13px uppercase, letter-spacing 0.08em, `#9aa5ce`, border-top separator). Since it will be the first section, it uses the `:first-child` exception rule that removes border-top and collapses margin-top — no code changes needed.

| Element | Copy |
|---------|------|

| Error state | `Could not save preference — [error message from backend]` |

| Destructive confirmation | None — this phase has no destructive actions |

Copywriting rules:
- Toggle label: sentence case, no period, imperative noun phrase
- Description: two sentences max, plain English, explains the effect and recovery path (click tray icon)
- Error copy: always includes the raw error from backend after the em dash for debuggability

## States and Error Paths Required

The executor must implement all of the following states:

| State | Trigger | Visual |
|-------|---------|--------|
| Default off | App first launch, no preference saved | Track: #16161e, thumb left |
| Enabled on | User toggled on, backend confirmed | Track: #7aa2f7, thumb right |
| Loading | Toggle clicked, Wails call in flight | Entire row opacity 0.6, pointer-events: none |
| Error | Wails call failed | `.settings-panel__error` below description, state reverted |
| Hydrating | Component mount, waiting for GetStartMinimized() | Toggle hidden or spinner — use hidden until value resolves to avoid flash |

Hydration approach: show toggle only after `GetStartMinimized()` resolves (use a loaded boolean in state). This prevents the toggle from flashing from off to on on mount.
