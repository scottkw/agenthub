# Phase 120 — UI Design Contract

> Visual and interaction contract for `FileBrowserTab.tsx` (Desktop + Web). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase adds a read-only file browser tab that opens per-session on the Wails desktop app and the Tailscale-HTTPS web frontend. The contract below is anchored to the existing AgentHub TokyoNight design language (hand-rolled CSS in `frontend/src/style.css`) — no new design system, no new dependencies beyond `react-markdown@10.1.0` + `remark-gfm@^4`.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (hand-rolled CSS, no shadcn / Tailwind / Mantine) |
| Preset | not applicable |
| Component library | none — React 19 + native elements + `@heroicons/react@^2.2.0` |
| Icon library | `@heroicons/react@^2.2.0` (already in `frontend/package.json`) |
| Font | `'Cascadia Code', 'MesloLGS NF', 'Fira Code', monospace` (body default) — see Typography for the prose escape used in markdown preview |
| Stylesheet | New rules append to `frontend/src/style.css` under a `/* ─── File Browser Tab (Phase 120) ─── */` section; reuse existing TokyoNight tokens — DO NOT introduce new hex values |
| Naming convention | BEM-like: `.file-browser`, `.file-browser__list`, `.file-browser__list-row--selected`, etc. — matches `.daemon-panel__*`, `.remote-panel__*` patterns |
| Markdown renderer | `react-markdown@10.1.0` + `remark-gfm@^4`. **No `rehype-raw`** (UI-07, Pitfall 9). Renderer is the only new runtime dependency. |

## Spacing Scale

Declared values (multiples of 4 — matches existing AgentHub rhythm of 4 / 6 / 8 / 10 / 12 / 16 / 20 / 24):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gap inside a row, breadcrumb segment chevron gap |
| sm | 8px | Inter-column gap in a row, padding inside small buttons |
| md | 12px | Row vertical padding, breadcrumb height interior |
| lg | 16px | Pane padding, preview-pane edge inset |
| xl | 24px | Tab outer padding (matches `.daemon-panel` and `.remote-panel`) |
| 2xl | 32px | Empty / error state vertical margins |

Exceptions:
- Row height for list items is **fixed 32px** (8px vertical padding + 16px line-height + borders) — chosen to match the existing `.daemon-panel__session-row` ~32px effective height so eye-rhythm is preserved when switching tabs.
- Status line height is **28px** (matches existing `.tab-status-bar` 32px minus 4px to differentiate visually that this is INSIDE the tab content, not the tab chrome).
- Icon-only action buttons in the preview header are **24×24px** clickable target (not 44px — desktop-first app; touch target relief is provided by row click-targets being 32px tall, which clears WCAG 2.5.5 Level AAA touch on the only on-by-default actionable region).

## Typography

Body default is monospace (Cascadia Code) inherited from `body`. The markdown preview region is the **only** place where a proportional (sans) stack is used — and only inside `.file-browser__preview--markdown`. Source-code preview (UI-08) is monospace.

| Role | Size | Weight | Line Height | Family | Usage |
|------|------|--------|-------------|--------|-------|
| Body (file rows, breadcrumb, status line) | 13px | 400 | 1.4 | inherit (Cascadia Code mono) | All list rows, breadcrumb text, status line |
| Label (column header, "Last refreshed", small captions) | 11px | 600 | 1.3 | inherit (mono) | Uppercase `letter-spacing: 0.08em` per existing `.welcome-tab__heading` / `.daemon-panel` headers |
| Heading (tab title shown in tab bar) | 13px | 400 | 1.4 | inherit | Composes as `{sessionName} — Files` (see Copywriting) |
| Mono preview (text + source code) | 12px | 400 | 1.5 | `'Cascadia Code', 'Fira Code', monospace` | UI-08 plain text / source files in `.file-browser__preview--text` |
| Prose preview (markdown body) | 14px | 400 | 1.6 | `system-ui, -apple-system, 'Segoe UI', sans-serif` | UI-07 rendered markdown body inside `.file-browser__preview--markdown`. Headings inside the rendered body follow `react-markdown` defaults; restrict to h1 24px / h2 20px / h3 16px / h4-h6 14px, all weight 600 |
| Filename in preview header | 13px | 600 | 1.4 | inherit (mono) | Bold weight differentiates filename from path segments without relying on color (colorblind-safe) |

Exactly **3 base sizes** (11/12/13) plus **two preview-only escape sizes** (14 prose, 16-24 markdown headings rendered by `react-markdown`). Exactly **2 weights**: 400 regular and 600 semibold. No italic except inherited `font-style: italic` for placeholders matching the existing `.tab-status-bar__hint` pattern.

## Color

AgentHub uses the **TokyoNight** palette across the whole frontend. The file browser MUST reuse the existing tokens already loaded into `style.css` — no new hex codes are introduced by this phase.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) — page surface | `#1a1b26` | Tab content background, list pane background |
| Secondary (30%) — chrome surface | `#16161e` | Breadcrumb bar background, status line background, preview pane background (so list/preview have a subtle 1-step contrast); column header background |
| Elevated surface | `#1e2030` | Hover row, selected row background, action button hover |
| Border / divider | `#292e42` | All borders (1px), divider between list and preview panes |
| Accent (10%) — primary action | `#7aa2f7` | Selection underline / left-border on the active row; "Download" primary button background; breadcrumb current-segment text; clickable breadcrumb segment text; the focus ring (`outline: 2px solid #7aa2f7; outline-offset: 2px;` matching existing `:focus-visible` style); the staleness "Refresh" link; the column-header sort indicator chevron |
| Primary text | `#c0caf5` | Filenames in rows, selected-row text, preview body text (mono + prose) |
| Secondary text | `#a9b1d6` | Mtime + size columns, breadcrumb non-current segments, action button labels |
| Muted text | `#9aa5ce` | Empty / placeholder copy, "0 items", column headers (uppercase), filter hint, error state body, "Last refreshed Ns ago" status |
| Subtle muted | `#565f89` | Disabled action button, "preview unavailable" caption inside binary refusal, broken-symlink target path |
| Destructive | `#f7768e` | Error state heading and left-border accent on error banner (matches `.banner--error` + `.exit-toast__item--error`); broken-symlink warning marker; "files.read permission required" left-border |
| Warning | `#f59e0b` | Over-cap notice left-border (warning, not destructive); "directory truncated at 10,000 entries" notice |
| Success | `#9ece6a` | (Reserved) — used only if a "Copy path" affordance lands in v3.5; not used in v3.4. Listed here so v3.5 has a defined token. |

**Accent reserved for** (exhaustive list — checker will fail if `#7aa2f7` appears anywhere else):
1. Active row left-border indicator (3px wide, `border-left: 3px solid #7aa2f7`) — primary selection signal
2. Active row text color override (filename only) — secondary selection signal
3. Primary "Download" button background (`background: #7aa2f7; color: #1a1b26;` — same recipe as `.settings-panel__btn--save`)
4. Current breadcrumb segment text color (also has `aria-current="page"` for non-color signal)
5. Clickable breadcrumb segment hover text color
6. Focus ring outline color (universal `:focus-visible`)
7. Sort indicator chevron in the active sort-column header
8. The "Refresh" action affordance text color (button-as-link styling)
9. Inline link inside markdown preview (`react-markdown` `<a>` color, no other styling change)

**Colorblind contract** (user is colorblind — per project memory):
- **Selection** is signalled by THREE non-color channels in addition to the accent color: (a) the 3px left border, (b) the `aria-selected="true"` state, (c) an inverted background (`#1e2030` vs `#1a1b26`).
- **File-type** is signalled by an icon prefix (Heroicons: `FolderIcon` for directories, `DocumentIcon` for files, `PhotoIcon` for images, `DocumentTextIcon` for markdown/text, `LinkIcon` for symlinks, `ExclamationTriangleIcon` for broken symlinks) — never by color alone.
- **Sort direction** is signalled by an explicit `▲` / `▼` glyph (Heroicons `ChevronUpIcon` / `ChevronDownIcon`) — never by color alone.
- **Error vs warning vs info banners** all reuse the existing `.banner` / `.banner--info` / `.banner--error` shape AND each includes an explicit textual label in the heading ("Cannot read file", "File too large to preview", "Permission required") — never expects the user to distinguish red-vs-amber-vs-blue.
- **Status indicators** (loading, stale, etc.) carry text ("Loading…", "Refreshed 12s ago") — never a bare colored dot.

**Contrast verification** (must hold at implementation time):
- `#c0caf5` on `#1a1b26` = primary text on dominant surface → **11.5:1** (passes AAA)
- `#c0caf5` on `#1e2030` = selected row text on selected background → **10.4:1** (passes AAA)
- `#9aa5ce` on `#1a1b26` = muted text on dominant surface → **7.2:1** (passes AA Large 3:1 and AA 4.5:1)
- `#565f89` on `#1a1b26` = subtle muted on dominant → **4.0:1** (passes AA Large 3:1 only; reserved for non-essential captions per Pitfall 9 / WCAG)
- `#7aa2f7` on `#1a1b26` = accent text on dominant → **8.4:1** (passes AAA)
- Selection left-border `#7aa2f7` on background `#1e2030` = **3.7:1** (passes AA non-text 3:1 for graphical indicators per WCAG 1.4.11)

```
│ └────────────────────────────────────────────────────────────────────┘ │

```

- **Split ratio:** 40/60 list/preview by CSS `flex-basis: 40%` with `min-width: 240px` and `max-width: 480px` on the list pane; the preview pane is `flex: 1 1 auto`.
- **Narrow viewport (< 720px):** the preview pane collapses; the list pane fills the row. Selecting a file opens the preview as a full-width overlay below the breadcrumb (still inside the tab, no modal). Triggered by container CSS query `@container (max-width: 720px)` — falls back to viewport media query if container queries are not viable.
- **Divider:** 1px `#292e42` between list pane and preview pane. No drag-to-resize in v3.4 (deferred — not in UI-02 scope which says "splitter OR fixed 60/40"; fixed 40/60 is the locked choice).
- **No left sidebar tree inside the tab** (UI-02 + FEATURES.md "Why NOT tree + list"). The AgentHub left sidebar (`.sidebar`) remains the only navigation chrome.

## Interaction Contract

### Keyboard map (UI-12)

| Key | Focus = List | Focus = Preview | Focus = Filter |
|-----|--------------|-----------------|----------------|
| ↑ / ↓ | Move row selection (wraps at top/bottom: no — stops at edge) | Scroll preview by line | Move match cursor through filter results |
| Home / End | Jump to first / last row | Scroll to top / bottom | (default text-input behavior) |
| PgUp / PgDn | Scroll list by viewport height | Scroll preview by viewport height | n/a |
| Enter | Open directory (if dir) / focus preview (if file already selected) | (no-op) | Apply filter — focus first match in list |
| Backspace | Navigate to parent directory (no-op at session cwd root — UI-05) | (default text-input behavior — but preview is non-editable, so no-op) | Delete last filter char; empty filter → no-op (does NOT trigger parent navigation — disambiguation per Pitfall 12) |
| Tab | Move focus to preview pane (UI-12) | Move focus to status line / next focusable | Move focus to list |
| Shift+Tab | Move focus to breadcrumb / previous focusable | Move focus to list | Move focus to refresh button |
| `/` | Activate filter input (move focus there) | Activate filter input | n/a (already focused) |
| Escape | (no-op) | Move focus back to list | Clear filter text AND dismiss; focus returns to list |
| Cmd/Ctrl-F | Browser/Wails native find (do NOT intercept — file browser tab has no xterm; let the native browser find bar appear) | Same | Same |
| Double-click (mouse) | Open directory / open preview for file (UI-01 success criteria; FEATURES.md confirms double-click = open semantics) | (default) | n/a |
| Single-click (mouse) | Select row (shows preview if file) | (default text selection in preview) | n/a |

**Focus order on tab mount:**
1. Breadcrumb root segment (skipped if not clickable — root segment is plain text)
2. Refresh control
3. Column headers (Name → Size → Modified)
4. First file row in the list (auto-selected = first directory entry, or first file if no directories)
5. Preview pane (if a file is selected)
6. Status line filter input (when focused via `/` or Tab)

**Initial selection:**
- If the current directory is non-empty: first row is `aria-selected="true"`, list pane has focus, preview reflects that selection.
- If empty: focus rests on the breadcrumb refresh control.

### Pointer interactions

- **Single-click row:** select + preview (no navigation into directory — matches GitHub web viewer pattern from FEATURES.md).
- **Double-click row (directory):** navigate into.
- **Double-click row (file):** focus preview pane (no-op if already focused).
- **Click column header:** toggle sort column. Sequence: click "Name" while name-ascending → name-descending; click "Size" while name-ascending → size-descending (first click on a new column always goes to its default direction per FEATURES.md sort defaults — size + mtime default descending; name defaults ascending).
- **Click breadcrumb segment:** navigate to that segment (no-op if it is the root segment, which is rendered as non-clickable text).
- **Click refresh:** re-fetch current directory listing; preserve selection if the file still exists.
- **Click Download (in preview header):** trigger browser download via `<a download href="/api/files/read?...">` element activation — uses the Range-capable endpoint (UI-10).

### State machine — preview pane

```
state          trigger                                  visual
─────          ───────                                  ──────
idle           No file selected                         "Select a file to preview" (muted #9aa5ce, centered)
loading        Selection changed                       Centered spinner (reuse .remote-panel__spinner CSS) + "Loading preview…"
text           file is text, size ≤ 5 MB               Monospace 12px, plain text, scrollable
markdown       extension in {.md, .markdown}           Rendered react-markdown + remark-gfm, prose stack 14px
image          extension in {.png,.jpg,.jpeg,.webp,.gif,.svg} | <img src> direct (UI-09), object-fit:contain
empty          file is 0 bytes                         "Empty file (0 bytes)." muted
unsupported    binary OR mime not previewable          Heading "Sorry, we can't display this file" + Download button (UI-06)
over-cap       size > 5 MB                             Heading "File too large to preview" + body "Showing previews up to 5 MB; this file is {actual.size}" + Download button
broken-symlink stat resolves to ENOENT via symlink     Heading "Broken symlink" + body "Target {target.path} does not exist."
read-error     read returned 5xx or net error          Heading "Could not read this file" + body "Network error" or "I/O error" + Retry button
forbidden-file specific file 403 from /read            Heading "Cannot read this file" + body "The session does not have permission to read it" (rare — list returned the entry but read denied)
```

### State machine — directory listing

```
state                trigger                                          visual
─────                ───────                                          ──────
loading              Initial mount / navigate / refresh in flight     Replace list rows with 6 skeleton rows (animated shimmer using #1e2030 → #292e42 transition; reuse .remote-panel__spinner for hold/wait > 250ms)
loaded               200 with N entries                               Render rows; status line shows "N items"
empty                200 with 0 entries                               Centered in list pane: heading "This directory is empty." body (muted) "{currentPath}" — UI-13
truncated            X-Directory-Truncated: true header               Banner above list (warning amber border-left, .banner shape): "Showing first 10,000 entries. Use the terminal to inspect deeper." Status line shows "10,000+ items (truncated)"
permission-denied    403 from /list (NOT a files.read failure — a per-directory chmod-denied) | UI-13: replace list with .banner--error: heading "Permission denied" body "Cannot list {currentPath}." NO retry button (won't change without write).
not-found            404 from /list                                   Replace list with .banner: heading "Directory not found" body "It may have been moved or deleted." Action: "Go to root" button (returns to session cwd)
files-read-denied    403 with body containing "files.read"            Full-tab takeover: heading "files.read permission required." body "Ask the session owner to re-share this session with file access enabled." network-error        fetch rejected / timeout                         Replace list with .banner--error: heading "Could not load directory" body "Network error." Action: "Retry" button. Also emit a banner-stack entry (use the existing `.banner` mechanism) so the user sees it if they navigate away.
not-authorized       401 (no cap token)                               Same shape as files-read-denied but copy: heading "Not authorized" body "Sign in or re-open this session to refresh credentials." NO retry.
```

### Filter activation (UI-04)

- Activation: `/` key when **focus is anywhere inside the file browser tab** AND no other text input has focus.
- Implementation: `useEffect`-mounted document-level key listener checks `event.key === '/'` AND `!(event.target instanceof HTMLInputElement)` AND `tabIsActive` AND `event.target` is inside the tab — same `isXtermFocused`-style gating pattern as `frontend/src/lib/isXtermFocused.ts` (focus-conditional handling).
- Filter input renders inline in the status line (`role="searchbox"` `aria-label="Filter files in current directory"`). Status line right-side shows the filter input only while active.
- As-you-type: case-insensitive substring match (NOT fuzzy — FEATURES.md "predictable for this context"). Current directory only. Directories and files both included.
- Status line shows `Filtering: "{query}" — {N} matches` while active.
- Escape clears the input AND closes filter mode AND returns focus to the list pane with the original selection restored (or first row if original is no longer visible).
- Filter does NOT persist across directory navigation — clears on every navigate.

### Sort interaction (UI-03)

- Default: Name ascending. Directories sticky at top (always — UI-03 + FEATURES.md "directories-first always ON in v3.4").
- Clicking the active sort column toggles direction.
- Clicking a different column moves sort to that column at the column's default direction (Name: asc; Size: desc; Modified: desc).
- The active sort column's header shows a `▲` or `▼` chevron in `#7aa2f7` (accent — also conveys via the explicit glyph for colorblind users) and `aria-sort="ascending"`/`"descending"`. Inactive columns have `aria-sort="none"` and no chevron.

### Refresh interaction (UI-11 / Pitfall 11)

- Refresh button in the breadcrumb bar right side: icon-only (`ArrowPathIcon` from Heroicons) with `aria-label="Refresh directory listing"`.
- Adjacent label "Last refreshed Ns ago" (#9aa5ce muted) — updates every 5s via a `setInterval` on the component, cleared on unmount.
- Keyboard shortcut: `R` when focus is inside the file browser tab (but NOT inside the filter input) re-fetches the current directory listing.
- The X-Refreshed-At header (Pitfall 11) sets the baseline timestamp. If the response lacks the header (older daemons), use `Date.now()` at fetch completion.

## Copywriting Contract

Voice: terse, functional, no apologies. Copy never says "Oops" or "Something went wrong" — it names the failure and the next step.

### Action labels

| Element | Copy |
|---------|------|
| Primary CTA in unsupported / over-cap preview | `Download` |
| Refresh button aria-label | `Refresh directory listing` |
| Filter input aria-label | `Filter files in current directory` |
| Filter input placeholder (visible only while active) | `Type to filter…` |
| Sort column headers (uppercase tracked, like existing `.daemon-panel` headers) | `NAME`, `SIZE`, `MODIFIED` |
| Tab name (in TabBar) | `{sessionName} — Files` |
| Open file browser context menu item | `Browse files` (lowercase verb + lowercase noun matches existing `.tab__context-menu__item` style — "Rename", "Save as…", "Browse files") |
| DaemonManagerPanel action button | `Browse files` (matches existing `Kill` / `Web` button style) |

### Empty / status copy

| Element | Heading | Body |
|---------|---------|------|
| Empty directory | `This directory is empty.` | `{relativePathFromCwd}` (muted, for context) |
| Empty file (preview) | `Empty file` | `0 bytes` (muted) |
| Idle preview (no file selected) | — | `Select a file to preview` (muted, centered) |
| Loading directory (during initial fetch > 250ms) | — | `Loading…` (muted in status line) |
| Loading preview | — | `Loading preview…` (muted, centered, with spinner) |
| Filter active, zero matches | — | `No files match "{query}"` (muted, centered in list pane below header) |
| Truncated directory | `Showing first 10,000 entries.` | `Use the terminal to inspect deeper directories.` |
| Stale indicator | — | `Last refreshed {N}s ago` (muted) — uses "s" for seconds, "m" for minutes >60s ("Last refreshed 2m ago"), "just now" for <5s |

### Error copy (UI-13)

Every error state must (a) name the problem in the heading, (b) give the next step in the body, (c) NOT show the raw HTTP status. The heading is the only place the user has to read to know what's wrong.

| Element | Heading | Body | Action button |
|---------|---------|------|---------------|
| files.read permission missing (full-tab takeover) | `files.read permission required` | `Ask the session owner to re-share this session with file access enabled.` | none — irrecoverable from the viewer side |
| Per-directory permission denied | `Permission denied` | `Cannot list {relativePathFromCwd}.` | none |
| Directory not found | `Directory not found` | `It may have been moved or deleted.` | `Go to root` |
| Network error on list | `Could not load directory` | `Network error. Check your connection and try again.` | `Retry` |
| Not authorized (401) | `Not authorized` | `Sign in or re-open this session to refresh credentials.` | none |
| Read error on file (network) | `Could not read this file` | `Network error. Check your connection and try again.` | `Retry` |
| Read forbidden on a specific file (rare 403 on /read) | `Cannot read this file` | `The session does not have permission to read it.` | none |
| Binary file refusal | `Sorry, we can't display this file.` | `This file is not text. Download it to view in another app.` | `Download` |
| Over-cap refusal (size > 5 MB) | `File too large to preview` | `Previews are limited to 5 MB. This file is {humanSize}.` | `Download` |
| Broken symlink | `Broken symlink` | `Target {targetPath} does not exist.` | none |
| HTML file source-display label (Pitfall 9 — `.html`/`.htm`/`.xhtml` always served as text/plain) | — | `HTML (displayed as source)` (muted label above the mono preview) | none |
| Directory truncated banner | `Showing first 10,000 entries.` | `Use the terminal to inspect deeper directories.` | none |

### No destructive actions in v3.4

There are no delete / overwrite / rename actions in this phase. Download is non-destructive (browser-mediated save). The closest-to-destructive trigger is "Refresh" which discards a stale listing — no confirmation needed because it cannot lose user work.

## Accessibility Contract (UI-12)

### Landmarks and roles

| Element | Role / ARIA |
|---------|-------------|
| Top-level tab container | `<section role="region" aria-label="File browser">` |
| Breadcrumb | `<nav aria-label="Path">` containing `<ol>` of `<li>` segments; current = `aria-current="page"` |
| File list | `role="listbox"` with `aria-label="Directory contents"` and `aria-multiselectable="false"` |
| Each row | `role="option"` with `aria-selected={true|false}` and `aria-label="{name}, {type}, {size}, modified {mtime}"` (mtime read as human-relative for screen readers) |
| Column header row | `<div role="row">` containing three `<button role="columnheader" aria-sort={"ascending"|"descending"|"none"}>` |
| Preview pane | `<section role="region" aria-label="File preview" aria-live="polite">` — `aria-live="polite"` so SR announces the filename and type on selection change |
| Status line | `<div role="status" aria-live="polite">` — wraps the item count and filter status |
| Filter input | `<input type="search" role="searchbox" aria-label="Filter files in current directory">` |
| Error / takeover regions | `role="alert"` with `aria-live="assertive"` |
| Loading skeleton | `aria-busy="true"` on the listbox during load |
| Icons | `aria-hidden="true"` on the Heroicons SVG — the text name is the accessible label |

### Focus visible

Universal `:focus-visible { outline: 2px solid #7aa2f7; outline-offset: 2px; }` matches existing `.settings-jump-bar__link:focus-visible` / `.banner > button:focus-visible` style. No element opts out of this — including double-clicked rows.

### Keyboard-only flow (must work end-to-end)

1. Tab into the file browser tab content from the TabBar.
2. Tab through: refresh → column headers → first row → ...
3. Arrow keys navigate rows.
4. Enter on a directory navigates in; Backspace navigates out.
5. Tab moves to the preview pane; arrow keys scroll preview.
6. `/` activates filter; Escape clears; Enter applies + returns to list.
7. Enter on the Download button in a preview header triggers browser download.

### Screen-reader announcements

- On directory navigate: announce "Loaded {N} items in {newDirName}" via the listbox `aria-busy` toggle and the `role="status"` count.
- On selection change: announce "{filename}, {type}, {size}" via the row's `aria-label` (consumed because focus moves to the new row).
- On preview load: the preview pane's `aria-live="polite"` announces "Previewing {filename}" via a hidden `<span class="sr-only">` (utility class to be added: `.sr-only { position: absolute; width: 1px; height: 1px; padding: 0; margin: -1px; overflow: hidden; clip: rect(0,0,0,0); white-space: nowrap; border: 0; }`).
- On error: the error region's `role="alert"` announces the heading immediately.

### Motion + reduced motion

- Skeleton shimmer animation is paused under `@media (prefers-reduced-motion: reduce)` (matches the existing `.webgl-recovery-banner` reduced-motion contract).
- Spinner rotation continues (250ms minimum) under reduced motion because it is a load-state semaphore, not decoration. If `prefers-reduced-motion: reduce` is set, the spinner is replaced with a static `…` character with the same `aria-busy` semantics.

## CSP Contract (UI Phase consequence of WEB-05 / Pitfall 9)

The existing CSP is:
```
script-src 'self' 'wasm-unsafe-eval';
style-src 'self' 'unsafe-inline';
img-src 'self' data:;
```

This phase MUST NOT amend the CSP. Specifically:
- **Image preview** uses `<img src="/api/files/read?session=…&path=…&cap=…">` — same-origin URL, covered by `img-src 'self'`. No `blob:` URLs are constructed. No base64 data URIs are constructed (UI-09).
- **Markdown rendering** uses `react-markdown` WITHOUT `rehype-raw` and WITHOUT MDX. Default `react-markdown` does not render embedded `<script>` or `<style>`; embedded raw HTML in `.md` files renders as escaped text — acceptable per UI-07.
- **HTML files** (`.html`, `.htm`, `.xhtml`) are served by the daemon as `Content-Type: text/plain` (Phase 118 contract) and rendered in the text preview path with the "HTML (displayed as source)" label.
- **SVG files** render via `<img src="…">` (UI-09) — the browser sandboxes inline behavior. Never inject SVG into the DOM via `dangerouslySetInnerHTML` or as React children.

The Playwright e2e CSP smoke (WEB-05) must continue to report zero violations after this phase ships.
