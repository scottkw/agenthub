## Phase 155 Interaction Contracts

### 1. Export Button (EXPORT-01)

**Placement:** Inside the ChatPanel drawer header, right side — positioned after the participant
count pill and before the close/collapse button. The header layout becomes:

```
[Chat]  [N participants]                    [Export]  [Close]
```

**Visual spec:**
- Icon: `ArrowDownTrayIcon` (heroicons/24/outline, 18×18px)
- Touch target: 36×36px minimum
- Resting foreground: `--hub-text-muted`
- Resting background: transparent
- Hover background: `--hub-surface-elevated`
- Active transform: `scale(0.95)` on pointer-down (2-frame snap, no duration)
- Border-radius: `var(--hub-radius-sm)` (8px)
- Tooltip: `title="Export chat as Markdown"` (native tooltip, no custom component)
- `aria-label`: `"Export chat as Markdown"`
- `data-chat-export` attribute: required (Playwright parity gate selector)

**Behavior:**
- Click triggers `triggerExport(buildExportURL(...))` using programmatic hidden-anchor pattern (see RESEARCH.md §Export Design)
- Desktop surface URL: `http://127.0.0.1:{relayPort}/api/chat/{sessionId}/export`
- Web-share surface URL: `{window.location.origin}/api/chat/{sessionId}/export?cap={encodeURIComponent(capToken)}`
- Browser receives `Content-Disposition: attachment; filename="chat-{id}.md"` from server — triggers native download prompt
- The `download` attribute on the hidden anchor is empty string: `a.download = ''` — lets the server's Content-Disposition filename win
- Export is available in both RO and RW cap modes (export is read-only access, not write)
- The button renders at all times the drawer is open (not gated on message count)

**Download trigger pattern (both surfaces):**
```typescript
function triggerExport(url: string): void {
  const a = document.createElement('a')
  a.href = url
  a.download = ''
  document.body.appendChild(a)
  a.click()
  document.body.removeChild(a)
}
```

### 2. RO-Cap Client-Side Suppression (PARITY-01 SC-3)

When the current user is a read-only cap holder, the UI must suppress the send path
as defense-in-depth (server-side gating is authoritative; this is supplementary UX).

**RO status detection:** Derived from the presence roster broadcast. When the current
user's own entry appears in the presence frame with `ReadOnly: true`, set local `isReadOnly`
state. On the web-share surface, the WebSocket is established with a RO JWT, so the server
marks the subscriber as ReadOnly before the first presence broadcast.

**Suppressed elements:**

| Element | RO State |
|---------|----------|
| Send button | `disabled` attribute present; `aria-disabled="true"`; `opacity: 0.4`; `cursor: not-allowed` |
| Inject gesture (press-and-hold) | Handler short-circuits immediately on pointer-down; no visual fill animation |
| Composer textarea | Remains interactive (user can still read and copy) but pressing Enter produces no send |
| `data-chat-send` attribute | Present on the button in both states; Playwright asserts `toBeDisabled()` when RO |

**RO indicator in composer area:**
- A read-only label renders below the composer: `"Read only"` — 11px, `--hub-text-dim`, left-aligned
- This label is present only when `isReadOnly === true`
- It does not replace the composer; the composer remains visible and selectable

**Send button `data-chat-send` attribute:** Must be present on the button element in both
RW (enabled) and RO (disabled) states so Playwright can query it regardless of state.

### 3. WebShareSessionView Component (PARITY-01)

A new thin wrapper component at `frontend/src/components/Hub/WebShareSessionView.tsx`
that composes `TerminalPanel` + `ChatPanel` for the web-share surface.

**Layout structure:** Identical to `HubInteractiveModal` (overlay mode, D-02) — the chat
drawer floats over the terminal with `position: absolute`. Same CSS class names must be
used so Playwright selectors work on both surfaces.

**Required CSS classes (must match HubInteractiveModal exactly):**

| Element | CSS Class |
|---------|-----------|
| Root container | `hub-modal__body hub-modal__body--interactive` |
| Chat toggle button | `hub-modal__chat-toggle` |
| Terminal container | `hub-modal__terminal` (or equivalent existing class) |
| Chat drawer root | `chat-panel` |
| Chat open state | `chat-panel--open` |

**Dimensions and positioning:** 100% width, 100% height of the enclosing tab content area.
ChatPanel overlay width: 360px (identical to desktop, D-01). Terminal fills full width
beneath (terminal is never resized by chat opening, D-02).

**Props the component receives:**
```typescript
interface WebShareSessionViewProps {
  sessionId: string
  capToken: string          // from readWebModeParams()
  relayPort: number         // 0 on web-share — safe sentinel, ignored when wsURL present
  theme?: TerminalTheme
  pluginConfig?: PluginConfig
}
```

**WS URL construction (inside the component):**
```typescript
const wsURL = `wss://${window.location.host}/sessions/${encodeURIComponent(sessionId)}/ws?cap=${encodeURIComponent(capToken)}`
const apiBaseURL = window.location.origin
```

Both `TerminalPanel` and `ChatPanel` receive the same `wsURL` override so they connect
to the webserver (not the loopback relay).

### 4. App.tsx Web-Mode Tab Layout (PARITY-01)

When `mode === 'web'` and `webParams.sessionId` is present, the App.tsx bootstrap opens:

1. **Primary tab (active):** Session view — `WebShareSessionView` with session ID and cap token. Tab label: `"Session"` (or the session ID truncated to 20 chars, `aria-label` = full session ID).
2. **Secondary tab (background):** File browser tab — `handleOpenFileBrowser(webParams.sessionId, webParams.sessionId)`. Shows `PermissionDeniedTakeover` if the cap lacks `files.read` (existing behavior, no change required).

The session view tab is set as the active tab on mount. File browser tab opens in background.
No change to the tab bar visual style — reuses existing tab patterns.

## Export File Format Contract (EXPORT-01)

The downloaded `.md` file must match this structure exactly (for both desktop and web-share):

```markdown
---
session: {sessionId}
exported_at: {ISO-8601 UTC timestamp}
participants:
  - "{alias} ({tailnetID})"
  - "{alias2} ({tailnetID2})"
---

# Chat: {sessionId}

## {alias} ({tailnetID}) — {ISO-8601 UTC timestamp}

{message content — Markdown preserved}

_injected into terminal_

---

```

Rules:
- YAML fences: `---` on their own line
- `session` value: bare session ID (no quoting needed — `[A-Za-z0-9_-]` only)
- `exported_at`: `time.Now().UTC().Format(time.RFC3339)` (Go)
- `participants`: ordered by first appearance; values always double-quoted to handle `:` and `#` in aliases
- Alias embedded `"` characters: escaped as `\"` in the YAML string value
- Message headers: `## {alias} ({tailnetID}) — {ISO-8601 UTC}`
- Inject indicator: `_injected into terminal_` on its own line, blank line before and after
- Section separator: `---` (blank line before and after each message separator)
- File is GitHub-compatible Markdown (YAML frontmatter recognized by GitHub renderer)
