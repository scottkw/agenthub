## Spacing Scale

This phase does not introduce new spacing. All spacing tokens are inherited from the Hub surface established in Phases 131–134. The existing 4-point scale is in use throughout the hub-card, hub-modal, and hub-filter rules.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- Focus ring `outline-offset: 2px` is a sub-4px exception for optical alignment — consistent with the existing pattern throughout style.css.
- Touch target minimum for keyboard-interactive cards: cards must be at least 44px tall to satisfy WCAG 2.5.5. The existing `padding: 12px 16px` on `.hub-card` already achieves this for non-empty cards; no change required.

### Colorblind-safe constraint (release-blocking)

The project owner is colorblind. Color may NEVER be the sole carrier of meaning. Every status and attention state must be uniquely identifiable without color. The contract below is the single authoritative record — verify at source against these hex constants, not by eye.

**Per-state icon + color + text inventory (SessionCard `STATUS_CONFIG`):**

| HubStatus | Icon (Heroicons) | Color token (dark) | Color token (light) | Text label | Attention |
|-----------|-----------------|-------------------|--------------------|-----------:|-----------|
| `running` | `ArrowPathIcon` (spinning) | `#3b82f6` (reinf.) | `#1d4ed8` (reinf.) | "Running" | no |
| `idle` | `CheckCircleIcon` | `#22c55e` (reinf.) | `#1a7f37` (reinf.) | "Idle" | no |
| `waiting` | `PauseCircleIcon` | `#f59e0b` (reinf.) | `#92400e` (reinf.) | "Needs input" | YES |
| `errored` | `ExclamationCircleIcon` | `#ef4444` (reinf.) | `#b91c1c` (reinf.) | "Error" | YES |
| `stopped-ok` | `StopCircleIcon` | `#565f89` (reinf.) | `#4b5563` (reinf.) | "Done" | no |
| `stopped-err` | `ExclamationCircleIcon` | `#f7768e` (reinf.) | `#c0394f` (reinf.) | "Exited {code}" | YES |

Note: `running` uniqueness is carried by spinning motion (ArrowPathIcon rotates). Under `prefers-reduced-motion: reduce` the spin stops — the icon shape (circular arrow) still distinguishes it from `idle` (CheckCircleIcon), `waiting` (PauseCircleIcon), and `stopped` (StopCircleIcon). No additional cue required.

Note: `waiting` and `stopped-err` both receive the **attention treatment** (BellAlertIcon overlay + pulse/static-border). The three attention states (`waiting`, `errored`, `stopped-err`) are distinguished from each other by their primary icon and text label even when the attention overlay is present.

### A11Y-02: Keyboard operability

**Status:** Partially implemented. Gaps identified in codebase scan.

#### 2a. Cards are keyboard-focusable (IMPLEMENTED)
`SessionCard` has `tabIndex={0}` and `onKeyDown` handling `Enter`/`Space` → `onCardClick`. Already in place (Phase 134).

#### 2b. Enter/Space expands card (IMPLEMENTED)
`SessionCard.onKeyDown` calls `onCardClick(session, rect)` on `Enter` or `Space`. Already in place.

#### 2c. Escape closes modal and returns focus (IMPLEMENTED)
`HubModal` registers a `document` keydown listener for Escape, calls `handleClose`. `cardFocusRef` captures `document.activeElement` at mount and calls `.focus()` on unmount. Already in place (Phase 134 WR-05/WR-06 were about scope concerns, not missing behavior).

**WR-05 fix required:** Replace `stopImmediatePropagation` on the document-level Escape handler with a scoped dialog-level `onKeyDown` handler so other document-level Escape handlers are not globally suppressed.

Contract: Escape key handler must be on the `role="dialog"` element's `onKeyDown`, not `document.addEventListener`. Use `e.stopPropagation()` (not `stopImmediatePropagation`) to prevent bubbling to the Hub card menu listener — this is sufficient because the dialog renders in its own overlay stacking context.

#### 2d. `/` focuses search (IMPLEMENTED)
`HubPanel` has `window.addEventListener('keydown', ...)` for `e.key === '/'` with the guard `document.activeElement?.tagName !== 'INPUT'`. Already in place. No change required.

#### 2e. Focus-visible rings (GAP — NOT IMPLEMENTED)

Current state: `.hub-card:focus` uses `outline: 2px solid var(--hub-accent)` (not `:focus-visible`). Filter pills, group sidebar items, modal buttons, and the Open button have no `:focus-visible` rules.

**Required changes:**

| Element | Selector | Required Rule |
|---------|----------|--------------|
| Session card | `.hub-card:focus-visible` | `outline: 2px solid var(--hub-accent); outline-offset: 2px;` |
| Session card (upgrade from `:focus`) | `.hub-card:focus` | Remove or change to `:focus-visible` |
| Filter pill | `.hub-filter__pill:focus-visible` | `outline: 2px solid var(--hub-accent); outline-offset: 2px;` |
| New session button | `.hub-filter__new-session:focus-visible` | `outline: 2px solid var(--hub-accent); outline-offset: 2px;` |
| Open button | `.hub-card__open:focus-visible` | `outline: 2px solid var(--hub-accent); outline-offset: 2px;` |
| Menu button | `.hub-card__menu-btn:focus-visible` | `outline: 2px solid var(--hub-accent); outline-offset: 2px;` |
| Menu item | `.hub-card__menu-item:focus-visible` | `outline: 2px solid var(--hub-accent); outline-offset: 2px;` |
| Modal close button | `.hub-modal__close:focus-visible` | `outline: 2px solid var(--hub-accent); outline-offset: 2px;` |
| Modal send button | `.hub-modal__send-btn:focus-visible` | `outline: 2px solid var(--hub-accent); outline-offset: 2px;` |
| Modal close-btn (briefing) | `.hub-modal__close-btn:focus-visible` | `outline: 2px solid var(--hub-accent); outline-offset: 2px;` |

Focus ring token (single source):

- Ring width: `2px solid`

#### 2f. Filter pill aria-pressed (GAP — NOT IMPLEMENTED)

Filter pill buttons have no `aria-pressed` or `aria-selected` attribute. Screen readers have no way to determine the active filter.

**Required change:** Add `aria-pressed={activeFilter === key ? 'true' : 'false'}` to each `.hub-filter__pill` button in `HubFilterBar.tsx`.

### A11Y-03: prefers-reduced-motion

**Status:** Partially implemented. Core pulse and modal grow/shrink already gated. Gaps identified.

#### Already implemented:
- `.hub-card--attention` pulse animation wrapped in `@media (prefers-reduced-motion: no-preference)` (style.css line 4927)
- Reduced-motion static border: `@media (prefers-reduced-motion: reduce)` sets `border-color: var(--hub-attn-static-border); animation: none` (line 4950)
- Modal grow/shrink keyframes gated in `@media (prefers-reduced-motion: no-preference)` (line 5357)
- Modal reduced-motion: instant appear/disappear with `animation: none; transition: none; opacity: 1; transform: none` (line 5374)
- `HubModal.tsx` reads `window.matchMedia('(prefers-reduced-motion: reduce)')` at mount and skips `entering`/`exiting` phases entirely (lines 95–99, 101–107) — prevents the modal from getting stuck when `onAnimationEnd` never fires (GAP-134-D fix)

#### Gaps:

**Gap 1 — Group sidebar width transition** (style.css line 4699)

The group sidebar collapse/expand uses a CSS `width` transition gated in `@media (prefers-reduced-motion: no-preference)`. This is ALREADY correct. No change required — confirming here for completeness.

**Gap 2 — Card hover transition**

`.hub-card` has `transition: border-color 100ms ease, background 100ms ease`. Under `prefers-reduced-motion: reduce`, this transition should be suppressed.

**Required addition:**
```css
@media (prefers-reduced-motion: reduce) {
  .hub-card {
    transition: none;
  }
}
```

**Gap 3 — Drag handle / menu button opacity transition** (style.css line 4965)

`.hub-card__drag-handle, .hub-card__menu-btn` opacity transition is already gated in `@media (prefers-reduced-motion: no-preference)`. Already correct.

**Gap 4 — Running (spin) animation under reduced-motion**

`ArrowPathIcon` with `.hub-card__status-icon--spin` uses `animation: spin 0.8s linear infinite` (style.css line 1543). This is NOT gated. Under `prefers-reduced-motion: reduce`, the spin must stop.

**Required addition:**
```css
@media (prefers-reduced-motion: reduce) {
  .hub-card__status-icon--spin {
    animation: none;
  }
}
```

The `running` state is still distinguishable without spin: ArrowPathIcon shape is unique among status icons. Text label "Running" is also present. No additional cue required.

**Static fallback summary for reduced-motion:**

| Animated feature | Motion path | Reduced-motion fallback |
|-----------------|-------------|------------------------|
| Attention pulse (hub-attn-pulse) | Pulsing amber border glow | Static `var(--hub-attn-static-border)` border, no glow, BellAlertIcon present |
| Modal grow (hub-modal-grow) | Scale from card origin | Instant appear at full size, opacity 1, no transform |
| Modal shrink (hub-modal-shrink) | Scale back to card origin | Instant disappear (synchronous onClose) |
| Overlay fade in/out | Opacity animation | Instant opacity 1 / removal |
| Running icon spin | Infinite rotation | Static icon (ArrowPathIcon shape still unique) |
| Card hover transition | 100ms border/bg ease | No transition (change is instant) |
| Group sidebar collapse | Width transition | Instant width change |

### A11Y-04: Modal focus trap

**Status:** NOT IMPLEMENTED. Explicitly deferred via `WR-06` comment in `HubModal.tsx` line 156.

#### Contract

While `HubModal` is mounted:
- Tab and Shift-Tab must cycle only through the focusable elements WITHIN the dialog.
- Background session cards (`tabIndex={0}`) must not receive focus.
- The close button (`hub-modal__close`) must be the first focusable element inside the dialog header so that Tab from the modal header leads into the modal body.

**Implementation approach: DOM `inert` attribute**

The executor must apply `inert` to all sibling DOM nodes of the modal overlay when the modal is open. This is the preferred WCAG 2.1 technique over a JavaScript Tab-cycle interceptor because `inert` also prevents AT (assistive technology) from announcing background content.

```
When HubModal mounts:
  document.querySelector('.hub') [or the HubPanel root] → set .inert = true
  OR the overlay's siblings via React ref → set inert=""

When HubModal unmounts:
  Remove inert from previously-inerted elements
```

If the `inert` attribute approach is used, no Tab-cycle interceptor JavaScript is needed — `inert` natively prevents focus from reaching inerted elements.

**Fallback: manual Tab trap (if inert has compatibility concerns)**

If `inert` is unavailable, implement a `useFocusTrap` hook:
```
On Tab: if focus would leave dialog → wrap to first focusable in dialog
On Shift-Tab: if focus would leave dialog → wrap to last focusable in dialog
Focusable query: 'button:not([disabled]), [href], input:not([disabled]), select:not([disabled]), textarea:not([disabled]), [tabindex]:not([tabindex="-1"])'
```

**Initial focus on open:**

When the modal enters the `open` phase, focus must be moved to the close button (`hub-modal__close`) or the first interactive element in the modal body. The focus return on close is already implemented via `cardFocusRef`.

**Required code changes in HubModal.tsx:**

1. Remove or scope the document-level Escape listener (WR-05). Move to `onKeyDown` on the `role="dialog"` div.
2. On modal mount (when `phase === 'open'`), use a `useEffect` to:
   - Apply `inert` to the Hub background (the `.hub` element or HubPanel root ref)
   - Move focus to the close button ref
3. On modal unmount (`useEffect` cleanup), remove `inert` from the background.
4. The `role="dialog"` and `aria-modal="true"` are already present. No change needed.

**CSS change for inert background:**

No CSS change needed — `inert` suppresses focus and pointer events natively. Optionally add:

```css
.hub[inert] {
  pointer-events: none;
  user-select: none;
}
```

This is defensive-only; `inert` already handles it.
