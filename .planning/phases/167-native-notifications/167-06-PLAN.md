<objective>
Close the Phase 167 M-41 live-delivery blocker (167-UAT.md Gaps, second gap: `status: failed severity: blocker test: 1`). On a signed production macOS build the native "session is waiting" notification never delivers even with the toggle ON, macOS permission granted, and the window backgrounded — while the tab dot, Hub-card glow, and "Needs Input" chip all fire correctly. The Go-side trigger path was already verified CORRECT by code reading during UAT (engine.ListSessions Status -> App.ListSessions -> refreshTrayState -> maybeNotifyWaiting -> sendNotification, status constants match end-to-end), so the failure is downstream in native delivery/authorization OR in unobservable runtime state. The native path has NO observability on its failure paths, which blocks black-box diagnosis.

This plan is instrumentation-first. It (1) adds logging on EVERY native-notification path so the next signed-build test is diagnosable, (2) requests UNUserNotificationCenter authorization PROACTIVELY when the toggle is enabled (the leading suspected fix — during UAT the app showed as "Off" in System Settings with NO prompt ever seen) and emits a Wails event on denial for the frontend hint (wired in 167-07), (3) registers a UNUserNotificationCenterDelegate so notifications also present while AgentHub is frontmost, and (4) hardens the notifyOnWaiting cache observability. Windows/Linux beeep wrappers get only the parallel attempt log plus a no-op authorization stub so the cross-platform App wiring compiles.

Purpose: Root-cause an invisible native-delivery failure by making it observable, and land the leading suspected fix (proactive authorization + foreground presentation) so the signed-build M-41 re-test can either pass or pinpoint exactly where delivery breaks from the new logs.
Output: Instrumented + delegate-registered + proactive-authorization darwin notification path, the cgo/Go wiring, cross-platform no-op parity, headless Go tests for the injectable authorization seam, and TESTING.md registration. The frontend denial hint and its vitest coverage land in 167-07; the live M-41 signed-build re-test remains a manual UAT item.
</objective>

| Settings toggle (SetNotifyOnWaiting) -> native macOS authorization API | Enabling the toggle now proactively drives `UNUserNotificationCenter requestAuthorizationWithOptions`, which surfaces a system permission prompt. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-167-09 | Denial of Service | tray_objc_darwin.m requestNotificationAuthorization / registerNotificationDelegate (native calls reachable from the RPC goroutine via SetNotifyOnWaiting) | high | mitigate | Reuse the 167-05 fail-safe pattern: bundle-id guard before dispatch + `@try/@catch` around the UNUserNotificationCenter usage, so an unbundled/unsigned process (wails dev / go test) log-and-swallows instead of aborting the GUI process. |
| T-167-10 | Tampering | onNotificationAuthResult exported cgo callback emitting a Wails event | low | mitigate | Hand off to a goroutine and nil-guard `appInstance`/`appInstance.ctx` (mirror onTraySession) so a callback firing before/after the Wails context exists cannot panic; the event payload is a fixed constant (no attacker-controlled data crosses the boundary). |
