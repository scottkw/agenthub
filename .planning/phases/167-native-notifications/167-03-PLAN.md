<objective>
Wire the GUI-side edge-detection trigger that fires a notification on the non-waiting→`waiting`
transition, plus the Wails-bound getter/setter for the toggle. This is the core of NTF-01/02/03
and the app-layer half of NTF-04. The trigger lives inside the existing 5s tray poller
(`refreshTrayState`), which runs independent of window visibility — satisfying the tray-hidden
requirement (NTF-01) without any daemon change (per LOCKED decision #3; the daemon's edge-triggered
detector is process-local and does not cross the socket).

Purpose: `maybeNotifyWaiting` is the once-per-transition de-dup (NTF-02) and the only genuinely
new logic in this phase. It is tested through an injected `sendNotificationFunc` seam so no real
OS notification fires in unit tests (per LOCKED decision #8).
Output: A live, tested waiting-transition notifier + the Get/Set binding the frontend consumes.

- `startup` loads the initial value from the daemon client into the atomic
- `app_test.go` tests: `TestMaybeNotifyWaiting_*`, `TestDisplayNameForCLI`
- Hand-added wailsjs bindings for the two new bound methods (4 files)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Daemon session data → GUI notification body | User-controlled session Name flows into the notification body string. |
| Wails RPC → App.SetNotifyOnWaiting | Local webview toggles the cached flag + persists via the daemon client. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-167-05 | Tampering | session Name (via RenameSession) in notification body | low | accept | Name is inserted as a discrete argument into the native/beeep title+body APIs, not interpolated into a shell/script (delivery hardening covered by Plan 02 T-167-04). Name is already shown in Hub/tab/tray — no new disclosure. |
| T-167-06 | Denial of Service | maybeNotifyWaiting map growth across ticks | low | mitigate | Sessions absent from the latest slice are pruned from lastWaitingStatus each tick — bounded by live session count. |
| T-167-07 | Spoofing/Repudiation | concurrent macOS notifications colliding on one identifier | medium | mitigate | Per-session identifier `agenthub.session-waiting.<id>` (enabled by Plan 02's identifier param) prevents replacement of a pending notification (RESEARCH Pitfall 2). |
</threat_model>
