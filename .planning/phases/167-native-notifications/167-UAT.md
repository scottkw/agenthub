Live daemon instrumentation showed a parked menu non-deterministically flapping waiting↔running↔idle: (1) the reANSI StripANSI regex doesn't strip DEC private-mode CSI (\\x1b[?2026h/l sync-output, \\x1b[?25h/l cursor, \\x1b[?1000h.. mouse, \\x1b[<u/\\x1b[>1u keyboard) so the escape torrent buries the waiting marker; (2) even with escapes stripped, continuous carriage-return cursor-blink CONTENT (\\r❯) accumulates and the trailing ❯ matches the idle-prompt pattern → misclassified idle. The screen can't be reconstructed from the append-only stripped byte stream because the menu is laid out with absolute cursor-move escapes that are stripped. Two heuristic patches (broaden StripANSI; carriage-return overwrite/collapse) were attempted live and BOTH REVERTED per user direction — the synthetic unit tests passed but real menus still failed/mangled."
  resolution: "Proper fix = terminal-emulator-aware classification (reuse the vt rendering /sessions/{id}/tail already produces) + event-driven daemon→GUI status push so all signals fire off one transition edge. Filed as scottkw/agenthub#122. Detector left at pre-session baseline (all detector changes reverted). Only the notification SOUND fix (tray_objc_darwin.m) was kept from this session."

  truth: "User asked whether the waiting notification can require acknowledgment (stay on screen until dismissed) instead of auto-dismissing after a few seconds."
  finding: "The toast auto-dismisses because AgentHub's macOS Alert style is 'Banners' (the default). Persistence is the user-controlled 'Alerts' style (System Settings → Notifications → AgentHub). Recommend filing a GitHub issue if app-side prominence (e.g. sound + time-sensitive interruption level) is desired; true stay-until-acknowledged is not achievable without the entitlement."
