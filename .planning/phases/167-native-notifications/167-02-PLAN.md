<objective>
Establish a per-call, identifier-aware, cross-platform `sendNotification(identifier, title, body)`
primitive. Reuse the existing native macOS path (per LOCKED decision #1 — real "AgentHub"
attribution, NOT beeep's "Script Editor") and add beeep-backed Windows/Linux wrappers
(per LOCKED decision #2). This is the delivery half of NTF-01; the trigger that calls it lands
in Plan 03.

Purpose: The current `sendNotification(title, body)` hardcodes a single macOS identifier
(`agenthub.quit-gui-only`), so two sessions transitioning to `waiting` close together would
collide and one notification would be silently replaced (RESEARCH Pitfall 2). Threading an
identifier fixes that and unlocks per-session notifications.
Output: A three-platform notification primitive with a consistent signature.

## Artifacts this plan produces
- `notification_windows.go`, `notification_linux.go` — new beeep wrappers, `sendNotification(identifier, title, body string)`
- `notification_darwin.go` — signature gains `identifier`; C call threads it through
- `tray_objc_darwin.m` — `void sendNotification(const char *identifier, const char *title, const char *body)`
- `notification_other.go` — DELETED
- `go.mod` / `go.sum` — `github.com/gen2brain/beeep v0.11.2`
- `app.go` — the single `QuitGUIOnly` call site updated to pass `agenthub.quit-gui-only`
</objective>
