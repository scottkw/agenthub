<objective>
Add the `NotifyOnWaiting` daemon setting end-to-end through the persistence layers
(engine → api → client), mirroring the existing `StartMinimized` boolean-setting template
exactly. This is the backend half of NTF-04 (Settings toggle, default OFF): a single
source of truth on disk (`settings.json`, 0600) that the GUI reads at startup and writes
when the user flips the toggle.

Purpose: The app-layer trigger (Plan 03) caches this flag in an `atomic.Bool` and the
frontend toggle (Plan 04) reads/writes it; both require this persistence layer to exist first.
Output: A persisted, socket-reachable boolean setting with unit coverage.

</objective>
