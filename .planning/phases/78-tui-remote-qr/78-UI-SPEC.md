# Phase 78 -- UI Design Contract: TUI Remote & QR

> Visual and interaction contract for Phase 78. This phase extends the Phase 77 TUI with
> two new surfaces: a remote sessions panel (TUI-07) that shows tailnet peer sessions grouped
> by hostname, and an ASCII QR code overlay (TUI-10) that renders a scannable QR code for
> any session's web URL without leaving the terminal.
>
> All design tokens (colors, typography, spacing, status indicators) are inherited from
> 76-UI-SPEC.md and 77-UI-SPEC.md and are NOT redefined here. This document specifies only
> the NEW surfaces, interactions, and copywriting added by this phase.

## Surface 1: Remote Sessions Panel (TUI-07)

### Design Decision: Integrated List Section (not a separate panel/tab)

Remote sessions are rendered as a **distinct section within the existing session list**, not
in a separate panel or navigation tab. Rationale:

1. The GUI Remote Sessions panel uses a sidebar tab -- TUI has no sidebar navigation
2. Keeping remote sessions in the same scrollable list preserves the single-flow UX of
   navigating with j/k across all sessions
3. The CLI `agenthub list` command already groups sessions this way: local sessions first,
   then remote sessions grouped by peer hostname
4. A section divider row with peer hostname heading mirrors the GUI panel's hostname header
   without requiring a separate navigation model

### Layout: Section Divider Rows

The session list is extended with section divider rows. Local sessions appear first (no
section header needed -- they are the primary context). Remote sessions are grouped by peer
hostname, each group preceded by a divider row.

```
AgentHub                                           3 sessions
  NAME           AGENT      HOST          VIEWERS
> ● my-session   claude     macbook-pro   1
  ○ docs-check   opencode   macbook-pro   0
  ── Remote: laptop-work (1 session) ──────────────
  ● their-proj   claude     laptop-work   0
  ── Remote: linux-box (2 sessions) ───────────────
  ● server-task  codex      linux-box     0
  ○ qa-review    claude     linux-box     0

Web: ● Running -- https://mac.tail.ts.net |  ? Help  q Quit
j/k Up/Down  Enter Attach  q Open URL  n New  d Kill  r Rename  ? Help  q Quit
```

### Section Divider Row

| Property | Value |
|----------|-------|
| Content | `── Remote: {hostname} ({N} session/sessions) ──...` |
| Fill | `──` repeated to fill terminal width after label |
| Style | `fg.accent` for the hostname and count, `fg.muted` for the `──` fill |
| Selection | Divider rows are NOT selectable (j/k skips over them) |
| Minimum label width | `── Remote: {hostname} ({N} sessions) ──` (no right fill if terminal too narrow) |

Exact format:
```
  ── Remote: {hostname} ({N} session) ──────────────...
```
Two leading spaces (to align with session cursor column), then `──` separator, then `Remote: {hostname} ({N} session/sessions)`, then ` ──────────...` filling to terminal width.

The fill character `──` (EN DASH repeated, or `─` box-drawing U+2500) extends to the right
edge of the terminal. If the label alone exceeds terminal width, render the label without fill.

### Remote Session Rows

Remote session rows render identically to local session rows with the same column layout:

```
  ● {name}        {agent}    {hostname}    {viewers}
```

| Column | Content | Note |
|--------|---------|------|
| Cursor | `  ` (2 spaces, never `> `) | Remote sessions are selectable but cursor shows normally |
| Status | Same glyphs and colors as local sessions | `CLIRemoteSession.Status` maps to same glyph set |
| Name | Session name, truncated to name column width | Same as local |
| Agent | `CLIRemoteSession.CLIType`, truncated to 12 | Same as local |
| Host | Peer hostname, truncated to 20 | Already populated in `CLIRemoteSession` |
| Viewers | Empty (remote sessions do not expose viewer count) | Omit the integer, render blank |

**Remote sessions are selectable.** The user can move the cursor to a remote session row
and press `q` (open URL) or `Enter` (attach via `hostname:id` syntax). See Keybindings section.

**Remote sessions are NOT killable or renameable from TUI.** Pressing `d` or `r` on a
remote session shows a toast: `Cannot kill remote session` or `Cannot rename remote session`.

### Data Source

Remote sessions are fetched by calling `client.ListTailnetPeers()` then probing each peer's
`/api/sessions` endpoint -- the same pattern used by `cmdList` in `cmd_cli.go` and by
`GetRemoteSessions()` in `app.go`. In the TUI, this fetch runs in the 2-second tick loop
alongside the existing `fetchSessions` and `fetchWebStatus` calls.

The fetch may be slow (network probe with 5-10s timeout). The TUI uses a separate
`remoteSessionsMsg` to avoid blocking the local session refresh. Remote sessions are shown
as stale data until the next successful probe; the UI does not show a loading spinner for
remote data -- the list simply shows the last known state.

### Remote Session Count in Header

The header count changes to include remote sessions when they are present:

| State | Header count |
|-------|-------------|
| No remote sessions | `{N} sessions` (unchanged) |
| With remote sessions | `{N} local, {M} remote` |

This matches the CLI `list` output which distinguishes local and remote counts.

### Empty States

| State | Display |
|-------|---------|
| No tailnet peers detected | No remote section rendered (remote section is absent, not an empty placeholder) |
| Tailnet peers present but no sessions | No remote section for that peer (peers with zero sessions are omitted) |
| Tailscale not connected | No remote section rendered; footer shows existing web status only |

Source: REQUIREMENTS.md TUI-07; RemoteSessionsPanel.tsx GUI implementation;
cmd_cli.go cmdList (remote grouping pattern); app.go GetRemoteSessions

## Surface 2: QR Code Overlay (TUI-10)

### Design Decision: Modal Overlay (not a new screen)

The QR code is rendered as a **modal overlay** centered on the session list, identical in
construction to the new-session and kill confirmation overlays. The user presses a key on
a selected session, the QR overlay appears, and Esc closes it. The TUI does not navigate
away or suspend.

This is NOT `tea.Exec` (no terminal hand-off). The QR code is rendered inline by Lip Gloss
within the alt-screen buffer.

### Trigger Key

| Key | Action | Condition |
|-----|--------|-----------|
| `q` | Open QR code overlay for selected session | Session must be web-served (has a URL) |

**Key conflict resolution:** `q` was previously bound to Quit. This key is reassigned:
- `q` now opens QR overlay (when a session with a URL is selected)
- `Q` (Shift+Q) becomes the new Quit key
- `Ctrl+C` remains Quit (unchanged)

Rationale: QR access is a primary UX goal of Phase 78. The requirement (TUI-10) explicitly
calls out QR as a key TUI feature. `q` is the most mnemonic key for QR. `Q` for quit is
still intuitive and `Ctrl+C` provides a universal exit path.

**Condition for QR trigger:** The selected session must have a web URL. This is determined
by checking whether the session's web-serve status is enabled and the web server is running.
For remote sessions, the URL is always available in `CLIRemoteSession.URL`. For local
sessions, the URL is constructed as `{webStatus.URL}/sessions/{sessionID}` if the session
is web-served.

If the session has no URL (not web-served), pressing `q` shows a toast:
`Web serving not enabled for this session` (2s, `fg.muted`).

### QR Generation

The existing `github.com/skip2/go-qrcode` library (already in go.mod, already used by
`cmdQR` in cmd_cli.go) generates the QR code. The same `ToSmallString(false)` method
is used, which renders with Unicode half-block characters (`▄`, `▀`, `█`) for double-density
pixel packing. This format occupies approximately half the rows that a pure ASCII (space/`#`)
QR would require, making it more practical for terminal display.

**Error correction level:** `qrcode.Medium` (same as `cmdQR`). This provides 15% error
correction, robust enough for a phone camera scanning from a monitor.

### QR Overlay Layout

```
+--- QR: my-session ----------------------------------------+
|                                                             |
|  ▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄                               |
|  █ ▄▄▄▄▄ █  █▀▀▄▄█ ▄▄▄▄▄ █                               |
|  █ █   █ █▄▄▀▀ ▀▄█ █   █ █                               |
|  █ █▄▄▄█ █ ▀▀▄  █ █▄▄▄█ █                               |
|  █▄▄▄▄▄▄▄█ █ ▄ █▄█▄▄▄▄▄▄▄█                               |
|  ... (QR rows continue) ...                               |
|  ▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀                               |
|                                                             |
|  https://mac.tail.ts.net/sessions/abc123                   |
|                                                             |
|                         Esc: close                         |
+-------------------------------------------------------------+
```

### QR Overlay Dimensions

| Property | Value |
|----------|-------|
| Width | `max(qr_cols + 6, url_len + 6, 50)` clamped to `min(terminal_cols - 4, 80)` |
| Height | `qr_rows + 6` (border + pad + qr content + url row + blank + hint + border) |
| Max height | `terminal_rows - 2` |
| Border | `lipgloss.RoundedBorder()` with `border.normal` color |
| Title | `QR: {session-name}` rendered in `border.accent` color via `injectBorderTitle` |
| Background | `bg.modal` |
| Padding | `qr-pad-h` (2 chars horizontal), `qr-pad-v` (1 row vertical) |

**QR size:** A `qrcode.Medium` QR code for a typical Tailscale HTTPS URL (`https://host.tail.ts.net/sessions/uuid`) generates a Version 4-5 QR code, which with `ToSmallString` is approximately 29-33 characters wide and 15-17 rows tall (half-block density). The overlay must accommodate this without truncation.

**Overflow handling:** If the terminal is too small to render the QR overlay at its natural
size, show a toast: `Terminal too small to display QR code` (3s, `fg.muted`) and do not open
the overlay.

**Minimum terminal for QR:** 55 columns x 25 rows. Check before opening the overlay.

### QR Overlay Content Elements

| Element | Position | Style |
|---------|----------|-------|
| Border | Outer frame | `border.normal`, `lipgloss.RoundedBorder()` |
| Title | Top border splice | `border.accent` via `injectBorderTitle` format: `QR: {name}` |
| QR code block | Centered horizontally | Default terminal colors -- no Lip Gloss styling applied to QR chars (preserves half-block rendering) |
| URL line | Below QR, left-aligned | `fg.accent` |
| Hint line | Bottom row, centered | `fg.muted`: `Esc: close` |

**Critical rendering note:** Do NOT wrap the QR code output in a `lipgloss.NewStyle()` that
sets background or foreground colors. The `ToSmallString(false)` output uses ANSI reset codes
internally and the half-block characters depend on the terminal's default color pair for
correct contrast. Apply only width-based layout (centering), not color styling, to the QR block.

### QR Overlay Interaction

| Key | Action |
|-----|--------|
| `Esc` | Close QR overlay, return to session list |
| `q` | Close QR overlay (same as Esc -- `q` is now Open QR, not Quit in main view) |
| `Q` / `Ctrl+C` | Quit TUI (works from QR overlay too, passes through) |
| Any other key | Ignored while QR overlay is open |

### QR Overlay State

```
// In Model (Phase 78 additions):
qrSession  *sessionRef  // session for which QR is shown (nil = no QR overlay)
qrContent  string       // pre-rendered QR string from ToSmallString(false)
qrURL      string       // full web URL for the session
```

Where `sessionRef` captures enough to regenerate the URL if needed:
```
type sessionRef struct {
    ID       string
    Name     string
    IsRemote bool
    URL      string  // for remote sessions (pre-built URL)
}
```

The QR string is generated once when the overlay opens (not re-generated on every render
call). If `qrcode.New` fails, the overlay is not opened and a toast shows the error.

### QR Overlay Error States

| Condition | Response |
|-----------|----------|
| Web server not running | Toast: `Web serving not enabled for this session` (2s, `fg.muted`) |
| No URL available | Toast: `No URL available for this session` (2s, `fg.muted`) |
| qrcode.New() fails | Toast: `QR code generation failed: {error}` (3s, `fg.danger`) |
| Terminal too small | Toast: `Terminal too small to display QR code` (3s, `fg.muted`) |

Source: REQUIREMENTS.md TUI-10; cmd_cli.go cmdQR (existing QR generation pattern);
github.com/skip2/go-qrcode ToSmallString API

## Loading / In-Flight States

| Operation | In-Flight Indicator | Duration |
|-----------|-------------------|----------|
| Remote session probe | No spinner -- remote data refreshes in background | Until tick |
| QR generation | Instant -- `qrcode.New()` is synchronous, < 1ms | None needed |

**Remote probe behavior:** The 2-second tick fires `fetchSessions`, `fetchWebStatus`, AND
`fetchRemoteSessions` as a `tea.Batch`. Remote probe may take up to 5 seconds (per-peer
timeout). The `fetchRemoteSessions` command uses a shorter aggregate timeout (10s max, same
as `cmdList`) and returns whatever data has arrived. Stale data from the previous probe
cycle is shown until the new probe completes.

**No "Probing peers..." spinner in the TUI.** The list renders with whatever remote data is
available. If no remote data has arrived yet, the remote section is simply absent. This
avoids visual jitter on every 2-second tick.

Source: app.go GetRemoteSessions (background probe pattern); 77-UI-SPEC.md Loading States

type CLIRemoteSessionWithHost struct {

**Selection index** (`m.selected`) operates on the unified list. Navigation skips

## Anti-Patterns Prohibited by This Contract

The executor must not do any of the following in Phase 78:

1. **Create a separate navigation tab for remote sessions** -- remote sessions live in the
   same scrollable list. No tab bar, no sidebar navigation, no separate screen.

2. **Style the QR code block with Lip Gloss colors** -- `ToSmallString(false)` uses ANSI
   reset codes internally. Wrapping it in a colored style corrupts the half-block rendering.
   Use `lipgloss.Place` for centering only.

3. **Block the Update loop during remote probe** -- `fetchRemoteSessions` runs in a `tea.Cmd`
   goroutine. Never call HTTP in `Update` directly.

4. **Show a loading spinner for remote probe** -- stale data is acceptable; a spinner on the
   2-second tick would create visual noise on every cycle.

5. **Allow `d` (kill) or `r` (rename) on remote sessions** -- these operations require local
   daemon access. Remote sessions are read-only. Show a toast instead.

6. **Use `q` for both QR and Quit** -- `q` is reassigned to QR in Phase 78. Quit is `Q`
   (Shift+Q) and `Ctrl+C`. Do not keep `q` as a quit binding.

7. **Renegerate the QR string on every View() call** -- generate once in Update when the
