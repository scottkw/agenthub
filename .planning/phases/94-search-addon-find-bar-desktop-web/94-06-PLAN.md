Wire the 200ms slide-in / 150-200ms slide-out animation that the existing CSS rules already define but the existing JS code never applies. Closes Phase 94 verification gap WR-01 / SC-4 / SRC-04 (animation not implemented). Mirrors the fix on the React desktop surface AND the plain-DOM web surface so both surfaces honor 94-UI-SPEC §"Animation" lines 197-202.

Purpose: SC-4 explicitly mentions "200ms slide-in/out animation"; UI-SPEC §"Animation" mandates `translateY(-100%) → translateY(0)` over 200ms ease + `opacity 0 → 1` over 200ms ease on entry, and `translateY(0) → translateY(-8px)` over 200ms ease + `opacity 1 → 0` over 150ms ease on exit. Both transitions must respect `@media (prefers-reduced-motion: reduce)` (CSS already does — verify rule still wraps the new modifier classes). Currently the bar appears/disappears instantly because no JS code touches `.find-bar--entering` or `.find-bar--exiting`.

Output: FindBar mounts with the modifier class applied, drops it on next frame so the transition fires. TerminalPanel intercepts close requests, sets an `exiting` flag (which adds `.find-bar--exiting`), and delays the actual unmount by 200ms. Web shows/hides apply the same modifier classes around `el.hidden = false/true`. New animation tests assert the wiring (not the animation feel — that's a UAT). Existing 81 Phase 94 tests must keep passing.
</objective>
