# Phase 94 — UI Design Contract

> Visual and interaction contract for the **Search Addon + Find Bar (Desktop + Web)** phase. This phase introduces one entirely new UI surface: a floating find bar that slides in over the terminal scrollback area when the user presses Cmd-F (focus-conditioned). The find bar is the most interaction-dense new surface in v3.2 — it owns keyboard focus while open, manages four interactive controls, and must be visually indistinguishable between the Wails desktop app and the web-served Tailscale terminal page. Phase 94 also wires the Search toggle in the existing Phase 92 Plugins section to a live effect. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase Scope (read this first)

**In scope (Phase 94) — visual/interaction surfaces:**

1. **Find bar overlay** — A floating toolbar that appears anchored to the top-right corner of the terminal scrollback area (inside `.terminal-session-container`, above the xterm canvas). Contains: search text input, match count, three toggle icons (regex / case-sensitive / whole-word), next/prev navigation buttons, and a close button. Slides in from above with a 200ms CSS transition. Esc or clicking the close button dismisses it with the same 200ms slide-out. (SRC-01, SRC-04)

2. **Keyboard shortcuts** — Cmd-F (focus-conditioned on `document.activeElement` being the xterm canvas DOM element) opens the find bar and focuses the search input. Enter / Cmd-G advances to next match; Shift-Enter / Cmd-Shift-G goes to previous match. Esc closes the find bar and returns focus to the terminal. All shortcuts must work identically on the Wails desktop app and on the web-served Tailscale terminal page. Tab cycles focus within the find bar; Tab out of the find bar's last focusable element wraps to the first (focus trap while find bar is open). (SRC-01, SRC-02, SRC-05)

3. **Match count display** — A read-only label inside the find bar showing "3 of 12" format when matches exist, "0 of 0" when the query yields no matches (no-results state), and empty (hidden) when no query has been entered yet. Updates live as the user types (debounced 100ms). (SRC-02)

4. **Search option toggles** — Three icon-toggle buttons: regex (`.*/`), case-sensitive (`Aa`), whole-word (`[ ]`). Each is a binary on/off control styled as an icon button. Active state: `#7aa2f7` icon color + `rgba(122, 162, 247, 0.12)` background tint. Inactive state: `#565f89` icon color, transparent background. Defaults are persisted via `SearchConfig` in daemon settings and loaded at find-bar mount. (SRC-02)

5. **Find bar Settings integration** — The existing "Find in scrollback" toggle row in PluginsSection now has a live effect: when search is OFF, Cmd-F does nothing (no find bar, no event handling). When search is ON (default), the find bar is enabled. No new UI surface for this toggle — it is already rendered in Phase 92 with the correct description (`Open a find bar with Cmd-F to search the terminal scrollback buffer.`). Phase 99 (PUI-03) will add the `<details>` disclosure for default regex/case/word options; those advanced options are NOT surfaced in this phase. (SRC-01)

6. **Web parity** — The web-served terminal page (`web/terminal.html`) must render the find bar with identical visual treatment, identical keyboard shortcuts, and identical match behavior. The web find bar is implemented in plain HTML/CSS/JS (no React) inside `web/terminal.html` + `web/assets/terminal.js` + `web/assets/terminal.css`, following the same pattern as the Phase 93 `#webgl-recovery-banner` element. (SRC-05)

7. **Vendor asset** — `web/terminal.html` gains a `<script src="/assets/xterm/addons/addon-search.js">` tag. The addon is vendored under `web/vendor/xterm/addons/` and must pass the existing `vendor_drift_test.go` CI gate.

**Explicitly NOT in scope for Phase 94 (deferred):**

- `<details>` disclosure for default regex/case/word search option under the Settings toggle — Phase 99 / PUI-03
- Find-in-all-sessions (Cmd-Shift-F) — deferred to SRC-FUT-01
- Highlight color theming beyond `theme.selectionBackground` — using xterm's existing built-in highlight mechanism

**Anti-goals:**

- No new Settings section, no new modal, no new route.
- No "no results" toast or banner — the "0 of 0" label inside the find bar is the entire feedback for zero matches.
- No auto-close after match — find bar stays open until Esc or close button.
- No history / recent searches.
- No persistence of the open/closed state of the find bar across sessions.

## Spacing Scale

Inherited from the locked Phase 92 8-point scale. Phase 94 introduces no new spacing tokens — the find bar composes entirely from existing values.

| Token | Value | Usage in Phase 94 |
|-------|-------|-------------------|
| xxs | 2px | Toggle icon button inner padding (tight, icon-sized target) |
| xs | 4px | Gap between adjacent icon toggle buttons; gap between close button and right edge |
| sm | 8px | Find bar horizontal padding (left/right inset from container edge); gap between input and match count; gap between match count and nav buttons; gap between nav buttons and toggle group |
| md | 16px | Find bar horizontal padding at container edge — `right: 16px` absolute positioning from terminal container right wall; `top: 8px` from top wall |
| lg | 24px | (existing — not used in find bar chrome, carried for completeness) |
| touch | 44px | NOT used for find bar icon buttons; icon toggle buttons are 28px × 28px (compact, keyboard-primary surface inside a toolbar; touch interaction is not primary for desktop terminal — matches tab close button precedent at 16px); close button is 28px × 28px |
| input-height | 28px | Find bar text input height; match count height; nav button height; toggle button height — uniform row height |
| bar-height | 40px | Total find bar height: 8px top padding + 28px inner row + 8px bottom padding (6px top + 6px bottom = 12px padding, but accounting for border = 40px total) — must not reduce terminal scrollback by more than 40px |

**Exceptions:**

- The `28px` icon button and input row height is not on the standard 8-point scale but is a deliberate compact choice for a toolbar-style surface inside a terminal. Rational: the find bar is purely keyboard-driven; the touch-target minimum (44px) applies to primary interactive surfaces, not secondary toolbar chrome. This is the same reasoning as the existing `16px` tab close button and the `20px` sidebar icon in the existing codebase.
- The `40px` total find bar height matches existing `.tab-bar { height: 42px }` and `.tab-status-bar { height: 32px }` as contextual anchors — it feels "native" within the existing chrome proportions.
- The `2px` inner padding on icon toggle buttons (token `xxs`) is inherited from the Phase 92 locked spacing scale and is not a Phase 94 introduction. It is a sub-pixel visual inset used only for icon-button padding — not a layout gap or positional offset — and its use predates the Phase 94 grid contract. It is carried forward as a locked pre-existing token.

### Animation

- **Slide-in (open):** `transform: translateY(-100%)` → `transform: translateY(0)` over `200ms ease` simultaneously with `opacity: 0` → `opacity: 1` over `200ms ease`. Both transitions fire together.
- **Slide-out (close):** reverse — `translateY(0)` → `translateY(-8px)` over `200ms ease` (soft up, not full reversal) + `opacity: 1` → `opacity: 0` over `150ms ease`. The asymmetric reverse (short, soft) is intentional — closing feels faster than opening.
- **Reduced motion:** When `prefers-reduced-motion: reduce` is set, both transitions are replaced with instant show/hide (no transform, no opacity transition). Consistent with Phase 93 `@media (prefers-reduced-motion: reduce)` pattern.

### Border and Shadow

- `border: 1px solid #292e42` — same border as all modals and panels in the app
- `border-radius: 6px` — slightly tighter than the 8px modal radius to feel "toolbar-like" rather than "dialog-like"
- `box-shadow: 0 4px 16px rgba(0, 0, 0, 0.4)` — lighter than the existing modal shadow (`0 8px 32px rgba(0, 0, 0, 0.5)`) to keep the find bar from visually dominating the terminal content behind it

### Input Field

- `background-color: transparent` (inherits find bar background `#16161e`)
- `border: none; border-bottom: 1px solid #292e42` — a bottom-border only input (hairline underline style), consistent with the find bar's compact, toolbar-like character. **Deviates from** the `.settings-panel__path-input` (full border box) because a toolbar input should feel lighter.
- `color: #c0caf5` (input text)
- `font-size: 13px; font-family: inherit` (system UI font — not monospace)
- `outline: none` — focus indicated by the bottom-border changing to `#7aa2f7` (`border-bottom-color: #7aa2f7` on `:focus`)
- `padding: 0 4px` — minimal, since the border is bottom-only
- Height: `28px`
- `::placeholder { color: #414868 }`

### Match Count

- `font-size: 12px; font-variant-numeric: tabular-nums`
- `color: #9aa5ce` (muted) in default / has-matches state
- `color: #f7768e` when query is non-empty AND match count is zero (no-results state)

## Interaction Contract

### Opening the Find Bar

**Trigger:** `keydown` handler attached to `window` (or the xterm container) checks:

1. `(event.metaKey || (process.platform !== 'darwin' && event.ctrlKey)) && event.key === 'f'`
2. `document.activeElement === terminalElement` (the `.xterm` div or its canvas child) — focus-conditioned to avoid intercepting browser find for non-terminal page content
3. `pluginConfig.search === true`

If all three conditions: `event.preventDefault()`, open find bar, focus the search input.

**On web terminal page:** identical logic, except the condition is `document.activeElement === document.getElementById('terminal')` (or the xterm canvas inside it). The web page does not use browser-native Cmd-F for any other purpose, so the focus-conditioning still applies as a guard against intercepting browser find on the surrounding page (e.g. the status bar text).

### Closing the Find Bar

**Triggers:** Esc key while find bar is open (input focused OR any element inside find bar focused); close button click.

**On close:**
1. Play the exit animation (150ms opacity fade + translateY(-8px) over 200ms).
2. After animation completes, unmount the find bar DOM (React: `useState(false)` gates render; web: `style.display = 'none'`).
3. Clear xterm match highlights (`searchAddon.clearDecorations()` if exposed; otherwise `searchAddon.findNext('')` with an empty query, which clears highlights).
4. Return focus to the xterm terminal element.

### Searching (live, debounced)

- As the user types, the search executes after a **100ms debounce** (prevents locking the browser on each keystroke for a 10,000-line scrollback).
- Calls `searchAddon.findNext(query, options)` where `options = { regex, caseSensitive, wholeWord }` from the current toggle states.
- The SearchAddon scrolls to the first match. The match count displayed is read from the SearchAddon's result set length; implementation detail: if the SearchAddon does not expose a match-count API, the UI shows "N of M" where N is the current match index and M is computed by a separate `findAll` call (only if SearchAddon exposes this; otherwise display is "Match N" without total). **Preferred:** use `@xterm/addon-search`'s `findAll` method if available in the vendored version; otherwise the match count display degrades gracefully to show only the current match index ("Match 3") without the total.
- **Cancellation:** closing the find bar cancels any in-progress search via the debounce clearing + `clearDecorations()`.

### Next / Previous Match

- **Enter** key while input is focused: `searchAddon.findNext(query, options)`.
- **Shift-Enter** while input is focused: `searchAddon.findPrevious(query, options)`.
- **Cmd-G** (desktop) / **Ctrl-G** (Windows/Linux): `findNext`.
- **Cmd-Shift-G** (desktop) / **Ctrl-Shift-G** (Windows/Linux): `findPrevious`.
- Clicking the `▶` button: `findNext`.
- Clicking the `◀` button: `findPrevious`.
- Each call updates the current match index in the match count display.
- At the last match, `findNext` wraps to the first match (SearchAddon default behavior — do NOT override this; wrapping is the standard browser find-bar behavior).

### Toggle Persistence

- On find bar mount, load the three boolean values from `SearchConfig` (daemon settings, via the `pluginConfig.searchConfig` sub-struct or equivalent — implementation detail for the planner).
- On toggle change: update local component state immediately (optimistic) AND persist to `SearchConfig` via the existing `SetPluginSettings` / `SetSearchConfig` Wails binding (or equivalent). The delay between toggle click and daemon-write is invisible to the user because the search re-runs instantly from local state.
- Web page: `SearchConfig` defaults are loaded once from `/api/plugin-config` at page init; toggle changes persist only in-memory for the current web session (web pages do not have a path to call `SetPluginSettings` — they are read-only consumers of daemon config). This is acceptable; persisted defaults are for desktop users who use the find bar frequently.

### Focus Trap

While the find bar is open:

- `Tab` moves focus in order: input → case toggle → regex toggle → word toggle → next button → prev button → close button → (wrap) input.
- `Shift-Tab` reverses the order.
- No focus escape to the terminal canvas while the find bar is open (the terminal is not interactive while the user is actively searching — this is correct, matches browser find bar behavior).

### Keyboard Shortcuts — No-Conflict Analysis

| Key combo | Find bar open | Find bar closed | Notes |
|-----------|--------------|-----------------|-------|
| Cmd-F | Focuses input if already open | Opens find bar | Focus-conditioned: only when xterm is `activeElement` |
| Esc | Closes find bar | No-op | Only when find bar is open |
| Enter | Next match (from input) | Normal terminal Enter | Only when input is focused |
| Shift-Enter | Prev match (from input) | Normal terminal Shift-Enter | Only when input is focused |
| Cmd-G | Next match | Ignored | Only when find bar is open |
| Cmd-Shift-G | Prev match | Ignored | Only when find bar is open |
| Tab | Focus trap within find bar | Normal terminal Tab | Only when find bar is open |

**No conflict with xterm key handling:** xterm's custom key handlers are suspended while the find bar input holds focus (the input captures all keydown events before they reach xterm). The Esc handler is attached at the `find-bar` container level, not the input level, so Esc correctly closes the bar regardless of which element inside the bar is focused.

### xterm Theme Integration (Match Highlight)

The `SearchAddon` uses xterm's built-in decoration system. Match highlights are rendered using the terminal's active `theme.selectionBackground` color (the same mechanism used for selection highlights in the terminal). No CSS is needed to control highlight color — the theme object passed to the xterm `Terminal` constructor already contains `selectionBackground`. Phase 94 does not need to read or translate this value in CSS; it is handled entirely by the xterm addon.

For the 138 curated themes, `selectionBackground` is always set (Phase 65 / Phase 71 themed terminal work established this invariant). No fallback color needed.

## Acceptance Snapshot (what the Phase 94 implementation looks like when done)

A v3.2 user (post-Phase-93) opens the app and:

1. Clicks into the terminal (focusing the xterm canvas), presses Cmd-F. A compact find bar appears at top-right of the terminal area, sliding in over 200ms. The search input is immediately focused.
2. Types a search query. After 100ms, matches are highlighted in the terminal scrollback using the active theme's selection color. The match count "3 of 12" appears to the right of the input.
3. Presses Enter: scrollback jumps to next match. Match count updates to "4 of 12". Presses Shift-Enter: moves back. Counts update correctly.
4. Clicks the `Aa` toggle: the icon turns `#7aa2f7` with a tint background, indicating case-sensitive mode is ON. Search re-runs with `caseSensitive: true`. Next open of the find bar in a new session: the `Aa` toggle is still ON (persisted via `SearchConfig`).
5. Types a query that matches nothing: match count shows "0 of 0" in `#f7768e`. No other visual changes.
6. Presses Esc: find bar slides out over 150ms. Match highlights clear. Focus returns to terminal. The terminal accepts keyboard input normally.
7. Opens Settings → Plugins → toggles Search OFF → presses Save Plugins. Presses Cmd-F in the terminal: nothing happens (find bar does not open when Search plugin is disabled).
8. On the Tailscale-served web terminal page: the experience is visually indistinguishable from the desktop — same find bar layout, same colors, same 200ms animation, same keyboard shortcuts. A screenshot of both at the same query state is pixel-equivalent (modulo OS rendering differences).
9. CI: pushing a PR that bumps `frontend/package.json`'s `@xterm/addon-search` version without updating `web/vendor/xterm/VERSION` causes `vendor_drift_test.go` to fail red.
