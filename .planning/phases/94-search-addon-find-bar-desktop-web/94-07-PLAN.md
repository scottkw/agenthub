<objective>
Close two coupled SC-2 gaps that share `frontend/src/components/TerminalPanel.tsx` and a single Wails generate cycle:

1. **WR-02 — first-load seed**: desktop `searchOptions` state is initialized via `useState(() => ...)` lazy initializer (TerminalPanel.tsx:99-103) which fires on the first render when `pluginConfig` is typically still null (App.tsx loads it asynchronously via GetPluginSettings). The state is never re-seeded, so saved toggle defaults are not honored on first session open after app restart.

2. **WR-03 — PluginsSection persistence race**: `handleSearchOptionsChange` (TerminalPanel.tsx:414-426) writes the FULL PluginSettings via `SetPluginSettings(next)`, constructed from the App-level prop. If PluginsSection has unsaved boolean toggle edits in its private edit buffer (lines 30-40 only fetch on mount), the find bar's persistence call silently overwrites them on the next "Save Plugins" click (because PluginsSection still holds the stale snapshot).

Purpose: SC-2 / SRC-02 says "per-flag defaults persist". Currently the WRITE path works (verified by 81-test sweep) but the READ-back-on-load path is broken (WR-02), and a narrow but real data-loss vector exists when find bar persistence races PluginsSection (WR-03). The surgical fix is a daemon-side `SetSearchConfig(SearchConfig)` RPC that writes ONLY the SearchConfig sub-key under the existing engine mutex, plus a `seededRef` one-shot useEffect on the desktop that seeds searchOptions from pluginConfig.searchConfig the first time it becomes non-null (preserving Pitfall #2 — never re-seed mid-open).

Output:
- New `(*SessionEngine).SetSearchConfig(SearchConfig)` Go method that mutates only `e.pluginSettings.SearchConfig`, calls `saveSettingsToDisk()`, and invokes `pluginSettingsListener` (so the existing SSE settings:plugins event continues to fire — web parity preserved).
- Wails-generated TypeScript binding for the new method.
- TerminalPanel `seededRef` one-shot useEffect that seeds searchOptions exactly once when pluginConfig.searchConfig first becomes non-null AND the find bar is not currently open (Pitfall #2 mid-open invariant).
- TerminalPanel.handleSearchOptionsChange now calls `SetSearchConfig(opts)` instead of constructing a full PluginSettings — drops the `decorations: {} as never` cast site is unchanged, but the `daemon.PluginSettings({ ...pluginConfig, searchConfig: opts })` construction is removed.
- Tests on both sides of the boundary.
</objective>
