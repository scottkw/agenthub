## What Changes

This section describes the exact and complete visual change for this phase.

### Before (broken state)

When `.sidebar--collapsed` is applied to the `<nav>`:
- `.sidebar__item` has `display: flex; align-items: center; gap: 8px; padding: 8px; width: 100%`
- `justify-content` is absent (defaults to `flex-start`)
- The label `<span>` is removed from the DOM (conditional render)
- The lone `<svg>` icon aligns to the left edge of the 32px content box (after padding), appearing visually off-center within the 48px rail

### After (fixed state)

Add to `frontend/src/style.css`:

```css
/* Collapsed sidebar: center the lone icon within the 48px rail */
.sidebar--collapsed .sidebar__item {
  justify-content: center;
  padding: 8px 0;
}
```

- `justify-content: center` centers the 20px icon within the full button width
- `padding: 8px 0` removes horizontal padding so the centering reference is the full 48px rail, not the 32px content box
- Vertical padding (`8px` top/bottom) is retained — touch target height unchanged
- Expanded state is unaffected — `.sidebar__item` base rule still applies when `.sidebar--collapsed` is absent
- `.sidebar__toggle` is unaffected — its selector (`sidebar__toggle`) does not match `.sidebar__item`

### Selector Scope

```
.sidebar--collapsed .sidebar__item  →  5 items: Home, Remote, Sessions, New Session, Settings
.sidebar__toggle                     →  excluded (different class, already correctly centered)
```

### Transition Safety

The collapsed class is toggled atomically with the label's conditional render in React. `justify-content: center` activates only while `.sidebar--collapsed` is present on the `<nav>`. On expand: class removed + label re-inserted at the same React state flip. No icon jump. The sidebar `width` CSS transition (0.15s ease) operates independently and does not conflict.
