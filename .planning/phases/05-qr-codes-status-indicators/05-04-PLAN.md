**Change 1: Extend reANSI to cover OSC sequences.**

Replace line 30:
```go
var reANSI = regexp.MustCompile(`\x1b\[[0-9;]*[a-zA-Z]|\x1b[()][AB012]|\x1b[=>]`)
```
With:
```go
var reANSI = regexp.MustCompile(`\x1b\[[0-9;]*[a-zA-Z]|\x1b[()][AB012]|\x1b[=>]|\x1b\][^\x07\x1b]*(?:\x07|\x1b\\)`)
```
The new alternation `\x1b\][^\x07\x1b]*(?:\x07|\x1b\\)` matches OSC sequences in both ST-terminated (`\x1b\`) and BEL-terminated (`\x07`) forms, which Claude Code uses for window title updates before the prompt.

```go
// feedSnapshot parses a raw scrollback snapshot (concatenated relay frames) and
// feeds only MsgOutput payloads to the detector in order.
func feedSnapshot(d *Detector, snap []byte) {
    for len(snap) > 0 {
        if len(snap) < 1 {
            break
        }
        msgType := snap[0]
        // Find next frame boundary: frames are variable-length output blobs.
        // The scrollback stores each PTY read as one frame. We cannot know
        // the exact boundary without a length prefix, so use a simpler heuristic:
        // feed the entire snapshot payload as-is after stripping the first byte
        // if it looks like a single large MsgOutput frame, otherwise split on
        // 0x01 boundaries.
        //
        // Actually the scrollback stores frames exactly as MakeOutputFrame produces them:
        // [0x01, ...payload bytes...]. Multiple frames are appended sequentially.
        // To split: scan for the next 0x01 byte that follows a complete payload.
        //
        // Simpler and correct approach: since we cannot reliably split without a
        // length prefix, feed the entire snapshot with the first byte stripped
        // if msgType==MsgOutput. For multi-frame snapshots, strip all leading 0x01
        // bytes by replacing them with the approach below.
        _ = msgType
        // Strip all framing: remove 0x01 prefix bytes that appear at positions
        // corresponding to frame starts. Use relay.ParseFrame iteratively on
        // what we know: each frame starts with exactly one type byte.
        // Since PTY output is arbitrary bytes, we cannot distinguish a 0x01
        // in the payload from a frame start byte without a length field.
        //
        // The safe approach: treat the snapshot as a single large blob and
        // strip only the very first byte if it is MsgOutput, then feed the rest.
        // This is correct when the snapshot is one large concatenated string
        // (which is the common case — scrollback.Append joins sequential reads).
        if snap[0] == relay.MsgOutput {
            detector.Feed(snap[1:])
        }
        break
    }
}
```

Wait — the scrollback buffer in relay/scrollback.go appends each PTY read as a full framed message. Reading the actual Scrollback.Append behavior is necessary. The snapshot is a contiguous byte slice of concatenated MakeOutputFrame calls. Each frame is: `[0x01, payload...]`. Without a length field, the only reliable split is on 0x01 prefix bytes at expected positions.

The correct approach for the snapshot: replace the single `detector.Feed(snap)` call with a scanner that splits on frame boundaries. Since `MakeOutputFrame` produces `[0x01 | payload]` and payload is raw PTY output (which may contain any byte including 0x01), a length-prefix split is required. But the current protocol has no length prefix.

Check relay/scrollback.go to confirm storage format, then implement accordingly. If scrollback stores raw concatenated frames without length-prefixing, feed the entire blob after stripping only leading 0x01 if present. If it stores each frame as a length-prefixed entry, iterate with the length.

The safest fix that avoids ambiguity: replace the scrollback feed with a bytes.ReplaceAll that removes MsgOutput framing prefix bytes. Since the detector uses a rolling 4KB tail and ANSI-strips before classifying, the worst case is a few stray 0x01 bytes in the tail — which ANSI stripping will pass through but will not match any regex pattern. The critical fix is in the live Watch loop (Change 2) where each frame is a discrete message.

For the snapshot, implement: strip 0x01 prefix if snap starts with 0x01, then feed the remainder. This is correct for the common case where scrollback contains a single large blob.

```go
if snap := hub.ScrollbackSnapshot(); len(snap) > 0 {

        snap = snap[1:]
    }
    detector.Feed(snap)

```

```go
// TestWatch_IdleTransition verifies that a framed MsgOutput message containing
// the Claude Code prompt triggers a transition to StatusIdle.
func TestWatch_IdleTransition(t *testing.T) {
    // Build a mock hub that sends one framed output frame then closes.
    prompt := relay.MakeOutputFrame([]byte("❯ "))
    hub := newMockHub([][]byte{prompt}, nil)

    var got SessionStatus
    var mu sync.Mutex
    Watch(hub, "test-session", "claude", func(id string, s SessionStatus) {
        mu.Lock()
        got = s
        mu.Unlock()
    })

    mu.Lock()
    result := got
    mu.Unlock()
    if result != StatusIdle {
        t.Errorf("expected StatusIdle, got %q", result)
    }
}

// TestWatch_NonOutputFrameIgnored verifies that MsgResize frames are not fed
// to the detector (do not change status).
func TestWatch_NonOutputFrameIgnored(t *testing.T) {
    resize := relay.MakeResizeFrame(80, 24)
    hub := newMockHub([][]byte{resize}, nil)

    var transitions int
    Watch(hub, "test-session", "claude", func(id string, s SessionStatus) {
        transitions++
    })
    // Only the initial transition (from empty sentinel) should fire; since the
    // resize frame produces no output, the status defaults to StatusRunning once.
    // transitions must be <= 1 (initial seed) not additional ones.
    if transitions > 1 {
        t.Errorf("expected at most 1 transition, got %d", transitions)
    }
}

// TestStripANSI_OSC verifies that OSC sequences are stripped.
func TestStripANSI_OSC(t *testing.T) {
    input := []byte("\x1b]0;Claude Code\x07❯ ")
    got := StripANSI(input)
    if string(got) != "❯ " {
        t.Errorf("expected %q, got %q", "❯ ", got)
    }
}
```
