- `TerminalPanel.tsx` — isActive useEffect (timing change only)

## Interaction Contract

### TerminalPanel — isActive Fit Behavior (TERM-04)

**Before (current, broken):**
```
isActive → document.fonts.ready.then(fit) + ResizeObserver
```

**After (required):**
```
isActive → double-rAF → fit() + ResizeObserver
```

- First `requestAnimationFrame` fires after the display:none → display:flex change is scheduled.
- Second `requestAnimationFrame` fires after the browser has committed layout and painted at least one frame.
- `fit()` is called only inside the second rAF, ensuring `getComputedStyle` on the parent returns real pixel dimensions.
- Both rAF IDs must be tracked and cancelled in the effect cleanup (see pitfall in RESEARCH.md).
- `cancelled` flag guards against calling `fit()` after cleanup.
- ResizeObserver continues to handle all subsequent size changes (window resize, font size change, etc.).
- The `document.fonts.ready` approach is fully replaced; do not retain it alongside double-rAF.

**No visible interaction change for the user.** The terminal simply fills the viewport correctly on first activation instead of requiring a manual window resize.

### App.createTab — Initial Dimension Estimation (TERM-03)

- At the moment the user clicks "Create Session", `createTab` reads `document.querySelector('.terminal-container')` clientWidth/clientHeight.
- Estimates cols = `Math.max(80, Math.floor(w / 8))`, rows = `Math.max(24, Math.floor((h - 32) / 17))`.
  - 8px: approximate character cell width at 14px font size.
  - 17px: approximate character cell height at 14px font size.
  - 32px: `.tab-status-bar` fixed height (established CSS token).
- Falls back to cols=220, rows=50 when container not found or has zero dimensions.
- These approximate dims reduce the visual "jump" from 80x24; the double-rAF fit will send the exact resize after mount.
- No user-visible input or control for this. Entirely internal to `createTab`.

### PTY Spawn Dimensions (TERM-03)

- `daemon.CreateRequest` gains `Cols int` and `Rows int` fields with `json:",omitempty"` tags.
- Old clients that omit cols/rows receive the 80x24 default (backward compatible wire format).
- `SessionEngine.CreateSession` applies guards: `if cols <= 0 { cols = 80 }`, `if rows <= 0 { rows = 24 }`.

## States and Transitions

### Terminal Panel Display States (existing — must remain unchanged)

| State | CSS | When |
|-------|-----|------|
| Hidden | `display: none` (inline style) | Tab is not active |
| Visible | `display: flex` (inline style) | Tab is active — triggers isActive effect |

The transition from hidden → visible is the exact timing window where the double-rAF is required.

### Terminal Sizing States (new behavior, no visual change)

| State | Trigger | Result |
|-------|---------|--------|
| Initial spawn | createTab called | PTY spawned at estimated cols/rows (≈ real viewport) |
| First fit | double-rAF fires after first paint | `fit()` measures real dims, terminal.resize() called, PTY resize sent |
| Subsequent fit | ResizeObserver | Same as before — no change |
