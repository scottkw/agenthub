<objective>
Implement the sub-key RPC + persistence + live-toggle plumbing for `WebLinksConfig`, mirroring Phase 94 Plan 07's `SetSearchConfig` pattern verbatim. This unlocks LNK-05 and LNK-06: a Settings change to the web-links sub-config (modifier choice, per-detector confirmation toggles) writes ONLY the sub-key — never the full PluginSettings — preserving any unsaved boolean edits the user has made in the PluginsSection edit buffer. The toggle change emits `settings:plugins`, App.tsx receives the event, prop-drills new `pluginConfig` to TerminalPanel, and the addon hot-swaps live.

Note on UI scope: per RESEARCH §"Locked Decisions" — the boolean `webLinks` toggle is already shipping from Phase 92 (PluginsSection.tsx already has it). The sub-fields (modifier, confirm*) are exposed via a `<details>` advanced disclosure in **Phase 99 / PUI-03** — out of scope here. This plan ships the sub-key WRITE path and bindings; the UI for editing the sub-config in v3.2 is the existing boolean toggle calling SetPluginSettings (full path), unchanged. The sub-key path becomes hot via Phase 99.

Why ship the sub-key writer now even though UI lands later: defaults-merge in Plan 95-01 populated the sub-fields; existing PluginsSection write goes through `SetPluginSettings` (full). For LNK-06 live-toggle (desktop), the existing `webLinks` boolean toggle via PluginsSection is sufficient — the sub-key writer is here to be CALLABLE in v3.3 without a follow-up plan, AND to satisfy the VALIDATION row 95-06-01 (sub-key persistence test). This plan's web-served live-toggle parity is owned by Plan 95-06 (Playwright e2e + terminal.js applyPluginConfig arm).
