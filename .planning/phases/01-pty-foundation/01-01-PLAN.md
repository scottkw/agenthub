  <files>internal/pty/registry.go, internal/pty/registry_test.go</files>
  <behavior>
    - TestRegistry_AddAndGet: adding a session then getting by ID returns the same session
    - TestRegistry_List: listing returns all added sessions
    - TestRegistry_Remove: removing a session makes Get return false
    - TestRegistry_GetNotFound: getting a non-existent ID returns nil, false
    - TestRegistry_ConcurrentAccess: 100 goroutines adding/getting sessions concurrently with no race (run with -race)
    - TestRegistry_SessionPersistsAfterSimulatedWindowClose: session remains in registry after the "close" signal (simulated by cancelling a context — the session itself is not removed)
  </behavior>
  <action>
    1. Create `internal/pty/registry.go`:
       - `SessionRegistry` struct: unexported `mu sync.RWMutex`, `sessions map[string]*Session`
       - `NewSessionRegistry() *SessionRegistry` constructor (initializes the map)
       - `Add(s *Session)` — write-locks, adds to map by s.ID
       - `Get(id string) (*Session, bool)` — read-locks, returns from map
       - `List() []*Session` — read-locks, returns slice of all sessions
       - `Remove(id string) bool` — write-locks, deletes from map, returns whether it existed
       - `Len() int` — read-locks, returns map length
       - `KillAll()` method — iterates all sessions, calls Kill on each (implementation deferred to Plan 02 where Kill is wired; for now, just mark state as StateStopped and remove from map)
    2. Create `internal/pty/registry_test.go`:

       - `TestRegistry_List`: add 3 sessions, list, assert length 3
       - `TestRegistry_Remove`: add session, remove it, verify Get returns false
       - `TestRegistry_GetNotFound`: empty registry, get "nonexistent", assert nil and false
       - `TestRegistry_ConcurrentAccess`: launch 100 goroutines that each Add a uniquely-IDed session, then verify Len() == 100
       - `TestRegistry_SessionPersistsAfterSimulatedWindowClose`: add session, create a context, cancel it (simulating window close), verify session is still in registry with StateRunning
  </action>
