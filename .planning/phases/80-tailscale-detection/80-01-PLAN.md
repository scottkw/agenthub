<objective>
Extend the Tailscale health check backend to support 4-state detection (Not Installed / Installed-daemon-stopped / Running-disconnected / Connected) with platform-specific binary path detection and custom path override from settings.

Purpose: TS-01 requires detecting Tailscale across all common installation methods. TS-02 requires reliable connection state. The current 2-state model (Installed/Connected) conflates "binary not found" with "daemon stopped," giving users no actionable guidance.

Output: Extended TailscaleHealth struct, new tailscale_paths.go file, updated app.go bindings, comprehensive tests.
</objective>

   ```go

   ```

3. Rewrite `checkHealth` body to implement 4-state cascade (per D-02):
   - Initialize: `h := TailscaleHealth{PlatformHint: runtime.GOOS}`
   - Step 1 — Binary detection: `binary := detectTailscaleBinary(customPath)`. If empty, return `h` (all bools false).
   - Set `h.BinaryFound = true`
   - Step 2 — Daemon probe: call `fn(ctx)`. If error, return `h` (BinaryFound=true, DaemonUp=false).
   - Set `h.DaemonUp = true` and `h.Installed = true` (legacy compat: Installed now means daemon reachable)
   - Step 3 — Connection state: `h.Connected = status.BackendState == "Running"`
   - Step 4 — Certs (only if connected): set `HasCerts`, `IP`, `Domain` from status (same logic as current code)
   - Return `h`

4. Keep `CheckHealth` as the public API but add new `CheckHealthWithCustomPath`:
   ```go
   func CheckHealth(ctx context.Context) TailscaleHealth {
       var lc local.Client
       return checkHealth(ctx, lc.StatusWithoutPeers, "")
   }

   func CheckHealthWithCustomPath(ctx context.Context, customPath string) TailscaleHealth {
       var lc local.Client
       return checkHealth(ctx, lc.StatusWithoutPeers, customPath)
   }
   ```

Add `"runtime"` to imports.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Settings -> CheckHealth | Custom path from user settings used as filesystem path |
| Filesystem -> CheckHealth | os.Stat on user-provided and well-known paths |
| Tailscale daemon -> CheckHealth | local.Client response trusted for state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-80-01 | Tampering | detectTailscaleBinary | accept | Custom path comes from daemon settings.json (user-controlled local file); path is only used for os.Stat existence check, not executed directly in this code path. The binary is already trusted as "tailscale" by the user. |
| T-80-02 | Information Disclosure | PlatformHint | accept | Exposes runtime.GOOS to frontend — this is already visible in User-Agent and binary type; no sensitive info. |
| T-80-03 | Denial of Service | checkHealth timeout | mitigate | CheckHealthWithCustomPath called with 5s context timeout (existing pattern in app.go). Daemon socket probe inherits this timeout via context cancellation. |
| T-80-04 | Spoofing | detectTailscaleBinary | accept | A malicious binary at a well-known path could impersonate tailscale. This is a local-machine-compromise scenario outside app scope. The binary is not executed by detection — only os.Stat. |
</threat_model>
