<objective>
Close FNL-03 end-to-end: the Tailscale Funnel "hop 2" (tailscaled → AgentHub listener) fails for every external guest, and the 165-04 fix (Option A `https+insecure://<bindIP>:443`) is PROVEN-DEAD live (off-tailnet device confirmed 502). This plan replaces 165-04's insufficient proxy-target fix.

Root cause (live UAT, real Funnel-granted tailnet): AgentHub's only listener is HTTPS-only with an SNI-driven cert (`ws.lc.GetCertificate`) that mints a cert ONLY for the `<hostname>.ts.net` name. tailscaled's Funnel proxy dials the raw bind IP and sends SNI=IP → no cert for an IP literal → TLS `internal_error` → HTTP 502. `https+insecure` disables the client's verification, not the SNI the server needs to select a cert. The sibling target `https+insecure://<FQDN>:443` is ALSO dead: public DNS resolves the `.ts.net` FQDN to Tailscale's Funnel ingress IPs (not the local tailnet IP) → Funnel→ingress→Funnel loop → hang. Both naive proxy-target host changes are rejected, proven live.

Locked fix (loopback-HTTP target — Tailscale owns ALL real TLS):
1. AgentHub adds a PLAIN-HTTP listener bound to LOOPBACK (127.0.0.1, ephemeral port) serving the SAME mux as the HTTPS listener. Today AgentHub binds ONLY the tailnet IP, so this loopback HTTP listener must be ADDED.
2. EnableFunnel sets the serve-config Proxy to `http://127.0.0.1:<loopbackPort>` (plain http, loopback host, the loopback listener's port). The `https+insecure://<bindIP>:port` target is removed.
3. WHY safe: tailscaled terminates the only PUBLIC TLS on hop 1 (guest→ingress, real verified Tailscale cert). Hop 2 is plain HTTP on loopback that NEVER leaves the machine (kernel loopback, not on any wire). Public posture UNCHANGED: cap token + dual-origin allowlist + real public cert on hop 1.
4. CO-LOCATION ASSUMPTION (recorded in the plan + a code comment + the threat model): loopback plaintext is safe ONLY because AgentHub's listener and tailscaled run on the SAME machine. If they ever split across tailnet nodes, the target MUST become a WireGuard-tunneled tailnet-IP target. A future split must not silently re-expose plaintext.
5. Lifecycle: the loopback HTTP listener starts when the web server starts (startTailscale) and is torn down with the web server (Stop) — reusing the existing single-listener lifecycle so the proven-live FNL-05 teardown path is unaffected. (RESOLVED — see <design_decisions> for why start-time, not enable-time.)

Critical test correction: the 165-04 guard `TestEnableFunnel_ProxyTargetReachable` was FALSE-GREEN — it dialed a loopback self-signed cert that answers for ANY SNI, so the SNI-vs-cert mismatch could never surface. The rewritten test asserts the loopback-HTTP target SHAPE (scheme http, host 127.0.0.1, port = the loopback listener's actual port — explicitly NOT https/https+insecure, NOT BindIP-or-FQDN-keyed), actually dials the loopback HTTP target with a PLAIN http.Client and requires a served response, and encodes an anti-regression guard against any return to an HTTPS-IP/FQDN target. The true end-to-end SNI/ingress failures are only reproducible on a live tailnet (M-34); the unit test guards target SHAPE + loopback reachability, and live M-34 from an off-tailnet device is the real acceptance gate.

Output: modified `server.go` (loopback HTTP listener + lifecycle + http loopback proxy target + co-location comment), rewritten webserver reachability test, TESTING.md re-coverage notes + M-34 update. No daemon changes — 165-04's GAP 2 kill-path teardown (FNL-05) PASSED live and is untouched.

<design_decisions>
RESOLVED from the real Start/Stop code (server.go 365-520):

- **Lifecycle hook point = start-time in startTailscale(), torn down in Stop().** startTailscale (line 426) is the only path that uses the SNI-driven Tailscale cert and the only path Funnel can run on; startLocal (line 469, local/fallback mode) never funnels, so it gets NO loopback listener. Binding the loopback HTTP listener in startTailscale (right after `ws.listener = ln`, before/after the `go http.Serve(ln, ws.mux)`) and closing it in Stop() (line 507, alongside `ws.listener.Close()`) reuses the existing single-listener teardown — the proven-live FNL-05 path (M-35 a/b/c PASS) is unaffected because the loopback listener is a local socket, NOT part of the Tailscale serve config that DisableFunnel clears. Enable-time binding was REJECTED: it would require double-bind guards on re-enable, a separate close path outside Stop, and binding a listener while holding ws.mu.Lock inside EnableFunnel — more surface, weaker teardown reuse.
- **Ephemeral loopback port (`127.0.0.1:0`)** never collides, so no EADDRINUSE fallback logic is needed (unlike the tailnet listener's port-in-use retry at lines 446-456).
- **Same mux, plain HTTP.** In tailscale mode the main listener already serves `ws.mux` directly with no basic-auth wrapper (line 462). The loopback HTTP listener serves the identical `ws.mux`, so the cap-token + dual-origin gates enforced inside the mux still apply on hop 2. `assertTailnetBindIP` (line 403) already treats loopback as an allowed bind, so the loopback surface is consistent with the existing trust model (loopback is strictly more restrictive than the tailnet bind — same-host only).
- **Dual-origin allowlist survives the loopback target (plan-checker WARNING-1 — the most likely way this fix could trade 502 for 403).** `requireAllowedOrigin` / `originAllowedForWrite` validate the request's **Origin** header (byte-matched against `BaseURL()`/`FunnelBaseURL()`), NOT the Host header. The Origin is set by the guest's browser to `https://<hostname>.ts.net` and is forwarded as-is by tailscaled's reverse proxy. So the allowlist passes regardless of whether tailscaled rewrites the **Host** to `127.0.0.1:<loopbackPort>` (which it may, dialing a loopback target) or preserves the funnel hostname — the gate keys off the browser-originated Origin, which is preserved either way. Do NOT introduce any Host-based check while making this change: an "Origin must equal Host" assumption would reintroduce the exact 165-04-class invisible failure. (Confirmed against requireAllowedOrigin in origin_mw.go / capability_mw.go.)
</design_decisions>
