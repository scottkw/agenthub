## Tests

### 1. M-34 — External-tailnet HTTP request gets 200 on the no-port Funnel URL
expected: A machine with no Tailscale installed opens https://<hostname>.ts.net/sessions/<id>?cap=TOKEN and receives 200 (not 403), with the Origin: https://<hostname>.ts.net header present.
result: issue
reported: "Live test on a real Funnel-granted tailnet (BackendState=Running, funnel node attr granted): enabling Funnel succeeds and `tailscale serve status` shows 'Funnel on' with no-port URL, BUT every request to the Funnel URL returns HTTP 502 — reproduced through the REAL public Funnel ingress (199.38.181.54, valid TLS). The Funnel-shared session is unreachable for all guests."
severity: blocker
root_cause: "EnableFunnel (internal/webserver/server.go:610-617) builds the serve-config reverse-proxy target as `https://localhost:<port>`, taking only the PORT from the listener and hardcoding host=localhost. But the AgentHub web server binds to the TAILNET IP (e.g. 100.86.210.104:<port>), not localhost — enforced in production by assertTailnetBindIP (server.go:403, which rejects any non-tailnet/non-loopback bind). Nothing listens on localhost:<port>, so tailscaled's Funnel proxy gets connection-refused → 502. Additionally the backend uses a self-signed cert (GenerateSelfSignedCert, server.go:470), which an `https://` proxy target would fail to validate even if the host matched. Net: Tailscale Funnel sharing (the v4.2 centerpiece, FNL-03) is broken end-to-end. Unit tests could not catch this because the fake funnelClient records SetServeConfig args but never actually proxies traffic."

### 2. M-35 — `tailscale serve status` shows empty config after each teardown trigger
expected: After each of the four production teardown paths (toggle-off, web-share-off, session natural end, daemon clean stop), running `tailscale serve status` on the host reports no serve entries / an empty config.
result: pass
source: live
note: "Verified live on a real Funnel-granted tailnet, all four triggers, each clearing the serve config to 'No serve config': (1) toggle-off via POST /sessions/{id}/funnel {enabled:false} → HTTP 204, config empty; (2) web-share-off (`unserve`) → config empty; (3) natural session end — a self-exiting session (sh -c 'sleep N') with Funnel on; after the process exited, the D-12 10s grace-period cleanup (onExit → runSessionExitCleanup → disableFunnelForSession, api.go:660/698) fired and the config cleared (~19s); (4) daemon clean stop (SIGTERM) → ws.Stop()→DisableFunnel cleared config. BONUS: on fresh daemon start, ClearLingeringFunnel wiped a lingering serve entry left by a prior run (0 entries at startup — TestStartupClearsLingeringFunnel confirmed live). NOTE on test method: an explicit `kill` (DELETE /sessions/{id}) is NOT one of M-35's four triggers and does NOT fire onExit (engine.go KillSession bypasses the natural-exit callback); see Gaps for the resulting kill-path teardown gap."
