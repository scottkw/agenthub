<objective>
Close the two defects that a live UAT on a real Funnel-granted tailnet exposed but the fake-based unit tests could not catch:

- GAP 1 (BLOCKER, FNL-03): the Funnel reverse-proxy target was hard-coded to `https://localhost:<port>`, but the AgentHub web server binds to the tailnet IP (`ws.config.BindIP`), not localhost. Nothing listens on localhost, so tailscaled's Funnel proxy got connection-refused and every external guest received HTTP 502. The v4.2 Funnel centerpiece was unreachable end-to-end.
- GAP 2 (MAJOR, FNL-05): an explicit kill (`DELETE /sessions/{id}` → `engine.KillSession`) never fires the natural-exit `onExit` callback, so `runSessionExitCleanup` → `disableFunnelForSession` was never invoked on the kill path. Funnel stayed exposed after kill and a stale `funnelSessions[id]` ref-count entry blocked teardown of a sibling session's later natural exit.

Purpose: restore the Funnel sharing flow for real external guests (200, not 502) and guarantee Funnel teardown on the explicit-kill path, with new tests that exercise real proxy-target reachability and the real kill entry point so this defect class is caught in CI going forward.

Locked planning decisions honored here (user-approved, do not deviate):
- GAP 1 fix is Option A: proxy target becomes `https+insecure://` + `net.JoinHostPort(ws.config.BindIP, localPort)`. The listener already serves TLS (real Tailscale cert via `ws.lc.GetCertificate` in Funnel mode); `https+insecure` keeps TLS encryption on the internal same-host hop but skips cert-HOSTNAME verification, which is required because the proxy dials the raw 100.x IP while the cert is issued for the `<hostname>.ts.net` DNS name. The Tailscale `ipn` serve config supports the `https+insecure` scheme (verified: tailscale.com@v1.96.3 ipn/serve.go ExpandProxyTargetValue supportedSchemes = {http, https, https+insecure}). This hop never leaves the host; the public guest↔tailscaled hop keeps full verified TLS with the real public cert, so guests see no certificate warning and the internet-facing posture (cap token + Origin allowlist + public cert) is unchanged.
  - Rejected (B): `https://<hostname>.ts.net:<port>` verified target — depends on an unproven MagicDNS hairpin from tailscaled's dialer (the exact unverified-assumption class that produced this 502).
  - Rejected (C): add a loopback listener — extra listener/cert surface and still needs insecure/self-signed anyway.
- GAP 2 fix: tear down Funnel (and web-serve) on the explicit kill/delete path WITHOUT the 10s D-12 grace period (a killed session has no output to flush), by converging on the existing shared teardown helpers rather than duplicating logic.

Output: modified `server.go` (one-line proxy-target fix), new webserver reachability test, modified `api.go` (kill-path teardown wiring), new daemon kill-path teardown test, TESTING.md re-coverage notes + M-34 update.
</objective>
