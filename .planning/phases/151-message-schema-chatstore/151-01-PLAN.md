<objective>
Define the durable `ChatMessage` wire/serialization contract and implement the core of the daemon-side per-session `ChatStore`: JSONL append-only persistence, restart-survival load, full-thread replay, the 10,000-message hard cap, sessionID path-traversal hardening, and concurrent-write safety.

Purpose: This is the foundation phase of v4.1 Session Chat. The `ChatMessage` schema is the stable contract that two client surfaces (desktop GUI, web-share) and four later phases (152 relay frames, 153 @session bridge, 154/155 UI) serialize to. The store is the durability substrate behind PERSIST-01/02/03. Getting the schema and store invariants right here avoids a coordinated migration across every later layer.

Output: `ChatMessage` + `ChatSchemaVersion` in `internal/relay/protocol.go`; `ChatStore` (construct/load/append/messages) in `internal/daemon/chat.go`; unit + `-race` tests.
</objective>

    Implement `AppendMessage(msg relay.ChatMessage) (relay.ChatMessage, error)` on ChatStore. Acquire the mutex for the WHOLE operation so the file write and the slice append are atomic together (prevents the mirror and disk diverging — key link). First enforce the cap: if len(mirror) >= MaxChatMessages return the zero message and a package-level sentinel `ErrChatCapReached` (define it via errors.New) WITHOUT writing — justify in a code comment that REJECT (not trim) is chosen because the file is append-only: trimming would require rewriting the whole JSONL under load, breaking the append-only invariant and introducing a rewrite race, and ROADMAP SC#4 specifies reject semantics ("AppendMessage rejects further writes"). <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sessionID → filesystem path | The sessionID string is interpolated into a JSONL filename; a crafted value must not escape the chats dir. |
| concurrent senders → single JSONL file | Multiple goroutines (later: multiple WS read pumps) append to one file + one in-memory slice. |
| daemon process → disk | Chat content persisted to disk on the local machine. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-151-01 | Tampering | NewChatStore sessionID→path | high | mitigate | validChatSessionID strict allowlist [A-Za-z0-9_-]; reject empty/"."/".."/separators; defense-in-depth filepath.Dir(path)==chatsDir() containment check before any file op (Task 2) |
| T-151-02 | Denial of Service | AppendMessage unbounded growth | medium | mitigate | MaxChatMessages=10000 hard cap enforced atomically inside AppendMessage; reject-not-trim keeps append-only invariant (Task 3) |
| T-151-03 | Tampering | concurrent JSONL append | high | mitigate | sync.Mutex spans both file write and mirror append; 200-goroutine -race test proves no corruption/loss (Task 3) |
| T-151-05 | Information Disclosure | chat content in logs | low | mitigate | message Content is never logged; metadata-only logging; grep gate in Task 3 acceptance |
| T-151-SC | Tampering | dependency supply chain | low | accept | Zero new Go modules this phase (stdlib encoding/json + os + sync + crypto/rand only); go.mod unchanged, so no package-legitimacy gate applies. |
</threat_model>
