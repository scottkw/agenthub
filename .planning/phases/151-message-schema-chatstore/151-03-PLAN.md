<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| web-share client → webserver chat read | Untrusted tailnet peer requests a session's thread; must hold a valid cap for THAT session. |
| webview → relay loopback (127.0.0.1) | Cross-origin browser request from the Wails webview to the loopback relay; network boundary is loopback-trusted. |
| webserver → daemon store | The webserver must reach chat data without importing the daemon package (cycle) — provider callback only. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-151-04 | Information Disclosure | web /api/chat/{id}/* without valid cap | high | mitigate | ws.requireCapability wraps both routes; reuses HMAC verify + claims.SID==={id} match + grant/enabled checks; tests assert 401 (no/invalid cap) and 403 (wrong-session cap) (Task 2) |
| T-151-08 | Spoofing | cross-origin webview request to relay chat routes | low | mitigate | relay.FilesCORS loopback-origin allowlist on the relay chat routes; relay bound to 127.0.0.1 is the real boundary (Task 1) |
| T-151-09 | Information Disclosure | daemon↔webserver coupling leaking store internals | low | mitigate | provider returns pre-serialized bytes/markdown; webserver never imports daemon ChatStore (grep gate, Task 2) |
| T-151-SC | Tampering | dependency supply chain | low | accept | Zero new Go modules this phase; go.mod unchanged. |
