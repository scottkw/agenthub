<objective>

This is the Wave 1 foundation: closes Pitfall 1 (CORS) by guaranteeing the frontend always fetches same-origin, and closes Pitfall 4 (no cross-machine cap acquisition path) by giving the desktop GUI + TUI a daemon-side place to deposit a cap obtained from a pasted join code.

No consumer surface changes in this plan — the routes light up, the cap store accepts deposits, and integration tests prove the proxy forwards correctly. Wave 2 plans (03 desktop GUI, 04 TUI) consume these.

Output: New files `internal/daemon/remote_files.go`, `internal/daemon/remote_caps.go` + their `_test.go` siblings; route registrations in `internal/daemon/api.go`; helpers on `DaemonClient` in `internal/daemon/client.go`. No frontend or TUI changes.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Loopback (Unix socket / TCP relay) → Daemon | Trusted; same-origin from Wails webview and TUI in-process |
| Daemon → Remote Webserver (Tailscale HTTPS) | Untrusted transport; mutual auth via Tailscale + cap token in URL |
| Wails Webview ↔ Local Daemon (relay port) | Same-origin; no CORS needed |
| Wails Webview ↛ Remote Webserver (direct) | BLOCKED by design — no `Access-Control-*` headers on remote webserver (Pitfall 1) |
