<objective>
The --shell=bash|zsh|pwsh|powershell flag on `agenthub new shell` is the last
surface that bypasses Phase 107's Settings-driven shell binary resolution.
This plan deletes the flag entirely (hard removal — no deprecation, no
warning, no allowlist), so the CLI always passes cli="shell" to
daemon.CreateSession and the daemon resolves the spawned binary via the
existing engine.GetShellPath() / shellPath path. The cmdNewShell tests in
cmd_cli_test.go are rewritten — the five --shell=X tests are deleted, the
two positional/no-args tests stay, and three new tests are added to cover
PARITY-CLI-01 (removed-flag rejection), PARITY-CLI-02 (Settings-driven
resolution), and PARITY-CLI-03 (invalid shellPath silent fallback).

This plan is independent of 108-01 at the file level (no overlap in
files_modified) and can run in parallel. The help-block update in cmd_cli.go
(usage()) and the README "Shell sessions" section are deferred to 108-03 so
this plan stays focused on the cmdNewShell code path and its tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User shell → agenthub CLI | Untrusted argv crosses here (flag values, positional paths) |
| CLI → daemon (unix socket) | Trusted in-process daemon connection over local socket |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-108-CLI-01 | T (Tampering) / S (Spoofing) | --shell flag input | mitigate (by removal) | Removing --shell eliminates the per-binary CLI override entirely; binary selection now flows exclusively through daemon-validated SetShellPath. Reduces input surface from 5 allowed strings to 0. |
| T-108-CLI-02 | I (Information Disclosure) | CLI stderr on bad flag | accept | Go flag package writes `flag provided but not defined: -shell` — leaks only the rejected flag name, no path or env information. Standard CLI behaviour. |
| T-108-CLI-03 | E (Elevation of Privilege) | shellPath resolution via daemon | accept | Daemon resolution path (engine.go:500-530, SetShellPath validation at 670-705) is unchanged from Phase 107; this plan removes a bypass (--shell=X) rather than adding new surface. Per PARITY-CLI-03 the CLI does not stat or validate the resolved path — daemon owns that. |
| T-108-CLI-04 | D (Denial of Service) | Invalid shellPath silent fallback | accept | If shellPath points to a nonexistent binary, the CLI returns 0 (SPEC mandate); the daemon's spawn failure surfaces via session-lifecycle, not the CLI. This is an intentional design choice — silent fallback prevents the CLI from leaking daemon internal state. Operator can diagnose via session list / logs. |

No new attack surface: this plan is a hardening (input surface reduction).
The hard removal of --shell is documented in SPEC §Constraints as an
acceptable v3.3 CLI break (flag introduced in same milestone, daemon-side
resolution makes the flag value redundant in 100% of cases).
</threat_model>
