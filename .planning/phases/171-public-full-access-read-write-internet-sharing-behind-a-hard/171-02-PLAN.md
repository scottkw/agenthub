<objective>
Add the daemon-side RW-gate lifecycle: a mint handler that registers the write grant + RW gate + single-use write code + expiry timer only on gate completion, a surgical teardown helper wired into all four triggers, removal of the accidental funnel write-rebasing (D-04), and the RPC surface (client + Wails binding) the frontend will call.

Purpose: This is where the accidental public-write path is closed and replaced with a deliberate one. The write cap is minted ONLY here (never at ordinary cap-issue time), terminal-only, short-lived, and instantly revocable — mirroring Phase 170's `funnelReadCode` lifecycle but single-use and write-scoped, with the teardown split by blast radius so an RW-only disable never kills the read share.

Output: `handleSetSessionFunnelWrite`, `revokeFunnelWriteLocked`/`disableFunnelWriteForSession`, the write-write struct fields, the `POST /sessions/{id}/funnel-write` route, `SessionInfo.FunnelWriteActive`, `DaemonClient.SetSessionFunnelWrite`, `App.SetSessionFunnelWrite`, and D-04 removal — with tests.
</objective>
