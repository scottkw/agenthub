<interfaces>
The existing Sandbox per-op pattern every new write method must mirror (source internal/files/sandbox.go:68-112).

Sandbox.Open is the structural template — validate, then os.OpenRoot, then defer Close, then call the native os.Root method:
  func (s *Sandbox) Open(relPath string) (*os.File, error)
  // body: cleaned,err := validateAndClean(relPath); root,err := os.OpenRoot(s.rootPath); defer root.Close(); return root.Open(cleaned)

validateAndClean(relPath string) (string, error) is the single path-validation authority — rejects "..", absolute paths, null bytes, Windows device names, ADS colons, UNC. Call it on EVERY path. For Rename call it on BOTH oldRel AND newRel.

s.rootPath is the cached EvalSymlinks'd root. Never cache the *os.Root handle — open a fresh os.OpenRoot per operation. Sandbox.RootPath() string returns s.rootPath.

Existing wire-type shape to mirror (internal/files/types.go:26-46): FileListResponse has Entries []FileEntry json:"entries" and Truncated bool json:"truncated", with declaration-order doc comments and camelCase JSON tags.

crypto/rand temp-suffix idiom: mirror internal/daemon/api.go:1034 — rand.Read into a fixed [8]byte array, then hex.EncodeToString.

VERIFIED CORRECTION (RESEARCH State of the Art): Go 1.26.4 *os.Root HAS native Rename(old,new), MkdirAll(name,perm), RemoveAll(name), Remove(name), OpenFile(name,flag,perm). Use these directly. Do NOT hand-roll with os.Rename on constructed absolute paths — the milestone PITFALLS.md / FSW-02 text claiming os.Root.Rename "does not exist" is stale and wrong for this toolchain.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → Sandbox method | relPath/newRel are untrusted strings; may contain traversal, encoded escapes, device names |
| Sandbox → kernel (os.Root) | os.Root is the syscall-level confinement boundary; rejects symlink/.. escape with no TOCTOU window |
| session cwd = $HOME | when a sandbox is rooted at/above $HOME, sandbox-correct writes can still hit dotfiles/SSH keys |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-123-01 | Tampering | Sandbox.Rename destination path | mitigate | validateAndClean on BOTH oldRel and newRel (Task 3); native root.Rename syscall backstop; TestRename_DestinationTraversalRejected + FuzzSandboxWrite rename-dest seeds |
| T-123-02 | Tampering | symlink TOCTOU on write/rename/mkdir/delete | mitigate | fresh os.OpenRoot per op; never cache handle; kernel rejects escape (Task 3); FuzzSandboxWrite |
| T-123-03 | Elevation of Privilege | shell-RC / SSH-key / .claude overwrite in $HOME-rooted sandbox | mitigate | denylistCheck inside ALL five write methods → ErrProtectedSystemFile (Task 2/3); TestDenylist_HomeRooted |
| T-123-04 | Tampering / DoS | partial/torn file visible to concurrent AI-agent reader | mitigate | WriteFileAtomic temp+Sync+rename, no O_TRUNC, temp is sandbox sibling (Task 3); TestWriteFileAtomic_ConcurrentReadNeverPartial |
| T-123-05 | Tampering | temp-file name collision / race between concurrent writers | mitigate | crypto/rand 8-byte suffix + O_EXCL on temp create (Task 3) |
| T-123-06 | DoS | Windows rename-over-open-file failure | mitigate | bounded 3-attempt retry loop around root.Rename on Windows (Task 3) |
</threat_model>
