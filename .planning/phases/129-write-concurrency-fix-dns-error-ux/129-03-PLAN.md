<objective>
Implement the DNS error UX: classify the unresolvable-MagicDNS / accept-dns=false failure specifically and surface an actionable message, plus probe accept-dns proactively in the health check.

This turns Plan 01's RED DNS tests GREEN: TestProxyRemoteFiles_AcceptDNSMessage (DNS-01/DNS-02) and TestCheckHealth_AcceptDNS (DNS-03).

Purpose: Today `proxyRemoteFiles` returns a generic opaque 502 for all dial failures, so a user with accept-dns=false sees "502 no such host" with no fix guidance. The classifier names the fix; the proactive probe warns before the failure path.

Output: AcceptDNS on TailscaleHealth (internal/webserver/tailscale.go), isUnresolvableMagicDNS + DNS branch in proxyRemoteFiles (internal/daemon/remote_files.go), and the matching frontend model field.
</objective>
