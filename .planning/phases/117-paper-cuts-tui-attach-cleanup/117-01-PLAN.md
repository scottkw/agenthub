## Tasks

### PAPER-01 — TUI lipgloss.Place defensive guard

**Symptom:** `internal/tui/modal.go::renderNewSessionModal` panicked with `index out of range [0] with length 0` when `m.width` or `m.height` was zero (race between TUI mount and the first `WindowSizeMsg`).

**Upstream context:** Phase 109 scope addition #3 (`84e1387`) closed the "no detected CLIs → empty content → panic" path by ensuring `agentEntries()` always returns at least the static Shell entry. That fix addressed the specific repro that surfaced during Phase 109 Windows UAT, but the broader class of "any zero-dimension render → lipgloss.Place panic" remained.

**Fix:** Guard at the top of `renderNewSessionModal`:

```go
if m.width <= 0 || m.height <= 0 {
    return ""
}
```

**Test:** New `internal/tui/modal_test.go`:
- `TestRenderNewSessionModal_ZeroDimensions` — 5 sub-cases (both zero / width zero / height zero / negative width / negative height) — each would panic pre-fix.
- `TestRenderNewSessionModal_NoDetectedCLIs` — defense-in-depth verifying the Phase 109 `agentEntries` always-include-Shell contract.

### PAPER-02 — `agenthub attach` clears local terminal on entry

**Symptom:** When a user runs `agenthub attach <sid>`, the local terminal retains the prior shell prompt + the typed-attach command + any other scrollback above the session's first frame. Paper-cut surfaced during Phase 110 UAT.

**Fix:** In `cmd_attach.go` `cmdAttach`, after wrapping stdout in `LockedWriter` and before starting the status bar, write ANSI Erase-in-Display + Cursor-Home:

```go
if term.IsTerminal(int(os.Stdout.Fd())) {
    _, _ = stdout.Write([]byte("\x1b[2J\x1b[H"))
}
```

Only emitted when stdout is a TTY — non-TTY callers (pipes, CI redirects) still get the existing one-shot banner on stderr.

**Test:** Manual UAT only — TTY-gated behavior cannot be reasonably exercised without TTY simulation infrastructure, which exceeds the paper-cut scope. UAT scaffold lives in `117-VERIFICATION.md`.

### PAPER-03 — cleanup.go cmd.Wait goroutine clarity + regression test

**Symptom:** Phase 110 REVIEW flagged WR-03: `internal/pty/cleanup.go::killSession` spawns a goroutine to call `cmd.Wait()`, then waits with a 2s SIGHUP timeout + 1s SIGKILL timeout, and if both elapse, "gives up" leaving the goroutine running.

**Investigation finding:** This is bounded-lifetime, not a true leak. After SIGKILL the kernel terminates the process; `cmd.Wait()` returns; the goroutine closes(done) and exits. On the rare "process stuck in D-state" path (uninterruptible kernel I/O), the goroutine may outlive `killSession`'s return but completes when the OS eventually reaps the process. Per-session resource cost: ~4 KiB stack frame for the duration of the stuck I/O.

**Fix:**
- Rewrote the comment block above the goroutine to accurately describe the bounded-lifetime contract.
- Rewrote the misleading "Give up — process is truly stuck" comment to point readers to the goroutine-lifetime note above.

**Test:** New `internal/pty/cleanup_test.go` (`//go:build !windows`):
- `TestKillSession_NoGoroutineLeak_NormalCase` — spawns N=5 sessions running `sleep 30`, kills each via `b.Kill` (which calls `killSession` → SIGHUP path), waits for settlement via GC + sleep cycles, asserts `runtime.NumGoroutine()` returns to baseline (tolerance ≤N for in-flight cleanup). Catches any regression that would make the normal-case path leak.

## Risks

- **PAPER-02:** Terminals that don't support `\x1b[2J\x1b[H` (very old / minimalist) would render those bytes literally. Mitigation: the sequence is part of ANSI X3.64 (1979); any terminal capable of running `agenthub attach` supports it. Defense-in-depth via the `term.IsTerminal` gate ensures non-TTY callers (pipes, CI) never receive the bytes.
- **PAPER-03 comment-only fix:** A future reviewer might think "no behavior change → no real fix." Mitigation: the regression test is the load-bearing artifact; the comment update prevents the next maintainer from "fixing" the goroutine pattern in a way that breaks the bounded-lifetime contract.
