## Summary

Reorganize the session **Share** modal so it stops feeling disheveled and stops scrolling as the user steps through options. Today the modal is a single growing column: every toggle a user flips *injects* another block (a risk panel, a link section, a danger gate) inline, pushing everything else down until the dialog overflows and scrolls.

**Chosen direction (from a reviewed set of four candidates):** a **fixed control strip + three-tab segmented access panel**. The three toggles stay pinned; the link details live under a segmented control with **Tailnet**, **Internet (read-only)**, and **Internet (full access)** tabs that *swap* instead of stacking. The dangerous public-write / command-execution flow is walled off entirely inside its own **Internet (full access)** tab.

This is UX/IA + polish only — no change to the sharing capability model, tokens issued, or Funnel behavior.

## Motivation

Walking the current modal's states: all-off is calm, but "Share the session" reveals two link sections with orphaned scope paragraphs floating between them; "Enable internet sharing" injects a Funnel risk panel **between** the toggles and the links, shoving them down; and once internet share is engaged, Read-Only + Full Access + INTERNET (PUBLIC) + the tall red PUBLIC WRITE ACCESS gate all stack in one column and the dialog scrolls.

### Concrete defects
- **Unbounded vertical growth in one column** — `.hub-share-modal__body` is `overflow-y:auto` inside `max-height: calc(100vh - 64px)` (`style.css:6318,6361`); enabling options only adds height.
- **Content jumps / reflows** — flipping a toggle mounts a panel *above* existing content (`FunnelRiskPanel` at `SessionShareModal.tsx:691`), so the links the user was looking at slide down. This is the "disheveled" feeling.
- **Controls and outputs interleaved** — the dialog is both a control panel (toggles) and an output panel (four link rows) with confirmation gates spliced between.
- **Orphaned scope descriptions** — read-only / full-access paragraphs aren't attached to their links (`SessionSharePanel.tsx:467,506`).
- **Four ad-hoc link rows** — Read-Only, Full Access, Public URL, Public write — same shape, hand-laid, so alignment drifts.
- **Danger gate always fully expanded** once Funnel is on, even for users who only want read-only internet sharing.

## Design goals
- **Stable frame** — controls stay put; enabling a toggle reveals detail in a predictable region, never reflows the whole dialog.
- **Bounded height** — any state fits `max-height: calc(100vh - 64px)` with no whole-dialog scroll.
- **One thing at a time** — show only the access tier the user is looking at.
- **Wall off the dangerous path** — public write (command execution) is a deliberate, separate tab, not persistent body content.
- **Consistent link presentation** — one reusable link-row component for every tier.

## Chosen design — three-tab segmented modal

### Information architecture
```
┌ Share — claude 1 ───────────────────────── ✕ ┐
│  [●] Share the session                    On  │  ← fixed control strip
│  [ ] Enable remote file browsing         Off  │     (toggles never move)
│  [ ] Enable internet sharing             Off  │
│ ────────────────────────────────────────────  │
│  ┌ Tailnet ─┬ Internet ──┬ Internet ──────┐   │  ← segmented control
│  │ Private  │ Read-only   │ ⚠ Full access  │   │     (swaps the panel below)
│  └──────────┴─────────────┴────────────────┘   │
│  … active tab body …                           │  ← the ONLY region that changes
└────────────────────────────────────────────────┘
```

- **Tailnet · Private** — the two on-tailnet links: Read-Only Link and Full Access Link (each: label · truncated URL · Copy/Open/QR · join code · scope description attached directly beneath).
- **Internet · Read-only** — public URL + reusable join code + "Disable internet share". The safe public share, isolated.
- **Internet · ⚠ Full access** — self-contained command-execution flow: terminal-exposure warning → "Enable public write access…" → hold-to-confirm gate (expiry select + `HoldToConfirmButton`) → collapses to an armed summary (write URL / single-use code / countdown / "Disable public write"). Nothing about public write appears anywhere else.

### Layout regions
1. **Header** (`.hub-share-modal__header`, fixed, `height:48px`) — unchanged.
2. **Control strip** (top of `.hub-share-modal__body`, non-scrolling) — the three existing toggles + the divider.
3. **Segmented control** — new, directly under the divider, shown only when `shareEnabled`.
4. **Panel body** — the active tab's content; the only region that swaps.

### Tab state machine
Inputs: `shareEnabled`, `internetEnabled` (toggle), `internetConfirmed` (risk acknowledged / Funnel engaged), `publicWriteArmed`.

| Condition | What renders in the panel |
|---|---|
| `!shareEnabled` | No tabs. Empty hint: "Turn on Share the session to get a link." |
| `shareEnabled && internetEnabled && !internetConfirmed` | **Transient confirm view** replaces the panel (risk ack + auto-expire + "Keep local only" / "Enable internet share"). No tabs shown. |
| `shareEnabled && (!internetEnabled \|\| internetConfirmed)` | Segmented control + active tab body (see below). |

Tab availability & default:
| Tab | Enabled when | Body |
|---|---|---|
| Tailnet · Private | `shareEnabled` | Read-Only + Full Access link cards |
| Internet · Read-only | `internetConfirmed` | Public URL + reusable code + Disable-internet |
| Internet · ⚠ Full access | `internetConfirmed` | Danger explainer + write-gate state machine |

- On successful internet confirm, the active tab **defaults to Internet · Read-only** (the safer landing), so Full-access is always a deliberate second click.
- Disabling internet sharing resets the active tab to **Tailnet** and disables both Internet tabs.
- The Internet tabs render as **disabled segments** (dimmed, `aria-disabled`) until `internetConfirmed`, so the tier structure is visible before it's reachable.

### Colorblind & accessibility affordances
(Owner is colorblind — state must not rely on hue.)
- The **⚠ Full access** tab is distinguished by a **glyph (⚠) in its label + a red inset ring when active** — not color alone.
- Toggles read state by **knob position + an "On/Off/N/A" text label**, not just track color.
- Segmented control is a real `role="tablist"` with `role="tab"`/`aria-selected`, arrow-key roving tabindex, and visible `:focus-visible` rings.
- The hold-to-confirm control keeps a text label and works under `prefers-reduced-motion` (falls back to a plain confirm rather than a timed fill).

### Modal width (decided)
Widen the card from `width: min(480px, calc(100vw - 48px))` to **`width: min(520px, calc(100vw - 48px))`** so the three segment labels and link rows breathe. Segments keep the stacked two-line labels ("Internet" / "Read-only") as a belt-and-suspenders fit on narrow viewports. Touches `.hub-share-modal` sizing (`style.css:6318`) — verify the responsive override at `:6405` still clamps correctly on small windows.

## Component breakdown
- **`SessionShareModal.tsx`** (shell) — keeps the three toggles as the fixed control strip; owns the tab/confirm state; renders the new `<ShareSegmentedControl>` + active-tab dispatch. The `FunnelRiskPanel` becomes the *transient confirm view* (no longer injected inline above the links).
- **`ShareSegmentedControl`** (new, small) — `role="tablist"`, three tabs, disabled state, roving tabindex.
- **`ShareLinkCard`** (new, extracted) — the one link-row layout (title · URL · Copy/Open/QR · join code · description). Used by all tailnet + internet link rows. Wraps the existing `CodeDisplay` for the join-code chip.
- **`SessionSharePanel.tsx`** — refactored from one long column into three tab-body renderers (`TailnetTab`, `InternetReadOnlyTab`, `InternetFullAccessTab`). Preserves `HoldToConfirmButton` and `CodeDisplay` as-is.

## Code sketches (non-normative — illustrate structure, not final)

**Shell: control strip stays, panel swaps**
```tsx
type ShareTab = 'tailnet' | 'internet-ro' | 'internet-fa';

const internetReady = internetEnabled && internetConfirmed;

<div className="hub-share-modal__body">
  {/* fixed control strip — unchanged toggles */}
  <ShareToggle checked={shareEnabled} onChange={handleShareToggle} label="Share the session" />
  <ShareToggle checked={browseEnabled} disabled={!shareEnabled}
               onChange={handleBrowseToggle} label="Enable remote file browsing" />
  <ShareToggle checked={internetEnabled} onChange={handleInternetToggle} label="Enable internet sharing" />
  <hr className="hub-share-modal__rule" />

  {!shareEnabled && <EmptyHint>Turn on “Share the session” to get a link.</EmptyHint>}

  {/* transient confirm view replaces the panel — not injected above it */}
  {shareEnabled && internetEnabled && !internetConfirmed && (
    <FunnelRiskPanel onConfirm={confirmInternet} onCancel={keepLocalOnly} />
  )}

  {shareEnabled && (!internetEnabled || internetConfirmed) && (
    <>
      <ShareSegmentedControl
        active={tab}
        onSelect={setTab}
        tabs={[
          { id: 'tailnet',     main: 'Tailnet',  sub: 'Private' },
          { id: 'internet-ro', main: 'Internet', sub: 'Read-only',    disabled: !internetReady },
          { id: 'internet-fa', main: 'Internet', sub: '⚠ Full access', disabled: !internetReady, danger: true },
        ]}
      />
      {tab === 'tailnet'     && <TailnetTab share={cachedShare} />}
      {tab === 'internet-ro' && <InternetReadOnlyTab share={cachedShare} onDisable={disableInternet} />}
      {tab === 'internet-fa' && <InternetFullAccessTab share={cachedShare} armed={publicWriteArmed} … />}
    </>
  )}
</div>
```

**Segmented control (a11y)**
```tsx
function ShareSegmentedControl({ tabs, active, onSelect }: Props) {
  return (
    <div className="share-segbar" role="tablist" aria-label="Share access tier">
      {tabs.map(t => (
        <button key={t.id} role="tab" aria-selected={active === t.id}
                aria-disabled={t.disabled} disabled={t.disabled}
                tabIndex={active === t.id ? 0 : -1}
                className={cx('share-seg', active === t.id && 'is-active', t.danger && 'is-danger')}
                onClick={() => !t.disabled && onSelect(t.id)}>
          <span className="share-seg__main">{t.main}</span>
          <span className="share-seg__sub">{t.disabled ? 'Off' : t.sub}</span>
        </button>
      ))}
    </div>
  );
}
```

## Alternatives considered (rejected)
- **Accordion** (collapsible sections, one open at a time) — good at-a-glance state pills, but still one column and users may not notice sections expand.
- **Wizard / stepper** (Scope → Confirm access → Links) — best for first-timers and forces a deliberate look at internet exposure, but adds clicks for the common "just give me the read-only link" case.
- **Fixed-height + inner-scroll only** (bound the dialog, scroll just the link list) — cheapest change; fixes "whole dialog scrolls" but not "disheveled / content reflows." Reasonable fallback if the segmented rework can't land in one phase.

## Acceptance criteria
- [ ] Toggle controls stay in a fixed position; toggling never reflows or pushes down content already on screen.
- [ ] No state causes the **whole dialog** to scroll in a normal viewport; scrolling (if any) is confined to one region.
- [ ] Access details use a **three-tab segmented control**: Tailnet · Private, Internet · Read-only, Internet · ⚠ Full access.
- [ ] The public-write / command-execution flow exists **only** in the Full-access tab (warning → enable → hold-to-confirm → armed summary → disable).
- [ ] Internet tabs are disabled until the internet-sharing risk is confirmed; after confirm the default tab is **Internet · Read-only**.
- [ ] Internet-sharing risk acknowledgment is a transient confirm view, not a block injected above the links.
- [ ] Each scope description is attached to the link it describes; all link rows share one component.
- [ ] Full-access tab is distinguishable **without relying on color** (⚠ glyph + inset ring), and the segmented control is keyboard-operable (`tablist`/`tab`, roving tabindex, visible focus).
- [ ] Modal card widened to `width: min(520px, calc(100vw - 48px))`; still clamps correctly on narrow windows.
- [ ] Behavior, tokens, capabilities, Funnel teardown, and the 3s hold-to-confirm safety gate are unchanged — layout/IA only.
- [ ] `SessionShareModal.test.tsx` and `SessionSharePanel.test.tsx` updated to the new structure; colorblind-safe assertions verify state via source/attributes, not hue.

## Out of scope
- Changing which capabilities/tokens are issued, TTL semantics, or Funnel teardown logic.
- The Sharing Guide Help content (already shipped).
