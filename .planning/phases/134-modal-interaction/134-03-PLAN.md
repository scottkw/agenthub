## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| briefing respond textarea → RelayClient.sendInput → relay WS → PTY | Untrusted user text written verbatim to the session PTY (terminal input is opaque bytes; no escaping needed, but length must be bounded) |
| modal terminal I/O → TerminalPanel RelayClient → PTY | Reuses the audited normal-tab path; no new boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-134-03-01 | DoS | briefing respond textarea | mitigate | `maxLength={4096}` on the textarea bounds a single submit (ASVS V5). Terminal input is opaque bytes — no content sanitization required or appropriate. |
| T-134-03-02 | Tampering | tail lines rendered in briefing body | mitigate | GetSessionTailLines returns ANSI-stripped strings; rendered as React text content (auto-escaped), no `dangerouslySetInnerHTML`. |
| T-134-03-03 | DoS / resource leak | briefing RelayClient | mitigate | The briefing RelayClient is created per-send and closed via `client.close()` inside onOpen (and on the 5s timeout reject path) — no lingering WS. TerminalPanel's own client (interactive) is disposed on unmount. |
| T-134-03-04 | Repudiation / silent failure | briefing Send | mitigate | sendInput only fires inside onOpen (Pitfall 5) so input is never silently dropped against a not-yet-OPEN socket; a 5s timeout surfaces a user-facing error instead of a silent no-op. |
| T-134-SC | Tampering | npm/pip installs | mitigate | No new packages (134-RESEARCH.md audit: none). No install task. |
</threat_model>
