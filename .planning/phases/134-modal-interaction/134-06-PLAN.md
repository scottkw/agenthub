<objective>
Add a cap-gated remote terminal WebSocket reverse proxy to the daemon relay loopback
surface. This is the missing backend that makes the Phase 134 modal actually connect for
REMOTE sessions (CR-01/CR-02 root cause): the modal currently attaches the LOCAL relay
with a session id that only exists on the remote peer. The new route accepts the webview's
WS, looks up the existing Phase 122 cap, dials the peer's already-cap-gated
`/sessions/{sid}/ws` with the InsecureSkipVerify tailnet transport and an injected Origin
header, and copies opaque frames both ways.

Purpose: the webview can only reach 127.0.0.1:<relayPort>, never the peer; the daemon must
proxy. The peer end already enforces HMAC cap verification, SID-match, grant-active, and
read/write perms — this proxy is a dumb pipe that keeps the cap token server-side.
Output: a ~60-line WS proxy + route registration + exported origin helper + Go tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| webview -> daemon relay (127.0.0.1:relayPort) | Inbound WS upgrade; loopback/Wails origin only. The webview never holds the cap. |
| daemon -> peer webserver (wss tailnet) | Outbound WS dial carrying the cap as ?cap=; TLS over Tailscale transport (InsecureSkipVerify). |
| untrusted PTY frames <-> proxy | Opaque binary frames copied verbatim; the proxy never parses or evals them. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-134-06-01 | Spoofing | inbound websocket.Accept | mitigate | OriginPatterns: relay.LoopbackOriginPatterns(r.Host) — reuse the tested relay allowlist; cross-site Origin rejected (WS-PROXY-05) |
| T-134-06-02 | Spoofing | upstream dial Origin | mitigate | Inject Origin: <baseURL> byte-exact; peer rejects empty/mismatched Origin (WS-PROXY-04) |
| T-134-06-03 | Information Disclosure | cap token in logs/URL | mitigate | Cap stays in RemoteCapStore + ?cap= on the daemon-side dial only; webview URL carries NO cap; never log the token (redact like remote_files.go) |
| T-134-06-04 | Elevation of Privilege | read->write escalation | accept | Read/write derived from signed claims.Perms on the PEER; client cannot escalate via query string; proxy is a dumb pipe (no client-asserted ?readonly= honored) |
| T-134-06-05 | Tampering | MITM via InsecureSkipVerify | accept | Tailscale WireGuard transport authenticity substitutes for cert verification; documented caveat carried from client_remote_files.go (Phase 122) |
| T-134-06-06 | Denial of Service | leaked WS connections | mitigate | defer CloseNow() on both conns; single <-errc tear-down; copy loop bounded by r.Context() (closes on webview disconnect) |
| T-134-06-07 | Denial of Service | dial-deadline kills live terminal | mitigate | Dial with bounded 10s ctx; copy with unbounded r.Context() (WS-PROXY-06) |
| T-134-06-SC | Tampering | npm/go installs | accept | No new dependencies — coder/websocket v1.8.14 already in go.mod; Package Legitimacy Audit N/A (research §Package Legitimacy Audit) |
</threat_model>
