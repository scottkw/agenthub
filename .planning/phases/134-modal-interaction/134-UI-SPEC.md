## Interaction Contract

### Card Click vs Open Button Disambiguation

The Phase 131 "Open" button (`hub-card__open`) on ROW 5 of `SessionCard` MUST be preserved and coexist with the new card-click→modal behavior.

**Disambiguation rule:**
- **Click on `.hub-card__open` button:** calls `onOpenSession` — opens/focuses the session's terminal tab in the existing tab bar. Event must NOT propagate to the card's `onClick` handler. Use `e.stopPropagation()` on the button's click handler or attach `onClick` only to the card body (not the article element).
- **Click on `.hub-card` article body** (anywhere not on `.hub-card__open`, `.hub-card__menu-btn`, `.hub-card__drag-handle`, or `.InlineSessionName` rename input): opens the Hub modal via a new `onCardClick` prop.
- **Enter/Space keypress on focused `.hub-card`:** triggers `onCardClick` (same as body click).
- **Drag start:** sets `isDragging = true`, does NOT trigger modal.

**Implementation pattern for click routing:**
```
article.hub-card onClick={onCardClick}
  button.hub-card__open onClick={e => { e.stopPropagation(); onOpenSession(...) }}
  button.hub-card__menu-btn onClick={e => { e.stopPropagation(); ... }}
  [drag-handle — no onClick, draggable only]
  [InlineSessionName — stopPropagation on its own clicks when in edit mode]
```

The card body `onClick` handler should also guard against clicks that originated from `.hub-card__open` by checking `(e.target as HTMLElement).closest('.hub-card__open')` is null, as a defense-in-depth measure.

### Modal Type Selection

Driven by `isAttentionStatus(deriveHubStatus(session))` from `lib/hubStatus.ts`:

| `isAttentionStatus` | Modal type | Component mounted |
|---------------------|------------|-------------------|
| `false` (running / idle / stopped) | Interactive terminal modal | Existing `TerminalPanel` + wired `RelayClient` |
| `true` (waiting / errored + non-zero exit) | Briefing modal | Terminal tail text display + respond input |

For remote sessions requiring a capability token (MODAL-06), show the existing `RemoteJoinCodeModal` flow before opening the interactive modal. The cap exchange is a prerequisite gate, not a separate modal type.

### Grow/Shrink Animation

**Trigger:** card body click → modal opens with grow animation originating from the card's bounding rect.

**Technique (shared-element illusion using CSS clip-path or transform-origin):**
1. On card click, read `card.getBoundingClientRect()` and store as `sourceRect`.
2. Render modal overlay (opacity 0, scale ~0.05 or clip-path inset to card rect).
3. On next animation frame, transition to full-screen (scale 1, clip-path inset 0) over 220ms cubic-bezier(0.25, 0.46, 0.45, 0.94).
4. On close, reverse: 180ms ease-in, then unmount.

**Specific animation values:**
- Open: 220ms, `cubic-bezier(0.25, 0.46, 0.45, 0.94)` (ease-out feel — expands quickly then settles)
- Close: 180ms, `cubic-bezier(0.55, 0, 1, 0.45)` (ease-in feel — starts slow then snaps shut)
- Transform origin: set to `${sourceRect.left + sourceRect.width/2}px ${sourceRect.top + sourceRect.height/2}px` to originate from card center

**Reduced-motion fallback (MANDATORY):**
```css
@media (prefers-reduced-motion: reduce) {
  .hub-modal {
    animation: none;
    transition: none;
    opacity: 1;
    transform: none;
  }
  .hub-modal-overlay {
    animation: none;
    transition: none;
    opacity: 1;
  }
}
```
With reduced-motion, modal appears/disappears instantly. No position interpolation. The `--hub-attn-static-border` token pattern (already established in Phase 133) is the template for this fallback.

### Focus Management

| Event | Focus behavior |
|-------|---------------|
| Modal opens (interactive) | Focus moves to TerminalPanel's xterm canvas container (so terminal is immediately interactive) |
| Modal opens (briefing) | Focus moves to the respond input field |
| Modal closes (any method) | Focus returns to the originating card element (`article.hub-card[tabIndex=0]`) via `cardRef.current?.focus()` |
| Tab inside open modal | Cycles within modal controls only (focus trap — Phase 135 will harden this; Phase 134 must wire the initial `focus()` calls at minimum) |
| Escape key | Closes modal and returns focus to card |
| Click outside modal (on overlay) | Closes modal and returns focus to card |

### Remote Session Modal Flow (MODAL-06)

Reuses the locked Phase 122 join-code/cap exchange:
1. User clicks remote session card.
2. If `!hasCap(session.id)`, show the existing `RemoteJoinCodeModal` (already built in Phase 122).
3. On successful cap exchange, close `RemoteJoinCodeModal` and open the Hub interactive modal mounting `TerminalPanel` with the remote `relayPort`.
4. No new remote-access UI architecture. No new modals.

## Modal Layout Anatomy

**Focal point:** On the interactive modal, the primary visual anchor is the `TerminalPanel` canvas (`flex: 1`, fills the body) — everything else (header, close button) is chrome. On the briefing modal, the primary anchor is the terminal-tail text block; the accent-filled "Send Response" CTA is the secondary anchor that draws the eye to the action. The dimmed grid scrim behind the panel keeps focus on the modal.

### Hub Modal Overlay (`.hub-modal-overlay`)

```
position: fixed; inset: 0; z-index: 200;
background: rgba(0, 0, 0, 0.6);
display: flex; align-items: center; justify-content: center;
```

z-index 200 — above the Hub panel (z-index 0) and any in-Hub menus (z-index 100 for `.hub-card__menu`), below the app-level modals (`.new-session-overlay` z-index 1000, `.qr-modal-overlay` z-index 1000).

### Hub Modal Panel (`.hub-modal`)

```
position: relative;
width: min(1100px, calc(100vw - 48px));
height: min(750px, calc(100vh - 64px));
background: var(--hub-surface-elevated);
border: 1px solid var(--hub-border);
border-radius: 12px;
box-shadow: 0 20px 60px rgba(0, 0, 0, 0.6);
display: flex;
flex-direction: column;
overflow: hidden;
```

**Width/height rationale:** Large enough to host a comfortable terminal (≥80 cols), small enough to show the hub grid is still present behind the scrim. `min(1100px, calc(100vw - 48px))` ensures 24px clearance on each side even on 1024px screens.

## Animation Keyframes (Phase 134 additions)

```css
/* hub-modal-grow: shared-element expand from card position */
@keyframes hub-modal-grow {
  from {
    opacity: 0;
    transform: scale(0.05);
  }
  to {
    opacity: 1;
    transform: scale(1);
  }
}

/* hub-modal-shrink: collapse back to card position */
@keyframes hub-modal-shrink {
  from {
    opacity: 1;
    transform: scale(1);
  }
  to {
    opacity: 0;
    transform: scale(0.05);
  }
}

/* hub-modal-overlay-in / out: scrim fade */
@keyframes hub-modal-overlay-in {
  from { opacity: 0; }
  to   { opacity: 1; }
}

@keyframes hub-modal-overlay-out {
  from { opacity: 1; }
  to   { opacity: 0; }
}
```

**All four keyframes MUST be wrapped in their respective `@media (prefers-reduced-motion: no-preference)` guard blocks.** The token `--hub-attn-static-border` pattern from Phase 133 is the established template.

**transform-origin** is set as an inline style at runtime: `${sourceRect.left + sourceRect.width / 2}px ${sourceRect.top + sourceRect.height / 2}px`. This is the only inline style permitted in modal CSS (the token system handles all other values).
