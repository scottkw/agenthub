<objective>
Wire the attention foundation through the live data path (ATTN-02, ATTN-03, ATTN-04, ATTN-05):

- **HubPanel**: add a `useDebouncedValue` hook and derive (a) a LIVE `attentionIds: Set<string>` (NOT debounced — drives per-card border/icon immediately) and (b) a `debouncedSortKey` (~1000ms — drives only the reorder). Thread both into `SessionCardGrid`. Because attention is always re-derived from the current poll, when a session's status leaves the attention set the next poll clears its card with NO reload — this is the entire mechanism for ATTN-03 (status-driven clear) and ATTN-05 (modal-resolve clear; Phase 134's modal merely triggers the same status change — do NOT import or reference any modal).

Thread `isAttention={attentionIds?.has(s.id)}` to each `SessionCard`. Add the reorder position animation (FLIP), suppressed under `prefers-reduced-motion`.

Output: Updated `HubPanel.tsx` + `SessionCardGrid.tsx`, with extended `HubPanel.test.tsx` + `SessionCardGrid.test.tsx`.

NO backend work. PRESERVE every Phase 131/132 feature: the single shared 3s `usePreviewPoller` (EXACTLY ONE setInterval — do not add a second timer; the debounce uses setTimeout, which is distinct and acceptable), filter + search, named-group/workDir grouping, group filter selection, GroupSidebar, drag-and-drop, MiniPreview threading, the Open button, and the empty/error states.

- The per-card `isAttention` uses the LIVE attention set, never the debounced key (RESEARCH Pitfall 5 — border/icon must not lag 1s).

- Sort is applied PER GROUP after grouping, never to the flat list (RESEARCH Pitfall 7 — must not break group boundaries).
- FLIP / reorder animation is suppressed when `window.matchMedia('(prefers-reduced-motion: reduce)').matches`. FLIP is enhancement, not release-blocking — if it adds risk, the 1s debounce is the primary non-jarring mechanism (RESEARCH Pattern 4 fallback), but the within-group attention-first ORDER is required regardless.
