## Attention Detection Contract

**Which sessions are in attention state:**

A session is in attention state when `deriveHubStatus(session)` returns `'waiting'` OR
`'errored'` OR `'stopped-err'`.

**New helper (add to `hubStatus.ts`):**

```typescript
export function isAttentionStatus(status: HubStatus): boolean {
  return status === 'waiting' || status === 'errored' || status === 'stopped-err'
}
```

This is the single canonical predicate for all attention logic across SessionCard, SessionCardGrid,
GroupSidebar, and HubPanel.

**No modal coupling:** ATTN-03 (clear on resolve) is implemented as status-change-driven clearing.
When the poll returns a status that `isAttentionStatus()` returns `false` for, the attention
treatment clears automatically. Phase 134 modal is merely one trigger that may cause this status
change — Phase 133 must not import, reference, or depend on Phase 134 code.

## ATTN-01 — Attention Card Treatment (Pulsing Border + Icon)

### Attention Icon

Icon: `BellAlertIcon` from `@heroicons/react/24/outline`, size 16px (w-4 h-4).

Placement: Inline within ROW 1, inserted to the LEFT of the existing status icon, separated by 4px
gap. This keeps the icon in the natural scan path (top-left of content) without introducing a new
layout row.

Updated ROW 1 structure for attention cards:

```
ROW 1: [BellAlertIcon 16px]  [StatusIcon 20px]  [InlineSessionName]  [CLI badge]
        ← attention icon     ← existing status   ← existing          ← existing
         color: --hub-attn-icon-color
         aria-label: "Needs attention"
```

For non-attention cards, `BellAlertIcon` is not rendered — no empty placeholder space.

BEM:
```
.hub-card__attn-icon   — wrapper span for BellAlertIcon; color: var(--hub-attn-icon-color)
                          display: inline-flex; align-items: center; flex-shrink: 0
```

### Pulsing Border

The `.hub-card--attention` modifier adds an animated pulsing border to the card:

```css
/* ATTN-01: attention card — pulsing border + glow (colorblind-safe: BellAlertIcon carries state) */
/* COLORBLIND-SAFE: attn border dark hex #e0af68 — reinforcement only; BellAlertIcon + pulse carries state */
/* COLORBLIND-SAFE: attn border light hex #b45309 — WCAG AA 7.6:1; icon carries state */
.hub-card--attention {
  border-color: var(--hub-attn-border);
}

@media (prefers-reduced-motion: no-preference) {
  .hub-card--attention {
    animation: hub-attn-pulse 2s ease-in-out infinite;
  }
}

@keyframes hub-attn-pulse {
  0%   { border-color: var(--hub-attn-border); box-shadow: 0 0 0 0 var(--hub-attn-border-glow); }
  50%  { border-color: var(--hub-attn-border); box-shadow: 0 0 0 4px var(--hub-attn-border-glow); }
  100% { border-color: var(--hub-attn-border); box-shadow: 0 0 0 0 var(--hub-attn-border-glow); }
}
```

**Pulse parameters:**
- Duration: 2 seconds (full cycle)
- Easing: ease-in-out
- Iteration: infinite (clears when attention clears)
- Border thickness: 1px (same as the existing `.hub-card` border — the border-color changes, not the width)
- Glow: `box-shadow: 0 0 0 4px var(--hub-attn-border-glow)` at peak — a soft outer ring, not an inner glow

**Why 2s:** Fast enough to catch the eye, slow enough not to be jarring. The 131-UI-SPEC motion
contract forbade pulse in Phase 131; Phase 133 is the designated introduction point.

### Reduced-Motion Fallback (prefers-reduced-motion: reduce)

Under `prefers-reduced-motion: reduce`, the animation is suppressed. The card still shows:
- Static border color: `var(--hub-attn-static-border)` (same hex as `--hub-attn-border` — no animation, no glow)
- `BellAlertIcon` in ROW 1 (always rendered regardless of motion setting)
- Float-to-top position within the group (always active regardless of motion setting)

```css
/* Reduced-motion: static attention border only — no animation, no glow */
@media (prefers-reduced-motion: reduce) {
  .hub-card--attention {
    border-color: var(--hub-attn-static-border);
    box-shadow: none;
    animation: none;
  }
}
```

These three non-animated cues (icon + static border + float-to-top position) fully satisfy
A11Y-03 — information previously conveyed by motion is conveyed by the static fallback.

### Clear Animation (ATTN-03)

When a card transitions from attention state to non-attention (status change detected by poll),
the attention treatment fades out gracefully:

```css
/* ATTN-03: attention clear — fade border back to normal over 400ms */
@media (prefers-reduced-motion: no-preference) {
  .hub-card {
    transition: border-color 400ms ease, box-shadow 400ms ease;
  }
}
```

The `hub-card--attention` class is removed from the element when `isAttentionStatus()` returns
`false`. The transition on `.hub-card` (not the modifier) ensures the border-color and box-shadow
animate back to their resting values. Under `prefers-reduced-motion: reduce`, the transition
property is not applied and the clear is instant.

## ATTN-02 — Float-to-Top + Debounced Reorder

### Sort Order Within Groups

Decision: **float-to-top within each group, not a global attention lane.**

Rationale: A global "attention lane" would break the group context that users rely on to
understand which project/workdir a session belongs to. Floating to the top of their group
preserves that context while still surfacing the attention card visually. This is consistent
with the Phase 132 GroupSidebar design where groups are the primary organizational unit.

**Sort rule (applied within each group — both named-group and workDir-group branches):**

```typescript
function sortSessionsForDisplay(sessions: SessionInfo[]): SessionInfo[] {
  return [...sessions].sort((a, b) => {
    const aAttn = isAttentionStatus(deriveHubStatus(a)) ? 0 : 1
    const bAttn = isAttentionStatus(deriveHubStatus(b)) ? 0 : 1
    return aAttn - bAttn
    // Stable: sessions with same attention level preserve their original order
  })
}
```

This sort is applied to each group's session array before rendering — not to the raw list passed
to `SessionCardGrid`. The `SessionCardGrid` receives pre-sorted groups from `HubPanel`, or the
grid sorts internally. The planner decides the implementation location; the contract is that
within every rendered group, attention cards appear before non-attention cards.

### Debounce Window

Reorder fires at most once per **1000ms (1 second)** after the last status change.

Implementation: A `useDebouncedValue` hook (or `useRef` + `setTimeout` pattern) in `HubPanel`
debounces the sort-key signal. The underlying session data (names, status, etc.) updates
immediately from the poll; only the ORDER of cards in the grid is debounced. This means a
card's content (status icon, label) updates in real-time; its position within the grid only
updates after the debounce settles.

```typescript
// Pseudocode for the debounce contract:
const debouncedAttentionOrder = useDebouncedValue(
  sessions.map(s => `${s.id}:${isAttentionStatus(deriveHubStatus(s))}`).join(','),
  1000 // ms
)

// The grid render uses debouncedAttentionOrder to determine position,
// but each card's own attention state (border, icon) uses live status.
```

**Why 1s:** A 1-second debounce prevents cards from visibly jumping on every 2-second (or
configurable) poll tick. Users see position settle once the system confirms the state is stable.
Shorter than 1s would not mask poll flicker; longer than 2s would feel laggy for newly created
attention states.

### Position Change Animation

When the sort order does change after the debounce settles, position changes animate smoothly:

```css
/* ATTN-02: smooth card reorder — CSS layout transition */
@media (prefers-reduced-motion: no-preference) {
  .hub__card-row {
    /* Cards in the grid animate when they shift position */
  }
  .hub__card-row > [role="listitem"] {
    transition: order 300ms ease;
  }
}
```

**Implementation note for executor:** Pure CSS `order` transitions are not supported in
browsers today. The reorder animation MUST be implemented using one of these approaches
(planner chooses):

1. **FLIP animation** (First/Last/Invert/Play): measure card positions before and after
   the sort, apply `transform: translate()` + `transition: transform 300ms ease` to each
   card, then remove the transform. This is the recommended approach for reorder animations.

2. **React key stability + CSS translate:** Keep card keys stable across sorts; use
   `transform: translateY()` transitions driven by comparing previous and next bounding rects.

Under `prefers-reduced-motion: reduce`, no reorder animation — positions snap immediately.

**Duration: 300ms, easing: ease** — matches the Phase 131/132 sidebar expand motion
philosophy (150ms was chosen for the sidebar as it is a small element; cards spanning the
full grid warrant slightly longer at 300ms).

## ATTN-03 — Status-Driven Clear (Poll-Driven, No Modal Coupling)

When the poll cycle returns a session with a status where `isAttentionStatus()` returns `false`:

1. `HubPanel` removes the session's ID from the attention set (or simply re-derives attention
   from live status — no separate set needed if attention is always derived from current status).
2. `SessionCard` receives `isAttention={false}` (or the prop is removed); the `.hub-card--attention`
   class is removed from the article element.
3. The CSS transition on `.hub-card` (border-color 400ms, box-shadow 400ms) animates the clear.
4. The `BellAlertIcon` is removed from ROW 1 as soon as `isAttention` flips to false.
5. The card's position within its group is updated after the 1-second debounce (same flow as
   any other reorder).

**No page reload required.** This is entirely driven by the existing `HubPanel` polling cycle.
The Phase 134 modal, when it exists, will cause a `waiting` session to transition to another
status — that transition will be detected at the next poll and clear the attention state
automatically through this same mechanism.

## ATTN-06 — Collapsed-Group Attention Badge

### Badge Specification

When a group sidebar item is **collapsed** AND the group contains one or more attention cards,
an attention badge is shown on the sidebar item.

The badge is DISTINCT from the existing needs-input badge:

| Badge | Icon | Color family | Condition |
|-------|------|--------------|-----------|
| Needs-input (Phase 132) | `PauseCircleIcon` (12px) | Amber `#f59e0b` | Session with status `waiting` |
| Attention (Phase 133) | `BellAlertIcon` (12px) | Amber-gold `#e0af68` / `#b45309` | Session with `isAttentionStatus()` true — includes `waiting`, `errored`, `stopped-err` |

**The attention badge is a superset of the needs-input badge.** When a group has attention
sessions, it will show the attention badge instead of (or alongside) the needs-input badge.
Decision: show ONLY the attention badge when `attnCount > 0` (it subsumes the needs-input
badge since `waiting` is a subset of attention). This avoids two overlapping badges.

### Badge Display Rules

| Sidebar state | attnCount | What shows |
|---------------|-----------|------------|
| Expanded | any | No badge (individual card borders + icons are visible) |
| Collapsed | 0 | No attention badge (needs-input badge continues to follow Phase 132 rules) |
| Collapsed | > 0 | Attention badge REPLACES needs-input badge (attention is the superset signal) |

When the group is expanded, no badge is needed — the pulsing cards themselves are visible.

### Badge Visual Spec

```
┌─────────────────────────────────────────┐
│  .hub__group-sidebar-item (collapsed)   │
│  ├─ [chevron strip only — no text]      │
│  └─ .hub__group-sidebar-item__attn-badge│
│      ├─ BellAlertIcon (12px)            │
│      └─ count span: "2"                 │
└─────────────────────────────────────────┘
```

Badge dimensions: 16px height, padding 0 4px, gap 4px, border-radius 8px (pill shape) — matches the Phase 132 needs-input badge slot (mutually exclusive); all spacing multiples of 4.
Badge position: right-aligned within the collapsed sidebar strip (same position as needs-input
badge in Phase 132).

```css
/* ATTN-06: collapsed-group attention badge */
/* COLORBLIND-SAFE: attn badge dark hex #e0af68 — reinforcement only; BellAlertIcon carries state */
/* COLORBLIND-SAFE: attn badge light hex #b45309 — WCAG AA 7.6:1; icon carries state */
.hub__group-sidebar-item__attn-badge {
  display: inline-flex;
  align-items: center;
  gap: 4px;
  padding: 0 4px;
  height: 16px;
  border-radius: 8px;
  background: var(--hub-attn-badge-bg);
  color: var(--hub-attn-badge-text);
  font-size: 11px;
  line-height: 1.0;
  font-family: system-ui, -apple-system, "Segoe UI", sans-serif;
}
```

### Expanded Group — No Badge, Attention Via Cards

When the group is expanded (normal sidebar state), no badge is shown. The attention treatment
is conveyed entirely through the pulsing card borders + `BellAlertIcon` on the cards themselves.
This keeps the sidebar uncluttered when cards are visible.

### Counts Computation

The `computeCounts` function in `GroupSidebar.tsx` must be extended to return an `attention` count:

```typescript
interface GroupCounts {
  running: number
  total: number
  waiting: number    // existing — Phase 132 needs-input badge
  attention: number  // NEW — Phase 133 attention badge (superset of waiting)
}
```

```typescript
function computeCounts(sessions: SessionInfo[], memberKeys: Set<string>): GroupCounts {
  let running = 0, total = 0, waiting = 0, attention = 0
  for (const s of sessions) {
    const key = memberKey(s.name, s.workDir)
    if (!memberKeys.has(key)) continue
    total++
    const st = deriveHubStatus(s)
    if (st === 'running' || st === 'idle' || st === 'waiting') running++
    if (st === 'waiting') waiting++
    if (isAttentionStatus(st)) attention++
  }
  return { running, total, waiting, attention }
}
```

Similarly extend `computeGlobalCounts` for the "All" sidebar item.

## Interaction Contract

| State | Rendering | Motion |
|-------|-----------|--------|

| Trigger | Response |
|---------|----------|

| Debounce settles | Sort order within group updates; attention cards appear first |
| Position change (with motion) | FLIP animation over 300ms ease |
| Position change (reduced-motion) | Instant snap, no animation |
| Session transitions out of attention | Debounce timer resets; card returns to natural order after 1s |

| Trigger | Response |
|---------|----------|

| All attention sessions in collapsed group clear | Attention badge disappears; needs-input badge may reappear if `waiting` count > 0 |
| Group expands | Badge disappears (cards + their borders are now visible) |

## Accessibility Contract

Extends Phase 131/132 rules. New Phase 133 requirements:

1. **Attention state uses three non-color signals:** (1) `BellAlertIcon` shape/form,
   (2) pulsing border animation (replaced by static border under reduced-motion), (3) float-to-top
   position within the group. Color (`--hub-attn-border` amber-gold) is a fourth reinforcing
   signal — never the sole carrier of state.

2. **Attention icon:** `BellAlertIcon` must have `aria-label="Needs attention"`. It is NOT
   `aria-hidden` — it carries semantic meaning for screen readers.

3. **Card aria-label update:** When `isAttention` is true, the card's `aria-label` must include
   the attention signal. Format: `"{name}, {status-label}, {cli}, {origin}, needs attention"`.
   The " needs attention" suffix is appended only for attention cards.

4. **Collapsed-group attention badge:** Must have `aria-label` as specified in copywriting table.
   The `BellAlertIcon` inside the badge is `aria-hidden="true"` (the parent aria-label carries
   the meaning).

5. **Reorder animation accessibility:** Position changes triggered by reordering must not
   cause `focus` to move or `aria-live` to announce. Cards maintain their `tabIndex={0}` and
   keyboard focus should remain on the focused card even after a sort.

6. **Source-level hex verification required** (see checklist below).
