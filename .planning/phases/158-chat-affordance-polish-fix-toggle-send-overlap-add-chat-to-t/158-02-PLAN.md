<objective>
Close the cross-surface chat parity gap (CHAT-PARITY-01, upstream PARITY-01) found during
v4.1 UAT: the chat affordance (toggle + ChatPanel) exists only in `HubInteractiveModal.tsx`
and `WebShareSessionView.tsx`. The raw GUI terminal TAB (`App.tsx` ~lines 1701-1737:
`.terminal-wrapper` → TerminalPanel + optional ExitCountdownBanner + StatusBar) has neither.

Purpose: Add the same overlay chat affordance to the terminal tab by extracting a reusable
`TerminalChatHost` (mirroring WebShareSessionView's structure) and mounting it in the tab,
reusing the existing ChatPanel WITHOUT forking it. Overlay mode (no PTY resize), per D-02.
Output: a new host component, App.tsx wiring, a CSS containing-block rule, a behavioral
vitest, and TESTING.md registration.
</objective>

| RO-cap participant → `@session` inject / chat-send | Server-side capability gating (HandleChatSend / HandleInject, SEC-01) remains the authoritative boundary — UI presence of the affordance on a new surface is not a security boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-158-03 | Elevation of Privilege | terminal-tab ChatPanel (chat-send / `@session` inject) | low | accept | The tab mounts the unmodified ChatPanel; chat-send and inject are gated server-side (SEC-01 RO check in HandleChatSend/HandleInject). Adding the UI on a third surface grants no new capability — a RO holder still cannot post/inject regardless of UI presence. No client-side gate is the security boundary. |
| T-158-04 | Information Disclosure | tab drawer overlay over terminal | low | accept | The drawer overlays terminal content visually but reads from the same capability-scoped chat history the modal already shows; no new data is exposed to a viewer who could not already see this session's chat. |
| T-158-05 | Tampering | App.tsx prop forwarding to TerminalPanel | low | mitigate | Dropping a forwarded prop (e.g. onWebGLContextLost) would degrade terminal recovery, not security; `tsc --noEmit` + the forwarding behavioral test catch missing props. |
