<objective>
Close the second scope gap found in Phase 159 live UAT: the web-share bootstrap opened
the file-browser tab unconditionally (old assumption: the cap is opaque client-side), so a
guest whose share lacked file access was left with a dead "files.read permission required"
tab. Gate the file-tab auto-open on the server-verified `files.read` perm from
`GET /api/sessions/{id}/info`. The guest now sees only terminal + chat unless their cap
grants file access, in which case the file-browser tab opens in the background.
</objective>
