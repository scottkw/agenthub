# Phase 146 Research — Out-of-Band Open (FIX-03 / #98)

**Revised:** 2026-06-22. Supersedes the broadcast "Mechanism B" research (now in
`superseded-broadcast/146-RESEARCH.md`). Authoritative design = out-of-band, per
`146-CONTEXT.md` decisions D-02/D-04/D-09..D-12.

## Requirement

| ID | Goal |
|----|------|
| FIX-03 | "Open in browser" on a remote session card opens the live session instead of the `capability required` (401) page (#98), without broadcasting any credential to the tailnet. |

## Chosen mechanism: reuse the Phase 122 out-of-band code/link flow

No broadcast. No new endpoint. No `app.go` code-carrying. The owner deliberately
delivers a credential out of band; the viewer exchanges it through machinery that
already exists and is production-proven.

### The three open cases (CONTEXT D-09)

| Case | Path | Status |
|------|------|--------|
| Owner reopens own session, **same machine** | `handleOpenSessionTab` → local relay WS, no cap (`App.tsx:1034-1048`) | **Already works — do not touch** |
| Owner reopens own session, **another machine** | out-of-band code/link → exchange → open `?cap=` URL | needs wiring |
| Viewer opens **someone else's** shared session | out-of-band code/link → exchange → open `?cap=` URL | needs wiring |

The two cross-machine cases are identical mechanically.

## Existing assets to reuse (do NOT rebuild)

- **Paste-a-code modal:** `frontend/src/components/RemoteJoinCodeModal.tsx` (Phase 122-03).
  Accepts a code, shows session name/host, maps `expired`/`invalid`/`not-found`/`session-gone`
  errors (lines 37-49). Today wired for a **file-browse** intent.
- **Exchange:** `App.ExchangeJoinCodeAtURL(remoteBaseURL, code)` → `internal/daemon/client_remote_files.go:67-172`.
  POSTs the code to the remote peer's `/join/exchange`, expects 303 with `?cap=<token>` in
  Location, returns the token. (Token must NOT reach React per T-122-03-01; for "open in
  browser" the token goes straight into the URL handed to `BrowserOpenURL`, which is fine —
  it's the same trust level as the existing share link.)
- **Owner code/link source:** `App.IssueCapabilities(sessionId)` → `internal/daemon/api.go:1089-1181`
  already mints RO+RW cap-bearing URLs **and** join codes. This is what the owner copies to
  hand out (CONTEXT D-12).
- **The cap gate:** `internal/webserver/capability_mw.go` `requireCapability` (~L37-75) — the
  `?cap=` check the opened URL must satisfy. Unchanged.

## What to BUILD

1. **"Open session" intent on the modal flow (D-11):** extend `RemoteJoinCodeModal` (or its
   caller in `App.tsx`) so that, for an open-in-browser intent, after `ExchangeJoinCodeAtURL`
   succeeds it opens `baseURL + "/sessions/" + sessionId + "?cap=" + token` via `BrowserOpenURL`
   (instead of, or in addition to, `RegisterRemoteCap` for file proxying).
2. **Rewire the remote card "Open in browser" button:** for a remote session with no held cap,
   open the modal (D-03) instead of `BrowserOpenURL(session.url)`. Keep local-session "Open"
   on the local path (D-09). Clean up the now-dead `isPeerSelf` RO/RW guess (WR-01).
3. **Owner copy affordance (D-12):** ensure the Share modal exposes a copy-the-code / copy-the-link
   control so the owner has something to send out of band.

## Security posture

- `/api/sessions/meta` returns to cap-free (RB-03 invariant fully restored).
- Codes remain single-use, 5-minute expiry (`capability.NewJoinCodeManager(5*time.Minute)`).
- No credential is ever exposed to a peer the owner did not deliberately hand one to.
- `/join/exchange` still has no caller-identity check — acceptable because possession of an
  out-of-band code is now the deliberate grant (vs. a broadcast anyone could read). Identity-auth
  one-click is explicitly deferred (CONTEXT deferred section).

## Testing approach (replaces the broadcast test contract)

- Go: a test asserting `/api/sessions/meta` does NOT contain `ro_join_code`/`rw_join_code`
  (RB-03 cap-free, the inverse of the superseded test).
- Frontend: `handleOpenRemoteSession` / open-button opens the paste modal when no cap is held;
  on successful exchange constructs a `/sessions/{id}?cap=` URL via `BrowserOpenURL`; not-shared/
  exchange-failure paths surface informative UI (no raw 401).
- An end-to-end / boundary test is the gap that hid the prior failure — include a test that
  exercises the actual open path, not just isolated source inspection.
- TESTING.md: revert the superseded Phase 146 registrations and register the new tests; the
  cross-machine open remains a live-tailnet manual UAT item.

## Validation Architecture

**Why this section matters here:** the prior execution shipped a dead-on-arrival feature with a
fully green suite because every test validated a layer *in isolation* and none exercised the actual
open path across the Go↔Wails boundary. Validation for this re-plan MUST include at least one test
that crosses that boundary (or an explicit manual UAT where automation is impossible), so a green
suite cannot again certify a non-working feature.

### Test infrastructure
| Property | Value |
|----------|-------|
| Go | `go test ./internal/... ./...` (package tests; webserver/daemon/tailnet + root `app` package) |
| Frontend | `cd frontend && pnpm test -- <file> --run` (vitest); `pnpm tsc --noEmit` for the build gate |
| Build gate | `cd frontend && pnpm tsc --noEmit` (vitest alone is NOT proof the app builds — standing rule) |

waves make it green — but Wave 0 MUST NOT repeat the prior mistake of only source-inspecting; include
at least one behavior-level assertion of the open path.
