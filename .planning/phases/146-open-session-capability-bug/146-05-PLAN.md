<objective>
Close GAP-146-A: "Open in browser" on a remote session card currently and
unconditionally re-prompts for a single-use join code (`handleOpenRemoteSession`,
`frontend/src/App.tsx:1069`). Because join codes are single-use (D-11), a code
already consumed by the in-app connect fails re-exchange, and the failure is
mislabelled "Code invalid" (WR-03). The locked product fix (2026-06-22): when the
viewer already holds a cap for the session, reuse it — build the cap-bearing URL
from the daemon's `RemoteCapStore` and open it directly, with NO second code.
Fall back to the modal only when no cap is held — achieving parity with
`handleBrowseFilesRemote` (`App.tsx:1090`).

The raw cap token never returns to React (it lives only in the daemon's
`RemoteCapStore`, deposited by `RegisterRemoteCap`). So a NEW daemon read path +
Wails binding is required to produce `baseURL + /sessions/{id}?cap=TOKEN` from the
stored entry. The cap already enters the URL by design in the existing
exchange→open path, so this introduces no new exposure.

Also closes the residual code-review warnings: WR-03 (error copy), WR-02 (the
behavior-level test blind spot crossing the open path), and WR-01 (the fallback
modal URL must be built from the cap's bound SID, not the clicked-session id).

Purpose: make remote open-in-browser actually work on the second open without a
fresh code — the literal user-reported failure on the live two-Mac tailnet.
Output: a held-cap reuse path, a corrected fallback path, corrected error copy,
and behavior-level test coverage that crosses both paths.
</objective>
