# Phase 76 -- UI Design Contract: TUI Foundation

> Visual and interaction contract for Phase 76. This phase is a full-screen terminal UI (TUI)
> surface built with Bubble Tea (Charm ecosystem), not a browser UI. The "design system" is
> Lip Gloss styles and ANSI colors rendered to a TTY. Generated by gsd-ui-researcher, verified
> by gsd-ui-checker.

## Spacing Scale

The TUI is a character-cell grid. All spacing is expressed in character-cell units (1 unit =
1 monospace character width or height). Pixel measurements do not apply.

| Token | Chars | Usage |
|-------|-------|-------|
| cell-pad-h | 1 | Horizontal padding inside styled boxes (1 char each side) |
| cell-pad-v | 0 | Vertical padding inside list rows (rows are single-height) |
| col-gap | 2 | Spaces between columns in the session list |
| separator | 3 | ` | ` (space + pipe + space) between footer fields -- consistent with Phase 75 |
| section-gap | 1 | Blank row between header area and list, and between list and footer |
| border-width | 1 | Single-character box-drawing border when used (help overlay) |
| list-gutter | 2 | Left margin before session row content (cursor indicator + space) |

Exceptions: none. All values are multiples of 1 character cell (the terminal's atomic unit).

Source: Phase 75 UI-SPEC -- separator convention ` | `

## Typography

Terminal typography is monospace by the host terminal. The following contracts govern content
formatting and emphasis, not font selection.

| Role | Formatting | Usage |
|------|-----------|-------|
| Title | Bold | Application title in header row: "AgentHub" |
| Column header | Bold + Muted foreground | Column labels above session list |
| Session row (normal) | Normal weight | Unselected session rows |
| Session row (selected) | Reverse video or highlight bg | Currently selected/focused row |
| Footer text | Normal weight | Web server status, keybinding hints |
| Help overlay heading | Bold | Group headings in help overlay (e.g. "Navigation", "Actions") |
| Help key | Bold accent | Keybinding key in help (e.g. "j/k") |
| Help description | Normal muted | Keybinding description (e.g. "move up/down") |
| Status indicator | Normal weight, colored fg | Unicode glyph with semantic color |

**Line height:** Every row is exactly 1 terminal row. No multi-line rows in the session list.

## Color

The TUI uses Lip Gloss `AdaptiveColor` (light/dark detection via `lipgloss.HasDarkBackground`)
for all semantic tokens. This ensures correct contrast on both light and dark terminal themes.
Colors are specified as ANSI 256 palette values where possible for broad terminal compatibility,
with hex fallbacks for TrueColor terminals.

### Semantic Color Tokens

| Token | Dark BG Value | Light BG Value | Usage |
|-------|--------------|----------------|-------|
| `fg.normal` | `#C6C6C6` (ANSI 251) | `#303030` (ANSI 236) | Default text |
| `fg.muted` | `#626262` (ANSI 241) | `#949494` (ANSI 246) | Column headers, help descriptions, secondary text |
| `fg.accent` | `#5F87FF` (ANSI 69) | `#005FD7` (ANSI 26) | Keybinding hints, interactive elements |
| `bg.selected` | `#303030` (ANSI 236) | `#E4E4E4` (ANSI 254) | Selected row background |
| `fg.selected` | `#FFFFFF` (ANSI 231) | `#000000` (ANSI 16) | Selected row foreground (high contrast) |
| `status.running` | `#5FAF5F` (ANSI 71) | `#008700` (ANSI 28) | Running session indicator |
| `status.idle` | `#5F87FF` (ANSI 69) | `#005FD7` (ANSI 26) | Idle session indicator |
| `status.waiting` | `#FFAF00` (ANSI 214) | `#AF8700` (ANSI 136) | Waiting-for-input indicator |
| `status.errored` | `#FF5F5F` (ANSI 203) | `#D70000` (ANSI 160) | Errored session indicator |
| `web.on` | `#5FAF5F` (ANSI 71) | `#008700` (ANSI 28) | Web server running indicator |
| `web.off` | `#626262` (ANSI 241) | `#949494` (ANSI 246) | Web server stopped indicator |
| `border.normal` | `#444444` (ANSI 238) | `#BCBCBC` (ANSI 250) | Help overlay border |
| `border.accent` | `#5F87FF` (ANSI 69) | `#005FD7` (ANSI 26) | Help overlay title border highlight |

### 60/30/10 Mapping for a TUI Surface

- **60% dominant:** Terminal's own background -- the TUI does not set a global background color
  (transparent to the user's terminal theme)
- **30% secondary:** `bg.selected` -- used only for the focused/selected row highlight
- **10% accent:** `fg.accent` -- reserved exclusively for: keybinding hint text in footer,
  keybinding keys in help overlay, and interactive element highlights

### Destructive Color

`status.errored` (red) serves as the destructive/error semantic color. In this phase no
destructive actions exist (kill/delete are Phase 77), but the token is defined for session
error state display.

Source: Phase 75 UI-SPEC -- "Functional, not decorative" constraint
Source: REQUIREMENTS.md Out of Scope -- "Rich color themes for status bar"

## Layout Contract

### Overall Structure

The TUI occupies the full alternate screen buffer. Layout is a vertical stack of three zones
with fixed header/footer and a flexible list area that fills remaining rows.

```
+------------------------------------------------------------------+
| Row 1: Header                                                     |
|   "AgentHub"  (bold)                          "[session-count]"   |
+------------------------------------------------------------------+
| Row 2: Column Headers                                             |
|   STATUS  NAME         AGENT     HOST          VIEWERS            |
+------------------------------------------------------------------+
| Rows 3..N-3: Session List (scrollable)                            |
|   > *  my-session     claude    macbook-pro   2                   |
|     *  another-one    opencode  linux-vm      0                   |
|     ...                                                           |
+------------------------------------------------------------------+
| Row N-2: (blank separator)                                        |
+------------------------------------------------------------------+
| Row N-1: Footer -- Web Server Status                              |
|   Web: * Running -- https://mac.tail.ts.net   |  ? Help  q Quit  |
+------------------------------------------------------------------+
| Row N: Footer -- Keybinding Hints (short form)                    |
|   j/k Up/Down  Enter Attach  n New  ? Help  q Quit               |
+------------------------------------------------------------------+
```

### Row Budget

| Zone | Rows | Content |
|------|------|---------|
| Header | 1 | App title + session count |
| Column headers | 1 | Column labels |
| Session list | `terminal_rows - 5` | Scrollable session items |
| Separator | 1 | Blank row |
| Footer line 1 | 1 | Web server status |
| Footer line 2 | 1 | Keybinding hint bar |

**Minimum terminal size:** 60 columns x 10 rows. Below this threshold, display a centered
message: "Terminal too small (need 60x10)" and re-render normally when the terminal is resized
above the minimum.

### Column Layout (Session List)

| Column | Align | Min Width | Max Width | Truncation | Content |
|--------|-------|-----------|-----------|------------|---------|
| Cursor | left | 2 | 2 | n/a | `> ` for selected, `  ` for others |
| Status | left | 2 | 2 | n/a | Unicode glyph (see Status Indicators) |
| Name | left | 8 | flexible | ellipsis `...` | Session name |
| Agent | left | 6 | 12 | ellipsis | CLI type string (e.g. `claude`) |
| Host | left | 6 | 20 | ellipsis | Machine hostname |
| Viewers | right | 3 | 7 | n/a | Integer count, or blank if 0 |

**Column width allocation strategy:** Name column gets all remaining space after fixed-width
columns (Cursor=2, Status=2, Agent=12, Host=20, Viewers=7, gaps=5*2=10) are allocated. Total
fixed = 53 chars. Name column = `terminal_cols - 53`, minimum 8 chars. If terminal is too
narrow for minimum name width, Host column truncates first, then Agent.

**Truncation:** When a value exceeds its max column width, truncate to `(max - 3)` characters
and append `...`. Never truncate Status or Cursor columns.

### Consistent Separator Style

Field separators within the footer use ` | ` (3 chars: space-pipe-space), consistent with
Phase 75's status bar convention. Column separators in the session list use 2-space gaps
(no pipe -- the list is a table, not a bar).

Source: Phase 75 UI-SPEC -- separator convention

## Status Indicators

Session status values come from `internal/status` package: `running`, `waiting`, `idle`,
`errored`. Each maps to a Unicode glyph and a semantic color token.

| Status Value | Glyph | Color Token | Description |
|-------------|-------|-------------|-------------|
| `running` | `*` (U+25CF BLACK CIRCLE) | `status.running` (green) | Session actively producing output |
| `idle` | `*` (U+25CB WHITE CIRCLE) | `status.idle` (blue) | Session at prompt, waiting for user |
| `waiting` | `*` (U+25CF BLACK CIRCLE) | `status.waiting` (yellow) | Session waiting for confirmation |
| `errored` | `*` (U+2716 HEAVY MULTIPLICATION X) | `status.errored` (red) | Session exited with error |

**Note on glyphs:** The actual Unicode characters to use are:

| Status | Character | Unicode |
|--------|-----------|---------|
| running | ● | U+25CF |
| idle | ○ | U+25CB |
| waiting | ● | U+25CF (same glyph as running, differentiated by color) |
| errored | ✖ | U+2716 |

**Web server status glyphs (footer):**

| State | Glyph | Color Token | Display |
|-------|-------|-------------|---------|
| Running | ● | `web.on` (green) | `Web: ● Running -- {url}` |
| Stopped | ○ | `web.off` (muted) | `Web: ○ Stopped` |

Source: `internal/status/detector.go` -- canonical status values: running, waiting, idle, errored

## Interaction Contract

### Keybindings -- Main View (Session List)

All keybindings use the `bubbles/key` package for consistent binding/help integration.

| Key | Action | Status in This Phase |
|-----|--------|---------------------|
| `q` | Quit TUI | **Active** |
| `Ctrl+C` | Quit TUI | **Active** |
| `?` | Toggle help overlay | **Active** |
| `j` / `Down` | Move selection down | **Active** |
| `k` / `Up` | Move selection up | **Active** |
| `Enter` | Attach to selected session | **Reserved** -- displays "Coming in next update" toast; Phase 77 activates |
| `n` | Create new session | **Reserved** -- displays "Coming in next update" toast; Phase 77 activates |
| `d` | Kill selected session | **Reserved** -- not shown in help; Phase 77 activates |
| `e` | Rename selected session | **Reserved** -- not shown in help; Phase 77 activates |
| `r` | Refresh session list | **Active** |
| `Esc` | Close help overlay (when open) | **Active** (contextual) |
| `g` / `Home` | Jump to first session | **Active** |
| `G` / `End` | Jump to last session | **Active** |

**Reserved keys** are consumed (not passed through) but produce no action beyond a brief
status message. This prevents future keybinding conflicts. `d` and `e` are not shown in the
help overlay until Phase 77 activates them.

**Mouse:** No mouse handling. REQUIREMENTS.md explicitly excludes mouse-driven TUI navigation
("Interferes with AI agent mouse usage during attach"). The Bubble Tea program must NOT enable
any mouse mode (`v.MouseMode` must remain unset / `tea.MouseModeNone`).

### Help Overlay

The help overlay is a modal that renders on top of the session list. It does NOT replace the
entire screen -- it is a centered box with a border drawn over the existing content.

**Dimensions:** Help overlay is `max(40, min(60, terminal_cols - 10))` columns wide,
height determined by content + 2 (border). If the overlay would exceed `terminal_rows - 4`,
it truncates to fit with a "..." indicator at the bottom.

**Structure:**

```
+--- Keybindings -------------------------+
|                                          |
|  Navigation                              |
|    j/k, Up/Down     Move up/down         |
|    g/Home            Jump to first        |
|    G/End             Jump to last         |
|    r                 Refresh list         |
|                                          |
|  Actions                                 |
|    Enter             Attach to session    |
|    n                 New session           |
|                                          |
|  General                                 |
|    ?                 Toggle help           |
|    q, Ctrl+C         Quit                 |
|                                          |
|           Press ? or Esc to close         |
+------------------------------------------+
```

**Groups:**
1. Navigation -- movement and refresh keys
2. Actions -- session operations (includes reserved keys that show as available)
3. General -- help toggle and quit

**Border style:** Lip Gloss `lipgloss.RoundedBorder()` with `border.normal` color,
title "Keybindings" rendered in `border.accent` color.

**Dismiss:** `?` (toggle) or `Esc`. No other key dismisses the overlay.

Source: REQUIREMENTS.md TUI-09

### Terminal Resize

On `tea.WindowSizeMsg`, recalculate all layout dimensions (list height, column widths,
help overlay size). Bubble Tea handles SIGWINCH and delivers window size messages automatically.
The `View()` method must be purely derived from `model.width` and `model.height` fields
(set in `Update` from `tea.WindowSizeMsg`).

### Refresh / Polling

The session list is refreshed by:
1. **On launch:** Initial fetch from daemon API (`GET /sessions` + `GET /webserver/status`)
2. **On timer:** A `tea.Tick` command fires every 2 seconds, triggering a background re-fetch
3. **On manual refresh:** `r` key triggers immediate re-fetch
4. **On window focus:** `tea.FocusMsg` triggers re-fetch (if supported by terminal)

Re-fetch is a `tea.Cmd` that calls the daemon client in a goroutine and returns the result
as a message. The `Update` function processes the response message and updates the model.
Never block the main Bubble Tea loop on HTTP calls.

## TTY Detection / Non-TTY Behavior

If `os.Stdout` is not a TTY (`!term.IsTerminal(int(os.Stdout.Fd()))`), the `agenthub tui`
command must print an error and exit:

```
Error: agenthub tui requires a terminal. Redirect to a TTY or use 'agenthub list' instead.
```

Exit code: 1. Do not attempt to start the Bubble Tea program.

Source: Phase 75 UI-SPEC -- TTY suppression pattern (SB-03)

## Alt-Screen Buffer and Cleanup

Bubble Tea v2 uses declarative alt-screen via `tea.View.AltScreen = true`. On program exit
(quit or crash), Bubble Tea automatically restores the original screen content and cursor
position. No manual cleanup sequences are needed (unlike Phase 75's DECSTBM approach).

**Mandatory:** Set `v.AltScreen = true` in the `View()` method. This ensures the TUI does
not pollute the user's scrollback buffer and restores cleanly on exit.

**On quit:** Bubble Tea restores the main screen buffer. The terminal returns to the state
before `agenthub tui` was launched -- no leftover artifacts.

Source: Bubble Tea v2 documentation -- `tea.View.AltScreen`

## Data Flow Contract

### Daemon Client Integration

The TUI uses `internal/daemon.DaemonClient` (already exists) to fetch data. No new API
endpoints are needed for this phase.

| API Call | Endpoint | Response Type | When Called |
|----------|----------|--------------|-------------|
| List sessions | `GET /sessions` | `[]daemon.SessionInfo` | Launch, tick, manual refresh |
| Web server status | `GET /webserver/status` | `daemon.WebServerStatusResponse` | Launch, tick, manual refresh |
| Daemon health | `GET /health` | `daemon.HealthResponse` | Launch (to validate daemon is running) |

### Model Fields (Bubble Tea)

| Field | Type | Source |
|-------|------|--------|
| `sessions` | `[]daemon.SessionInfo` | `GET /sessions` response |
| `webStatus` | `daemon.WebServerStatusResponse` | `GET /webserver/status` response |
| `selectedIdx` | `int` | User navigation (j/k/arrows) |
| `width` | `int` | `tea.WindowSizeMsg` |
| `height` | `int` | `tea.WindowSizeMsg` |
| `showHelp` | `bool` | `?` key toggle |
| `loading` | `bool` | True during initial fetch, false after first response |
| `err` | `error` | Non-nil when daemon is unreachable |

## Anti-Patterns Prohibited by This Contract

The executor must not do any of the following:

1. **Enable mouse mode** -- `tea.View.MouseMode` must not be set (violates REQUIREMENTS.md
   "No mouse-driven TUI navigation")
2. **Block in Update()** -- all daemon API calls must be `tea.Cmd` functions that return
   messages, never synchronous calls in `Update`
3. **Hard-code terminal dimensions** -- always derive layout from `model.width` / `model.height`
   updated via `tea.WindowSizeMsg`
4. **Use external ANSI libraries** -- Lip Gloss handles all styling; do not import raw ANSI
   constant packages alongside Lip Gloss
5. **Poll faster than 2 seconds** -- the daemon API is local-socket but excessive polling
   wastes CPU; 2-second tick is the contract
6. **Show reserved keybindings (d, e) in help** -- only show them once Phase 77 activates them
7. **Render the help overlay as a full-screen replacement** -- it must be a centered modal
   drawn over the existing list content
8. **Use fmt.Print/Println for rendering** -- all output goes through Bubble Tea's View()
   return value; never write directly to stdout
9. **Ignore the minimum terminal size** -- always check dimensions and show the "too small"
   message when below 60x10
