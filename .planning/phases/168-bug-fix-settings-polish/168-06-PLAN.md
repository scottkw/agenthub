<objective>
FIX-02 (#117): support multiple simultaneous remote viewers of a shared session and give the
owner a "Disconnect all viewers" escape hatch in the Share modal.

Purpose: RESEARCH (A1) found NO eviction code path anywhere — the "second viewer kicks first"
half of #117 does not reproduce in current code, so this plan adds a regression guard rather than
a fix, and delivers the genuinely-missing piece: an owner-only force-disconnect of all
web-origin viewers (D-04..D-06). Force-close reuses Subscriber.CloseSlow with unlock-before-IO
lock discipline; the RPC sits behind the daemon-local trust boundary (never guest-reachable).
Output: Hub.DisconnectWebViewers + the daemon RPC chain + the modal button, with Go + vitest
tests including a two-web-viewer no-eviction regression test.
</objective>

|----------|-------------|
| GUI (owner) → daemon /sessions/{id}/disconnect-viewers | Daemon-local RPC; only the owning desktop app can call it — NOT the guest browser. |
| guest WS connection ← webserver | The connections being force-closed live in the webserver process; DisconnectWebViewers acts on Origin=="web" subscribers only. |
