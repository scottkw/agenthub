# Phase 168 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Scope note

This is a bug-fix/polish phase. Five of six requirements (FIX-01, FIX-02, FIX-03, FIX-04, and the
enabling half of UX-02) are **wiring fixes with zero new visual surface** — they change what data
flows into UI that already exists (viewer count, plugin-config, in-app tab routing) without adding
new components. Only two elements are genuinely new pixels:

1. A **"Disconnect all viewers" button** inside the existing `SessionShareModal` (FIX-02/D-04).
2. A **new Settings toggle** ("Stay on Hub after creating a session") in the existing Session
   Behavior section (UX-01/D-08).

Everything else (footer button rename UX-02, viewer-count display FIX-04) reuses components and
CSS classes that already exist pixel-for-pixel — this contract locks their **exact reuse**, not new
styling. No new design tokens, no new component patterns, no new icon usage beyond what's already
imported in the touched files.

| Property | Value |
|----------|-------|

**Hard rule for this phase:** every new style declaration MUST reference an existing `var(--hub-*)`

no existing class fits the exact layout need (in which case, name it in the same
`.hub-<component>__<part>` / `.settings-panel__<part>` BEM-ish convention already used throughout
`style.css`).

## Spacing Scale

Declared values (must be multiples of 4 for anything net-new in this phase):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, button internal padding (`.tab-status-bar__btn` = `4px 8px`) |
| sm | 8px | Compact element spacing, most `gap:` values in the codebase (53 occurrences) |
| md | 16px | Section padding, `.hub-share-internet-section` top padding/margin |
| lg | 24px | not used by this phase's new elements |

Exceptions: the surrounding codebase is **not** strictly on a 4pt grid (it uses 6px/10px/12px/20px
in places, e.g. `.hub-share-internet-section__disable { padding: 4px 12px }`, `padding: 12px 20px`).
This is **pre-existing, out-of-scope debt** — do not "fix" it. New elements this phase introduces
(Disconnect button, Settings toggle row) MUST reuse the exact spacing of the class/pattern they
copy (see Visual Reuse Map below), not invent new spacing values.

sizes/weights:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Micro / state label | 11px (hardcoded in `.tab-status-bar__state`, uppercase, `letter-spacing: 0.05em`) | 600 | 1 (single line) |

  `.settings-panel__description` exactly.

  `.hub-share-internet-section__disable` exactly (see Visual Reuse Map).

## Color

Dark-theme canonical values shown (`style.css:4641-4710`); **every reference in code MUST use the
`var(--hub-*)` token, never the hex** — the same token resolves differently in the light theme
(`style.css:4715-4763`), and this app is used by a colorblind developer (state must never be
color-only; see Copywriting Contract).

| Role | Value (dark) | Usage |
|------|-------|-------|
| Dominant (60%) | `--hub-bg` `#14151b` | App background, tab content area |
| Secondary (30%) | `--hub-surface` `#16181f` / `--hub-surface-elevated` `#1c1e28` | Modals (`hub-share-modal`), settings panel, footer status bar, card surfaces |
| Accent (10%) | `--hub-accent` `#7aa2f7` | Reserved for: toggle-track checked state (`.settings-panel__toggle-row--checked`), focus rings (`outline: 2px solid var(--hub-accent)`), active/hover button borders (`.tab-status-bar__btn--active`), links. **Do NOT use accent for the new Disconnect button or the new Settings toggle's static (unchecked) state** — those follow the existing patterns below. |
| Destructive | `--hub-destructive` `#f7768e` | Reserved for genuinely destructive, hard-to-reverse actions (delete session, remove group) via `.settings-panel__btn--destructive` (filled red bg). **NOT used for the Disconnect-viewers button** — see next section for why. |

### Disconnect-all-viewers button color — explicit ruling

D-06 (locked) frames "Disconnect all viewers" as a **reversible escape hatch** (viewers can
reconnect with the same join code; the capability is never revoked) — the same shape as the
existing "one-click Funnel disable" action (FUI-04), not the same shape as a destructive delete.
**Use the `.hub-share-internet-section__disable` visual pattern** (transparent background, 1px
`var(--hub-border)` outline, `var(--hub-text-muted)` text, `var(--hub-accent)` focus ring) —
**not** the filled-red `.settings-panel__btn--destructive` pattern. This keeps the visual weight
proportionate to the actual risk (dropping a connection, not destroying data).

## Registry Safety

| Registry | Blocks Used | Safety Gate |
|----------|-------------|-------------|
| shadcn official | none — shadcn not initialized for this project | not applicable |
| third-party | none | not applicable |

This project has no `components.json` and does not use shadcn or any component registry. All UI is
hand-authored React + the shared `style.css` token system. The shadcn initialization gate was
evaluated and skipped: the codebase is a mature (150+ shipped phases), fully custom design system
with its own established conventions — introducing shadcn mid-milestone for a two-element polish
phase would fragment the visual language rather than serve it. No registry vetting required.
