<objective>
FIX-03 (#118): opening a remote tailnet session from the Hub opens an in-app terminal tab
(streaming the relay) instead of launching an external browser window.

Purpose: handleOpenRemoteSession currently routes through OpenRemoteSessionURL(id) →
BrowserOpenURL(url) (the Phase 146 out-of-band design). Now that WebShareSessionView exists and
is baseURL-parameterized (plan 02), D-17 reroutes remote-open to the in-app web-session tab.
This also requires making the web-session tab resolution per-tab (currently a mount-stable
singleton correct only for the app's own single web-share bootstrap), so a user can open two
different remote peers concurrently.
Output: A per-tab web-session param model + an in-app remote-open path, covered by vitest.
</objective>
