<objective>
UX-01 (#116): add a Settings → Session Behavior toggle that, when enabled, keeps the user on
the Hub after creating a session instead of auto-switching to the new session's tab.

Purpose: Today creating a session from the Hub always switches to it (App.tsx createTab's single
setActiveId). D-11 confirmed this is the ONLY auto-switch in the app (CLI-created sessions never
run through createTab). This plan mirrors the Phase 167 NotifyOnWaiting end-to-end daemon-setting
pattern (D-12) for persistence and gates that one setActiveId.
Output: A persisted stayOnHubAfterCreate setting (full daemon chain) + the Settings toggle +
the gated create path, all covered by Go and vitest tests.
</objective>
