## Component Inventory

These are the existing components this phase touches. No new components are introduced.

### Error Banner (existing — `App.tsx` lines 297-333)

The banner already exists and is fully styled. Phase 26 changes its **trigger mechanism** and **body copy** only.

**Current trigger:** `daemonError` state set by `init()` catch block only.
**Phase 26 trigger:** Also set by `EventsOn('daemon:error', ...)` subscription (catches pre-init failures).

**Current body copy (to be updated):**
> "The background daemon did not start in time. Your sessions are not accessible. Check the system log or restart AgentHub."

**Phase 26 body copy contract (two lines):**
- Static heading: `Unable to connect to session daemon`
- Dynamic detail: render `{daemonError}` string directly below heading (replaces the hardcoded sentence)
- Rationale: The actual error message from Go is specific (e.g., "daemon binary not found at /path/to/agenthub", "daemon did not respond within 3s"). Showing it directly matches the detail-below-heading pattern used in browser dev tools and is consistent with how `settings-panel__error` works.

**Retry button:** Label stays `Retry Connection`. Interaction changes: calls `RetryDaemon()` Go method first, then re-runs `init()` on success. Shows error if `RetryDaemon()` rejects.

**Visibility rule (unchanged):** Banner renders only when `daemonError !== null && tabs.length === 0`.

### No New Components

Phase 26 requires zero new TSX components. All changes are:
1. `app.go` — Go-side: `startup()` emits event + returns, `RetryDaemon()` bound method added
2. `frontend/src/App.tsx` — subscribe to `daemon:error` event, update `retryInit` to call `RetryDaemon()` first, update banner body copy

## Interaction Contract

### State Machine: daemon error banner

```
[startup() fires]
  ├─ EnsureDaemon OK  →  normal init → no banner shown
  └─ EnsureDaemon FAIL
       ├─ emits runtime.EventsEmit "daemon:error" (msg)   [Go → frontend]
       └─ EventsOn('daemon:error') sets daemonError state [frontend]
            → banner renders with heading + raw error detail

[user clicks "Retry Connection"]
  ├─ call RetryDaemon()         [frontend → Go]
  │    ├─ success (nil error)
  │    │    → clear daemonError
  │    │    → run init() Promise.all
  │    │    → banner dismissed, tabs load
  │    └─ failure (error returned)
  │         → setDaemonError(new error string)
  │         → banner re-renders with updated detail
  └─ (no double-click guard needed — button is synchronous)
```

### Race Condition Defense (from RESEARCH.md Pitfall 2)

`init()` already catches errors from `GetRelayPort()` (nil client returns error) and calls `setDaemonError(String(err))`. This serves as the fallback if `daemon:error` event fires before the React mount cycle registers the `EventsOn` listener. No separate `GetDaemonError()` polling method is required — the `init()` catch block covers the race.

### Nil-Guard on App Bound Methods (defensive)

Methods `ListSessions()`, `GetRelayPort()`, and any other method that calls `a.client.XXX()` must return a zero/empty value (not panic) when `a.client == nil`. This is a Go-side guard, not a UI interaction, but it affects what the frontend error catch block receives.
