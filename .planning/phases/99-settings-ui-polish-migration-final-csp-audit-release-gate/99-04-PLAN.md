<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → repo | Workflow files execute with repo write permissions when triggered. SHA-pinned third-party actions (Phase 90 SEC-09) prevent floating-tag supply-chain attacks. |
| Browser engine vs CSP | Three browser engines (Chromium V8, Firefox SpiderMonkey, WebKit JSC) parse CSP independently. Cross-browser e2e proves the header is correctly enforced across all three. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-99-11 | Tampering | Workflow action SHAs | mitigate | All `uses:` directives in e2e.yml use 40-char SHA pins (per Phase 90 SEC-09). The acceptance criteria runs `diff` against build.yml's pins to enforce uniformity. |
| T-99-12 | Information Disclosure | Playwright report artifacts | accept | The `actions/upload-artifact` step uploads `playwright-report/` only on failure, retained 7 days. No secrets in the report (Playwright traces session HTML/console — same surface as the running web app). |
| T-99-13 | Spoofing | CSP violation false positives | mitigate | `web-csp.spec.ts` listens specifically for console messages matching /csp|content security policy/i; not all browser warnings (e.g., favicon 404) trigger the assertion. |
| T-99-14 | Denial of Service | CI minutes consumption | accept | Workflow timeout 20 min; runs only on main + PR (not on every branch). Total cost per run: ~3-5 min × 1 OS (ubuntu-latest). Acceptable for release-gate enforcement. |
</threat_model>
