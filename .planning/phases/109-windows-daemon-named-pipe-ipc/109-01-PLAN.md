<objective>
Land third-party PR #53 (by Alexandre Castro / `im-alexandre`) onto v3.3 `main` so the AgentHub daemon, GUI, CLI, and TUI all start and connect on Windows 11 by listening on `\\.\pipe\agenthub-daemon` instead of failing to bind a Unix socket. Closes GitHub Issue #52.

Purpose: Windows is currently 100% broken — `net.Listen("unix", socketPath)` fails with "bind: A socket operation encountered a dead network" because Windows treats the `\\.\pipe\...` path as a filesystem path it cannot bind a unix socket to. The fix is a build-tag-split IPC abstraction (`ipc_windows.go` + `ipc_nonwindows.go`) wrapped around listener creation, client dial, and stop-side cleanup — exactly what PR #53 implements. Research confirmed (`git merge-tree --write-tree main pr-53-temp`) a clean three-way merge with no conflicts; the cherry-pick path is therefore preferred over re-apply because it preserves author attribution automatically for IPC-06.

Output:
- Three commits derived from PR #53 (design doc + named-pipe fix + Windows regression tests, then the separate kernel32 tray fix), each carrying `Author: Alexandre Castro <im.alexandre07@gmail.com>` via `git cherry-pick`.
- A phase evaluation note (`109-PR53-EVALUATION.md`) documenting the decision and merge-tree evidence (closes IPC-06 documentation requirement).
- A VERIFICATION.md that records cross-platform smoke (macOS auto-passes) and surfaces Windows GUI / CLI / TUI as three discrete `human_needed` items (cannot be performed from a macOS executor).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local user ↔ daemon over Unix socket (macOS/Linux) | Same machine, same OS user; access bounded by socket file mode `0600`. |
| Local user ↔ daemon over named pipe (Windows) | Same machine, same Windows user; access bounded by named-pipe default ACL (creating user only). |
| Local user A ↔ local user B (cross-user on same Windows machine) | Implicitly denied by named-pipe ACL — non-owner gets `ACCESS_DENIED`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-109-01 | Spoofing | `winio.ListenPipe(path, nil)` default ACL | mitigate | `winio.ListenPipe(path, nil)` defaults to user-scoped ACL (verified in `tailscale/go-winio` source per RESEARCH.md §Security Domain). PR #53 passes `nil` for `*PipeConfig` — correct. No code change needed beyond honoring the PR's call signature. |
| T-109-02 | Spoofing | Pipe-name squatting (malicious local process pre-registers `\\.\pipe\agenthub-daemon`) | accept | Pre-existing issue mirrored on the Unix side (any local process can register a Unix socket file at the daemon's path if they get there first). `CleanupStaleSocket` probes the pipe at startup — a squatter would have to **be** the daemon (answer `GET /health` correctly). Acceptable for local-trust model; out of scope per RESEARCH.md §Security Domain. |
| T-109-03 | Tampering / DoS | Pipe-message overflow on incoming HTTP frames | mitigate | Existing `http.MaxBytesReader` calls at handler entry points (`handleSetPluginSettings`, `handleUpdateShellPath` per WR-03 from Phase 107) are unchanged. Transport-layer framing is `winio`'s responsibility — vetted upstream. No new mitigation required. |
| T-109-04 | Information Disclosure | `removeDaemonSocket(addr)` operating on a path supplied by `a.ln.Addr().String()` after `Close()` | mitigate | PR #53 captures `addr := a.ln.Addr().String()` BEFORE `Close()` (per RESEARCH.md Pattern 2). Defensive against `winio`'s post-close `Addr()` semantics not being guaranteed. Code review during Task 2 cherry-pick confirms the capture-then-close ordering. |
| T-109-05 | Tampering | `os.Remove` invoked on `\\.\pipe\agenthub-daemon` accidentally on Windows | mitigate | `ipc_windows.go::removeDaemonSocket` short-circuits via `if isWindowsNamedPipe(path) { return nil }` BEFORE any `os.Remove` call. Verified by inspection during Task 2; verified by `TestAPIStop_WindowsNamedPipe` test added by PR #53 (IPC-04). |

The transport substitution preserves the existing local-trust security model byte-for-byte. No new ASVS controls are introduced. Phase 109 is **security-neutral** — the same user-boundary enforcement that Unix-socket file mode `0600` provides on POSIX is provided by named-pipe default ACL on Windows.
