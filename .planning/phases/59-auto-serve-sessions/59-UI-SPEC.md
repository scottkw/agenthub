## Component Inventory

Components touched or added in Phase 59:

### 1. DaemonManagerPanel — web toggle button

**Existing component:** `frontend/src/components/DaemonManagerPanel.tsx`

**Current state:** Web toggle shows "Web On" / "Web Off" text. Button is disabled (`opacity: 0.4`) when `webServerRunning` is false.

**Phase 59 change:** After auto-start, `webServerRunning` is true before the panel renders. For newly created sessions, `webEnabled[id]` starts as `true` (not `false`). The button label and visual state must correctly reflect this.

**Button states to support:**

| State | Label | Border | Color | Background |
|-------|-------|--------|-------|------------|
| Server not running | "Web On" | `#292e42` | `#a9b1d6` at 0.4 opacity | transparent |
| Server running, web off | "Web On" | `#292e42` | `#a9b1d6` | transparent |
| Server running, web on | "Web Off" | `#292e42` | `#a9b1d6` | transparent |
| Hover (server running, web off) | "Web On" | `#7aa2f7` | `#7aa2f7` | transparent |
| Hover (server running, web on) | "Web Off" | `#7aa2f7` | `#7aa2f7` | transparent |

No visual change to the button class structure is needed. The toggle remains interactive (users can still disable web serving per session). The "on by default" behavior is a state seeding change, not a visual redesign.

### 2. StatusBar — web-enabled indicator

**Existing component:** `frontend/src/components/StatusBar.tsx`

**Current state:** Shows a web-serving indicator based on `webEnabled` prop.

**Phase 59 change:** When a new session is created while server is running, `webEnabled[id]` is `true` immediately. The status bar should show the "Web On" state and the session URL without any additional interaction from the user.

**Indicator states (existing CSS classes — no new classes needed):**

| State | CSS class | Color |
|-------|-----------|-------|
| Web on | `.tab-status-bar__state--on` | `#9ece6a` |
| Web off | `.tab-status-bar__state--off` | `#565f89` |
| Server not running | `.tab-status-bar__state--inactive` | `#414868` |

URL link (`.tab-status-bar__url`): `#7aa2f7`, 12px, no underline until hover.

### 3. SettingsTab — Web Server section

**Existing component:** `frontend/src/components/SettingsTab.tsx`

**Current state:** Web Server sub-tab shows "Start Web Server" / "Stop Web Server" button. After auto-start, the server is running when the user opens Settings.

**Phase 59 change:** On mount, `loadWebState()` already calls `IsWebServerRunning()`. When auto-started, this returns `true`, so the button already renders as "Stop Web Server" (`.settings-panel__btn--cancel` style). No visual change needed; the existing logic handles this correctly.

**No new CSS classes are needed for SettingsTab.**

## Interaction Contracts

### Auto-started web server — user perception

The user opens the app after daemon launch. The web server is already running. The expected visual outcome:

1. **DaemonManagerPanel (Sessions tab):** Web toggle buttons for all sessions created after daemon start are in the "Web Off" state (server running, not yet enabled for pre-existing sessions) OR "Web Off" clickable state for sessions created before this phase shipped. For newly created sessions (post-phase-59), web toggle is "Web Off" (toggle label; the session IS enabled — "Web Off" means "click to disable").
2. **StatusBar:** New sessions show green "WEB" indicator and the URL immediately, without the user clicking "Web On".
3. **Settings tab / Web Server section:** "Stop Web Server" button is active (not greyed). Server URL is displayed.

### Session restore after window re-open

When the Wails window is re-opened (daemon already running, server already running):
- `init()` calls `IsWebServerRunning()` → `true`
- `ListSessions()` returns sessions with `webEnabled: true` for each auto-enabled session (requires `WebEnabled bool` field in `SessionInfo` — see RESEARCH.md Option A)
- Frontend seeds `webEnabled` state from `SessionInfo.WebEnabled`
- Web toggles and status bars reflect correct state immediately, without flicker

**No loading state or skeleton is required** — the init call is fast and the daemon is local IPC.

### Web toggle (per-session, post-phase-59)

Users retain the ability to disable web serving per session. The toggle is always interactive when `webServerRunning` is true. The default is ON for new sessions; the interaction flow is the same as before.

## States and Transitions

### DaemonManagerPanel session row — web toggle

```
Server not running
  → button disabled (opacity 0.4)
  → title: "Web server not running"

Server running + session web-disabled
  → button enabled, label "Web On"
  → hover: border #7aa2f7, color #7aa2f7

Server running + session web-enabled   [new default for new sessions]
  → button enabled, label "Web Off"
  → hover: border #7aa2f7, color #7aa2f7
```

### StatusBar web indicator

```
Server not running
  → .tab-status-bar__state--inactive (#414868)
  → no URL shown

Server running + session web-disabled
  → .tab-status-bar__state--off (#565f89)
  → no URL shown

Server running + session web-enabled   [new default for new sessions]
  → .tab-status-bar__state--on (#9ece6a)
  → URL shown as .tab-status-bar__url link (#7aa2f7)
```
