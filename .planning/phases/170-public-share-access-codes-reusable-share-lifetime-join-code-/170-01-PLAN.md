<objective>
Add per-code TTL + reusable (non-single-use) semantics to `JoinCodeManager` so a single code can be
exchanged by multiple anonymous viewers over the lifetime of a public Funnel share, WITHOUT changing the
existing 5-minute single-use behavior that the Read-Only / Full-Access link codes depend on. Prove the new
primitive both at the unit layer (`joincode_test.go`) and end-to-end at the public HTTP boundary the recipient
actually hits (`/join/exchange`, `join_test.go`).

This is the foundation for FNL-08: everything in later waves (daemon minting, frontend display) consumes
`IssueReusable`/`Revoke` and the reusable-Exchange behavior established here.

Purpose: Today all join codes are 5-min single-use — `Exchange` always deletes on success (joincode.go:91).
That is wrong for a public share meant to last the auto-expiry window and serve an unbounded number of viewers.
Output: `IssueReusable`, `Revoke`, a `reusable` flag on `joinEntry`, conditional-delete in `Exchange`, and the
tests that lock the behavior in — including a brand-new `internal/webserver/join_test.go` (no dedicated
join-exchange test file exists today).

## Artifacts this plan produces
- `IssueReusable(token string, ttl time.Duration) (string, error)` — mints a reusable code with a per-call TTL
- `Revoke(code string)` — removes a code from the manager (idempotent; no error if absent)
- `reusable bool` field on `joinEntry`
- Conditional `delete` in `Exchange` (skipped when `entry.reusable`)
- `internal/webserver/join_test.go` (new file)
- Extended `internal/capability/joincode_test.go`
</objective>
