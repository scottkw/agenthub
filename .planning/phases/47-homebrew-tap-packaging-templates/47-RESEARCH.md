# Phase 47: Homebrew Tap + Packaging Templates - Research

**Researched:** 2026-04-04
**Domain:** Homebrew Cask distribution, WinGet manifests, GitHub Actions cross-repo automation
**Confidence:** HIGH

## Summary

Phase 47 delivers three concrete artifacts: (1) a functioning Homebrew tap at `scottkw/homebrew-agenthub` with a cask formula for the macOS DMG produced by Phase 46, (2) a `distribute.yml` GitHub Actions workflow in the main repo that automatically updates the tap on each release, and (3) packaging templates committed to `packaging/` in the main repo for both Homebrew and WinGet.

The Homebrew side is well-understood: the tap is a GitHub repo named `homebrew-agenthub` under the `scottkw` account, containing a `Casks/agenthub.rb` formula. The `distribute.yml` workflow triggers on `release: published`, downloads the macOS DMG SHA256 from the release's `checksums.txt`, updates `Casks/agenthub.rb` in the tap repo via `git push` using a PAT stored as `TAP_DEPLOY_TOKEN`, with retry logic for the notarization-to-release propagation delay. The WinGet side for Phase 47 is template-only (three YAML files at schema 1.12.0 in `packaging/winget/manifests/`); first submission to `microsoft/winget-pkgs` is Phase 48.

The macOS DMG artifact name is locked by Phase 46 as `agenthub-${VERSION}-darwin-universal.dmg`, where `VERSION` is the full git tag (e.g., `v1.8.0`). The `checksums.txt` file generated by Phase 46 contains `sha256sum` output with filenames as-is, so SHA256 can be extracted with `grep` + `awk`. Verified: the .app bundle is named `agenthub.app` (lowercase, confirmed from `build/bin/`). No LICENSE file exists in the repo — WinGet template will use `License: Proprietary` and omit `LicenseUrl` pending a license decision.

**Primary recommendation:** Implement `distribute.yml` as a self-contained bash script (sed-based formula update + git push to tap) rather than a third-party Action. Use `nick-fields/retry@v3` to wrap the checksums.txt download step with 5 retries and 60-second wait between attempts. For the tap repo, create it manually from GitHub UI, initialize with `Casks/agenthub.rb` committed directly.

### Pattern 2: Homebrew Cask Formula for macOS DMG App

**What:** Complete Ruby cask formula for a signed/notarized universal macOS DMG.

**When to use:** Any GUI macOS app distributed as a .dmg file via GitHub Releases.

```ruby
# Source: https://docs.brew.sh/Cask-Cookbook
cask "agenthub" do
  version "1.8.0"
  sha256 "abc123..."

  url "https://github.com/scottkw/agenthub/releases/download/v#{version}/agenthub-v#{version}-darwin-universal.dmg"
  name "AgentHub"
  desc "AI coding session manager with tabbed terminals and Tailscale web access"
  homepage "https://github.com/scottkw/agenthub"

  depends_on macos: ">= :ventura"

  app "agenthub.app"

  zap trash: [
    "~/Library/Application Support/agenthub",
    "~/Library/Preferences/com.scottkw.agenthub.plist",
    "~/Library/Caches/com.scottkw.agenthub",
    "~/Library/Logs/agenthub",
  ]
end
```

**Notes on this specific app:**
- Phase 46 DMG naming: `agenthub-${VERSION}-darwin-universal.dmg` where `VERSION = GITHUB_REF_NAME` (e.g., `v1.8.0`)
- The `url` stanza must reference the full tag in the release path: download URL is `releases/download/v1.8.0/agenthub-v1.8.0-darwin-universal.dmg`. In the cask formula, `version` stores the bare version (`1.8.0`) so the URL pattern is `v#{version}/agenthub-v#{version}-darwin-universal.dmg`.
- No `uninstall` stanza needed for `.app` artifacts (only required for `pkg`/`installer`).
- The `zap` stanza handles cleanup of leftover preferences/caches on `brew uninstall --zap`.
- `.app` bundle name is `agenthub.app` (lowercase) — confirmed from `build/bin/agenthub.app`.

### Pattern 4: distribute.yml — Homebrew Tap Auto-Update Workflow

**What:** GitHub Actions workflow that fires on release publication, extracts DMG SHA256 from checksums.txt, and pushes updated formula to tap repo.

**Critical detail:** notarization + GitHub CDN propagation after release.yml completes can take 1-5 minutes. The `checksums.txt` is uploaded to the Release by Phase 46's `publish` job. The distribute.yml must retry the checksums.txt download in case of brief propagation delay.

```yaml
# Source: research synthesis from builtfast.dev, josh.fail, nick-fields/retry docs
name: Distribute

on:
  release:
    types: [published]

jobs:
  update-homebrew-tap:
    runs-on: ubuntu-latest
    steps:
      - name: Extract version
        id: version
        run: |
          VERSION="${GITHUB_REF_NAME#v}"   # strip leading 'v' → '1.8.0'
          echo "version=${VERSION}" >> "$GITHUB_OUTPUT"
          echo "tag=${GITHUB_REF_NAME}" >> "$GITHUB_OUTPUT"

      - name: Download checksums with retry
        uses: nick-fields/retry@v3
        with:
          timeout_seconds: 30
          max_attempts: 5
          retry_wait_seconds: 60
          command: |
            curl -fsSL \
              "https://github.com/scottkw/agenthub/releases/download/${GITHUB_REF_NAME}/checksums.txt" \
              -o checksums.txt

      - name: Extract DMG SHA256
        id: sha256
        run: |
          SHA256=$(grep "agenthub-${GITHUB_REF_NAME}-darwin-universal.dmg" checksums.txt | awk '{ print $1 }')
          if [ -z "$SHA256" ]; then
            echo "ERROR: SHA256 not found in checksums.txt"
            cat checksums.txt
            exit 1
          fi
          echo "sha256=${SHA256}" >> "$GITHUB_OUTPUT"

      - name: Checkout tap repo
        uses: actions/checkout@v4
        with:
          repository: scottkw/homebrew-agenthub
          token: ${{ secrets.TAP_DEPLOY_TOKEN }}
          path: tap

      - name: Update cask formula
        run: |
          VERSION="${{ steps.version.outputs.version }}"
          SHA256="${{ steps.sha256.outputs.sha256 }}"
          sed -i "s/version \"[^\"]*\"/version \"${VERSION}\"/" tap/Casks/agenthub.rb
          sed -i "s/sha256 \"[^\"]*\"/sha256 \"${SHA256}\"/" tap/Casks/agenthub.rb

      - name: Commit and push formula update
        run: |
          cd tap
          git config user.name "github-actions[bot]"
          git config user.email "github-actions[bot]@users.noreply.github.com"
          git add Casks/agenthub.rb
          git commit -m "agenthub ${{ steps.version.outputs.version }}"
          git push
```

**Source:** [WinGet manifest docs](https://learn.microsoft.com/en-us/windows/package-manager/package/manifest)

**Package identifier convention:** `Publisher.PackageName` — must be globally unique in winget-pkgs. `scottkw.agenthub` follows this pattern.

**NSIS installer note:** Phase 46 produces an NSIS installer (`agenthub-${VERSION}-windows-amd64-installer.exe`) via `nsis: true` in wails-build-action. WinGet type `nullsoft` enables automatic `/S` silent install inference — no explicit `InstallerSwitches` needed.

**LICENSE note:** No LICENSE file exists in the repo (verified 2026-04-04). The `License: Proprietary` value is used as a placeholder. The planner should flag this — if the repo gets a LICENSE file before Phase 48, update to `License: MIT` or appropriate SPDX identifier and add `LicenseUrl`.

### Anti-Patterns to Avoid

- **Using GITHUB_TOKEN to push to another repo:** `GITHUB_TOKEN` is scoped to the current repo only. Cross-repo push always requires a PAT.
- **Fine-grained PAT for cross-repo workflow dispatch or winget-releaser:** Fine-grained PATs are not supported; must use classic PAT with `repo` scope.
- **Downloading DMG immediately after release publication:** The CDN propagation and notarization can take minutes. Always retry the checksums.txt download.
- **Using `brew bump-cask-pr` in CI for an owner-operated tap:** `bump-cask-pr` creates a PR which requires review; direct push is correct for a tap you own.
- **Putting cask file in repo root:** Homebrew searches `Casks/` subdirectory first; always use `Casks/agenthub.rb`.
- **Using `on: push: tags:` for distribute.yml:** Tag push fires before artifacts are uploaded to the Release. Use `on: release: types: [published]` which fires after `release.yml` has completed and attached assets.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Retry with backoff | Custom sleep loop in bash | `nick-fields/retry@v3` | Handles exit codes, timeout, configurable wait, tested across thousands of workflows |
| WinGet manifest validation | Manual YAML linting | `wingetcreate validate` or CI in winget-pkgs PR | The microsoft/winget-pkgs CI runs schema validation automatically on PR |
| Cross-platform SHA256 | `sha256sum` (Linux) vs `shasum -a 256` (macOS) | Extract from existing `checksums.txt` (already computed by Phase 46) | checksums.txt is already attached to the Release; no re-computation needed |
| Formula version parsing | Custom regex on release tag | `GITHUB_REF_NAME` env var | GitHub provides the tag name directly; strip `v` prefix with `${GITHUB_REF_NAME#v}` |

**Key insight:** Phase 46 already generates `checksums.txt` with SHA256 for all artifacts. The distribute.yml should parse this file rather than re-downloading and hashing the DMG itself. This is faster, avoids downloading a 50MB+ binary, and is more reliable.

## Common Pitfalls

### Pitfall 1: `on: push: tags:` vs `on: release: published`
**What goes wrong:** `distribute.yml` triggers before release.yml has finished uploading artifacts. `checksums.txt` download fails with 404.
**Why it happens:** Tag push and release publication are separate GitHub events. A tag push fires before `softprops/action-gh-release` has run.
**How to avoid:** Use `on: release: types: [published]`. The release is "published" only after all assets are attached (Phase 46's publish job completes before the release is marked published by `action-gh-release`).
**Warning signs:** 404 on checksums.txt download despite release existing.

### Pitfall 2: Notarization delay causes SHA256 mismatch window
**What goes wrong:** checksums.txt lists the DMG SHA256, but the CDN serves a different (pre-staple) binary during the propagation window.
**Why it happens:** Apple's notarization staples a ticket into the binary, changing its hash. If a user downloads immediately after the Release is published but before CDN sync, they may get the unstapled binary — but this is rare and outside our control. The real risk in CI is when the distribute workflow itself tries to verify the download.
**How to avoid:** Don't re-download the DMG to verify SHA256. Trust the checksums.txt that Phase 46 generated (which hashes the final stapled DMG).
**Warning signs:** `brew install` reports SHA256 mismatch on first install attempt.

### Pitfall 3: sed pattern failure on version strings with dots
**What goes wrong:** `sed -i "s/version \"1.8.0\"/version \"1.9.0\"/"` fails silently because `.` matches any character in regex.
**Why it happens:** Dots in version strings are regex metacharacters.
**How to avoid:** Use a sed pattern that matches the entire quoted string value, not the literal version: `sed -i "s/version \"[^\"]*\"/version \"${VERSION}\"/"`. The `[^"]*` match is safe regardless of dots.
**Warning signs:** Formula file unchanged after distribute.yml run.

### Pitfall 4: checksums.txt filename format mismatch
**What goes wrong:** `grep "agenthub-${GITHUB_REF_NAME}-darwin-universal.dmg" checksums.txt` returns empty.
**Why it happens:** Phase 46 uses `sha256sum *` which includes the filename exactly as-is. If the grep pattern doesn't match the exact filename (e.g., missing path prefix, different tag format), extraction fails.
**How to avoid:** Double-check Phase 46's checksums.txt format. The `sha256sum` output format is `<hash>  <filename>` (two spaces). The filename has no path prefix. The DMG is named `agenthub-v1.8.0-darwin-universal.dmg` (tag includes `v`). Use `awk '{ print $1 }'` (not `cut`) to handle variable spacing.
**Warning signs:** Empty SHA256 in distribute.yml output; formula updated with empty sha256.

### Pitfall 5: WinGet InstallerType for NSIS vs generic exe
**What goes wrong:** Setting `InstallerType: exe` for an NSIS installer causes WinGet CI to warn about missing silent install switches.
**Why it happens:** WinGet has specific installer types: `exe`, `nullsoft` (NSIS), `inno`, etc. `nullsoft` enables automatic `/S` inference.
**How to avoid:** Use `InstallerType: nullsoft` since Phase 46 produces an NSIS installer (`build-platform: windows/amd64` + `nsis: true` in wails-build-action).
**Warning signs:** WinGet PR CI fails with "silent install not verifiable."

### Pitfall 6: `brew tap scottkw/agenthub` requires repo named `homebrew-agenthub`
**What goes wrong:** If the tap repo is named `agenthub` or `agenthub-tap`, the short `brew tap scottkw/agenthub` command will fail with "No available formula or cask".
**Why it happens:** Homebrew's short tap syntax strips the `homebrew-` prefix — it requires the prefix to be present.
**How to avoid:** Create the GitHub repo as `scottkw/homebrew-agenthub` (not `scottkw/agenthub-tap` or `scottkw/agenthub`).
**Warning signs:** `brew tap` fails with repository not found.
