<objective>
Build the core inject machinery: the hub-level `HandleInject` (gate → sanitize → WriteInput →
persist → broadcast), the relay read-pump `case MsgSessionInject:`, the `engine.go` callback
wiring that breaks the relay→daemon import cycle, and the relay-path integration tests covering
MENTION-02, MENTION-03, and SEC-01 (relay path).

Purpose: This is the dangerous PTY-write path. `Hub.WriteInput` writes directly to PTY stdin, so
the RW-cap gate (SEC-01) and the dedicated-frame guard (D-02) are load-bearing. The gate lives
server-side in the hub, not in any UI.
Output: New methods/field/sentinel in `internal/relay/hub.go`; new read-pump case in
`internal/relay/server.go`; callback wiring in `internal/daemon/engine.go`; new
`internal/relay/server_inject_test.go`.

UI scope note: There is NO chat composer, trigger affordance, or press-and-hold gesture in this
phase — those are Phase 154 (D-01). At THIS layer the "deliberate confirm" guarantee (MENTION-03)
is the dedicated inject verb itself (D-02): only MsgSessionInject reaches the PTY, so a stray
keypress or normal chat-send is structurally incapable of writing. The ROADMAP "chat thread shows
→ injected into terminal indicator" criterion is satisfied here by PERSISTING and BROADCASTING the
SessionInject:true message; the visual RENDERING is Phase 154. The executor and verifier must NOT
chase non-existent UI.
</objective>
