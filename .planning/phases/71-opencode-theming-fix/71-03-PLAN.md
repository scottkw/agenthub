Create a new file `internal/daemon/opencode_ansi_test.go` with an integration test.

The test should:

1. **Skip conditions:** Skip if opencode is not installed (`exec.LookPath("opencode")` fails) or if running in CI (`os.Getenv("CI") != ""`). Use `-short` flag to skip: `if testing.Short() { t.Skip("skipping integration test in short mode") }`.

2. **Setup managed tui.json:** Call `ensureOpenCodeTUIConfig(t.TempDir())` to get a path to a managed tui.json with system theme.

3. **Spawn opencode in a PTY-like context:** Use `exec.CommandContext` with a 10-second timeout to run opencode with the env var. The command should be:
   ```go
   ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
   defer cancel()
   
   tuiConfigPath := ensureOpenCodeTUIConfig(t.TempDir())
   cmd := exec.CommandContext(ctx, "opencode", "--help")
   cmd.Env = append(os.Environ(),
       "OPENCODE_TUI_CONFIG="+tuiConfigPath,
       "TERM=xterm-256color",
       "COLORTERM=truecolor",
       "NO_COLOR=",  // ensure color output is not suppressed
   )
   ```

   Note: `--help` may not produce colored output. If opencode has a `--version` flag or if `--help` does produce ANSI output, use that. An alternative approach: run `opencode` without arguments but with a very short timeout, capturing whatever startup output it produces (banner, UI chrome). Use `cmd.CombinedOutput()` and accept that the process may be killed by timeout — that is fine, we just need the initial output.

   **Best approach:** Run opencode without arguments, capture stdout+stderr for up to 5 seconds, then kill. OpenCode's TUI startup renders colored UI elements that will contain the escape sequences we want to verify.

   ```go
   cmd := exec.CommandContext(ctx, "opencode")
   cmd.Env = append(os.Environ(),
       "OPENCODE_TUI_CONFIG="+tuiConfigPath,
       "TERM=xterm-256color",
       "COLORTERM=truecolor",
   )
   
   var buf bytes.Buffer
   cmd.Stdout = &buf
   cmd.Stderr = &buf
   
   // Start and let it run briefly, then the context timeout kills it.
   _ = cmd.Run() // Will likely exit non-zero due to timeout — that's fine.
   output := buf.Bytes()
   ```

4. **Analyze escape sequences in output:**
   ```go
   outputStr := string(output)
   
   // Count 24-bit RGB sequences: \033[38;2;R;G;Bm or \033[48;2;R;G;Bm
   rgb24Regex := regexp.MustCompile(`\x1b\[(?:38|48);2;\d+;\d+;\d+m`)
   rgbMatches := rgb24Regex.FindAllString(outputStr, -1)
   
   // Count ANSI palette sequences: \033[30-37m, \033[90-97m (foreground)
   // and \033[40-47m, \033[100-107m (background)
   ansiPaletteRegex := regexp.MustCompile(`\x1b\[(?:3[0-7]|4[0-7]|9[0-7]|10[0-7])m`)
   ansiMatches := ansiPaletteRegex.FindAllString(outputStr, -1)
   
   t.Logf("Output length: %d bytes", len(output))
   t.Logf("24-bit RGB sequences found: %d", len(rgbMatches))
   t.Logf("ANSI palette sequences found: %d", len(ansiMatches))
   if len(rgbMatches) > 0 {
       t.Logf("First 5 RGB sequences: %v", rgbMatches[:min(5, len(rgbMatches))])
   }
   if len(ansiMatches) > 0 {
       t.Logf("First 5 ANSI sequences: %v", ansiMatches[:min(5, len(ansiMatches))])
   }
   ```

5. **Assertions:**
   ```go
   // If we captured meaningful output, verify ANSI palette is dominant
   if len(output) < 50 {
       t.Skip("insufficient output captured from opencode — may need TTY allocation")
   }
   
   // Primary assertion: system theme should NOT produce 24-bit RGB
   // Allow a small number (e.g. from 3rd-party libs) but palette should dominate
   if len(rgbMatches) > 0 && len(ansiMatches) == 0 {
       t.Errorf("system theme produced %d 24-bit RGB sequences but 0 ANSI palette sequences — assumption A1 violated", len(rgbMatches))
   }
   
   // Informational: log the ratio for debugging
   if len(ansiMatches)+len(rgbMatches) > 0 {
       ratio := float64(len(ansiMatches)) / float64(len(ansiMatches)+len(rgbMatches)) * 100
       t.Logf("ANSI palette ratio: %.1f%% (%d palette / %d total color sequences)",
           ratio, len(ansiMatches), len(ansiMatches)+len(rgbMatches))
   }
   ```

6. **Fallback for insufficient output:** If opencode does not produce output to stdout/stderr (because it is a TUI that writes to the terminal directly), the test should note this and skip gracefully. TUI apps typically write to `/dev/tty` not stdout, so capturing may not work without a real PTY. In that case, add a note that this test works best when run with a real PTY allocator (e.g., `script` command or `go-pty`).

   If stdout capture is insufficient, try using `go-pty` (already a project dependency) to allocate a real PTY:
   ```go
   import gopty "github.com/aymanbagabas/go-pty"
   
   p, err := gopty.New()
   if err != nil {
       t.Fatalf("open pty: %v", err)
   }
   defer p.Close()
   
   cmd := p.CommandContext(ctx, "opencode")
   cmd.Env = append(os.Environ(), "OPENCODE_TUI_CONFIG="+tuiConfigPath, "TERM=xterm-256color", "COLORTERM=truecolor")
   if err := cmd.Start(); err != nil {
       t.Fatalf("start opencode: %v", err)
   }
   
   // Read PTY output for up to 5 seconds
   var buf bytes.Buffer
   done := make(chan struct{})
   go func() {
       io.Copy(&buf, p)
       close(done)
   }()
   
   select {
   case <-done:
   case <-time.After(5 * time.Second):
   }
   cancel() // kill the process
   cmd.Wait()
   ```
   This approach should capture TUI output since it goes through the PTY.

Use the `go-pty` approach as the primary method since opencode is a TUI app.
