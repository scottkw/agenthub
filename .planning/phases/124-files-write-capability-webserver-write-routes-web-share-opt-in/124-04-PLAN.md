<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GUI toggle → Wails binding → daemon engine | Owner intent to enable per-session write; only the local owner reaches this binding |
| viewer opt-in → issued cap | Deciding whether a shared cap carries files.write — must default OFF and require explicit confirm |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-124-14 | Elevation of Privilege | viewer opt-in defaulting ON | mitigate | "Allow file editing" defaults OFF; the write-bearing cap is minted ONLY after explicit confirm; toggling OFF reverts the Full Access Link to non-write on next issuance. |
| T-124-15 | Elevation of Privilege | viewer write granted without owner enabling write | mitigate | Surface 2 is disabled (aria-disabled, opacity 0.6) until Surface 1 (owner toggle) is ON; a session whose owner has not enabled writes cannot grant write to a viewer. |
| T-124-16 | Information Disclosure (UX safety) | colorblind user cannot see the home-dir warning | mitigate | Banner carries the `⚠` glyph + literal "Warning:" text token (not amber color alone); verified at source level per the colorblind rule. |
| T-124-SC | Tampering | npm/pnpm installs | mitigate | This plan adds ZERO packages (@heroicons/react and React already vendored). No install task → no legitimacy checkpoint needed. |
</threat_model>
