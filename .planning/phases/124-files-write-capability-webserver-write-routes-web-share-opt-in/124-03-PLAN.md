<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| daemon proxy → tailnet peer webserver | The proxy is a byte pipe to a remote machine; it must not smuggle a caller-chosen cap and must not leak the store cap into errors |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-124-10 | Spoofing | caller smuggling a different `?cap=` through the write proxy | mitigate | KEEP the existing caller-cap strip + force-set `?cap=` from the remoteCaps store (remote_files.go:154-165); applies identically to write verbs. |
| T-124-11 | Information Disclosure | cap token leaking in proxy error strings | mitigate | KEEP `redactCapTokenFromError` on all error paths when adding the body branch. |
| T-124-12 | Tampering | forwarding a body on GET/HEAD or dropping it on write | mitigate | Forward `r.Body` ONLY for PUT/POST/PATCH; leave nil for GET/HEAD. Forward inbound Content-Type only on write verbs so multipart boundary + application/json survive. |
| T-124-13 | Tampering | remote SSRF via attacker-controlled upstream URL | accept | `baseURL` comes from the operator-deposited remoteCaps store (not caller input); `op` is a fixed route-handler constant. No caller-controlled host. |
</threat_model>
