# Phase 124 — UI Design Contract

> Visual and interaction contract for the `files.write` opt-in surface: a web-share grant "Enable file writes" toggle (default OFF), a per-session owner write toggle, and a colorblind-safe home-directory write warning that must appear in BOTH the desktop GUI and the TUI.
>
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** This phase ships the *capability opt-in controls and the home-dir warning only*. The CodeMirror editor, file-action buttons (create/delete/rename/upload), and TUI `$EDITOR` shell-out are Phases 125/126 — out of scope here. Mirror the existing design language; introduce zero new color hexes and zero new CSS files.

### Colorblind safety (RELEASE-BLOCKING — user is colorblind)

Every warning and every ON/OFF state MUST carry a non-color signal:

- **Home-dir warning (GUI):** amber left-border + `⚠` WARNING SIGN glyph + the word "Warning:" in the text. The glyph + text label carry the meaning; the amber border is decoration only.
- **Home-dir warning (TUI):** `⚠` glyph prefix + literal `Warning:` text token, rendered in `StatusWaiting`. A reader who cannot distinguish amber from muted still reads the glyph and the word.
- **Toggle ON/OFF (GUI):** thumb position (left=OFF, right=ON via `translateX(16px)`) is the primary signal — position, not color. Add an `aria-checked` attribute and a visible textual state is NOT required (position suffices and matches existing Settings toggles), but the toggle MUST expose `role="switch"` + `aria-checked` for assistive tech.
- **Toggle ON/OFF (TUI):** render an explicit text token — `[writes ON]` / `[writes OFF]` — never a bare colored dot alone. If a dot is used (`●`), it must be paired with the ON/OFF word.
- **Verification:** UAT must confirm warning/state at the source level (glyph + text tokens in code), not by eye — per the colorblind verification rule.

All copy below is VERBATIM — do not paraphrase. Locked by CAP-05 and CAP-06.

| Element | Copy |

## Component & Interaction Contract

### GUI Surface 1 — Owner per-session "Enable file writes" toggle (CAP-04)

- **Placement:** Inside the session controls where web-share is toggled today (the `DaemonManagerPanel` session row that hosts `SessionSharePanel`). Render the toggle in the same column as the existing web-share enable control, directly above the `SessionSharePanel` for that session.
- **Markup:** Reuse `settings-panel__toggle-row` / `__toggle-track` / `__toggle-thumb` / `__toggle-input` verbatim. Add `role="switch"` + `aria-checked={filesWrite}` to the input. Label text: `Enable file writes`.
- **States:**
  - OFF (default): thumb left, track `#16161e`/border `#292e42`. This is the initial state for every session (migration default `FilesWrite: false`).
  - ON: thumb right (`translateX(16px)`), track + border `#7aa2f7`, thumb `#1a1b26`.
  - Saving: `pointer-events: none; opacity: 0.6` (reuse existing `toggleSaving` pattern).
  - Error: show `Couldn't save the write setting. Try again.` in `settings-panel__error` styling below the row.
- **Effect:** Toggling ON causes the owner cap token to include `files.write`; toggling OFF strips it. The Full Access Link in `SessionSharePanel` only carries `files.write` while this is ON.
- **Gating:** The web-share write opt-in (Surface 2) is DISABLED (greyed, `opacity: 0.6`, `aria-disabled`) until this owner toggle is ON. A session whose owner has not enabled writes cannot grant write to a viewer.

### GUI Surface 2 — Web-share "Allow file editing" opt-in (CAP-05)

- **Placement:** Inside `SessionSharePanel`, as a new `session-share-panel__write-optin` row rendered above the existing `Full Access Link` row.
- **Markup:** Reuse the `settings-panel__toggle-row` toggle. Label: `Allow file editing`. Default OFF.
- **Interaction:** Toggling ON opens an inline confirmation (reuse existing inline confirmation styling; no new modal component) showing the verbatim CAP-05 body. Confirm → the issued viewer/join-code cap includes `files.write`. Cancel → toggle reverts to OFF.
- **Default-OFF guarantee:** The write-enabled token is minted ONLY after explicit confirm. The QR / join-code (`joinURLFor`) for the write link is regenerated to encode the write-enabled grant; the read-only link is unaffected. Toggling OFF reverts the Full Access Link to read-only on next issuance.
- **Disabled precondition:** Disabled unless Surface 1 (owner toggle) is ON.

### GUI Surface 3 — Home-directory write warning (CAP-06)

- **Trigger:** When the owner toggle (Surface 1) transitions to ON for a session whose resolved cwd is `$HOME` (or a sensitive ancestor as determined server-side). The GUI receives a `homeDir: true` signal from the daemon for that session.
- **Placement:** Render in the existing `banner-stack` (Phase 81 vocabulary) OR inline directly beneath the toggle row — prefer inline beneath the toggle so the warning is co-located with the action that triggered it.
- **Markup:** Reuse `webgl-recovery-banner` structure with a NEW BEM modifier `--home-write-warning` that sets `border-left: 3px solid #f59e0b` (warning amber, matching `local-network-banner`, NOT destructive red). Prefix the message with a `⚠` icon span (`local-network-banner__icon` color `#f59e0b`).
  - Line 1 (emphasis 13px/600): `Warning: writes can affect your home directory`
  - Line 2 (body 13px/400, 1.5): the verbatim CAP-06 body copy.
- **Dismiss:** Reuse `webgl-recovery-banner__dismiss` (`XMarkIcon`, 16px). Dismissal is per-session-per-enable; re-enabling re-shows it.
- **Persistence:** Warning is NOT auto-dismissed on a timer (it is a standing caution, unlike `PluginToggleBanner`). It stays until dismissed or until writes are disabled.

### TUI Surface 4 — Home-directory write warning (CAP-06, cross-surface parity, RELEASE-BLOCKING)

- **Trigger:** Same condition — `files.write` active for a `$HOME`-cwd session. The TUI already knows web-share/cap state per session.
- **Placement:** A dedicated warning line rendered above `renderFilesStatusLine` in `renderFilesTab` (a new line between the body panes and the status line), OR appended into the Files tab header for the affected session. Prefer a line directly above the status line so it sits with the file view it concerns.
- **Rendering:** `lipgloss.NewStyle().Foreground(m.styles.StatusWaiting)`, width-clamped via the existing `truncate` helper. Content (verbatim):
  `⚠ Warning: cwd is $HOME — writes can affect dotfiles, SSH keys, and shell config. Protected files are blocked.`
- **Colorblind requirement:** the `⚠` glyph and the literal word `Warning:` carry the signal; `StatusWaiting` amber is reinforcement only. Do NOT rely on the amber alone.
- **Parity contract:** This line MUST be present whenever the GUI banner would show, for the same session/cwd condition. A parity-gap UAT (GUI banner shown ⇔ TUI line shown) is release-blocking.

### TUI Surface 5 — Write-enabled state indicator (optional, parity nicety)

- If the Files view shows a per-session web/share indicator, append a text token `[writes ON]` / `[writes OFF]` (never a bare dot) so the write-capability state is legible without color. Use `WebOn`/`WebOff` tokens for the dot if a dot is paired with the word.
