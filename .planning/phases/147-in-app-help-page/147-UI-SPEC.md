## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage in Help page |
|-------|-------|-------------------|
| xs | 4px | Icon gaps, inline badge padding, `sidebar__group-item__count` margin |
| sm | 8px | Item padding, gap between search input and section nav |
| md | 16px | Default content element spacing, section nav link padding, search margin-bottom |
| lg | 24px | Section heading margin-top, help body padding sides |
| xl | 32px | Between major doc sections |
| 2xl | 48px | Top/bottom padding for the help page container |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Search input sticky bar: `padding: 8px 0` (nearest multiple of 4 to the `.settings-jump-bar` precedent; 10px was non-compliant and is corrected here)
- Section headings `scroll-margin-top: 80px` (clears sticky search bar, mirrors Settings precedent; 80 = 20×4)
- Sidebar item hit targets: `padding: 8px 0` (13px text, 20px icon — existing pattern)

## Typography

All type must use `font-family: var(--hub-font-ui)` (Plus Jakarta Sans). Monospace content (keyboard shortcuts, code snippets) uses `font-family: var(--hub-font-mono)` (JetBrains Mono).

| Role | Size | Weight | Line Height | Token |
|------|------|--------|-------------|-------|
| Body / FAQ answer | 14px | 400 | 1.5 | `--hub-font-size-base: 14px` |
| Small label / secondary text | 12.5px | 400 | 1.5 | `--hub-font-size-sm: 12.5px` |
| Section heading (h2) | 19px | 600 | 1.2 | `--hub-font-size-heading: 19px` + `--hub-font-weight-emphasis: 600` |
| Sub-heading (h3) | 14px | 600 | 1.2 | base size, emphasis weight (matches Settings h3 pattern) |

Code / keyboard inline: 12.5px, `font-family: var(--hub-font-mono)`, rendered inside a `<code>` or `.help__kbd` span with background `var(--hub-surface)` and border `var(--hub-border)`. Mirrors `.settings-panel__code` pattern.

Heading hierarchy contract:
- `h1`: page-level title "Help" — 19px / weight 600 (one per page)
- `h2`: top-level sections (Getting Started, FAQ, …) — 19px / weight 600
- `h3`: sub-sections within each — 14px / weight 600, uppercase + letter-spacing 0.08em (matches `.settings-panel__body h3` pattern)

## Color

All color values are referenced via `--hub-*` CSS tokens — no hardcoded hex in new `.help-*` CSS classes. Both themes (dark default, `[data-ui-theme="light"]` override) are satisfied by the token system automatically.

| Role | Dark Token → Hex | Light Token → Hex | Usage |
|------|-----------------|------------------|-------|
| Dominant surface (60%) | `--hub-bg` → `#14151b` | `#f5f5f7` | Help page background, body fill |
| Secondary surface (30%) | `--hub-surface` → `#16181f` | `#ffffff` | Left section-nav panel, sticky search bar |
| Section nav active bg | `--hub-sidebar-item-active-bg` → `rgba(122,162,247,0.12)` | `rgba(61,111,232,0.10)` | Active section link |
| Elevated surface | `--hub-surface-elevated` → `#1c1e28` | `#ececf0` | Search input background, code blocks |
| Accent (10%) | `--hub-accent` → `#7aa2f7` (dark) / `#3d6fe8` (light) | same | Section nav active text, search focus ring, external link text, `<mark>` highlight border, jump anchor links |
| Text primary | `--hub-text-primary` → `#f4f5f8` | `#1a1b26` | Headings, FAQ question text |
| Text secondary | `--hub-text-secondary` → `#c7cad6` | `#3a3b50` | Body paragraphs, FAQ answer text |
| Text muted | `--hub-text-muted` → `#9398a8` | `#5c5d80` | Section nav inactive text, metadata, keyboard shortcut labels |
| Text dim | `--hub-text-dim` → `#6e7180` | `#9999b0` | Hint text, "last updated" annotations |
| Border | `--hub-border` → `#41454f` | `#d1d1db` | Section nav separator, search input border, code block border |
| Destructive | `--hub-destructive` → `#f7768e` (dark) / `#c0394f` (light) | same | Not used in this phase (no destructive actions) |
| Search highlight bg | `--hub-search-highlight-bg` → `rgba(122,162,247,0.25)` (dark) / `rgba(61,111,232,0.20)` (light) | Token declared in `:root` and `[data-ui-theme="light"]` | `<mark>` element background for matched search terms; text color remains `var(--hub-text-primary)` |

**Token declaration (add to style.css alongside other `--hub-*` tokens):**
```css
:root {
  --hub-search-highlight-bg: rgba(122, 162, 247, 0.25);
}
[data-ui-theme="light"] {
  --hub-search-highlight-bg: rgba(61, 111, 232, 0.20);
}
```
All `.help-*` CSS classes reference `var(--hub-search-highlight-bg)` — no inline rgba values.

**Accent reserved for:**
- Active section nav link text color
- Search input focus border (`border-color: var(--hub-accent)`)
- External link text color (GitHub, website)
- Search term `<mark>` highlight border
- Jump-anchor links in the top bar (mirrors `.settings-jump-bar__link` pattern)

**Colorblind-safe requirements (D-11, inherited from v4.0 norm):**
- Active section nav item: use `aria-current="true"` + visual highlight (bg + text color change) — not color alone
- External links: carry `aria-label` indicating they open externally; also use an external-link icon (Heroicons `ArrowTopRightOnSquareIcon`) — not color alone
- Search highlight: `<mark>` uses `var(--hub-search-highlight-bg)` background + the token accent color for the border; shape/contrast carries meaning, not color alone

**prefers-reduced-motion:** All hover/transition animations on `.help-*` classes must be gated with `@media (prefers-reduced-motion: no-preference)` / `@media (prefers-reduced-motion: reduce)` pairs, matching the existing pattern in `style.css`.

## Layout Contract

**Source:** CONTEXT.md D-10 (locked decision)

```
┌─────────────────────────────────────────────────────────────┐
│  [Search input — pinned sticky at top, full width]          │
├──────────────────┬──────────────────────────────────────────┤
│  Left nav        │  Right content pane                      │
│  (section list)  │  (rendered Markdown, anchor-scrolled)    │
│  ~200px fixed    │  flex: 1, overflow-y: auto               │
│                  │                                          │
│  • Getting Started  h1 Section Title                        │
│  • FAQ           │  Body content…                           │
│  • Keyboard      │                                          │
│    Shortcuts*    │  h2 Sub-section                          │
│  • External Links│  Body content…                           │
│                  │                                          │
└──────────────────┴──────────────────────────────────────────┘
```

- Search bar: `position: sticky; top: 0; z-index: 5` — matches `.settings-jump-bar` precedent
- Left nav width: 200px, `flex-shrink: 0` — matches existing `.sidebar` width
- Content pane: `flex: 1; overflow-y: auto; padding: 24px`
- The whole Help tab fills the same content area as other special tabs (`__settings__`, `__hub__`)

**Tab / Routing model (D-02):** Help opens as a special tab with `id: '__help__'` following the `__settings__` pattern in `App.tsx`. The Sidebar gets a 4th item: `QuestionMarkCircleIcon` + label "Help" (D-01).

**Sidebar placement:** Help goes in `sidebar__bottom` alongside Settings — both are utility items, not workspace items. Order in the bottom section: Settings above Help (Settings is accessed more often).

## Component Inventory

New components to build for this phase (all in `frontend/src/components/`):

| Component | Role | Precedent |
|-----------|------|-----------|
| `HelpTab.tsx` | Top-level help page container; owns search state + section routing | `SettingsTab.tsx` |
| `HelpSearch.tsx` | Debounced search input + result list with snippet/highlight display | `SettingsSearch.tsx` (structure only — body-level indexing is new) |
| `HelpSectionNav.tsx` | Left sticky section-nav with anchor links | `SettingsJumpBar.tsx` |
| `HelpContent.tsx` | Renders Markdown content with `<mark>` highlighted spans | new |

**Markdown rendering (Claude's Discretion):** Use a runtime renderer. `react-markdown` with `rehype-sanitize` is the recommended approach — it is XSS-safe and supports injecting `<mark>` spans via a custom rehype plugin that wraps matched terms. Do not use `dangerouslySetInnerHTML` without sanitization.

**Bundled content location:** `frontend/src/content/help/` — Markdown files importable via Vite's `?raw` import or bundled as static strings. Must work offline (no network fetch).

## Interaction Contract

### Search behavior (D-07, D-08, D-09)

- Debounce: 200ms after last keystroke before filtering
- Index scope: full body text of both Documentation and FAQ sections (not section titles only)
- Snippet format: ~1–2 lines of surrounding context with matched term wrapped in `<mark>`
- Jump-to-section: each snippet result includes a "Go to section →" affordance that scrolls the content pane and updates the section nav active state
- Empty state: shown when query is non-empty AND results are zero. Do NOT show empty state for an empty query (show full content instead)
- Clear: clicking × in the search input (or pressing Escape) clears the query and restores full content view; the clear button (`aria-label="Clear search"`) is an icon-only `<button>`

### Section nav behavior (D-10)

- Clicking a section nav item scrolls the content pane to the corresponding anchor
- Active section updates on scroll via IntersectionObserver (mirrors `SettingsJumpBar` scroll behavior)
- Keyboard: Tab navigates between section nav items; Enter / Space activates
- `aria-current="true"` on the active nav item

### External links (D-13)

- Call `BrowserOpenURL` from `wailsjs/runtime/runtime` — identical pattern to `SettingsTab.tsx:609`
- Render as `<button>` elements (not `<a href>`) to avoid in-app webview navigation
- Each carries an `aria-label` indicating external destination + "(opens in browser)"
- Display an `ArrowTopRightOnSquareIcon` (Heroicons outline, 16px) alongside the label text

### Keyboard accessibility (D-12)

- Search input: visible `<label>` + associated `id`; focus style uses `outline: 2px solid var(--hub-accent); outline-offset: 2px`
- Search clear button: `aria-label="Clear search"` — no visible text, icon only
- Section nav: keyboard navigable; `aria-current="true"` on active item
- Content headings: correct h1 → h2 → h3 hierarchy (no skips)
- `scroll-margin-top: 80px` on all anchor targets to clear the sticky search bar
- `scroll-behavior: smooth` on the content pane (matches `.settings-panel__body` pattern)

## CSS Naming Convention

All new CSS classes follow the project's BEM-style convention with `.help-` prefix:

```
.help-tab          — top-level container (mirrors .settings-tab)
.help-tab__search  — sticky search wrapper
.help-tab__layout  — flex row containing nav + content
.help-tab__nav     — left section nav panel
.help-tab__content — right scrollable content pane
.help-nav__list    — <ul> of section items
.help-nav__item    — <li>
.help-nav__link    — <button> inside item (keyboard accessible)
.help-nav__link--active — active state modifier
.help-search__input     — the text input
.help-search__clear     — × clear button (aria-label="Clear search")
.help-search__results   — results list
.help-search__result    — single result item (snippet + jump link)
.help-search__mark      — matched term highlight (use <mark> element)
.help-search__empty     — no-results state
.help-content__section  — each doc/faq section
.help-content__external-link — external link button
```

All classes use only `var(--hub-*)` tokens — no hardcoded hex values, no inline rgba values. The `<mark>` background uses `var(--hub-search-highlight-bg)`.
