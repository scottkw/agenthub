## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App state (remoteCapsCached) → React props → DOM | Connection state crosses into presentational components as a boolean only |
| remote peer data → card rendering | hostname/url originate from untrusted peer metadata, rendered as text |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-138-02 | Information Disclosure | CARD-03 connection chip | mitigate | isConnected is derived solely from `remoteCapsCached.has(id)` (boolean); the cap token never enters React state or the DOM (token stays in daemon RemoteCapStore — T-122-03-01). The chip renders only "Connected"/"Available", never any token/URL. |
| T-138-03 | Spoofing | local/remote origin indicator | mitigate | isRemote is provenance-based (session arrived on remoteSessions prop), not hostname-derived, so a remote peer cannot spoof a "Local" badge by reporting the host's hostname (RESEARCH Pattern 1 / anti-pattern). |
| T-138-04 | Tampering (XSS via peer text) | hostname rendered in origin/chip | accept | hostname/url are rendered as React text children (auto-escaped), not via dangerouslySetInnerHTML; existing rendering path unchanged. |
| T-138-SC | Tampering | npm/pip/cargo installs | accept | No package installs — edits against existing @heroicons + vitest only. |
</threat_model>
