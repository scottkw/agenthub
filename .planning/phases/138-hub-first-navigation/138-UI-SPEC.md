**Accent reserved for:**
- Active sidebar item background tint (`--hub-sidebar-item-active-bg`)
- Focus-visible outlines on interactive card children
- "Connected" indicator chip border (CARD-03 — see Interaction Contracts below)
- HubFilterBar "New Session" button border/text (existing — sole creation entry point)

- Local/remote origin indicator (uses icon shape + text, no accent tint)

**Colorblind constraint (RELEASE-BLOCKING):** Every status, origin, and connection indicator MUST be distinguishable without color alone. Color is reinforcement only. Icon + text label is the primary signal for all indicators. See Accessibility section.

## Interaction Contracts

### NAV-02/03/04/05 — Sidebar collapse to Home / Hub / Settings

**Before:** 5+ items (Home, Hub, New Session, Sessions, Remote, Settings)
**After:** Exactly 3 items in this order: Home, Hub, Settings

- Home and Hub and Settings items remain visually identical to their current state.
- No re-ordering or icon changes — existing `.sidebar__item` class and icon set.
- The sidebar collapse/expand toggle and its width variables (`--hub-sidebar-width: 200px`, `--hub-sidebar-collapsed-width: 32px`) are unchanged.
- Removed items: Sessions (ServerStackIcon), Remote (GlobeAltIcon), and the New Session "+" item (PlusIcon).

### CARD-01 — Remove `.hub__header`

**Deleted element:** The `<div class="hub__header">` block at HubPanel.tsx:461-467, which contained:
- `<span class="hub__title">Hub</span>` — deleted
- `<button class="hub__new-session-btn">New session</button>` — deleted

**After:** The `HubFilterBar` "New Session" button (HubFilterBar.tsx:135-141) is the sole top-of-page session creation entry. Its appearance and position are unchanged.

**CSS cleanup:** Remove or comment out `.hub__header`, `.hub__title`, `.hub__new-session-btn` rules from style.css after the TSX block is deleted.

### CARD-02 — Local vs Remote origin indicator

**Current state (partially satisfied):** The card's ROW 2 already renders `ComputerDesktopIcon` + "Local" for local sessions, and `GlobeAltIcon` + `{hostname}` for remote sessions. The CSS `.hub-card__origin` and `.hub-card__origin-icon` already exist.

**Required change:** Switch the `isLocal` derivation from hostname-based (`!hostname || hostname === ''`) to provenance-based (explicit `isRemote` prop derived from whether the session ID is in the remote set). This is a correctness fix — the existing visual rendering is already colorblind-safe.

**Contract:**
- Local: `ComputerDesktopIcon` (24px outline) + span text "Local"
- Remote: `GlobeAltIcon` (24px outline) + span text `{hostname}` (peer name)
- Icon size: 16px × 16px (existing `.hub-card__origin-icon` rule)
- Color: `var(--hub-text-secondary)` — reinforcement only; icon shape is the primary signal

**New prop:** Add `isRemote?: boolean` to `SessionCardProps`. When `true`, the card uses remote rendering path. Derive this in HubPanel from `remoteIdSet.has(session.id)` (already computed at HubPanel:302).

### CARD-03 — Connected vs Available indicator (remote cards only)

**New element:** A connection-state chip rendered below ROW 2 (origin row) on remote cards only. When the user has exchanged a join code (`remoteCapsCached.has(sessionId)` is `true`), the chip reads "Connected"; otherwise it reads "Available".

**Colorblind-safe contract (RELEASE-BLOCKING):**
- Connected state: `LinkIcon` (16×16, 24/outline) + span text "Connected"
- Available state: `GlobeAltIcon` (16×16, 24/outline) + span text "Available"
- Color is reinforcement only: connected uses `var(--hub-accent)` border tint; available uses `var(--hub-text-muted)` — but NEITHER state is identifiable by color alone; the icon shape and text label are always present.

**Aria contract:** The card's `aria-label` (built at SessionCard:180) must be extended: append `, connected` or `, available` when `isRemote` is true.

**Placement:** Immediately after ROW 2 (origin row), before ROW 3 (uptime/viewers). Only rendered when `isRemote === true`.

**CSS:**
```
.hub-card__conn {
  display: inline-flex;
  align-items: center;
  gap: 4px;
  padding: 0 8px;
  height: 20px;
  border-radius: 10px;
  border: 1px solid currentColor;
  font-size: 12px;
  font-family: system-ui, -apple-system, "Segoe UI", sans-serif;
  color: var(--hub-text-muted);       /* default: available */
}
.hub-card__conn--connected {
  color: var(--hub-accent);           /* reinforcement: connected tint */
}
.hub-card__conn-icon {
  width: 12px;
  height: 12px;
  flex-shrink: 0;
}
```

**New prop:** Add `isConnected?: boolean` to `SessionCardProps`. Thread from `remoteCapsCached.has(session.id)` in HubPanel/SessionCardGrid.

### CARD-04 — Card resize to accommodate new affordances

**Constraint:** Card must fit within min-width 240px / max-width 360px (existing `.hub-card` rule at style.css:4296). Grid density and responsive reflow (`.hub__card-row { repeat(auto-fill, minmax(240px, 1fr)) }`) must be preserved.

**Layout after Phase 138 (all rows):**

```
ROW 1: [status-indicator] [SessionName] [CLI badge]     ← unchanged
ROW 2: [origin icon] [Local / hostname text]             ← provenance-fixed (no visual change)
ROW 2b: [connection chip] (remote cards only — NEW)      ← CARD-03
ROW 3: [uptime/duration] [viewer count]                  ← unchanged
ROW 4: [exit chip] (stopped sessions only)               ← unchanged
ROW 5: [Open button] (live sessions only)                ← unchanged
       [Kill button] (overflow menu — see below)
       [Open in browser button] (remote only, overflow)
       [Browse files button] (remote only, overflow)
ROW 5b: [Share button]                                   ← unchanged (Phase 137)
ROW 6: [MiniPreview]                                     ← unchanged
```

**Preserved behaviors (must not regress):**
- Attention pulse: `.hub-card--attention` + `@media (prefers-reduced-motion)` guard
- Float-to-top: `useFLIPAnimation` reads `getBoundingClientRect` — card resize must not change layout measurement timing
- Mini-preview: `<MiniPreview>` as last row; `usePreviewPoller` 3s interval unchanged
- Share button: `.hub-card__share` at Phase 137 position, guarded against card-click modal

### CARD-04 — Kill session affordance (overflow menu)

**Placement:** In the existing overflow menu (`hub-card__menu`, opened by `hub-card__menu-btn`). Appears as a new menu item below "Move to group" items.

**Menu structure after Phase 138:**
```
[Move to group: ...]    ← existing group items
[──────────────────]    ← hub-card__menu-divider (new)
[Kill session]          ← new destructive item
```

**Destructive affordance contract:**
- Item text: "Kill session"
- Item class: `hub-card__menu-item` (existing) + `hub-card__menu-item--destructive` (new modifier)
- Color: `var(--hub-destructive)` text — reinforcement; the word "Kill" is the primary signal
- Confirmation: inline two-step — on first click, the item label changes to "Confirm kill" with a secondary description "This will stop the session". A second click confirms. No modal — inline flip within the same menu item. This matches the low-friction pattern already used by the overflow menu.
- Guard: `e.stopPropagation()` to prevent card-click modal trigger; `if (target.closest('.hub-card__menu')) return` guard in article onClick (existing pattern at SessionCard:252).

**New prop:** Add `onKill?: (sessionId: string) => void` to `SessionCardProps`. Wired to `handleCloseTab` in App.tsx (existing at App.tsx:749).

### CARD-04 — Remote "Open in browser" affordance

**Placement:** Overflow menu on remote cards only. Appears below Kill session item.

**Contract:**
- Item text: "Open in browser"
- Icon: `ArrowTopRightOnSquareIcon` (or fallback: none — text is the primary signal)
- Only rendered when `isRemote === true`
- Action: calls `handleOpenRemoteSession(url)` → `BrowserOpenURL(url)` (existing in App.tsx:1062)
- Guard: `e.stopPropagation()` as per Kill pattern above

**New prop:** Add `onOpenInBrowser?: (url: string) => void` to `SessionCardProps`.

**Note:** This coexists with the Phase 134 card-click in-app modal. Both affordances are present. Card-click opens the in-app HubModal; "Open in browser" explicitly routes to the system browser.

### CARD-04 — Remote "Browse files" affordance

**Placement:** Overflow menu on remote cards only. Appears below "Open in browser".

**Contract:**
- Item text: "Browse files"
- Only rendered when `isRemote === true`
- Action: calls `handleBrowseFilesRemote` → opens `RemoteJoinCodeModal` (existing cap flow)
- Guard: `e.stopPropagation()` as per Kill pattern above

**New prop:** Add `onBrowseFiles?: () => void` to `SessionCardProps`.

### Overflow menu structure (remote card — complete)

```
[Move to group: ...]
[──────────────────]
[Open in browser]       ← remote only
[Browse files]          ← remote only
[──────────────────]    ← only if at least one remote action + Kill
[Kill session]          ← all cards with live sessions
```

For local cards, the divider and Kill item only appear; no Open in browser / Browse files.

### Per-peer "Unreachable / no shareable sessions" hint

**Decision (CONTEXT.md):** Migrate a lightweight status hint. Placement: NOT on individual cards (no cards exist for unreachable peers). Instead, surface as a filter-bar informational message or a collapsed group header state.

**Contract:** When `remotePeers` data includes a peer with `reachable: false` or zero shareable sessions, render a muted text line in the Hub body (below the filter bar, above the card grid) reading: "[peer name] is unreachable" or "[peer name] has no shared sessions". Style: `var(--hub-text-muted)`, 12px, no icon required — text is the full signal.

**Implementation note:** This is a minimum-viable hint, not a full peer-status component. One line per unreachable/empty peer, rendered only when such peers exist in the `remotePeers` data.

## Accessibility Contract

This section encodes the RELEASE-BLOCKING colorblind-safe requirement.

### Colorblind-safe indicator matrix

| Indicator | Icon (shape) | Text label | Color (reinforcement only) | aria-label contribution |
|-----------|-------------|------------|---------------------------|------------------------|
| Local origin | `ComputerDesktopIcon` | "Local" | `var(--hub-text-secondary)` | `, local` (already in aria-label via originText) |
| Remote origin | `GlobeAltIcon` | `{hostname}` | `var(--hub-text-secondary)` | `, {hostname}` |
| Connected (CARD-03) | `LinkIcon` | "Connected" | `var(--hub-accent)` border | `, connected` appended to card aria-label |
| Available (CARD-03) | `GlobeAltIcon` | "Available" | `var(--hub-text-muted)` border | `, available` appended to card aria-label |
| Running status | `ArrowPathIcon` (spinning) | "Running" | blue reinforcement dot | existing STATUS_CONFIG |
| Idle status | `CheckCircleIcon` | "Idle" | green reinforcement dot | existing STATUS_CONFIG |
| Waiting status | `PauseCircleIcon` | "Needs input" | amber reinforcement dot | existing STATUS_CONFIG |
| Error status | `ExclamationCircleIcon` | "Error" | red reinforcement dot | existing STATUS_CONFIG |
| Attention pulse | `BellAlertIcon` | — | amber border pulse | `, needs attention` (existing) |
| Share disabled (remote) | `LockClosedIcon` | tooltip text | opacity + color | existing Phase 137 |
| Kill (destructive) | none — text only | "Kill session" | `var(--hub-destructive)` text | menu item text is the signal |

**Rule:** Zero indicators in this phase may be identified by color alone. Every indicator carries at minimum one non-color cue (icon shape, text label, or position).

**Verification method:** Verify at source level — check hex constants in code and icon names in TSX. Do NOT verify by eye (owner is colorblind — MEMORY.md: `user_colorblind`).

### Focus management

- All new interactive card children (Kill, Open in browser, Browse files overflow items) must be keyboard-reachable within the overflow menu.
- Overflow menu already implements `role="menu"` / `role="menuitem"` — new items follow the same pattern.
- No new modal dialogs introduced in this phase (Kill uses inline two-step, not a dialog).
- Existing card aria-label construction at SessionCard:180 must be extended to append connection state for remote cards.

### Reduced-motion

- No new animations introduced. Connection indicator chip has no transition.
- Existing `@media (prefers-reduced-motion: reduce)` guards for attention pulse and hub modal are preserved.

## Claude's Discretion Areas

The following were not specified in upstream artifacts and are decided here:

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Kill confirmation UX | Inline two-step label flip within menu item (no modal) | Consistent with low-friction overflow menu pattern; avoids introducing a new modal type; menu already open means intent is clear |
