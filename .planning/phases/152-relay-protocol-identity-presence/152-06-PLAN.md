## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| web-share peer→webserver (Tailscale) | A tailnet peer (possibly RO-cap) connects over TLS; r.RemoteAddr feeds lc.WhoIs; alias/typing payloads are untrusted |
| WhoIs→identity | The Tailscale control plane cryptographically attests the peer's node identity |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-152-01 | Tampering | handleWSSRelay MsgAliasSet | high | mitigate | The web read-pump case calls relay.ValidateAlias before persisting/broadcasting — identical control-char/over-length rejection to the relay surface (Pitfall 3 closes the two-surface gap). |
| T-152-02 | Spoofing | alias vs TailnetID | medium | accept | Alias is a non-unique label (D-03); the authoritative identity is the WhoIs-derived TailnetID. Non-unique aliases are an accepted design property, not a defect. |
| T-152-04 | Spoofing/Info | WhoIs failure fallback | low | mitigate | On WhoIs error the path uses a non-"local" sentinel TailnetID, so a web client can never be silently merged into the owner's "local" entry; criterion 5 holds even without a live tailnet. |
| T-152-05 | Elevation of Privilege | RO-cap chat vs PTY | low | accept | D-06: MsgAliasSet/MsgTyping are not readonly-gated; only MsgInput remains gated on claims.Perms=="read". The web test asserts RO clients can chat while the existing readonly-input test still discards PTY input. |
| T-152-03 | Denial of Service | typing storm (web) | medium | mitigate | Inherits the Hub's per-personKey typing rate limit + non-blocking CloseSlow fan-out from Plan 03. |
| T-152-SC | Tampering | go module installs | low | accept | No packages added — uses existing tailscale.com/client/local (already in go.mod) and stdlib. |
