## Interaction Contract

This section documents the keyboard interaction model unique to Phase 10, which has no direct visual UI analogue.

### Keyboard Shortcuts

| Shortcut | Action | Applies When |
|----------|--------|--------------|
| SHIFT+= | Increase font size by 1px | Terminal is focused (xterm has keyboard focus) |
| SHIFT+- | Decrease font size by 1px | Terminal is focused (xterm has keyboard focus) |

**Key event contract:**
- Handler registered via `term.attachCustomKeyEventHandler` — NOT `window.addEventListener`
- Handler checks `ev.type === 'keydown'` first; returns `true` for all non-matching events
- For SHIFT+=: check `ev.shiftKey && ev.key === '='` (NOT `ev.key === '+'`)
- For SHIFT+-: check `ev.shiftKey && ev.key === '-'` (NOT `ev.key === '_'`)
- Handler returns `false` for both matched keys — this suppresses PTY injection
- Handler is called exactly once during terminal setup; not called again on prop changes

**Source:** RESEARCH.md Pattern 2, Pitfall 1, Pitfall 4, Pitfall 5.

### Font Size State Machine

| State | Value | Trigger |
|-------|-------|---------|
| Default | 14px | New tab created; no entry in `fontSizes` Record |
| Increased | current + 1px (max 32px) | SHIFT+= intercepted |
| Decreased | current - 1px (min 6px) | SHIFT+- intercepted |
| Restored | 14px | Tab closed and re-created (new sessionId) |

**State location:** `fontSizes: Record<string, number>` in `App.tsx` — mirrors `webEnabled`, `sessionURLs`, `sessionStatuses` patterns.

**Cleanup:** On tab close, remove `fontSizes[sessionId]` entry to prevent memory leak.

### Reflow Contract

After every font size change, `fitAddon.fit()` must be called immediately after `term.options.fontSize = newSize`. The two calls must be adjacent in the same synchronous execution path. This prevents garbled output (stale col/row counts).

**Source:** RESEARCH.md Pattern 3, Pitfall 2.

## Visual Continuity Constraints

These are pre-existing decisions that Phase 10 must not disturb:

3. Status bar height 32px — `flex-shrink: 0` — font size changes in the terminal panel must not affect the status bar dimensions.
4. Tab bar height 42px — same constraint.
5. `display: none` / `display: flex` toggle for inactive terminal-wrapper panels — Phase 10 state changes must not interfere with visibility logic.
