<objective>
Wire the daemon's `SessionInfo.FunnelWriteActive` boolean across the ONE load-bearing seam where it is currently dropped: the app.go Wails bridge (SessionInfo struct + ListSessions conversion). After this plan, the already-built, already-correct frontend consumers (Hub-card FULL ACCESS badge, session-tab write-exposure icon, share-modal teardown resync) receive a real `true`/`false` value on the existing 3s ListSessions poll and render.

The runtime mechanism (verified at source 2026-07-09, correcting audit §3 point 4): the app imports the `SessionInfo` TYPE from the hand-authored stub `frontend/src/wailsjs/go/main/App.d.ts` (`App.tsx:41`) — which ALREADY declares `funnelWriteActive: boolean` (Phase 171-02) — and gets the runtime value from `App.js`, whose `ListSessions = () => Call('main.App.ListSessions', [])` is a RAW passthrough with no `createFrom`/field-filtering. `grep` across `frontend/src` finds ZERO imports of the double-nested `wailsjs/wailsjs/go/models.ts` tree, so that file is dead for the runtime path. Therefore `funnelWriteActive` is present in each session object at runtime iff app.go serializes it — the app.go fix (D-01/D-02) is necessary AND sufficient.

Purpose: Phase 171 shipped the public read-write ("FULL ACCESS") Funnel flow end-to-end, but the persistent colorblind-safe exposure indicator is silently dead in the shipped native GUI because `funnelWriteActive` never crosses daemon -> app.go. This is a surgical cross-phase integration gap-closure (FNL-09), NOT a new feature. Mirror the working `funnelActive` (FNL-01) reference; change nothing else.

Output: The load-bearing app.go wiring (D-01, D-02) plus a verify-only App.d.ts confirmation and optional non-load-bearing models.ts hygiene (D-03, D-04).
</objective>
