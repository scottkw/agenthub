The existing `funnelBinding.contract.test.tsx` asserts the App.d.ts stub TEXT, not the real Go bridge — it certified this broken seam green (the same failure mode as tests encoding the same wrong assumption). This plan closes that blind spot with a genuine Go-side guard that fails if app.go drops a daemon funnel-exposure field, then records the new test in the TESTING.md Suite Manifest and Traceability map per the repo's standing convention.

Why the Go serialization guard is the load-bearing one (verified at source 2026-07-09): the runtime frontend path is `App.js`'s raw `Call('main.App.ListSessions', [])` passthrough — no `createFrom`/field filtering — so the session objects the consumers read are exactly app.go's serialized JSON. A guard asserting that a `SessionInfo{FunnelWriteActive:true}` serializes to `"funnelWriteActive":true` therefore protects the real runtime seam directly, unlike the stub-text contract test.

Purpose: The app.go change in Plan 01 is the runtime fix; this Go regression guard is what protects the seam long-term against a future edit silently dropping `funnelWriteActive` (or `funnelActive`) again.

Output: One new Go test function (D-05), optionally an extended assertion on the actually-imported `funnelBinding.contract.test.tsx` stub (D-05b), and the TESTING.md reconciliation (Suite Manifest note + FNL-09 traceability row).
