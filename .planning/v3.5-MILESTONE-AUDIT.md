## Live Two-Machine UAT (2026-06-15)

Executed the deferred RMW-06 UAT (this Mac as GUI client ↔ `kens-macbook-air-1574` as host, over a real tailnet). Driven via `wails dev` + the `dev-browser` CLI and direct relay-port probes.

**Data path — PROVEN live (the hard part works):**
- v3.4.2 host: `LIST`/`READ` `200`; `WRITE` `405` → mapped to the verbatim v3.4 version-gate copy (`filesApi.ts:118`). = the RMW-04 405 gate + reads-unaffected checks (runbook 53–55) **passed**.
- v3.5 host: `WRITE`/`MKDIR`/`RENAME`/`DELETE` all `200`, read-back confirmed, dir restored. = the core write matrix.

**But the desktop GUI remote *feature* was non-functional — 4 stacked breakages:**
1. **Relay routes not mounted** → every `/api/files/remote/{sid}/...` 404'd. **FIXED `58af6d6`** (+ regression tests on the relay surface). Proven live.
2. **Client `accept-dns=true` required** — else the daemon can't resolve the peer's MagicDNS name (opaque `502 no such host`; IP fallback fails TLS SNI). → **#83**.
3. **Discovery probe rejected cap-protected peers** — `probePeer` accepted only HTTP 200, but a shared peer's `/api/sessions` returns `401 capability required`. **FIXED `3508bd7`** (**#84**); daemon `/tailnet/peers` now lists the peer.
4. **Session listing blocked** — the Remote panel's `FetchAllPeerSessions` calls cap-less `/api/sessions`, but it's intentionally cap-gated (D-18, returns only the capped session) and peers with 0 listable sessions are dropped. Architectural conflict (enumerate-then-pick vs no-enumeration). **DEFERRED v3.5.1 → #86** (options a/b/c in the issue).

Also: **share-link scope relabel `e45ccba`** (#24 UX) — the Sessions-tab links now state that View-Only = session-only (no file access) and Full Access = full session control + file browsing.

**Process lesson:** the automated integration score (98/100) was blind to this because it never drove the relay loopback surface the Wails GUI uses. A relay-surface regression gate now exists for the write routes (`internal/relay/server_files_test.go`, `internal/daemon/relay_remote_files_test.go`); discovery has unit coverage for the 401 case. Future remote work should test the relay surface explicitly.
