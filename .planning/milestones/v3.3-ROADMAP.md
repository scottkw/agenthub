## Overview

v3.3 lands raw shell sessions (bash/zsh/pwsh/system-default) as a first-class agent type across all three surfaces (GUI, TUI, CLI), unblocking the ~9 deferred v3.2 UAT scenarios that required raw PTY. It then closes v3.2 polish/tech-debt items (mailto/IDN web-links, find-bar dismiss + animation, IIP decision, Sidebar test-env), ships the Settings hyperlinked index (jump-link bar + autocomplete search, Issue #45), absorbs the deferred v3.1 distribution-pipeline followups (Phase 91), and re-runs the deferred v3.2 UAT batches end-to-end.

Mid-milestone, two phases were inserted as audit-driven scope additions:
- **Phase 107** (2026-05-13) — captured a shell-UX scope flip (single "Shell" entry + Settings binary picker) and a clean-exit ExitToast bug discovered after the initial code-complete audit.
- **Phase 108** (2026-05-16) — extended Phase 107's GUI shell-entry collapse to TUI + CLI as a release-blocking cross-surface parity gap surfaced during 101-UAT Test 3.

## Milestone Summary

**Decimal Phases:** None — Phases 107 and 108 are full integer phase numbers, but both were inserted mid-milestone after audit-driven scope discovery (107 from 2026-05-13 audit surfacing shell-UX scope flip + clean-exit bug; 108 from 101-UAT Test 3 surfacing cross-surface parity gap).

**Key Decisions:**

- **Single-shell-entry collapse (mid-milestone scope flip):** Reversed Phase 101's multi-row design (`Shell — system default` / `Shell — bash` / `Shell — zsh`) to a single `Shell` entry across all three surfaces (Phases 107 GUI + 108 TUI/CLI). Driven by first-user-test feedback ("too many shells, just give me one") and validated by 101-UAT Test 3 declaring the multi-row pattern an unacceptable v3.3 release state.
- **shellPath plumbing mirrors shellWebShareWarned line-for-line:** Same engine field + Get/Set methods + GET/PATCH HTTP routes + DaemonClient methods + Wails wrappers + TS bindings. Pattern is load-bearing across all settings additions; future settings should mirror it.
- **`resolveDefaultShellPath` fallback chain (`$SHELL` → `DiscoverShells Name=="shell"` → platform hardcode) is resolved at `GetShellPath()`/`CreateSession` time, NOT at settings-load.** Preserves "clear field to use system default" semantics — empty stored value means "use platform default", not uninitialized state.
- **SHELL-12 final behavior:** auto-close on any natural exit (zero or non-zero). ExitToast for non-zero natural exits is not a v3.3 requirement — tester accepted "tab-close gesture is sufficient; I don't need to know error state anyway." Recorded in memory: [[project_shell_exit_toast_descoped]].
- **POLISH-05 outcome:** sixel-only support; iTerm2 IIP (OSC 1337) declared out-of-scope for v3.3 (and indefinitely). Decision recorded in `105-UAT-RUNBOOK.md` (traceability deviation — no separate `103-IIP-DECISION.md` artifact; flagged as v3.4 process debt).
- **Cross-surface parity is a release-blocking contract:** 101-UAT discovered TUI/CLI still exposing multi-shell rows after Phase 107 GUI collapse. Phase 108 inserted as new release-blocking phase (not deferred). Pattern established: GUI/TUI/CLI must stay in sync.
- **Phase 105 UAT triage:** 3 pass / 2 issue / 2 partial. Issues filed to GitHub (#54/#55/#56) and deferred to v3.4 backlog after operator verification that all 3 are pre-existing (not v3.3 regressions).
- **Phase 91 backfill via Phase 106:** Deferred v3.1 distribution-pipeline followups absorbed into v3.3 (DIST-01..03). Code-complete; operator must provision `RELEASE_PUBLISH_TOKEN` PAT + `WINGET_FIRST_SUBMISSION=true` variable before next release.
