## Component Inventory

### BannerStack (new)

A wrapper `div.banner-stack` rendered as the first child of `.app`, before `.app__row`.

```
.banner-stack {
  display: flex;
  flex-direction: column;   /* D-01: vertical stacking */
  flex-shrink: 0;
  max-height: calc(3 * 53px);  /* D-02: cap at 3 banners (~53px each at 12px v-pad + 13px text + borders) */
  overflow-y: auto;
}
```

- When 0 banners are active: renders nothing (component returns null or empty fragment)
- When 1–3 banners active: stacks vertically with no gap between rows (banners use border-bottom to separate visually)
- When >3 banners active: max-height clips and container scrolls internally (edge case only)

### Banner structure (shared layout pattern)

Each banner row follows:
```
[left-border stripe] [icon 14px] [message group: message + sub-text] [optional CTA button] [dismiss X button]
```

- All items on a single flex row (`align-items: center`)
- Message group (`flex: 1`, `min-width: 0`) takes remaining space
- CTA and dismiss X are `flex-shrink: 0` at the right end
- Dismiss X button: 24×24px minimum touch target, ghost style

### LocalNetworkBanner (modified)

Add `onDismiss?: () => void` prop. When provided, render dismiss X button at far right:
- Button class: `.local-network-banner__dismiss`
- aria-label: "Dismiss local network notification"
- Icon: `XMarkIcon` from `@heroicons/react/20/solid`, 16px

Dismiss behavior (D-04): hides banner for current session. Parent manages dismissed state via `useState<boolean>` at App level. Banner reappears if `webServerMode` changes back to `'local'` in a new condition.

### UpdateBanner (extracted from WelcomeTab)

New standalone component `UpdateBanner` at app level. Props: `update: UpdateInfo | null`, `onDismiss: () => void`.

- Mirrors existing `.update-banner` markup from WelcomeTab
- `update` state lifted from WelcomeTab to App level
- `EventsOn('update:available', ...)` subscription moves to App
- `GetLastUpdateInfo()` call moves to App
- Dismiss button triggers `onDismiss` which calls `setUpdate(null)` at App level

### Dismiss animation (D-05)

CSS transition on the banner wrapper: `opacity` and `max-height` collapse.

```css
.banner-exit {
  opacity: 0;
  max-height: 0;
  overflow: hidden;
  padding-top: 0;
  padding-bottom: 0;
  transition: opacity 150ms ease, max-height 200ms ease, padding 200ms ease;
}
```

Apply `.banner-exit` class on dismiss, then remove the banner from state after `200ms` via `setTimeout`. No animation library required — pure CSS transition.

## Interaction Contract

### Stacking order (when multiple banners active)

Top to bottom:
1. LocalNetworkBanner (if `webServerMode === 'local'` and not dismissed)
2. UpdateBanner (if update available and not dismissed)

Rationale: LocalNetwork is a persistent system state warning; updates are informational. System state takes priority.

### Dismiss X placement

- Far right of each banner row
- `margin-left: auto` on the dismiss button (or `justify-content: space-between` on the flex row with dismiss as last item)
- Dismiss does NOT affect other banners (D-04, BAN-02)

### Accessibility

- Each banner: `role="status"` for informational, `role="alert" aria-live="polite"` for update-available
- Dismiss button: explicit `aria-label` on each (distinct labels — not both "Dismiss")
- Dismiss X keyboard focusable, minimum 24×24px hit target
- Focus ring: `outline: 2px solid #7aa2f7; outline-offset: 2px` on focus-visible
