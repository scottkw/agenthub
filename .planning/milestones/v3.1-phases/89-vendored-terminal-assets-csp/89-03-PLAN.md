```go
func (ws *WebServer) cspHeaders(next http.HandlerFunc) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        base := ws.BaseURL()
        if base == "" {
            // Fail-closed: listener not ready. Theoretically unreachable
            // because handlers don't run until Start() succeeds, but
            // documented defensively (CLAUDE.md Silent Fallbacks Forbidden).
            http.Error(w, "internal error", http.StatusInternalServerError)
            return
        }
        wssOrigin := "wss://" + strings.TrimPrefix(base, "https://")
        var b strings.Builder
        b.Grow(256)
        b.WriteString("default-src 'none'; ")
        b.WriteString("script-src 'self'; ")
        b.WriteString("style-src 'self'; ")
        b.WriteString("connect-src 'self' ")
        b.WriteString(wssOrigin)
        b.WriteString("; ")
        b.WriteString("img-src 'self' data:; ")
        b.WriteString("font-src 'self'; ")
        b.WriteString("base-uri 'none'; ")
        b.WriteString("form-action 'self'; ")
        b.WriteString("frame-ancestors 'none'")
        w.Header().Set("Content-Security-Policy", b.String())
        w.Header().Set("Cache-Control", "no-store")
        next(w, r)
    }
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP response → browser | CSP header instructs the browser's content-security policy engine. Once set, the browser enforces script-src, style-src, connect-src, etc. The middleware is the server-side half of the contract. |
| ws.BaseURL() → CSP directive | Dynamic per-request composition. If BaseURL() were wrong, the connect-src clause would mis-state the allowed wss:// origin and the browser would reject the WebSocket upgrade. Mitigated by Phase 88's identical use of BaseURL() already being in production. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-89-01 | Tampering | Inline script injection via any HTML bug | mitigate | cspHeaders sets `script-src 'self'` which blocks inline script execution. Combined with Plan 02's inline-block extraction, the browser has no path to execute attacker-controlled scripts from the page body. |
| T-89-03 | Information Disclosure | WSS connect-src bypass via attacker-controlled origin string | mitigate | connect-src is composed from `ws.BaseURL()` which is server-authoritative (reads listener address under RLock). Attacker cannot influence the directive value from the request path. Per-request re-read handles random-port fallback automatically. |
| T-89-06 | Tampering | Client-side caching of stale HTML with old (or permissive) CSP | mitigate | Middleware sets `Cache-Control: no-store` so browsers refetch HTML on every request. Short-term cost (one extra HTML fetch per session open); long-term correctness benefit (CSP changes propagate immediately). |
</threat_model>
