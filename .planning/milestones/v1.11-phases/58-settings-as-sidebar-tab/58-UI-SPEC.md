## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 13px | 400 regular | 1.5 | Default text, table cells, button labels, tab labels |
| Label | 12px | 400 regular | 1.4 | Field labels, descriptions, URL text, status bar |
| Heading | 16px | 600 semibold | 1.2 | Panel/section headings (e.g. "Settings" title if retained; sub-section h3 upgraded to label role) |
| Caption | 11px | 400 regular | 1.3 | Code snippets inside panels (`.settings-panel__code`), fine-print details |

Weights declared: regular (400) and semibold (600) only.

Note on Caption/Label/Body density: Caption (11px), Label (12px), and Body (13px) are 1px apart. This is intentional — all three sizes are preserved verbatim from the existing `SettingsPanel` implementation to avoid visual regression. The monospace font stack (Cascadia Code / Fira Code) renders these three sizes with sufficient x-height differentiation at typical desktop display densities (1x–2x DPR). The distinction between Caption and Label is reinforced by context (code block vs. form field label) rather than size alone. Do not increase any of these sizes; doing so would break the existing compact panel layout.

**Source:** Measured from `style.css` — `.settings-panel__header h2` is 16px, `.settings-panel__tab-btn` is 13px, `.settings-panel__label` is 13px, `.settings-panel__description` is 12px, `.settings-panel__code` is 11px. ## Interaction Contracts

### Sidebar Settings Button
- **Single click:** If no `settings` tab exists in tab array → add `SETTINGS_TAB` and set as active. If `settings` tab exists → set as active (focus existing, no duplicate).
- **Collapsed sidebar:** Clicking the Cog6ToothIcon button (no label visible) follows identical singleton logic.
- **Visual feedback:** Settings button uses the same `.sidebar__item` hover and active styles as all other sidebar items. No special active state needed (tab bar communicates active state).

### SettingsTab Lifecycle
- **Mount:** `useEffect([], [])` fires unconditionally on mount. Loads `IsWebServerRunning()` and `HasCTDisclosure()` in parallel. No `isOpen` guard.
- **Unmount:** No cleanup required (no subscriptions in current SettingsPanel implementation).
- **Tab close (× button):** Uses existing `handleCloseTab` in App.tsx. Since `sessionId` is `''`, no `KillSession` backend call is made. Tab removed from `tabs` array. Next available tab becomes active.
- **Web server toggle:** After `handleToggleServer` completes, call `onWebServerStateChange()` prop to sync parent `webServerRunning` state. This replaces the old `onClose` side-effect refresh.

### Internal Sub-Tab Navigation (CLI Paths / Web Server)
- Tab buttons use `role="tab"` and `aria-selected` (already present in SettingsPanel — retain).
- Active tab indicated by blue bottom border (`border-bottom-color: #7aa2f7`) on active tab button — retain existing CSS class `.settings-panel__tab-btn--active`.
- No animation on sub-tab switch.

### Save Paths Button
- Label: "Save Paths" (idle state)
- Label: "Saving..." (in-flight, button disabled)
- On success: button returns to "Save Paths" with no toast or confirmation (existing behavior — retain)
- On error: red error text appears below button (`#f7768e`, 12px)

### Web Server Toggle Button
- Label: "Start Web Server" (server stopped, CT disclosed)
- Label: "Stop Web Server" (server running)
- Label: "Starting..." / "Stopping..." (in-flight, button disabled)
- Disabled state when CT not yet disclosed and server is stopped (existing behavior — retain)
- Tooltip: "Acknowledge the Certificate Transparency disclosure first" (when disabled due to CT)

### CT Disclosure Acknowledgment
- "I Understand" button: label unchanged
- After acknowledgment: button replaced by green checkmark + "Certificate Transparency acknowledged" text
- Error state: red 12px error text beneath button

## Layout Contract

Primary visual anchor: sub-tab selector row (CLI Paths / Web Server).

```
.app
  .sidebar (existing — no change)
  .app__content
    .tab-bar (existing — Settings tab appears here with × close)
    .terminal-container
      {activeId === '__settings__' && <SettingsTab ... />}
      {other panel tabs...}
      {terminal tabs...}
```

SettingsTab fills `.terminal-container` using the same layout as `WelcomeTab` and `DaemonManagerPanel` — no fixed positioning, no z-index, no backdrop.

SettingsTab internal layout:
```
.settings-tab                        (flex column, full height, overflow-y: auto)
  .settings-panel__tabs              (sub-tab row — retain existing class)
    .settings-panel__tab-btn         (CLI Paths)
    .settings-panel__tab-btn         (Web Server)
  .settings-panel__body              (flex column, padding 20px [legacy value — not a token], flex: 1)
    {cli-paths content or web-server content}
```

No header block. No footer block. No close button. The tab bar's × button serves as the close affordance.
