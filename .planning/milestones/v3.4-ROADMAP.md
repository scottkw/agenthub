# Milestone v3.4: File Browser (Read-Only) + TUI Parity

**Status:** ✅ SHIPPED 2026-05-21
**Phases:** 118-122 (5 phases, including audit-driven Phase 122 inserted mid-milestone)
**Total Plans:** 20/21 (one Plan 122-01 superseded by 122-01-recovery)
**Closes:** GitHub Issues #62 (read-only file browser) + v3.4 slice of #64 (TUI browse+preview parity). Umbrella epic #24 stays open across v3.4 + v3.5.

## Overview

Ships the read-only half of the file browser epic (Issue #24): TOCTOU-safe sandboxed filesystem API (`os.OpenRoot`-based, fuzz-proven), capability-gated `/api/files/{list,stat,read}` routes on both the daemon socket and the Tailscale-HTTPS webserver, a React `FileBrowserTab` (desktop + web-share) with breadcrumb-bounded navigation and text/markdown/image previews, a TUI Files view with `tea.Cmd` filesystem discipline and glamour-rendered markdown, and cross-surface remote-session parity wired in Phase 122 (GUI + TUI both browse remote tailnet sessions via the same `/api/files/*` contract). Cross-surface (GUI/TUI/web/CLI) parity remains a release-blocking contract per the v3.3 Phase 108 standard.

**Pattern proved in v3.3 reapplied:** Phase 122 inserted mid-milestone after Phase 121's local-only scope cut surfaced cross-surface remote-browse as a release-blocking parity gap. Same pattern as v3.3 Phases 107/108 (audit-driven phase insertion).

## Milestone Summary

**Inserted phases:**

- **Phase 122** (audit-driven insert): inserted after Phase 121 scoped local-only — remote-session cross-surface parity was a release-blocking gap that materialized during 121 verification. Same audit-driven-insertion pattern proven in v3.3 (Phases 107/108).

**Key Decisions:**

- **`os.OpenRoot` (Go 1.24+) for sandboxing — not `filepath.EvalSymlinks` + `os.Open`.** The two-step pattern has a TOCTOU race window demonstrated exploitable by CVE-2026-27976 (Zed) and CVE-2026-43998 (vm2). `os.OpenRoot` provides kernel-level TOCTOU-free path resolution. (✓ Good — `FuzzSandboxPath` 60s fuzz reports zero crashes against 40+ payload corpus.)
- **40+ payload fuzz corpus as a merge gate.** Path traversal payloads including `../../etc/passwd`, `%2e%2e%2f`, `%252e%252e%252f`, U+FF0F fullwidth slash, U+2024 one-dot-leader, null bytes, Windows reserved device names (`CON`, `NUL`, `COM1`–`COM9`), Windows alternate data streams (`:`), Windows 8.3 short names (`PROGRA~1`), trailing dots/spaces, symlink escape. (✓ Good — proven exhaustive against PITFALLS.md research.)
- **`HasPerm` whole-token comma-split, NOT `strings.Contains`.** Substring match would false-positive `"no-files.read"`. Static-grep gate `TestHasPerm_NoStringsContains` enforces.  (✓ Good — clean separation, no foot-gun.)
- **Separate `requireFilesRead` middleware — not added to `requireCapability` switch.** Avoids risk of breaking existing terminal relay routes. Static gate `requireCapability` grep for `files.read` returns 0. (✓ Good — load-bearing isolation.)
- **Daemon Unix-socket `/api/files/*` is auth-less by design (WEB-01).** Local in-process trusted IPC; only the network-facing webserver surface is cap-gated. (✓ Good — clean trust boundary.)
- **Session-owner cap includes `files.read` by default; web-share viewer cap excludes by default.** Read-only viewers must be granted explicitly. (✓ Good — least-privilege default.)
- **0-byte file via `/read` returns 200 with empty body (not 416).** Explicit unit test guards against `http.ServeContent` golang/go#54794 default behavior. (✓ Good — special-case correctness locked.)
- **HEAD on `/read` (not on `/list` or `/stat`).** Stat already returns full metadata; HEAD on `/read` is the only preflight needed for inline-preview vs download decision. (Resolved OQ-1.) (✓ Good — surface minimization.)
- **`react-markdown@10.1.0` + `remark-gfm@^4`; NO `rehype-raw`.** Raw HTML passthrough is an XSS risk in preview pane. Code-file syntax highlighting deferred to v3.5 when CodeMirror lands. (Resolved OQ-3.) (✓ Good — secure-by-default markdown.)
- **Image previews via `<img src="/api/files/read?...">` — NOT base64-in-state.** 33% overhead + GC pressure for non-trivial files; direct stream is correct. SVG rendered as text (never as embedded SVG). (✓ Good — performance and security.)
- **TUI: `bubbles list.Model` + `viewport.Model` joined via `lipgloss.JoinHorizontal` — NOT `bubbles/filepicker`.** filepicker is a selection-dialog primitive, not a browse pane. (✓ Good — correct primitive choice.)
- **TUI: ALL filesystem I/O via `tea.Cmd` (returning `tea.Msg`).** Synchronous `os.ReadDir` freezes the Bubble Tea render loop. Static-grep gate `TestFiles_NoSyncFSCalls` enforces. (✓ Good — Bubble Tea idiom respected.)
- **TUI: left-truncate status line (`…/utils/helper.ts`).** Preserves high-information leaf-end. (Resolved OQ-2.) (✓ Good — UX-correct truncation.)
- **TUI: `charmbracelet/glamour` promoted from indirect to direct dep.** Markdown rendering parity with desktop preview pane. (✓ Good — single source of truth for markdown.)
- **Phase 122 daemon proxy + `RemoteCapStore`.** Desktop GUI hits the local daemon, which proxies to the remote peer's Phase 119 routes. Keeps cap material out of the renderer process. (✓ Good — clean trust separation.)
- **Phase 122 TUI direct HTTPS.** TUI has no daemon hop need — `RemoteFilesClient` dials the remote peer directly with the cap. (✓ Good — minimal indirection for TUI.)
- **Phase 122 cross-surface parity proven by 3 independent observers.** daemon-proxy Go + tui.RemoteFilesClient Go + Playwright HTTPS browser observe byte-identical responses against shared fixture. (✓ Good — strongest possible automated evidence pending two-machine UAT.)
- **Phase 122 mid-milestone insertion.** Phase 121 local-only scope cut surfaced cross-surface remote-browse as a release-blocking gap. Cross-surface (GUI/TUI/CLI) parity remains release-blocking contract from v3.3 Phase 108. (✓ Good — pattern reaffirmed.)
- **Settings `schemaVersion: 3` migration via established defaults-merge constructor.** Same pattern as v3.2 `schemaVersion: 2`. (✓ Good — load-bearing pattern; future settings should mirror.)
