### Non-blocking observations (pre-existing TUI UX, not Phase 108 regressions)

These were surfaced by the operator during UAT. Code inspection of `internal/tui/update.go:652-692` confirms Phase 108 did NOT touch the affected paths.

1. **After session create, TUI returns to session list instead of auto-attaching.**
   `submitNewSession` (`internal/tui/update.go:687-691`) closes the modal, shows "Creating session..." toast, and dispatches `createSession`. There's no auto-switch to the session view. Behavior is identical for AI CLI and Shell sessions.
   → Candidate for a separate GitHub issue: "TUI: auto-attach to newly-created session".

2. **Initial prompt requires Enter keypress to render.**
   On attaching to the newly-created shell session, the prompt is blank until the user hits Enter. This is a PTY rendering / xterm.js initial-flush quirk that affects all session types, not Shell-specific. Phase 108 did not touch attach or PTY paths.
   → Candidate for a separate GitHub issue: "TUI: shell prompt requires Enter on first attach".

Neither observation gates v3.3 release; both are general TUI polish items.
