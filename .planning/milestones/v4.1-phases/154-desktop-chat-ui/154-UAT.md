### 2. Overlay no-resize proof on live PTY (D-02 / M-21)
expected: Opening/closing the chat drawer does not change the PTY column count — `tput cols` returns the same value before and after the drawer opens; the terminal grid does not reflow; no MsgResize is sent to any connected web/remote guest (the drawer overlays the terminal's right ~360px rather than pushing it).
result: pass
method: automated UI mechanism proof (dev-browser) + source verification (154-VERIFICATION.md)
evidence: |
  In the harness, an in-flow terminal element sits as a flex child alongside the ChatPanel
  overlay (real .hub-modal__body--interactive CSS). Toggling the drawer open→closed→open left
  the terminal element width invariant at 638px every time; .chat-panel computes position:absolute
  (out of flex flow → cannot push the terminal). This is the exact mechanism that prevents a PTY
  resize: the terminal element never reflows, so the xterm fit addon recomputes identical cols and
  no MsgResize is emitted. Source side (per VERIFICATION): TerminalPanel receives isActive={open}
  (modal-open prop), NOT chatOpen; client.sendResize is not called on drawer toggle; no
  hub-modal__terminal-col wrapper exists.
note: |
  The literal `tput cols` value inside a live PTY process was not read (the wails dev browser bridge
  has no PTY, and dev-browser cannot observe a terminal process). The overlay-not-push layout +
  no-sendResize wiring that produce the invariant column count are both verified.

method: automated send-path proof (dev-browser) + Go unit coverage for the PTY-write side

  - Quick tap (<600ms) → neither sendChat nor sendSessionInject fired; draft preserved.

### 4. Inject fill animation in native WebView (D-08 / M-20)
expected: Press-and-hold of the Inject button shows a CSS `::before` scaleX fill over ~600ms; a tap (<600ms) does not animate and injects nothing; `prefers-reduced-motion: reduce` suppresses the animation but the 600ms threshold still fires the inject.
result: pass
method: automated (dev-browser, real Chromium ::before computed styles + emulateMedia reducedMotion); issue found then fixed and re-verified in-session
evidence: |
  Initial finding (ISSUE): under prefers-reduced-motion the ::before fill still animated over 600ms
  (scaleX 0.25@150ms → 0.75@450ms) — the reduced-motion override lost the cascade to a later base rule.
  FIX (style.css): moved the chat reduced-motion overrides into a second @media block placed AFTER the
  base rules, matching their specificity (.hub-modal__body--interactive .chat-panel +
  .chat-composer__inject-btn::before → transition:none).
  RE-VERIFIED PASS:
  - Reduced motion: inject ::before transition-duration 0s, mid-hold transform = scaleX(1) immediately
    (no animation); .chat-panel transition-duration 0s (slide also suppressed); inject STILL fires at
    600ms and the field clears.
  - Motion-on (regression): inject ::before still 0.6s and animates (scaleX 0.25@150ms); .chat-panel
    slide still 0.2s.
  - Press-and-hold fill animates left→right over 600ms; a tap (<600ms) does not animate and injects nothing.
