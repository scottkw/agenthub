<objective>
Wire the two outstanding server-side MsgChatSend (0x31) dispatch stubs so the desktop ChatPanel built later in this phase can actually round-trip a chat message. Today `internal/relay/protocol.go` documents MsgChat/MsgChatSend as "Phase 154 dispatch stubs" and the dispatch `case MsgChatSend:` is absent from BOTH the relay read pump (`internal/relay/server.go`) and the webserver read pump (`internal/webserver/server.go`). A client can encode and send the frame, but nothing persists or echoes it.

Purpose: A normal chat message sent over the WebSocket must be sanitized, persisted via the existing `chatAppendFn`, and broadcast to every subscriber as a MsgChat frame — exactly like `HandleInject` does for `SessionInject:true` messages, but without any PTY write and gated to RW clients only (SEC-01).
Output: `ChatSendPayload` struct, `Hub.HandleChatSend`, two read-pump dispatch cases, and Go tests proving the RO gate and the broadcast.
</objective>
