<objective>
Close the scope gap discovered during Phase 159 live UAT: the `/app/` redirect (159-01)
correctly delivers chat to remote guests, but `/app/` renders the FULL desktop app shell —
the Sidebar (Home / Hub / Settings / session groups) and TabBar are rendered
unconditionally in `App.tsx`, with no `mode === 'web'` gate. Web mode only suppressed
Wails RPCs, the Settings tab *content*, and the Welcome tab; the navigation chrome was
never hidden. This is unfinished web-mode scoping from Phase 120/155, never exposed
because nothing routed a real guest to `/app/` until 159-01's redirect.

Impact: a guest handed a capability for ONE session sees the whole app frame and can
navigate away from the scoped session (Home / Hub / Settings). The session terminal,
chat, and `/api/sessions` are correctly cap-scoped, but the open `/api/sessions/meta`
endpoint (lists all web-enabled sessions, by-design tailnet trust) becomes reachable via
the exposed Hub.

Fix: gate `<Sidebar>` behind `mode !== 'web'` so a web-share guest sees ONLY the scoped
session surface — the WebShareSessionView (terminal + chat) plus the TabBar's session and
file-browser tabs. Desktop (Wails) rendering is unchanged.

Output: one-line render gate in App.tsx, a new Playwright e2e regression spec, and
TESTING.md registration. Re-verified live in a fresh wails build.
</objective>
