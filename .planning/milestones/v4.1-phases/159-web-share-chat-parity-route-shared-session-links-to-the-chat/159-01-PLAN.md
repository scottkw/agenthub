<objective>
Route the actually-shared web-share link to the chat-capable surface. The daemon mints share URLs of the form `/sessions/{id}?cap=TOKEN`, which land on `handleTerminalPage` and serve the vanilla-JS `terminal.html` viewer — a surface that has no chat UI and silently discards chat frames 0x30–0x34. The chat-capable React SPA at `/app/` (WebShareSessionView, built in Phase 155) is fully wired but no remote guest is ever sent to it. Phase 155 verified PARITY-01 only on `/app/` directly — a false-parity gap.

This plan changes a single Go handler: `handleTerminalPage` issues an HTTP 302 redirect to `/app/?session={id}&cap={token}` (after cap validation), so remote guests land on the chat-capable SPA. No frontend changes — the SPA already carries ChatPanel, the toggle, the unread/mention badge, and presence.

Purpose: Close the REAL cross-surface parity gap (WEBCHAT-01/02, upstream PARITY-01) on the link guests actually receive; also pre-unblocks the upcoming Tailscale Funnel session-sharing milestone.
Output: Modified `handleTerminalPage`, updated + new Go tests, and TESTING.md regression-suite registration (traceability + manual M-31).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| remote browser → webserver | Untrusted HTTP GET to /sessions/{id} carrying a cap token in the query string crosses here |
| cap token (URL query) → requireCapability | Token is validated (HMAC-SHA256 verify, SID match, grant active, session web-enabled) before any handler logic runs |
| handleTerminalPage → browser (302 Location) | Server-controlled RELATIVE redirect target; sessionID + token are forwarded as URL-encoded query params, never as a redirect host |
