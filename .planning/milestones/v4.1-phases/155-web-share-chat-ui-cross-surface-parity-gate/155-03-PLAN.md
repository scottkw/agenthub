<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| web-share browser page → webserver WS upgrade | `wss://{host}/sessions/{id}/ws?cap=` — the cap is the credential; the upgrade is gated server-side |
| URL `?session=`/`?cap=` params → app bootstrap | Untrusted query params drive which session view mounts |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-155-04 | Elevation of Privilege / Spoofing | webserver WS upgrade `GET /sessions/{id}/ws?cap=` | high | mitigate | The upgrade is gated by `requireCapability` (HMAC-verified `?cap=`) + `requireAllowedOrigin` (Phases 87/88) — unchanged. WebShareSessionView only constructs the URL; an invalid/expired cap is rejected by the server before any frames flow. Verified by the e2e in Plan 155-04 (valid caps connect; the RO path is gated). |
| T-155-05 | Information Disclosure | cap token in the `wss://` URL | low | accept | Existing production pattern (time-bounded JWTs in `?cap=`); web/assets/terminal.js uses the same shape. No change. |
| T-155-SC | Tampering | npm/pip/cargo installs | n/a | accept | No new packages (RESEARCH: NONE). Component reuses existing Phase 154 chat components. |
</threat_model>
