<objective>
Close the frontend wire-layer gap so the shared ChatPanel can both SET an alias and LEARN its own identity:
1. Add RelayClient.sendAliasSet(alias) — a one-to-one mirror of the existing sendChat/sendSessionInject senders, wrapping the already-written encodeAliasSetFrame (relayClient.ts:94, currently called only in tests).
2. Parse the new server MsgSelf (0x37) frame from Plan 161-01 and expose it via an onSelf(personKey, alias) callback (mirror of onPresence), giving web-share guests their own personKey/alias for pre-fill (approach d).

Purpose: These are the only two RelayClient changes the alias UI needs. ChatPanel already owns a live RelayClient (clientRef) on all three surfaces, so adding these here means every host inherits them with zero host-component changes (parity by construction).

Output: sendAliasSet method; MSG_SELF parse + onSelf callback + ServerFrame union variant; extended relayClient unit tests.
</objective>
