<objective>
Add a server→client self-identity frame (MsgSelf, 0x37) emitted once on WS connect on both server read-pump paths, carrying the connecting client's own {personKey, alias}. This is the one missing seam (RESEARCH Open Q1, adopted recommendation) that lets a web-share guest learn its own identity for alias pre-fill (approach d) — the presence roster broadcasts identical bytes to every client and carries no "self" marker, and the web client never otherwise learns its own tailnetID.

Purpose: Satisfy decided approach (d) — web-guest pre-fill — uniformly across both surfaces with a thin, additive, one-way hint. It also repairs the currently-broken web "mention-of-me" highlight (which compares against the literal 'local' fallback) as a bonus, consumed in Plan 161-03.

Output: MsgSelf wire constant + encoder in protocol.go; on-connect emission on the relay path (internal/relay/server.go) and the web path (internal/webserver/server.go); Go round-trip tests on both paths.

This phase does NOT rebuild the alias backend. MsgAliasSet (0x34), AliasStore, ValidateAlias, and NotifyPresence are already complete and symmetric — this plan only ADDS the server→client self hint.
</objective>
