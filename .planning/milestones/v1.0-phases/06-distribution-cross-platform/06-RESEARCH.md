## Summary

AgentHub is built on Wails v2 with a Go backend. The codebase already has the hardest platform work done: `go-pty` uses ConPTY on Windows, `win32input.go`/`win32input_other.go` provide cross-platform win32-input-mode parsing, and `cleanup_windows.go`/`job_windows.go` handle Windows job-object lifecycle. The macOS tray uses native CGO Objective-C (`tray.go`) which will not compile on Linux or Windows — this requires platform stubs.

The main Phase 6 work is: (1) CI matrix wiring with three runners, (2) macOS code signing + notarization, (3) Linux WebKitGTK variant handling, (4) Windows NSIS installer + WebView2 bootstrap, and (5) tray stubs for Linux/Windows.

**Critical insight about `ubuntu-latest`:** As of January 2025, `ubuntu-latest` maps to Ubuntu 24.04, which ships WebKitGTK 4.1 (not 4.0). The CI Linux job must use `-tags webkit2_41` and install `libwebkit2gtk-4.1-dev`. To also test Ubuntu 22.04 (WebKitGTK 4.0), add a second explicit `ubuntu-22.04` job.

**Primary recommendation:** Use `dAppServer/wails-build-action@v3` for the CI matrix. Implement tray stubs behind `//go:build !darwin` so Linux/Windows compile without Cocoa. Add `Info` fields to `wails.json` before building the NSIS installer. Use `xcrun notarytool` (not the deprecated `gon`/`altool`) for macOS notarization.

### Pattern 1: Platform Tray Stubs

**What:** `tray.go` uses `#cgo darwin` with Objective-C Cocoa. This cannot compile on Linux or Windows. Add stubs.

**When to use:** Required — without stubs, `wails build -platform linux/amd64` fails.

`tray_linux.go`:
```go
//go:build linux

package main

func (a *App) initTray()    {}
func (a *App) cleanupTray() {}
```

`tray_windows.go`:
```go
//go:build windows

package main

func (a *App) initTray()    {}
func (a *App) cleanupTray() {}
```

> Source: Direct codebase analysis of `tray.go` — file has no build tag, uses `#cgo darwin` CFLAGS/LDFLAGS. Go's CGO constraint means the Objective-C code fails to compile on non-darwin targets.

### Pattern 2: GitHub Actions CI Matrix

```yaml
# Source: dAppServer/wails-build-action README
name: Build
on: [push, pull_request]
jobs:
  build:
    strategy:
      fail-fast: false
      matrix:
        build:
          - name: agenthub
            platform: darwin/universal
            os: macos-latest
          - name: agenthub
            platform: linux/amd64
            os: ubuntu-latest          # Ubuntu 24.04 as of Jan 2025
            webkit_tag: webkit2_41
            webkit_pkg: libwebkit2gtk-4.1-dev
          - name: agenthub
            platform: linux/amd64
            os: ubuntu-22.04           # Explicit 22.04 for WebKitGTK 4.0 test
            webkit_pkg: libwebkit2gtk-4.0-dev
          - name: agenthub
            platform: windows/amd64
            os: windows-latest
    runs-on: ${{ matrix.build.os }}
    steps:
      - uses: actions/checkout@v4
      - name: Install Linux deps
        if: runner.os == 'Linux'
        run: sudo apt-get install -y build-essential pkg-config libgtk-3-dev ${{ matrix.build.webkit_pkg }}
      - uses: dAppServer/wails-build-action@main

          build-name: ${{ matrix.build.name }}

          build-webview2: embed          # Windows only — ignored on other platforms
```

### Pattern 3: macOS Code Signing + Notarization

**Required prerequisites:**
- Apple Developer Program membership ($99/year)
- "Developer ID Application" certificate from developer.apple.com/account
- Export certificate + private key as `.p12` from Keychain Access
- App-specific password from appleid.apple.com
- Team ID from developer.apple.com/account/#!/membership

**GitHub Secrets required:**
| Secret | Value |
|---|---|
| `MACOS_CERTIFICATE` | `base64 Certificates.p12` output |
| `MACOS_CERTIFICATE_NAME` | Full cert string: `"Developer ID Application: Name (TEAMID)"` |
| `MACOS_CERTIFICATE_PWD` | p12 export password |
| `MACOS_CI_KEYCHAIN_PWD` | Random strong password for CI keychain |
| `MACOS_NOTARIZATION_APPLE_ID` | Apple developer email |
| `MACOS_NOTARIZATION_PWD` | App-specific password |
| `MACOS_NOTARIZATION_TEAM_ID` | Team ID |

**Signing + notarization steps (after wails build):**
```bash
# 1. Import certificate into ephemeral CI keychain
echo $MACOS_CERTIFICATE | base64 --decode > certificate.p12
security create-keychain -p "$MACOS_CI_KEYCHAIN_PWD" build.keychain
security default-keychain -s build.keychain
security unlock-keychain -p "$MACOS_CI_KEYCHAIN_PWD" build.keychain
security import certificate.p12 -k build.keychain -P "$MACOS_CERTIFICATE_PWD" -T /usr/bin/codesign
security set-key-partition-list -S apple-tool:,apple:,codesign: -s -k "$MACOS_CI_KEYCHAIN_PWD" build.keychain

# 2. Sign with hardened runtime (required for notarization)
/usr/bin/codesign --force -s "$MACOS_CERTIFICATE_NAME" \
  --options runtime \
  --entitlements build/entitlements.plist \
  build/bin/agenthub.app -v

# 3. Notarize
xcrun notarytool store-credentials "notarytool-profile" \
  --apple-id "$MACOS_NOTARIZATION_APPLE_ID" \
  --team-id "$MACOS_NOTARIZATION_TEAM_ID" \
  --password "$MACOS_NOTARIZATION_PWD"
ditto -c -k --keepParent build/bin/agenthub.app notarization.zip
xcrun notarytool submit notarization.zip --keychain-profile "notarytool-profile" --wait

# 4. Staple the ticket
xcrun stapler staple build/bin/agenthub.app
```

**Entitlements file** (`build/entitlements.plist`):
```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>com.apple.security.network.client</key>
    <true/>
    <key>com.apple.security.network.server</key>
    <true/>
</dict>
</plist>
```

> AgentHub opens network connections (WebSocket server, TLS) and may need both `network.client` and `network.server`. No JIT, no unsigned memory, no debugger — minimal footprint.

### Pattern 5: Windows CA Cert Installation

**Context:** AgentHub generates a self-signed CA cert for TLS (Phase 4). On Windows, users need to install this cert in the Windows cert store for the browser to trust `wss://` connections.

**Programmatic installation via `golang.org/x/sys/windows` (already in `go.mod`):**
```go
// Source: Windows CryptoAPI via golang.org/x/sys/windows
import "golang.org/x/sys/windows"

func installCACertWindows(certDER []byte) error {
    store, err := windows.CertOpenStore(
        windows.CERT_STORE_PROV_SYSTEM,
        0,
        0,
        windows.CERT_SYSTEM_STORE_LOCAL_MACHINE|windows.CERT_STORE_OPEN_EXISTING_FLAG,
        uintptr(unsafe.Pointer(windows.StringToUTF16Ptr("ROOT"))),
    )
    if err != nil {
        return err
    }
    defer windows.CertCloseStore(store, 0)
    ctx, err := windows.CertCreateCertificateContext(
        windows.X509_ASN_ENCODING|windows.PKCS_7_ASN_ENCODING,
        &certDER[0],
        uint32(len(certDER)),
    )
    if err != nil {
        return err
    }
    defer windows.CertFreeCertificateContext(ctx)
    return windows.CertAddCertificateContextToStore(store, ctx, windows.CERT_STORE_ADD_REPLACE_EXISTING, nil)
}
```

> Note: `CERT_SYSTEM_STORE_LOCAL_MACHINE` requires elevated (admin) privileges. Consider `CERT_SYSTEM_STORE_CURRENT_USER` for user-level trust, or fall back to `certutil` CLI guidance if privileges are unavailable.

**Alternative (shell out to certutil):**
```go
exec.Command("certutil", "-addstore", "Root", certPEMPath).Run()
```

### Anti-Patterns to Avoid

- **Using `gon` for notarization:** `gon` relied on `altool` which Apple decommissioned. Use `xcrun notarytool` directly.
- **Cross-compiling macOS on Linux/Windows:** Impossible — CGO requires native Cocoa frameworks. macOS must build on macOS runner.
- **`ubuntu-latest` for WebKitGTK 4.0 testing:** As of Jan 2025, `ubuntu-latest` is Ubuntu 24.04 (WebKitGTK 4.1). Use explicit `ubuntu-22.04` for 4.0 testing.
- **`wails build -nsis` without `Info` in wails.json:** NSIS template uses `{{.Info.ProductName}}` etc. — missing fields produce empty strings in installer UI.
- **Skipping `xcrun stapler staple`:** Without stapling, the notarization ticket requires internet access to validate. Stapling embeds the ticket for offline Gatekeeper checks.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---|---|---|---|
| CI matrix setup | Custom shell scripts per OS | `dAppServer/wails-build-action@main` | Handles Go, Node, Wails install, nsis install, pnpm/npm detection per platform |
| macOS certificate import | Custom keychain manipulation | Standard `security` CLI commands in CI step | Apple's toolchain is authoritative; custom approaches break on keychain policy changes |
| macOS notarization | HTTP requests to Apple API directly | `xcrun notarytool submit --wait` | notarytool handles polling, authentication, status — complex to replicate |
| Windows installer | Hand-written NSIS script | `wails build -nsis` auto-generates from template | Wails knows the correct WebView2 runtime check patterns |
| WebView2 detection/install | Custom registry check | `-webview2 embed` flag | Wails' bootstrapper embed handles the full detection + install flow |

**Key insight:** The `dAppServer/wails-build-action` handles the non-obvious per-platform incidentals (NSIS binary availability, pnpm vs npm detection, Go CGO environment variables on Windows). Avoid reimplementing these.

## Common Pitfalls

### Pitfall 1: tray.go Compilation Failure on Linux/Windows
**What goes wrong:** `wails build -platform linux/amd64` fails with CGO compilation errors — Cocoa headers not found.
**Why it happens:** `tray.go` has `#cgo darwin CFLAGS: -x objective-c` and imports `<Cocoa/Cocoa.h>`, but has **no `//go:build darwin` tag**. Go compiles it on all platforms.
**How to avoid:** Add `tray_linux.go` and `tray_windows.go` stubs before attempting non-darwin builds. These must be Wave 1 — everything else blocks on them.
**Warning signs:** `fatal error: 'Cocoa/Cocoa.h' file not found` during `wails build`.

### Pitfall 2: ubuntu-latest = Ubuntu 24.04 (WebKitGTK 4.1)
**What goes wrong:** CI job installs `libwebkit2gtk-4.0-dev`, it's not found, build fails.
**Why it happens:** GitHub changed `ubuntu-latest` from 22.04 to 24.04 in January 2025. Ubuntu 24.04 dropped webkit2gtk-4.0.
**How to avoid:** Install `libwebkit2gtk-4.1-dev` and build with `-tags webkit2_41` on any ubuntu-latest job. Use explicit `ubuntu-22.04` runner for 4.0 coverage.
**Warning signs:** `Package webkit2gtk-4.0 was not found in the pkg-config search path`.

### Pitfall 3: Notarization Fails — `com.apple.security.get-task-allow`
**What goes wrong:** Notarization returns "Invalid" status.
**Why it happens:** Debug builds include `com.apple.security.get-task-allow` entitlement (allows debugger attach). Apple rejects notarization for apps with this entitlement.
**How to avoid:** Never include `get-task-allow` in production `entitlements.plist`. Always use release build (`wails build` not `wails dev`).
**Warning signs:** `xcrun notarytool log <ID>` reports entitlement violation.

### Pitfall 4: Notarization Fails — Hardened Runtime Not Enabled
**What goes wrong:** Notarization returns "The executable does not have the hardened runtime enabled."
**Why it happens:** `codesign` called without `--options runtime` flag.
**How to avoid:** Always include `--options runtime` in the codesign invocation.
**Warning signs:** Error message explicitly states "hardened runtime".

### Pitfall 5: Windows WebView2 Missing on CI Runner
**What goes wrong:** `wails build` on `windows-latest` produces an executable that requires WebView2, which is absent on clean CI VMs.
**Why it happens:** Windows Server (used for GitHub Actions `windows-latest`) often doesn't have WebView2 pre-installed.
**How to avoid:** Use `-webview2 embed` when building — the bundled bootstrapper handles installation at first launch.
**Warning signs:** App launches but shows blank window or "WebView2 runtime not found".

### Pitfall 6: CFBundleIdentifier Default `com.wails.agenthub`
**What goes wrong:** Notarization or App Store submission conflicts if the bundle ID is not unique and properly registered.
**Why it happens:** Wails default `Info.dev.plist` uses `com.wails.{{.Name}}` — the production `Info.plist` (which must exist in `build/darwin/`) needs a real bundle identifier.
**How to avoid:** Create `build/darwin/Info.plist` with a proper `CFBundleIdentifier` (e.g., `com.agenthub.app`). The `Info.dev.plist` is only for `wails dev` mode.
**Warning signs:** `wails build` uses `Info.dev.plist` if no `Info.plist` exists in `build/darwin/`.

## Open Questions

1. **tray.go on Linux/Windows — no-op or native implementation?**
   - What we know: macOS has native NSStatusBar; `tray_linux.go` and `tray_windows.go` stubs would produce a binary with no system tray.
   - What's unclear: Does Phase 6 require functional system tray on Linux/Windows, or just compilation + launch? Phase 3 success criteria mention "system tray when window is closed" but PLAT-02/03 only require "builds and runs."
   - Recommendation: Stubs are sufficient for Phase 6. Tray on Linux/Windows is a v2 feature if desired.

2. **macOS DMG vs. raw .app bundle**
   - What we know: `wails build` produces an `.app` bundle. No built-in DMG generation.
   - What's unclear: Phase 6 success criteria say "macOS build is signed and notarized" but don't specify DMG. Notarization works on `.app` directly.
   - Recommendation: Skip DMG for Phase 6 — ship signed `.app` in a zip (which is the notarization input anyway). DMG is cosmetic.

3. **Windows CA cert installation privileges**
   - What we know: `CERT_SYSTEM_STORE_LOCAL_MACHINE` ("ROOT" store for browser trust) requires admin elevation. Current Phase 4 provides "in-app guidance for installing CA cert."
   - What's unclear: Phase 6 success criteria say "self-signed TLS certs can be installed in the Windows cert store" — is this automated or guided?
   - Recommendation: Implement guided path (show `certutil` command for user to run) with optional programmatic path behind an "Install CA cert (requires admin)" button. Windows UAC will prompt for elevation automatically if needed.

4. **win32-input-mode on `windows-latest` GitHub Actions runner**
   - What we know: The win32input parser is implemented. GitHub Actions uses Windows Server without a real terminal.
   - What's unclear: Can PTY integration tests run on the Windows runner without a real ConPTY/Windows Terminal?
   - Recommendation: Go unit tests (`./...`) can run headlessly. PTY smoke tests that require a real ConPTY session may need to be skipped or marked manual on CI. Existing `kill_windows_test.go` pattern (build-constrained test) is the right model.
