<objective>
Implement the DNS error UX: classify the unresolvable-MagicDNS / accept-dns=false failure specifically and surface an actionable message, probe accept-dns proactively in the health check, AND show a proactive frontend warning before the user hits the failure path.

This turns Plan 01's RED DNS tests GREEN: TestProxyRemoteFiles_AcceptDNSMessage (DNS-01/DNS-02) and TestCheckHealth_AcceptDNS (DNS-03), and completes the DNS-03 UX surface (ROADMAP Success Criterion 6 — "the user is warned before hitting the failure path").

Purpose: Today `proxyRemoteFiles` returns a generic opaque 502 for all dial failures, so a user with accept-dns=false sees "502 no such host" with no fix guidance. The classifier names the fix; the proactive probe warns at failure time; the frontend banner warns BEFORE the user even attempts a remote browse.

Output: AcceptDNS on TailscaleHealth (internal/webserver/tailscale.go), isUnresolvableMagicDNS + DNS branch in proxyRemoteFiles (internal/daemon/remote_files.go), the matching frontend model field, and a proactive RemoteBrowseDNSWarning component wired into App.tsx.
</objective>
