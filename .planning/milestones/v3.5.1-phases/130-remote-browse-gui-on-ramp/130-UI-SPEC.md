## Spacing Scale

The app uses a practical 4-point scale; tokens below are extracted from
existing rule measurements in `style.css`.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap between icon and text inside session row |
| sm | 8px | Button padding, peer section bottom margin subunit |
| md | 16px | Panel horizontal padding unit |
| lg | 24px | Panel padding (`.remote-panel { padding: 24px }`) |
| xl | 32px | Not used in this phase |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Documented-value corrections (UI Review 2026-06-16):
- `.remote-panel__session-list { gap }` is `2px` in the implementation (not `sm=8px`). The 2px value pre-dates Phase 130 and was preserved correctly; the spec table was wrong.
- `.remote-panel__peer-header { padding-bottom }` is `8px` in the implementation (not `md=16px`). Same: pre-existing value preserved; spec table was wrong.

Exceptions (justified — reuse of established design-system tokens, NOT new values):
- **Badge padding `2px 8px`** and **`border-radius: 3px`** on `.remote-panel__peer-unreachable` deliberately reuse the app-wide badge/tag convention already defined in `style.css` (e.g. lines 1449–1451, 1458–1460, 1638–1640 all use `padding: 2px 8px`). The 2px vertical badge padding is the existing codebase standard for inline badges; using `4px` here would make the unreachable badge inconsistent with every other badge in the app. Design-system consistency takes precedence over the generic 4-point heuristic for this established token.

> Source: existing `.remote-panel` rules in `style.css` lines 1515–1693; existing badge padding `2px 8px` at lines 1449–1460, 1638–1640.

## State Inventory

Phase 130 introduces one new state layer: per-peer session-list states
(previously the panel only knew about the whole-panel loading/empty).
Every state MUST be distinguishable without relying on color alone.

### Panel-level states (unchanged from Phase 52, still required)

| State | Text indicator | Icon/Shape | Color (secondary) |
|-------|---------------|------------|-------------------|
| Loading — initial probe | "Probing peers..." + spinner | Spinner (rotating ring, 20×20) | `#7aa2f7` top arc |
| Empty — no tailnet peers | "No remote peers found" (bold 14px) + "No tailnet peers are running AgentHub." | Centered layout (vertical stack) | — |
| Populated | Peer hostname sections listed | — | — |

### Per-peer session-list states (NEW in Phase 130)

These states are required by RB-04 (honest states). Each must be text-labeled.

| State | Text indicator | Icon/Shape | Color (secondary) |
|-------|---------------|------------|-------------------|
| Peer reachable — has shareable sessions | Session rows listed with "Browse Files" + "Open Session" buttons | Session rows with status dot + action buttons | Status dot color per session state |
| Peer reachable — zero shareable sessions | Peer hostname shown + "No shareable sessions" sub-label + body text | Inline text block under peer header | — |
| Peer unreachable | Peer hostname shown + **"Unreachable"** text badge | Badge/chip shape (text in `#1e2030` bg, `#f7768e` text — label carries meaning) | `#f7768e` text (reinforcement) |
| Discovery loading per-peer | Peer hostname shown + "Loading..." text | Inline text | — |

**Colorblind contract:** The "Unreachable" badge uses the text "Unreachable" as
the primary signal. The `#f7768e` color is reinforcement only. The distinction
between "has sessions" (rows present) and "no sessions" (text label) is
structural/positional, not color-based.

### Session row status dots (existing, unchanged)

Status dots already carry a `title` attribute for tooltip text (existing
`RemoteSessionsPanel.tsx` line 65: `title={s.status}`). This satisfies the
colorblind contract because the text label is available on pointer hover.
State text is also included in `aria-label` on action buttons.

| Status | Dot color | Text available via |
|--------|-----------|-------------------|
| running | `#3b82f6` | `title="running"` attribute |
| idle | `#22c55e` | `title="idle"` attribute |
| waiting | `#f59e0b` | `title="waiting"` attribute |
| errored | `#ef4444` | `title="errored"` attribute |

## Interaction Contract

### Pick flow: discover → list → pick

1. User navigates to Remote Sessions panel (sidebar icon, existing).
2. Panel shows loading spinner ("Probing peers...") during initial 30s-interval poll.
3. On response from the new metadata endpoint:
   - Peers with shareable sessions render as session rows with "Open Session" + "Browse Files" buttons.
   - Peers with zero shareable sessions render with "No shareable sessions" text label under their hostname header — they are NOT dropped.
   - Unreachable peers render with "Unreachable" text badge — they are NOT dropped.
4. User clicks "Browse Files" on a session row.
5. `onBrowseFiles(sessionId, sessionName)` is called (existing prop).
6. `App.tsx` `handleBrowseFilesRemote` triggers the existing join-code cap flow:
   - If cap already cached: opens `FileBrowserTab` directly.
   - If no cap: opens `RemoteJoinCodeModal` (existing Phase 122 modal).
7. File Browser tab opens with `isRemote=true`, `pathPrefix="/api/files/remote/{sessionId}"`.

### Button interaction states

| Button | Default | Hover | Disabled |
|--------|---------|-------|---------|
| "Browse Files" | `#9ece6a` bg, `#1a1b26` text, weight 600 | `#b6dd86` bg | `opacity: 0.5`, `cursor: not-allowed` (add if not already present) |
| "Open Session" | `#7aa2f7` bg, `#1a1b26` text, weight 600 | `#89b4fa` bg | `opacity: 0.5`, `cursor: not-allowed` |

### Focus management

- All session row buttons use `focus-visible` outline: `2px solid #7aa2f7`, `outline-offset: 2px` — consistent with all other interactive elements in the app.
- Modal focus trap: `RemoteJoinCodeModal` already implements focus trap (input auto-focused on mount, Escape closes).

### Keyboard navigation

- Tab order within a session row: status (non-interactive, skip), name (non-interactive), CLI badge (non-interactive), "Open Session" button, "Browse Files" button.
- Existing keyboard behavior is unchanged.

## Layout Contract

The Remote Sessions panel layout is unchanged from Phase 52. Phase 130 adds
sub-states within the existing per-peer section, not new layout regions.

**Primary focal point (populated state):** the session rows and their action
buttons — specifically the **"Open Session" / "Browse Files"** CTAs on each
discovered session row are the dominant interactive elements that draw the eye
first. Peer headers and meta/state text are secondary; empty/unreachable/error
sub-states are tertiary. The eye should land on actionable session rows when a
reachable peer has shareable sessions.

```
.remote-panel                          (padding: 24px, overflow-y: auto)
  └── .remote-panel__peer              (margin-bottom: 20px, per peer)
        ├── .remote-panel__peer-header (hostname, 11px uppercase, border-bottom)
        ├── .remote-panel__peer-meta   (meta line: "Shows shareable sessions")
        │   [NEW] OR:
        │   .remote-panel__peer-unreachable  (text: "Unreachable")
        └── .remote-panel__session-list (gap: 2px)
              ├── .remote-panel__session-row × N  (each session)
              │     ├── status dot (8×8 circle, title=status)
              │     ├── session name (13px, flex: 1)
              │     ├── CLI badge (11px, bg #1e2030)
              │     └── .remote-panel__actions
              │           ├── "Open Session" button
              │           └── "Browse Files" button
              [NEW] OR if zero sessions:
              └── .remote-panel__peer-empty-sessions
                    text: "No shareable sessions"
                    sub: "This peer has no sessions with web-sharing enabled."
```

**No changes to the panel chrome, sidebar, or tab bar.**

## Accessibility Contract

1. **Color is never the sole state indicator.** Every state (reachable, unreachable, loading, empty, errored) is labeled with text. Color is secondary reinforcement only. This satisfies the colorblind-user mandate from the project memory.

2. **Status dots carry `title` attribute.** Existing implementation: `title={s.status}`. This must be preserved in Phase 130 changes.

3. **Action button `aria-label`s** include the session name: `aria-label="Browse files on {sessionName}"`, `aria-label="Open {sessionName} in browser"`. Existing pattern in `RemoteSessionsPanel.tsx` lines 70–80.

4. **Unreachable badge is text-first:** The glyph (e.g. `⚠`) is optional decoration; the word "Unreachable" is the primary signal.

5. **`role="status"` on the loading region** — existing spinner div should carry `role="status"` and `aria-label="Loading remote peers"` for screen reader announcement. Add if missing.

6. **`RemoteBrowseDNSWarning`** already uses `role="status"` (Phase 129). Do not duplicate.

7. **`focus-visible` outline** on all interactive elements: `2px solid #7aa2f7`, `outline-offset: 2px`. Consistent with every other interactive element in the app.

8. **`prefers-reduced-motion`**: The existing loading spinner uses `animation: spin 0.8s linear infinite`. A reduced-motion variant should substitute static "..." text (mirroring the `file-browser__spinner` pattern in `style.css` lines 3516–3527). Add if missing.
