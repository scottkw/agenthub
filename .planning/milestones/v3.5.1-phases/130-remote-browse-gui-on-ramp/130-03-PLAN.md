## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tailnet peer → webserver `100.x:7443` | New `/api/sessions/meta` is reachable only by tailnet members (Tailscale WireGuard mesh enforces routing to the bind IP). No application-layer cap; trust is network-layer per the resolved #86 decision. |
| local daemon → remote peer (outbound HTTPS) | FetchPeerSessionsMeta dials peers' webservers over TLS (MinVersion TLS1.2); IP fallback sets ServerName to preserve cert validation. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-130-05 | Information Disclosure | handleSessionsMeta response | mitigate | Handler emits only id/name/cli_type/status/url (no cap/grant/content); RB-03 whitelist test enforces this. Metadata is already non-secret (session URLs appear in QR codes). |
| T-130-06 | Information Disclosure | enumeration by non-tailnet caller | mitigate | Endpoint mounted on webserver bound to Tailscale IP; non-tailnet callers cannot route to `100.x`. No `/api/sessions/meta` on the daemon socket or relay loopback (Pitfall 1/2). |
| T-130-07 | Spoofing | TLS man-in-the-middle on outbound peer fetch | mitigate | TLS MinVersion 1.2; IP-fallback client sets ServerName=fqdn so the peer cert is validated against its hostname (no skip-verify). |
| T-130-08 | Tampering | stale session appearing in metadata | accept | webEnabledSessions() reads the live web-enabled map; DisableSession removes on exit — metadata reflects live state (RESEARCH Security Domain row). |
