## Interaction Contract

### Update Banner Visibility

| State | Condition | Banner |
|-------|-----------|--------|
| Hidden | No update available, or `Version == "dev"`, or update not yet fetched | `display: none` (controlled via React `update` state being `null`) |
| Visible | `update:available` event received OR `GetLastUpdateInfo()` returns non-null on mount | Render `.update-banner` |
| Dismissed | User clicks "Dismiss" | `setUpdate(null)` — banner hidden for session; re-appears on next startup if update still available |

### Download Update Button Behavior

- Calls `BrowserOpenURL('https://github.com/scottkw/agenthub/releases')` via Wails JS runtime
- No in-place binary replacement (out of scope per REQUIREMENTS.md)
- No loading state — `BrowserOpenURL` is fire-and-forget

### Check for Updates (Help Menu)

- Menu item: "Check for Updates" — triggers `appInstance.runUpdateCheck(appCtx)` in a goroutine
- If update found: emits `update:available` event → banner appears (or refreshes if already visible)
- If already on latest: no UI change — silent (no "You're up to date" toast in this phase)
- Rate limit is bypassed for manual checks (user-initiated)

### Startup Race Avoidance

- Frontend calls `GetLastUpdateInfo()` bound method on mount (alongside existing `GetVersion()` call)
- Also subscribes to `update:available` via `EventsOn` for future poller events
- This matches the `GetDaemonError()` pattern already in the codebase

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Download Update" |
| Banner message | "Update available: {currentVersion} → {latestVersion}" |
| Banner message (version emphasis) | Versions shown in brighter color (`#c0caf5`); arrow muted (`#565f89`) |
| Dismiss action | "Dismiss" |
| Help menu item | "Check for Updates" |
| Empty state | No empty state — banner is simply absent when no update is available |
| Error state | Silent — no user-visible error when update check fails (network error, 429, 404) |
| Dev build skip | No banner shown — update check skipped entirely when `Version == "dev"` |

Notes:
- No toast or alert for "already on latest" — this phase intentionally has no "up to date" confirmation
- No progress indicator — update check is background-only; user does not see loading state
- No confirmation dialog for destructive actions — no destructive actions in this phase

Source: ROADMAP.md Success Criteria 2 ("banner appears in the Welcome tab showing current version, new version, and a 'Download' button"), REQUIREMENTS.md UPD-02/UPD-03. CTA updated to "Download Update" (noun added for clarity).

## States and Transitions

| UI State | Trigger | Visual Result |
|----------|---------|---------------|
| Banner hidden | App start, `Version == "dev"`, no update found | `.welcome-tab__content` unchanged |
| Banner visible | `update:available` event OR `GetLastUpdateInfo()` non-null | `.update-banner` renders above first section |
| Banner dismissed | "Dismiss" click | Banner removed from DOM (session-scoped; no persistence) |
| Banner refreshed | Second `update:available` event while banner visible | `setUpdate(info)` — same banner, no visible flicker |
