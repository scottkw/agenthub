# Milestone v3.3 Requirements — Shell Sessions & Polish

**Defined:** 2026-05-12
**Last updated:** 2026-05-13 (added SHELL-10/11/12 + Phase 107 mapping); 2026-05-16 (added PARITY-01..04 + Phase 108 mapping)
**Core Value:** One app to launch, manage, and share AI coding terminal sessions across local and remote access — with zero manual setup for web serving, TLS, or session persistence.

**Milestone Goal:** Land raw shell sessions (bash/zsh/pwsh) as a first-class agent type — unblocking the ~9 deferred v3.2 UAT scenarios that require raw PTY — then close v3.2 polish/tech-debt and re-run the deferred UAT batches end-to-end.

**Closes GitHub Issues:** #44 (shell agent), #45 (Settings hyperlinked index).
**Carry-forward absorbed:** v3.2 polish P-1..P-6 (`v3.2-RELEASE-BLOCKERS.md`); 9 deferred v3.2 UAT scenarios; Phase 91 v3.1 distribution-pipeline followups.

## v3.3 Requirements

### SHELL — Raw shell session type (Issue #44)

- [x] **SHELL-01** — User can select a shell in the new-session modal agent picker (Phase 101 — initial multi-row, collapsed by SHELL-10)
- [x] **SHELL-02** — User can launch a shell session from CLI with `agenthub new shell <path>` (Phase 101 — initial `--shell=<name>` flag, removed by PARITY-CLI-01)
- [x] **SHELL-03** — User can launch a shell session from TUI via the existing new-session modal flow (Phase 101 — initial multi-row, collapsed by PARITY-TUI-01)
- [x] **SHELL-04** — Daemon discovers available shells per platform (Phase 100 — `internal/pty/shells.go DiscoverShells()` + Windows PowerShell paths)
- [x] **SHELL-05** — Shell sessions spawn as interactive (not login) with user's WorkDir honored (Phase 100 — `resolveShellSpawn` argv `-i` / `-NoLogo`; empty WorkDir → `os.UserHomeDir()`)
- [x] **SHELL-06** — Shell sessions display distinct slate-cyan #89ddff agent badge in GUI tab + TUI list (Phase 101)
- [x] **SHELL-07** — Shell sessions do NOT auto-enable web serving (Phase 101 — `SHELL_CLIS` set + opt-in gate)
- [x] **SHELL-08** — User sees one-time confirmation banner when first enabling web serving for a shell session (Phase 101 — `ShellWebShareBanner` + `SetShellWebShareWarned` daemon round-trip)
- [x] **SHELL-09** — Shell sessions excluded from CLI-status heuristics; only `running` / `stopped` (Phase 100 — `isShellSession` guard around `status.Watch`)
- [x] **SHELL-10** — New-session modal shows a single "Shell" entry (Phase 107 — reverses SHELL-01's multi-row design after first-user-test feedback)
- [x] **SHELL-11** — Settings → Paths exposes "Shell binary" field; daemon spawns from `shellPath` with `$SHELL` / `/bin/zsh` / `pwsh.exe` fallback; path validated executable (Phase 107)

## Outcomes Note

**Adjusted requirements:**
- **SHELL-01/02/03** — initial multi-row design shipped in Phase 101, then reversed mid-milestone by SHELL-10 (Phase 107 GUI) and PARITY-01/02 (Phase 108 TUI/CLI). Final shape: single "Shell" entry on all three surfaces, binary resolved from Settings-stored `shellPath`.
- **SHELL-12** — scope narrowed during runtime UAT: final behavior is auto-close on any natural exit (zero or non-zero), not zero-only. ExitToast for non-zero descoped per tester decision (commit 5c58277).
- **POLISH-05** — decision rather than implementation: sixel-only support adopted; iTerm2 IIP (OSC 1337) declared out-of-scope indefinitely.

**Dropped:** none.
