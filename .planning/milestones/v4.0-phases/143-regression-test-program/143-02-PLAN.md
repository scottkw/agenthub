<objective>
Create the lightweight (~10-12 line) path-existence CI check (D-03) and wire it into the existing build.yml as a new step on the ubuntu-latest build job (D-05 — reuse existing CI, no new regression.yml). The check parses repo-relative test paths from TESTING.md's traceability table and fails loudly (`exit 1`) when any referenced test file no longer exists — catching the one drift that bites: renamed/deleted tests silently making the map lie.

Purpose: The traceability map is hand-maintained Markdown (D-02); the only automated guard it needs is a path-existence assertion (D-03). Hosting it on the ubuntu-latest build job makes it part of the merge gate (it marks that required build context red when a path is missing).
Output: `tests/check-traceability-paths.sh` and a new "Verify traceability paths exist" step in build.yml.

NOTE ON ORDERING: This plan creates the script and CI step BEFORE TESTING.md exists (Plan 03). The script must therefore tolerate a missing TESTING.md gracefully (treat absent file as "nothing to check, exit 0") so build.yml does not fail on this wave. Plan 03 creates TESTING.md with the conforming table, after which the check has real paths to validate.
</objective>
