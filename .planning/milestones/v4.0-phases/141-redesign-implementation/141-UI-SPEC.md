### Phase 141 task for non-Hub surfaces

The tab bar, sidebar, settings panel, welcome tab, file browser, and editor
currently use **hardcoded hex values** (TokyoNight palette) rather than the
`--hub-*` token system. Phase 141 migrates these surfaces to consume the same
tokens so that the light/dark theme toggle (`[data-ui-theme="light"]`) works
uniformly across all surfaces.

Migration target: every hex constant in non-Hub CSS sections is replaced with
the equivalent `--hub-*` token. New tokens may be introduced only if no
existing token covers the semantic need — introduce them in both `:root`
(dark) and `[data-ui-theme="light"]` blocks.

## CARRY-01: Hub GroupSidebar ARIA Contract

**Requirement:** CARRY-01 / Issue #97. The current GroupSidebar has a
mismatched ARIA pattern: `<ul role="listbox">` contains `<li role="option">`
items each with `tabIndex={0}`. This is incorrect — a `listbox` with `option`
roles requires roving tabindex (exactly one item has `tabIndex={0}`, others
`tabIndex={-1}`) and `aria-activedescendant` on the listbox owner. Currently
every item is independently tabable, which is the `menuitem` / plain button
pattern, not the `listbox` pattern.

**Chosen resolution: drop `listbox`/`option` roles, use plain focusable list.**

Rationale: GroupSidebar is a navigation filter (select a group to view), not a
data selection widget. Plain `<ul>` + `<li>` + `<button>` (or `role="button"`)
is the correct pattern for a list of navigation filter controls. It requires
no roving-tabindex machinery, is simpler to implement correctly, and matches
how screen readers expect navigation filters to work.

**ARIA contract after CARRY-01:**

```
<aside aria-label="Session groups">
  <button aria-label="Expand/Collapse group sidebar" aria-expanded={!collapsed} />
  <span id="hub-group-sidebar-heading">Groups</span>
  <ul aria-labelledby="hub-group-sidebar-heading">
    <!-- Remove role="listbox" entirely -->
    <li>
      <button
        type="button"
        aria-pressed={isActive}   <!-- pressed=true for active group -->
        aria-label="{label} group, {running}/{total} sessions"
      >
        ...
      </button>
    </li>
  </ul>
</aside>
```

Key changes:
1. Remove `role="listbox"` from `<ul>` (no replacement role needed — it is already
   a list via the `<ul>` element)
2. Remove `role="option"` from `<li>` (no replacement role needed)
3. Remove `aria-selected` from `<li>` (that attribute belongs to listbox/option or
   tab/tabpanel patterns, not navigation filters)
4. Replace `<li onClick/onKeyDown>` as the interactive element with an inner
   `<button type="button">` — buttons are natively keyboard-operable; no
   onKeyDown needed for Enter/Space
5. Add `aria-pressed={isActive}` on the button to communicate selected state
   (toggle button pattern — correct for a stateful filter)
6. Add `aria-label` on the button that includes the count: e.g.
   `"All groups, 3/5 sessions"` or `"Frontend group, 2/3 sessions"` so
   screen reader users get count context without needing to read the separate
   count span
7. Add `aria-label="Session groups"` on `<aside>` for landmark labeling

NeedsInputBadge and AttnBadge: these are decorative (`aria-hidden="true"` on
icons already set); the count is communicated via the button's `aria-label`.
Retain the existing badge visuals unchanged.

The "New group" inline input and create button: no changes needed — they are
already correct (a plain `<button>` and a text `<input>`).

**Focus behavior:** Standard tab order through the group list (each button is
individually focusable). No roving-tabindex needed.

## Motion Contract

All animations and transitions in restyled surfaces must follow the established
Hub pattern:

```css
/* Animations: inside no-preference guard */
@media (prefers-reduced-motion: no-preference) {
  .element--animated {
    animation: my-keyframe 200ms ease;
  }
}

/* Static fallback: inside reduce guard */
@media (prefers-reduced-motion: reduce) {
  .element--animated {
    animation: none;
    transition: none;
  }
}
```

Existing examples that already comply: `.find-bar`, `.banner`, `.webgl-recovery-banner`,
`.hub-card--attention`, `.hub-modal`. Phase 141 migrated surfaces must follow this
exact pattern.
