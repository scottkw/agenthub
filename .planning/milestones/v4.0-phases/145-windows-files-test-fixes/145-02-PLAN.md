<objective>
Fix the concurrent-read test failure (Test 3 in RESEARCH.md) on Windows CI.

`TestWriteFileAtomic_ConcurrentReadNeverPartial` runs a reader goroutine that calls `os.ReadFile` in a tight loop while a writer calls `WriteFileAtomic` 200 times. On Windows, `os.ReadFile` opens the file WITHOUT `FILE_SHARE_DELETE`, which blocks the writer's `windows.Renameat` call (it uses `FILE_RENAME_POSIX_SEMANTICS`, which requires all open destination handles to permit delete). The rename fails, the retry loop exhausts, `WriteFileAtomic` returns an error, and the writer's `t.Errorf` fires. This is a test-side POSIX assumption — the production `writeAtomicRename` is correct.

The fix: introduce a build-tagged test helper `readFilePlatformSafe`. On Windows it opens via `syscall.CreateFile` with `FILE_SHARE_READ|FILE_SHARE_WRITE|FILE_SHARE_DELETE` then `io.ReadAll`; on non-Windows it delegates to `os.ReadFile`. The reader goroutine calls the helper. The production retry loop in `sandbox.go` is left untouched.

Purpose: Closes the third and last FIX-02 (#101) failure without changing production atomic-write logic.
Output: Two NEW build-tagged files plus a one-line reader change in `write_test.go`.
</objective>
