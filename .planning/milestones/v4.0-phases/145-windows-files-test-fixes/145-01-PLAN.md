<objective>
Fix the two home-rooting test failures (Tests 1 and 2 in RESEARCH.md) so they pass on the Windows CI runner without weakening the denylist security property.

On the GitHub Actions `windows-latest` runner, `t.TempDir()` lands under `%USERPROFILE%` (i.e. under `$HOME`). `TestHandlerUpload_FilenameSanitized` therefore sees the denylist correctly fire 403 (test expects 200), and `TestDenylist_NonHomeRootedUnaffected` either skips via its case-sensitive `strings.HasPrefix` guard or fails. Both are POSIX-assumption bugs in the test setup, not production bugs.

The fix in both cases: redirect `$HOME` (and `USERPROFILE` on Windows) to a fake directory distinct from the sandbox root via the existing `setHomeEnv(t, fakeHome)` helper, so `denylistCheck` reads a home that is genuinely outside the sandbox root. This is the exact pattern `TestDenylist_HomeRooted` already uses (in reverse — it sets HOME *to* the sandbox root to make the denylist fire).

Purpose: Two of the three FIX-02 (#101) failures are home-rooting POSIX assumptions; this plan closes them without touching production logic.
Output: Modified `internal/files/handler_test.go` and `internal/files/write_test.go`.
</objective>
