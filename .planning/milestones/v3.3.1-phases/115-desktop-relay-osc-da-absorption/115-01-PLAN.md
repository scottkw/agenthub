## Goal

`chafa --format=sixel` and OSC 10/11 + DA1 probes on the desktop Wails surface (and CLI `agenthub attach`) produce clean prompts — no `10;rgb:…`, `11;rgb:…`, `?1;2c`, `62;4;9;22c` typed into shell stdin. Matches the web-surface fix shipped in Phase 111 (`internal/webserver/server.go` `handleWSSRelay`).

## Architecture context

There are two sibling relay code paths from xterm.js bytes to PTY stdin:

| Path | Surface | File | Function |
|------|---------|------|----------|
| Web-share (auth via signed cap-URL) | Browser → webserver:443 → hub | `internal/webserver/server.go` | `handleWSSRelay` |
| Daemon-direct (loopback) | Wails desktop GUI, CLI `agenthub attach` → relay:loopback → hub | `internal/relay/server.go` | `handleSession` |

Both sibling-call `hub.WriteInput`. Phase 111 added `InputAbsorber` to the first path only; the second path was empirically unprotected (RESEARCH Open Question 1 deferred at Phase 111 sign-off, then resolved as FAIL during the post-tag-candidate desktop UAT on 2026-05-19).

## Plan

1. **Move `InputAbsorber`** from `internal/webserver/oscabsorb.go` → `internal/relay/oscabsorb.go` (package rename only — Go import direction was already webserver → relay).
2. **Move `oscabsorb_test.go`** (26-subtest state-machine unit suite) to `internal/relay/`, package rename only.
3. **Update `internal/webserver/server.go`** `handleWSSRelay`: `&InputAbsorber{}` → `&relay.InputAbsorber{}` (one-line type qualification).
4. **Write `internal/relay/oscabsorb_relay_test.go`** — 6 RED integration tests against `handleSession` mirroring the existing webserver-layer suite:
   - OSC 10 reply absorbed
   - OSC 11 reply absorbed
   - DA1 reply absorbed
   - Keystrokes still forwarded (regression guard)
   - OSC 11 split across two frames absorbed in full (state-persistence guard)
   - Mixed reply+keystrokes yields only the keystrokes at PTY
5. **GREEN: Add absorber to `internal/relay/server.go`** `handleSession` read pump — per-subscriber `&InputAbsorber{}` declared before the goroutine, applied to `MsgInput` payload before `hub.WriteInput`. Mirrors the Phase 111 wiring.
6. **Verify**: full `internal/relay` suite under `-race -count=3 -shuffle=on`; full `internal/webserver` suite under `-race -count=1`; existing 26 unit + 6 integration tests still green.
7. **Cross-surface manual UAT**: rebuild Wails app, re-run the OSC 11 + DA1 probe on the desktop surface that previously leaked.

## Out of scope

- CLI `agenthub attach` UAT — covered by the same code path (no separate test required; Go integration tests against `handleSession` exercise the exact wire format).
- Removing the webserver-layer absorber — kept as the absorber for the web-share path (NOT duplicate work; webserver and relay are siblings, not nested).
- Other relay frame types (MsgResize2, MsgPing) — out of scope; absorber only intercepts MsgInput.

## Risks

- **Risk:** Lifting absorber state to per-subscriber level in `handleSession` introduces a state-leak across reconnections of the same session.
  **Mitigation:** Each `handleSession` invocation allocates a new `&InputAbsorber{}`; the zero value is the legitimate starting state. State lives in the goroutine closure and dies with the read pump (matches Phase 111 wiring exactly).
- **Risk:** Webserver layer's absorber becomes redundant.
  **Verified:** Webserver and relay are sibling paths, both call `hub.WriteInput` directly. Each path has its own absorber instance. No double-filtering — they handle disjoint client populations.
