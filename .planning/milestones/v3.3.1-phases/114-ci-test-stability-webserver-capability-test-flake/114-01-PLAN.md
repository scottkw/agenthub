<objective>
Eliminate the wall-clock-dependent flake in TestPluginConfigStream_ExpiredCap_Returns401 by replacing the broken last-byte base64-flip corruption in issueExpiredCapFor with a deterministic wrong-key sign — the Variant A fix locked by 114-RESEARCH.md §6 and 114-CONTEXT.md.

Purpose: Issue #58 closure. Linux CI currently fails ~6% of runs because the helper's "corrupt the last base64 char" pattern is a no-op when the HMAC-SHA256 signature's tail character lands in {A,B,C,D} — those four chars share their top 4 data bits, and the trailing 2 bits are base64 padding the decoder discards. Wall-clock-second of IAT determines which char lands there, so a single CI run either all-passes or all-fails. Variant A (sign with a deliberately wrong key) removes base64/HMAC/wall-clock variance entirely and exercises the same production ErrInvalidSignature → 401 path already proven non-flaky by TestCapability_InvalidSignatureReturns401.

Output: A single fixed helper, a passing local macOS stress run, a VERIFICATION.md documenting evidence + human-gated Linux CI step, and a commit whose message states the base64-padding-bit root cause in writing (TEST-02 acceptance).
</objective>
