## Surface 1: Attach Flow (TUI-03)

### Interaction Model

Pressing `Enter` on a selected session in the list initiates the attach flow. The TUI uses
Bubble Tea's `tea.Exec` mechanism to release terminal control and run the attach logic as
a blocking `ExecCommand`. This is NOT `tea.Suspend` (which sends SIGTSTP) -- it is
`tea.Exec` which releases the terminal, runs the command, and restores the terminal on
completion.

### Attach Sequence

```
1. User presses Enter on selected session
2. TUI validates: session must exist and not be in "errored" state
3. If invalid: show toast "Session not available" (2s, status.errored color)
4. If valid: TUI returns tea.Exec(attachCmd, callback)
5. Bubble Tea calls releaseTerminal (exits alt-screen, restores terminal)
6. attachCmd.Run() executes:
   a. Connect WebSocket to relay (same as cmd_attach.go)
   b. Set terminal to raw mode
   c. Optionally start status bar (same as cmd_attach.go)
   d. Run I/O pump (stdinPump + wsOutputPump)
   e. On Ctrl-\ detach: clean up, return nil
   f. On error: return error
7. Bubble Tea calls RestoreTerminal (re-enters alt-screen, re-enters raw mode)
8. Callback fires: sends attachDoneMsg{err} to Update
9. TUI resumes: refresh sessions, preserve selected index, show any error
```

### What the User Sees

| Phase | Screen State |
|-------|-------------|
| Before attach | TUI session list (normal view) |
| Transition out (step 5) | Instant: alt-screen exits, terminal shows previous scrollback for one frame |
| During attach (step 6) | Raw PTY output fills the terminal, status bar at bottom (if TTY), user interacts normally with the agent session |
| Detach (Ctrl-\) | Status bar cleans up, terminal restored to cooked mode |
| Transition back (step 7) | Instant: alt-screen re-enters, TUI renders fresh list |
| After resume (step 9) | TUI session list with updated data, same session selected |

**No flash or blank screen:** The transition between alt-screen and raw PTY is imperceptible
because both operations write to the same terminal. The user sees the PTY output immediately
after the alt-screen exits.

### ExecCommand Interface

The attach command implements `tea.ExecCommand`:

```
type attachCmd struct {
    client    *daemon.DaemonClient
    sessionID string
    session   *daemon.SessionInfo
}

func (a *attachCmd) Run() error           -- executes the full attach flow
func (a *attachCmd) SetStdin(io.Reader)   -- captures stdin from Bubble Tea
func (a *attachCmd) SetStdout(io.Writer)  -- captures stdout from Bubble Tea
func (a *attachCmd) SetStderr(io.Writer)  -- captures stderr from Bubble Tea
```

The `Run()` method reuses the core attach logic from `cmd_attach.go`: WebSocket dial,
raw mode, status bar, I/O pumps, detach on Ctrl-\. The difference is that stdin/stdout/stderr
are provided by Bubble Tea via the Set* methods rather than using `os.Stdin`/`os.Stdout`
directly.

### Error Handling

| Condition | Response |
|-----------|----------|
| Session not found (deleted during attach) | Toast: "Session ended" (2s, `status.errored` color) |
| WebSocket dial fails | Toast: "Cannot connect to session" (2s, `status.errored` color) |
| Raw mode fails | Toast: "Terminal error: {message}" (2s, `status.errored` color) |
| Attach completes normally (Ctrl-\ detach) | No toast, silent resume, refresh list |

### Keybinding

| Key | Action | Condition |
|-----|--------|-----------|
| `Enter` | Attach to selected session | Session list has items, session not errored |
| `Ctrl-\` | Detach from attached session | During raw PTY attach (not a TUI keybinding) |

## Surface 2: New Session Modal (TUI-04)

### Modal Surface

The new-session modal is a bordered overlay rendered on top of the session list.
The list behind the modal is NOT dimmed or hidden -- the modal simply renders over it
using `lipgloss.Place`, same technique as the help overlay.

```
+--- New Session -----------------------------------+
|                                                    |
|  Agent:      [claude         ] v                   |
|                                                    |
|  Directory:  [/Users/ken/dev/project____]          |
|                                                    |
|  Arguments:  [--model opus________________]        |
|                                                    |
|          Tab: next field  Enter: create  Esc: cancel
+----------------------------------------------------+
```

### Dimensions

| Property | Value |
|----------|-------|
| Width | `max(50, min(70, terminal_cols - 10))` |
| Min height | 11 rows (border + padding + 3 fields + 3 gaps + hint row + border) |
| Max height | Content-driven, never exceeds `terminal_rows - 4` |
| Border | `lipgloss.RoundedBorder()` with `border.normal` color |
| Title | "New Session" rendered in `border.accent` color (same technique as help overlay title) |
| Background | `bg.modal` |
| Padding | `modal-pad-h` (2 chars horizontal), `modal-pad-v` (1 row vertical) |

### Form Fields

| Field | Type | Default Value | Placeholder | Validation |
|-------|------|---------------|-------------|------------|
| Agent | Picker (cycle) | First detected CLI | -- | Must be a detected CLI; if no CLIs detected, show error state |
| Directory | Text input | Current working directory (`os.Getwd()`) | `/path/to/project` | Non-empty; directory existence not validated (daemon handles that) |
| Arguments | Text input | Empty | `--model opus (optional)` | None (can be empty) |

### Agent Picker

The Agent field is NOT a free-text input. It is a cycle-through picker:

- Displays the current agent name (e.g., `claude`)
- `Left`/`Right` arrow keys cycle through detected CLIs
- `Tab` moves to next field (does not cycle agent)
- The detected CLI list is fetched once when the modal opens via `pty.DetectCLIs()`
  (called on the TUI side, not via daemon API -- `pty.DetectCLIs` is a local PATH scan)
- If no CLIs are detected, display: `(none found)` in `fg.danger` and disable `Enter`

Visual format:

```
  Agent:      < claude >
```

The `<` and `>` arrows are rendered in `fg.muted` to indicate cyclability. When focused,
the label "Agent:" is `fg.focused-label` (bold accent). When unfocused, `fg.normal`.

### Text Input Fields

Use `bubbles/v2/textinput.Model` for Directory and Arguments fields:

- `textinput.Model` handles cursor movement, character insertion/deletion, clipboard
- Style: `fg.input` text on `bg.input` background
- Placeholder: `fg.placeholder` on `bg.input`
- Width: modal inner width minus label width minus 2 (for padding)
- When focused: blinking cursor visible (Bubbles textinput default behavior)
- When unfocused: no cursor, value displayed normally

### Focus Cycling

| Key | Action |
|-----|--------|
| `Tab` | Move focus to next field (Agent -> Directory -> Arguments -> Agent) |
| `Shift+Tab` | Move focus to previous field |
| `Enter` | Submit form (create session) |
| `Esc` | Cancel and close modal |
| `Left`/`Right` | Cycle agent picker (only when Agent field focused) |

Focus order: Agent -> Directory -> Arguments (wraps around with Tab).

When a `textinput` field is focused, all key events are delegated to the `textinput.Model`
Update method EXCEPT: `Tab`, `Shift+Tab`, `Enter`, and `Esc` which are intercepted by
the modal's own key handler.

### Submit Flow

1. User presses `Enter`
2. Validate: Agent must be selected (not `(none found)`), Directory must be non-empty
3. If invalid: set error text below the invalid field in `fg.danger`: "Agent is required"
   or "Directory is required"
4. If valid: close modal, show toast "Creating session..." (in `fg.muted`)
5. Fire `tea.Cmd` that calls `client.CreateSession(agent, name, workDir, args, 0, 0)`
   where `name` is `filepath.Base(workDir)`
6. On success: `createSessionMsg{id, nil}` -- refresh session list, select newly created
   session, show toast "Session created" (2s, `status.running` color)
7. On error: `createSessionMsg{"", err}` -- show toast "Create failed: {err}" (3s,
   `status.errored` color)

### Modal State

The modal adds the following state to the Model:

```
type modalState int
const (
    modalNone modalState = iota
    modalNewSession
    modalKillConfirm
)

// In Model:
modal         modalState
agentPicker   agentPickerModel   // agent cycle state
dirInput      textinput.Model    // directory field
argsInput     textinput.Model    // arguments field
focusedField  int                // 0=agent, 1=directory, 2=arguments
detectedCLIs  []pty.DetectedCLI // cached on modal open
```

bubbles/v2/textinput (component API); pty/detect.go DetectCLIs

## Surface 3: Kill Confirmation Dialog (TUI-05)

### Dialog Surface

The kill confirmation is a compact modal overlay, much smaller than the new-session modal.

```
+--- Kill Session ----------------------------------+
|                                                    |
|  Kill session "my-session"?                        |
|  This will terminate the running process.          |
|                                                    |
|              [ No ]    [ Yes ]                     |
|                                                    |
+----------------------------------------------------+
```

### Dimensions

| Property | Value |
|----------|-------|
| Width | `max(40, min(55, terminal_cols - 20))` |
| Height | 7 rows (border + padding + question + detail + gap + buttons + border) |
| Border | `lipgloss.RoundedBorder()` with `border.normal` color |
| Title | "Kill Session" rendered in `fg.danger` color (NOT `border.accent` -- danger context) |
| Background | `bg.modal` |
| Padding | `modal-pad-h` (2 chars), `modal-pad-v` (1 row) |

### Content

| Element | Copy | Style |
|---------|------|-------|
| Question line | `Kill session "{name}"?` | Bold + `fg.danger` |
| Detail line | `This will terminate the running process.` | Normal + `fg.muted` |
| Default option | `[ No ]` | Bold + Reverse video (default focus) |
| Danger option | `[ Yes ]` | Normal + `fg.danger` |
| Selected indicator | Reverse video on the focused option | Swaps when user presses Left/Right |

### Interaction

| Key | Action |
|-----|--------|
| `Left`/`Right` or `h`/`l` or `Tab` | Toggle between No and Yes |
| `Enter` | Confirm the focused option |
| `Esc` | Cancel (same as selecting No) |
| `y` | Quick-confirm Yes (shortcut) |
| `n` | Quick-confirm No (shortcut) |

**Default focus is No.** This is a safety measure -- pressing Enter without thinking
dismisses the dialog without killing the session.

### Kill Flow

1. User presses `d` on a selected session
2. Kill confirmation dialog opens with default focus on No
3. User selects Yes and presses Enter (or presses `y`)
4. Dialog closes, show toast "Killing session..." (in `fg.muted`)
5. Fire `tea.Cmd` that calls `client.KillSession(sessionID)`
6. On success: `killSessionMsg{nil}` -- refresh session list, clamp selection index,
   show toast "Session killed" (2s, `fg.muted`)
7. On error: `killSessionMsg{err}` -- show toast "Kill failed: {err}" (3s,
   `status.errored` color)

### Kill State

```
// In Model (additions):
killTarget    *daemon.SessionInfo // session being killed (for dialog display)
killFocusYes  bool                // false = No focused (default), true = Yes focused
```

## Surface 4: Rename (TUI-06)

### Design Decision: Inline Edit (not modal)

Rename uses **inline edit** rather than a modal. Rationale:

1. Rename is a single-field operation -- a modal is heavyweight for one text input
2. Inline edit provides immediate spatial context (user sees which session is being renamed)
3. Matches the pattern of spreadsheet/table inline editing which is familiar in TUI contexts
4. The Phase 76 UI-SPEC future-phase hook already specified: "Selected row must support an
   'editing' state with text input" (76-UI-SPEC.md line 457)

### Visual

When the user presses `r` (changed from `e` -- see Keybindings section), the selected row's
Name column transforms into an editable text input:

```
Before:
  > ● my-session       claude    macbook-pro   2

During rename:
  > ● [my-session____]  claude    macbook-pro   2
```

The text input replaces the Name column content. The `[` and `]` brackets are NOT literal --
the text input field is styled with `bg.input` background to visually distinguish it from
the normal row. The cursor blinks at the end of the current name.

### Dimensions

| Property | Value |
|----------|-------|
| Input width | Same as Name column width (`terminal_cols - 53`, min 8) |
| Input style | `fg.input` on `bg.input`, same as modal form fields |
| Placeholder | None (pre-filled with current name) |

### Interaction

| Key | Action |
|-----|--------|
| `r` | Enter rename mode on selected session (replaces `e` from Phase 76 reservation) |
| `Enter` | Submit rename |
| `Esc` | Cancel rename, restore original name |
| All other keys | Delegated to `textinput.Model` for editing |

When in rename mode, the model is in `editing` state. All navigation keys (`j`, `k`, `g`,
`G`, `?`, `q`, `d`, `n`) are suppressed -- only the textinput keys, `Enter`, and `Esc`
are active. This prevents accidental navigation while typing.

### Submit Flow

1. User presses `Enter` to submit
2. Validate: name must be non-empty after trimming whitespace
3. If empty: show inline error "Name cannot be empty" as toast (2s, `status.errored` color),
   keep editing mode active
4. If same as original: exit editing mode silently (no API call)
5. If changed: exit editing mode, show toast "Renaming..." (in `fg.muted`)
6. Fire `tea.Cmd` that calls `client.RenameSession(sessionID, newName)`
7. On success: `renameSessionMsg{nil}` -- refresh session list, show no toast (name
   visually updated in list is sufficient feedback)
8. On error: `renameSessionMsg{err}` -- show toast "Rename failed: {err}" (3s,
   `status.errored` color)

### Duplicate Name Handling

No client-side duplicate checking. The daemon API does not enforce unique names
(sessions are identified by UUID). If the user sets a duplicate name, it succeeds.
This matches the existing CLI behavior (`agenthub rename` does not check for duplicates).

### Rename State

```
// In Model (additions):
editing       bool               // true when inline rename is active
editInput     textinput.Model    // rename text input
editOriginal  string             // original name (for cancel restoration)
editSessionID string             // ID of session being renamed
```

## Updated Keybinding Map

### Key Changes from Phase 76

| Key | Phase 76 Status | Phase 77 Status | Change Reason |
|-----|----------------|----------------|---------------|
| `Enter` | Reserved (toast) | **Active** -- attach | TUI-03 implementation |
| `n` | Reserved (toast) | **Active** -- new session modal | TUI-04 implementation |
| `d` | Consumed silently | **Active** -- kill confirmation | TUI-05 implementation |
| `e` | Consumed silently | **Freed** -- no longer consumed | Replaced by `r` for rename (see below) |
| `r` | Active (refresh) | **Changed** -- rename (refresh moved) | Rename is more frequent than manual refresh; `r` = rename is mnemonic |
| `R` | Not used | **Active** -- refresh list | Manual refresh moved to Shift+R |

**Key reassignment rationale (`r` -> rename, `R` -> refresh):**
- Phase 76 reserved `e` for rename, but `r` is the more intuitive mnemonic (r=rename)
- Manual refresh (`r` in Phase 76) is rarely needed due to 2-second auto-polling
- `R` (Shift+R) is still discoverable and logical for "Refresh"
- `d` = delete/kill is the standard TUI convention (vim, ranger, lazygit)
- No collision: `d` was already consumed silently, `r` was refresh, `e` was consumed silently

When a modal or inline edit is active, the main view keybindings are suppressed.
Each context has its own key handling:

`Tab` / `Shift+Tab` (cycle fields), `Enter` (submit), `Esc` (cancel),

**Kill Confirmation:**
`Left` / `Right` / `h` / `l` / `Tab` (toggle focus), `Enter` (confirm),
`Esc` (cancel), `y` (quick-yes), `n` (quick-no).

**Inline Rename:**
`Enter` (submit), `Esc` (cancel), plus all textinput keys.

## Loading / In-Flight States

When daemon RPC calls are in-flight (creating session, killing session, renaming),
the UI provides feedback via toast messages. There is NO spinner -- the operations
are fast (local Unix socket) and a spinner would add visual noise to the character-cell
grid.

| Operation | In-Flight Indicator | Duration |
|-----------|-------------------|----------|
| Create session | Toast: "Creating session..." (`fg.muted`) | Until response |
| Kill session | Toast: "Killing session..." (`fg.muted`) | Until response |
| Rename session | Toast: "Renaming..." (`fg.muted`) | Until response |
| Attach (connecting) | No indicator -- transition is instant | < 100ms |

**Toast display location:** Same as Phase 76 -- replaces the web status text in footer
line 1 for the toast duration (2-3 seconds depending on success/error).

**Toast expiry:** Success toasts: 2 seconds. Error toasts: 3 seconds. In-flight toasts:
replaced by success/error toast when response arrives.

Source: 76-UI-SPEC.md (toast mechanism already exists in Phase 76 for reserved keys)

## State Machine Overview

The Model transitions between these states:

```
                                  +---------+
                          Esc     |  Help   |
                     +----------->| Overlay |<---------+
                     |    ?       +---------+    ?     |
                     |                                 |
                     v                                 |
+--------+  Enter  +---------+  n   +-----------+     |
| (init) |-------->|  Main   |----->| New Sess  |     |
|        |         |  View   |<-----| Modal     |     |
+--------+         |         | Esc  +-----------+     |
                   |         |                         |
                   |         |  d   +-----------+     |
                   |         |----->| Kill      |     |
                   |         |<-----| Confirm   |     |
                   |         | Esc  +-----------+     |
                   |         |                         |
                   |         |  r   +-----------+     |
                   |         |----->| Inline    |     |
                   |         |<-----| Rename    |     |
                   |         | Esc  +-----------+     |
                   |         |                         |
                   |         | Enter +-----------+    |
                   |         |------>| Attached  |    |
                   |         |<------| (Exec)    |    |
                   +---------+ done  +-----------+    |
```

**State priority for key handling:**
1. If `editing` (inline rename) -- handle rename keys only
2. If `modal == modalKillConfirm` -- handle kill confirm keys only
3. If `modal == modalNewSession` -- handle new session modal keys only
4. If `showHelp` -- handle help dismiss only
5. Otherwise -- handle main view keys

Modals prevent interaction with the list behind them. When a modal is open, the 2-second
tick continues to fire and update session data in the background, but navigation keys are
suppressed.

## Anti-Patterns Prohibited by This Contract

The executor must not do any of the following in Phase 77:

1. **Use `tea.Suspend` for attach** -- `tea.Suspend` sends SIGTSTP which backgrounds the
   process. Use `tea.Exec` which releases the terminal for a blocking operation and restores
   it on completion.
2. **Block Update() during attach** -- the attach flow runs inside `tea.Exec`, not in Update.
   Update only dispatches the `tea.Exec` command.
3. **Implement a spinner for RPC calls** -- local Unix socket calls are < 100ms. Toast
   messages are sufficient. A spinner adds character-cell rendering complexity for no
   user benefit.
4. **Validate directory existence client-side** -- the daemon validates the path when creating
   the session. Client-side `os.Stat` would add latency and may give stale results.
5. **Check for duplicate session names** -- the daemon does not enforce unique names. Do not
   add client-side uniqueness checks.
6. **Show kill confirmation for stopped/errored sessions differently** -- use the same
   confirmation dialog regardless of session state. The daemon handles cleanup.
7. **Dim the background when a modal is open** -- `lipgloss.Place` overlays the modal content;
   character-cell terminals cannot dim arbitrary regions. The modal border provides sufficient
   visual separation.
8. **Use `os.Stdin`/`os.Stdout` directly in attachCmd.Run()** -- use the io.Reader/io.Writer
   provided by `SetStdin`/`SetStdout`/`SetStderr` from the ExecCommand interface.
9. **Call `pty.DetectCLIs()` on every modal open** -- cache the result for the lifetime of
   the TUI process (the PATH is unlikely to change during a session).
10. **Allow `q` or `Ctrl+C` to quit during modal/rename** -- these keys must be consumed by
    the active surface. Only `Esc` cancels a modal. `q` quits only from the main view.
