<objective>
Wire query parameter parsing (?readonly=, ?client=) and read-only enforcement into both WebSocket server handlers (relay/server.go and webserver/server.go), and replace the unconditional hub.Resize() call with hub.ResizeClient() for max-wins arbitration.

Purpose: This is the enforcement layer — Hub extensions from Plan 01 store per-client metadata, but this plan makes the server handlers actually populate those fields and gate behavior on them. Both the TCP relay path (CLI attach) and the HTTPS relay path (browser) must be updated identically.
Output: Modified server.go files with query param parsing + read-only enforcement + ResizeClient call; test proving read-only enforcement works end-to-end.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client -> WebSocket handler | URL query params (?client=, ?readonly=) carry untrusted input from connecting clients |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-74-03 | Tampering | client name query param | mitigate | Cap clientName at 64 characters in both server.go handlers: `if len(clientName) > 64 { clientName = clientName[:64] }` — prevents oversized strings in session metadata |
| T-74-04 | Elevation of Privilege | readonly bypass | accept | Read-only is user convenience, not security boundary. Clients on the same Tailscale network can already connect without ?readonly=1. Network-level trust model applies. |
| T-74-05 | Spoofing | client identity | accept | Client name is self-reported via ?client= param. No authentication of identity — same trust model as existing WebSocket connections (Tailscale network membership). |
</threat_model>
