# Phase 75 — UI Design Contract: CLI Status Bar

> Visual and interaction contract for Phase 75. This phase is a terminal UI (TUI) surface,
> not a browser UI. The "design system" is ANSI escape sequences rendered to a TTY.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — pure ANSI escape sequences via Go stdlib |
| Preset | not applicable |
| Component library | none — hand-rolled via `internal/statusbar` package |
| Icon library | none — Unicode box-drawing characters only (`│`, `…`) |
| Font | terminal's default monospace — not specified by app |

**shadcn gate result:** Not applicable. This is a Go CLI application with no React/Next.js/Vite frontend. The "UI" surface is a one-row ANSI status bar drawn to stdout.

Source: RESEARCH.md — "No New Dependencies Required. All functionality can be implemented with stdlib and existing go.mod dependencies."

## Spacing Scale

The status bar is a single terminal row. Traditional pixel spacing does not apply. Column
spacing is expressed in character-cell units (each cell is one monospace character width).

| Token | Characters | Usage |
|-------|-----------|-------|
| inner-pad | 1 | Leading/trailing space inside bar: `" " + content + " "` |
| separator | 3 | ` │ ` (space + pipe + space) between fields |
| truncation-indicator | 1 | `…` appended when content exceeds terminal width |

Exceptions: none. Status bar occupies exactly one terminal row (row `height` for bottom,
row `1` for top). No other spatial dimensions are declared for this phase.

Source: RESEARCH.md Pattern 6 — `" " + strings.Join(parts, " │ ") + " "`

---

## Typography

Terminal typography is monospace by the host terminal. The following contracts govern
content formatting, not font selection.

| Role | Width | Weight | Formatting |
|------|-------|--------|------------|
| Bar text | truncated to `cols` chars | normal (no bold) | reverse video (`\033[7m`) entire bar |
| Field separator | 3 chars: ` │ ` | normal | inherits bar reverse video |
| Truncation marker | 1 char: `…` | normal | replaces last visible character |
| Elapsed time | `M:SS` or `H:MM:SS` | normal | right-most field |

**Line height:** exactly 1 row (no leading/trailing newlines in bar draw — `fmt.Fprint` only,
never `fmt.Println`).

Source: RESEARCH.md Pattern 6 — format function and anti-pattern "Using fmt.Println inside the bar draw."

## Color

The terminal status bar uses exactly two ANSI SGR states. No hex values — this is a TTY
surface rendered by the host terminal's own color scheme.

| Role | ANSI Code | Usage |
|------|-----------|-------|
| Bar background + foreground | `\033[7m` (reverse video) | Entire status bar line — inverts terminal's default fg/bg |
| Reset | `\033[m` (SGR reset) | Appended at end of bar text — restores normal terminal colors |

**60/30/10 mapping for a TTY bar:**
- 60% dominant: transparent — the scrollable PTY region uses the terminal's own colors
- 30% secondary: not used in this phase
- 10% accent: not used in this phase — REQUIREMENTS.md explicitly defers: "Rich color themes for status bar — Functional, not decorative — ship one well-chosen scheme"

**Destructive color:** not applicable — no destructive actions exist in the status bar.

Source: RESEARCH.md Pattern 6 — `return "\033[7m" + text + "\033[m"`
Source: REQUIREMENTS.md Out of Scope — "Rich color themes for status bar"

## Status Bar Content Contract

> This section replaces the standard "Copywriting Contract" for terminal UI surfaces.
> The bar is not a form or dialog — it is a persistent informational strip.

### Field Layout (left to right)

```
 <session-name> │ <agent-type> │ <hostname> │ Ctrl-\ to detach [│ <N> viewers] [│ <conn-state>] │ <elapsed>
```

All fields mandatory unless conditionally suppressed (see rules below).

| Field | Content | Condition |
|-------|---------|-----------|
| session-name | Session name string (as stored in daemon) | Always shown |
| agent-type | CLI type string, e.g. `claude`, `opencode` | Always shown |
| hostname | Machine hostname | Always shown |
| detach hint | Literal: `Ctrl-\ to detach` | Always shown |
| viewer count | `N viewers` where N is integer | Shown only when N > 1 (SB-04) |
| connection state | `[reconnecting]` | Shown only for remote sessions with no frame for >5s (SB-05). When connected, this field is omitted. |
| elapsed time | `M:SS` when hours = 0; `H:MM:SS` when hours >= 1 | Always shown, right-most field |

### TTY Suppression

The entire bar — including all setup ANSI sequences — is suppressed when `os.Stdout` is not
a TTY. `term.IsTerminal(int(os.Stdout.Fd()))` must return `true` before any bar code runs.

Copy: none (no output is produced when suppressed).

Source: REQUIREMENTS.md SB-03, RESEARCH.md Pattern 2.

### Empty State

Not applicable. The bar is present as long as attach is active. There is no "no data" state —
session name, agent type, and hostname are known at attach time and never absent.

### Error / Degraded States

| Condition | Bar Behavior |
|-----------|-------------|
| `term.GetSize` fails on tick | Skip the draw cycle silently — do not write partial output |
| Bar draw goroutine panics | `bar.Stop()` must still be callable via `defer` — use `sync.Once` to guard stop |
| `bar.Stop()` called multiple times | Safe — `sync.Once` ensures reset + clear runs exactly once |

### Cleanup Copy

On `bar.Stop()`, the bar line is cleared and the cursor is left in the scrollable region.
No user-visible message is shown. The terminal must be restored to pre-attach state with
no leftover artifacts.

Source: REQUIREMENTS.md SB-07, RESEARCH.md Pattern 1 cleanup sequence.

## Interaction Contract

### Keyboard

| Input | Response |
|-------|----------|
| `Ctrl-\` | Triggers detach (handled by `cmd_attach.go` signal handler, not by bar) |
| Any other key | Forwarded to PTY unchanged — bar does not intercept input |

### Terminal Resize (SIGWINCH)

On each 1-second tick, `bar.draw()` calls `term.GetSize(fd)` and compares to stored dimensions.
If dimensions changed, re-issue `ESC[1;{rows-1}r` (or `ESC[2;{rows}r` for top placement)
before drawing. This self-healing approach requires no explicit SIGWINCH listener in the bar
package.

Source: RESEARCH.md Pattern 5.

### Placement Flag

| Flag | Bar Row | Scroll Region |
|------|---------|---------------|
| (default — bottom) | row `rows` | `ESC[1;{rows-1}r` |
| `--status-top` | row `1` | `ESC[2;{rows}r` |

Source: REQUIREMENTS.md SB-06.

### Refresh Rate

Fixed 1-second tick via `time.NewTicker(time.Second)`. Not configurable in this phase.

## ANSI Escape Sequence Contract

All escape sequences used by `internal/statusbar`. No others are permitted in the package.

| Constant name | Escape string | Effect |
|--------------|--------------|--------|
| `setScrollRegion` | `\033[%d;%dr` | Set scrollable rows to [top, bottom] |
| `resetScrollRegion` | `\033[r` | Reset scroll region to full terminal |
| `cursorSave` | `\033[s` | Save current cursor position (DECSC/SCO variant) |
| `cursorRestore` | `\033[u` | Restore saved cursor position |
| `moveCursor` | `\033[%d;1H` | Move cursor to row r, column 1 (1-indexed) |
| `eraseLineEntire` | `\033[2K` | Erase entire current line |
| `reverseVideo` | `\033[7m` | Enable reverse video attribute |
| `sgReset` | `\033[m` | Reset all SGR attributes |

Source: RESEARCH.md Pattern 1 — VT100 specification, verified against vt100.net/docs/vt510-rm/DECSTBM.html.

## Anti-Patterns Prohibited by This Contract

The executor must not do any of the following in `internal/statusbar`:

1. Write to stdout inside `wsOutputPump` — bar draws must happen only in the ticker goroutine
2. Use `fmt.Println` in bar draw — no trailing newlines (causes spurious scroll)
3. Check `os.Stdin.Fd()` for TTY — must check `os.Stdout.Fd()`
4. Allow `bar.Stop()` to panic on double-call — must use `sync.Once`
5. Use an external ANSI/color library — the 8 constants above are sufficient
6. Block `Hub.BroadcastMeta` on slow clients — must use non-blocking send (same pattern as `hub.broadcast()`)
7. Poll the daemon API for viewer count — viewer count arrives via `MsgMeta` push frame only

Source: RESEARCH.md Anti-Patterns section.
