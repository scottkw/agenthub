# Milestone v3.5: File Browser — Write Operations & Editor

**Status:** ✅ SHIPPED 2026-06-15
**Phases:** 123-128 (6 phases)
**Total Plans:** 27/27
**Closes:** GitHub Issues #63 (editing + upload) + #64 (TUI edit parity). Umbrella epic #24 retires on the two-machine tailnet write UAT (committed checklist, RMW-06).

## Overview

Ships the write-side half of the file-browser epic (Issue #24) with full cross-surface parity. Extends the v3.4 `internal/files/` `os.OpenRoot` sandbox with TOCTOU-free write primitives (atomic write, rename/move, mkdir, recursive delete, multipart upload), enforces a shell-RC denylist on every write path, and exposes auth-less daemon local-socket write routes. A new opt-in `files.write` capability bit (never default-on — owner explicitly enables per session; web-share viewers require a further explicit grant) gates the network-facing webserver write routes behind `requireFilesWrite` + a CSRF Origin check, with `schemaVersion: 4` migration. The milestone centrepiece is a CodeMirror 6 editor (vendored, zero new CSP amendments) replacing the v3.4 plain-text preview — syntax highlighting by extension, atomic Cmd/Ctrl+S save with `If-Match`/412 conflict detection, dirty-state + unsaved guard, and the full write-affordance suite (create/mkdir/delete/rename/cross-directory-move/single+multi upload with drag-and-drop). TUI write parity arrives via `$EDITOR` shell-out plus `d`/`r`/`m` keyboard ops (upload formally descoped, #82). A dedicated security-hardening phase audits the most-exposed (web-share) write surface end-to-end, and the final phase proves remote tailnet peer write parity with the same 3-independent-observer pattern as v3.4 Phase 122.

**Pattern reaffirmed:** the v3.4 read stack's unifying contracts were extended verbatim — the Go `FilesClient` interface grew from 4 to 8 methods (read + write), and the TS `FilesApiClient` switches local vs remote via `pathPrefix`. One pipeline drives local AND remote writes across all surfaces. Cross-surface (GUI/TUI/web/CLI) parity remained a release-blocking contract throughout (v3.3 Phases 107/108 standard).

## Milestone Summary

**Audit status:** `tech_debt` (audited 2026-06-15, accepted). 55/55 requirements satisfied at code/test level via 3-source cross-reference; 6/6 phases verified (5 passed, Phase 128 `human_needed` for the operator two-machine UAT only); cross-phase integration 98/100 PASS (all E2E flows WIRED; the one integration WARNING — TUI cap-expiry toast missing the GUI's reassurance suffix — was fixed during the audit). No unsatisfied requirements, no critical blockers.

**Key Decisions:**

- **CodeMirror 6, NOT Monaco.** Monaco's `worker-src blob:` CSP requirement violates the vendored-only / single-binary discipline; ~135 KB vs 2.4–6 MB. Zero new CSP amendments — `style-src 'unsafe-inline'` already covers CodeMirror's inline style injection. (✓ Good — research-ratified at scoping, no plan-time gate.)
- **`files.write` opt-in for ALL tokens — never default-on.** No cap (owner or viewer) carries `files.write` by default; the owner enables per session (toggle default OFF), web-share viewers require a further explicit grant. A home-directory session (Claude Code's default `cwd=$HOME`) is never one mis-share away from RC-file overwrite. (✓ Good — least-privilege; shell-RC denylist + home-dir warning are defense-in-depth.)
- **Atomic write via sibling temp + `f.Sync()` + `root.Rename`, no `O_TRUNC`.** A concurrent AI-agent reader must never observe an empty/partial file. Temp file stays inside the sandbox root (system temp dir escapes the sandbox and loses cross-filesystem rename atomicity). `crypto/rand` 8-byte suffix + `O_EXCL` for race-free temp naming. (✓ Good.)
- **`os.Root.Rename` does not exist (golang/go#69462) — validate BOTH paths, then `os.Rename`.** Destination-path traversal is the #1 write-side traversal risk; the destination is validated identically to the source. Same path serves same-directory rename AND cross-directory move. (✓ Good.)
- **Separate `requireFilesWrite` middleware — NOT added to `requireCapability` switch.** Mirrors the load-bearing v3.4 `requireFilesRead` isolation; avoids risk to terminal relay routes. Adds the CSRF Origin check that the GET-only read surface didn't need. (✓ Good.)
- **CSRF Origin inversion: absent Origin passes, present must match FQDN.** Desktop Wails `fetch()` sends no Origin (passes vacuously); browser web-share requests must match. Reapplies the Phase 88 WebSocket Origin pattern to write verbs. (✓ Good.)
- **ETag = `"<UnixNano>-<size>"` (mtime + size), NOT full-content hash.** Cheap optimistic-concurrency validator confined to `os.Root` via `Sandbox.Stat`. Force-overwrite sends `If-Match: *` (server contract: wildcard = skip-check). (✓ Good.)
- **ConflictModal (412) defaults focus on "Discard my changes" — the safe choice, not Force overwrite.** Matches the QuitConfirmModal safe-default-focus invariant; the editor buffer is never silently discarded. (✓ Good.)
- **Auto-save explicitly OUT.** AI agents watch the filesystem; auto-saving partial edits would feed corrupt files into a live coding session. Explicit Cmd/Ctrl+S only. (✓ Good — anti-feature avoided.)
- **TUI edit via `$EDITOR` shell-out (`tea.Exec`), NOT in-TUI CodeMirror.** The TUI is a real terminal, not a WebView; shell-out is the correct Unix pattern (`git commit`, `crontab -e`). Fallback chain `$EDITOR` → `$VISUAL` → `nano` → `vim` → `vi`; `tea.ClearScreen` + unconditional refresh on exit. (✓ Good.)
- **`FilesClient` interface grows 4 → 8 methods; one pipeline drives local AND remote.** Both `*daemon.DaemonClient` and `*tui.RemoteFilesClient` satisfy all 8; duck-typed parity preserved. TS side switches local vs remote via `pathPrefix`. (✓ Good — single unifying contract, mirrors v3.4.)
- **ASCII case-fold (`strings.ToLower`) for the denylist, not NFC normalization.** All protected names are ASCII; NFC documented as LOW residual. EvalSymlinks-rebase pattern handles macOS `/var/...` vs `/private/var/...`; `os.UserConfigDir` derives the daemon config dir; static `.config/agenthub/` prefix kept as belt-and-suspenders for cross-platform copied trees. (✓ Good.)
- **Remote write parity proven by 3 independent observers.** daemon-proxy Go + `tui.RemoteFilesClient` Go + Playwright HTTPS browser observe byte-identical write-then-read against a shared persisting fixture peer — strongest automated evidence pending the two-machine UAT. Mirrors the Phase 122 read-parity proof. (✓ Good.)
