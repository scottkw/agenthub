## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#1a1b26` | Main background, terminal container, daemon panel body |
| Secondary (30%) | `#16161e` | Tab bar, status bar, code blocks, input backgrounds |
| Accent (10%) | `#7aa2f7` | Active tab underline, focused input borders, link text, primary CTA buttons |
| Destructive | `#f7768e` | Kill button hover, close button hover, error state text |

Accent reserved for: active tab indicator (2px bottom border), focused input/select border, URL link text, primary action buttons (Save, Create Session), "Kill" button hover border only.

Source: `style.css` — verified from `.tab--active` (#7aa2f7 border-bottom), `.settings-panel__btn--save` (#7aa2f7 background), `.daemon-panel__btn--kill:hover` (#f7768e color).

**Tray icon color:** The tray icon (`assets/tray_icon.png`) is an 18x18 monochrome black+alpha PNG. `[NSImage setTemplate:YES]` is already set in `tray.go` — macOS renders it white on dark menu bars and black on light menu bars automatically. This is outside the CSS color contract.

**Tray error icon color:** Same monochrome format — error state communicated by shape change (hollow or "!" glyph), not by color. macOS template images do not support color tinting.

**Daemon state indicator in tray tooltip:** Text only, no color — tooltip is plain NSString rendered by macOS.

### New Frontend Surface: `tray:focus-session` Event Handler

**Location:** `App.tsx`

**Behavior:** When the Go backend emits `tray:focus-session` (with a session ID payload), `App.tsx` calls `setActiveId(sessionId)` to focus the matching tab. If no tab with that session ID exists, the event is silently ignored.

**Visual result:** The tab for the clicked session gains `.tab--active` styling (existing pattern — no new CSS needed).

**Implementation pattern:**
```tsx
// In App.tsx useEffect, alongside existing Wails event subscriptions
EventsOn('tray:focus-session', (sessionId: string) => {
  const tab = tabs.find(t => t.sessionId === sessionId)
  if (tab) setActiveId(tab.id)
})
```

No new CSS classes. No new React components. No design tokens needed beyond existing `.tab--active`.

## Tray Menu Structure (Native — macOS NSStatusItem)

This is informational for the executor. The tray menu is rendered by Objective-C via `NSMenuDelegate`, not by React. Copy below defines the exact menu item labels.

| Position | Label | Action | State condition |
|----------|-------|--------|-----------------|
| 0 | Open AgentHub | `runtime.WindowShow` | Always visible |
| 1 | — (separator) | — | Always |
| 2..N | `{session.name}` | `tray:focus-session` event + WindowShow | One item per active session; hidden when 0 sessions |
| N+1 | — (separator) | — | Always |
| N+2 | Quit | `ShutdownDaemon` + `runtime.Quit` | Always visible |

**Tray tooltip format:** `"AgentHub — {N} session"` / `"AgentHub — {N} sessions"` / `"AgentHub — no sessions"` (source: RESEARCH.md Pattern 4 code example).

**Tray icon states:**
- Normal (daemon reachable): `assets/tray_icon.png` — 18x18 monochrome filled glyph
- Error (daemon unreachable): `assets/tray_icon_error.png` — 18x18 monochrome with hollow or "!" variant

| Action | Location | Confirmation approach |

**No new in-app dialogs** are introduced in Phase 41. The daemon shutdown flow is silent (no toast, no modal) — the app simply exits.

## Interaction States

### Window Close (Red Traffic Light)

| State | Visual | User expectation |
|-------|--------|-----------------|
| Window closes | Window disappears | Tray icon remains in menu bar |
| App continues | Tray icon visible with normal state | Sessions continue uninterrupted |

No frontend UI change needed — `HideWindowOnClose: true` handles this in Go.

### Tray Icon State Transitions

| Trigger | Icon | Tooltip |
|---------|------|---------|
| Daemon reachable, N sessions | `tray_icon.png` (filled) | "AgentHub — {N} session(s)" |
| Daemon unreachable | `tray_icon_error.png` (error variant) | "AgentHub — no sessions" |
| Poll interval | 5 seconds (Go background goroutine) | Updates on each poll cycle |

### Tab Focus via Tray

| Event | Frontend action | Visual result |
|-------|----------------|---------------|
| User clicks session name in tray menu | `tray:focus-session` emitted | Window shows, tab with matching `sessionId` becomes active (`.tab--active`) |
| Session not found in tabs | Event silently ignored | No visual change |
