## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser/remote → webserver write route | Untrusted HTTP crosses here; cap token + Origin are the only gates |
| desktop Wails fetch → webserver write route | Local, no Origin header; trusted by absence-of-Origin |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-124-01 | Elevation of Privilege | `requireFilesWrite` perm check | mitigate | Use `capability.HasPerm(claims.Perms, PermFilesWrite)` (comma-split whole token); a cap with `"read,write"` but no `files.write` reaches the HasPerm branch and gets 403. NEVER `strings.Contains` (`"no-files.write"` false-positives). |
| T-124-02 | Elevation of Privilege | substring check regression | mitigate | `TestHasPerm_NoStringsContains_Write` static-grep gate fails any write-path file containing `strings.Contains(` together with `"files.write"`. |
| T-124-03 | Tampering | CSRF on POST/PUT/DELETE write verbs | mitigate | `originAllowedForWrite`: present Origin must byte-match `BaseURL()`; mismatch → 403. Fail closed when `BaseURL()` empty AND Origin present. |
| T-124-04 | Elevation of Privilege | adding files.write to requireCapability switch | mitigate | `requireFilesWrite` is a THIRD separate wrapper; `TestRequireCapability_UnchangedByPhase118` pins that requireCapability never mentions files.read/files.write. |
| T-124-05 | Information Disclosure | wrong status (404/401 instead of 403) leaks route existence/auth state | mitigate | Wrapper ordering requireCapability (401) → HasPerm (403) → Origin (403); `TestRequireFilesWrite` asserts exactly 403 (not 404/401) on a valid-cap-missing-perm. |
</threat_model>
