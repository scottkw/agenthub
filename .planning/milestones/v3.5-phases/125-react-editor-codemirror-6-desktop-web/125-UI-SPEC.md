# Phase 125 — UI Design Contract

> Visual and interaction contract for the milestone centrepiece: a CodeMirror 6 text editor plus the full write-affordance suite (create file, mkdir, delete, rename, cross-directory move, single + multi-file upload, drag-and-drop) wired into the existing `FileBrowserTab`. Identical UX on the desktop (Wails) and web-share surfaces.
>
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** This phase ships the editor (EDIT-01..08, EDIT-11) and the directory write affordances (EDIT-09, EDIT-10), all gated on `canWrite` (EDIT-12). The capability opt-in toggles and home-dir warning were Phase 124 — out of scope here. The TUI `$EDITOR` shell-out is Phase 126 — out of scope. Mirror the existing v3.4 read-side design language exactly: BEM `file-browser__*` classes, `@heroicons/react/24/outline` glyphs, the QuitConfirmModal overlay/dialog pattern, the TokyoNight palette. Introduce zero new color hexes. CodeMirror's own theme uses the same TokyoNight token values declared below.

## Color

TokyoNight palette — every value already exists in `style.css` (verified in `.file-browser__btn`, `.file-browser__preview-header`, `QuitConfirmModal`). **Introduce no new hexes.** The CodeMirror 6 theme is configured to consume these same tokens.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#1a1b26` / `#16161e` | App + editor background; header bar (`#16161e`); modal overlay scrim is `rgba(0,0,0,0.6)` |
| Secondary (30%) | `#1e2030` (modal/dialog surface, button hover), `#292e42` (borders), `#c0caf5` / `#9aa5ce` (body / muted text) | Modal surfaces, borders, editor gutter background, body + caption text |
| Accent (10%) | `#7aa2f7` | Primary CTA fill (Save, Replace, Move here, Upload-confirm); focus outlines (`outline: 2px solid #7aa2f7`); dirty-marker bullet `●`; CM6 active-line gutter / cursor |
| Destructive | `#f7768e` | Delete confirm button fill; conflict "Force overwrite" emphasis; recursive-delete warning glyph |

Accent (`#7aa2f7`) reserved for: the single primary action button in each surface (Save in the editor header; Replace / Move here / Upload in modals), keyboard focus outlines, the dirty-state bullet, and CodeMirror cursor/active-line. NOT for body text, NOT for every button (secondary buttons keep the `#292e42` outline + transparent fill), NOT for the save "Saved" success state (that uses a green check glyph — see colorblind contract).

Status colors for the save indicator (existing dot palette from `QuitConfirmModal.dotColor`):
- saving — `#e0af68` (amber/idle dot) reinforcement only
- saved — `#9ece6a` (green/running dot) reinforcement only
These are reinforcement; the glyph + word carry the meaning (see below).

### Colorblind safety (RELEASE-BLOCKING — user is colorblind)

Every editor state and every destructive confirmation MUST carry a non-color signal (icon glyph + text word). Color is decoration only. Verification is at the source level (glyph + literal text token in code), never by eye.

| State / element | Non-color signal (carries meaning) | Color (decoration only) |
|-----------------|-------------------------------------|--------------------------|
| Dirty (unsaved) | `●` bullet glyph + `aria-label="Modified"` + visible `Modified` text in header tooltip/sr | `#7aa2f7` bullet |
| Save: idle | no indicator (absence = clean/idle) | — |
| Save: saving | `ArrowPathIcon` (spinner) + literal text `Saving…` | `#e0af68` |
| Save: saved (~1.5s transient) | `CheckCircleIcon` + literal text `Saved` | `#9ece6a` |
| Save: error | `ExclamationTriangleIcon` + literal text in `EditorErrorBar` | `#f7768e` |
| Conflict (412) | `ExclamationTriangleIcon` + heading text `This file was modified by another process` | `#f7768e` border-left |
| Delete confirm | `TrashIcon` + verb `Delete` in the button label + count text | `#f7768e` fill |
| Recursive-dir delete | `ExclamationTriangleIcon` + literal `N files` count in the body copy | `#f7768e` |
| Collision (409) | `ExclamationTriangleIcon` + literal filename in body | amber border |
| Binary / no-edit | absence of the Edit affordance is the signal (no Edit icon rendered) | — |
| Upload per-file: in-progress / done / failed | text `N%` / `CheckCircleIcon` + `Done` / `ExclamationTriangleIcon` + `Failed` | green / red reinforcement |

Save indicator markup is a `role="status" aria-live="polite"` region so the transition (idle→saving→saved) is announced to assistive tech; the green/amber are never the sole signal.

## Component & Interaction Contract

### 1. Edit mount + per-row Edit affordance (EDIT-02, EDIT-03, EDIT-12)

- **Per-row Edit affordance:** In `FileRow`, when `canWrite` AND `!entry.isDir` AND `!entry.isBinary`, render a `PencilSquareIcon` (`/24/outline`, 14px) icon button in a `FileRowActions` cluster revealed on row hover/focus (CSS `:hover`/`:focus-within` on `.file-browser__list-row`). The icon button reuses `.file-browser__btn--icon`. `aria-label="Edit {name}"`. Absent entirely when `isBinary` or `!canWrite` (absence is the colorblind-safe signal — no greyed ghost).
- **Preview-pane Edit toggle:** The `PreviewPane` text/markdown header gains a `PencilSquareIcon` Edit button (right-aligned, after the existing Download button) when `canWrite && state.kind === 'text'|'markdown' && !isBinary`. NO auto-edit-on-open — explicit toggle only.
- **Mount:** `Editor.tsx` mounts CM6 via `Compartment.reconfigure()` to flip read-only↔editable without remount (EDIT-02). The pane keeps the same dimensions as the read-only preview (no layout shift). Initial content = the already-loaded preview text (reuse — no re-fetch). On edit-enter, CM6 takes focus.
- **Cancel edit:** returns to read-only `PreviewPane` rendering; if dirty, fires the Unsaved-changes guard first.

### 2. Editor header + three-state save indicator (EDIT-06)

- Reuse `.file-browser__preview-header` structure. Left: filename (`.file-browser__preview-name`, ellipsized) + a caption subline with the cwd-relative path (11px muted). Right cluster (in order): DirtyMarker, SaveIndicator (`role="status" aria-live="polite"`), Save button (`--primary`), Cancel (`--secondary`).
- **Dirty marker:** `●` bullet prefixed to the filename when `EditorState.doc !== savedSnapshot` (EDIT-06), with `aria-label="Modified"`. Disappears when clean.
- **Save indicator three states** (idle shows nothing; saving = spinner + `Saving…`; saved = check + `Saved` for ~1.5s then fades to idle). Each state is icon+text (see colorblind table). Mirrors the Settings save 1.5s transient.

### 3. Save flow + unsaved-changes guard (EDIT-05, EDIT-07)

- **Cmd/Ctrl+S:** CM6 keymap intercepts `Mod-s`, `preventDefault`, calls `useFilesWrite.write` → `PUT /api/files/write?session&path` with header `If-Match: <etag>` (etag = mtime+size, EDIT-05). On 200: snapshot the saved doc, clear dirty, show `Saved`, refresh the directory listing (mtime/size). On 412: open ConflictModal (do not clear buffer). On other error: `EditorErrorBar` inline (non-takeover — content stays visible so the user can copy it out, per RESEARCH §5.1).
- **Navigation guard (React-level only):** Intercept file-switch, navigate-up, and tab-close while dirty → `UnsavedChangesModal`. NO `beforeunload` (Wails blocks it, EDIT-07). Default focus on `Keep editing`.

### 4. Conflict modal — HTTP 412 (EDIT-08)

- QuitConfirmModal-pattern dialog. `ExclamationTriangleIcon` + heading. Three buttons (`Force overwrite` destructive / `Save as new file` primary / `Discard my changes` default focus). `Save as new file` → inline name input prefilled `{basename}-copy{ext}`, then a fresh PUT (no If-Match, new path). `Force overwrite` → re-PUT with `If-Match: *` semantics (overwrite). Buffer preserved on every path.

### 5. Directory write affordances (EDIT-09, EDIT-10)

- **Toolbar (in `BreadcrumbBar.__breadcrumb-actions`, before refresh, `canWrite` only):** New file (`DocumentPlusIcon`), New folder (`FolderPlusIcon`), Upload (`ArrowUpTrayIcon` → triggers hidden `<input type="file" multiple>`). All `.file-browser__btn--icon` with `aria-label`.
- **Create file / mkdir:** inline name-input row inserted at the top of `FileListPane` (not a modal) — Enter commits, Escape cancels. On 409 → CollisionConfirmModal (`Cancel` default).
- **Rename (F2 or row action):** in-place input replacing `.file-browser__row-name` for the selected row; current name pre-selected. Enter commits, Escape cancels. 409 → CollisionConfirmModal.
- **Move (`Move to…` row action):** `MoveToPickerModal` — `new-session-modal`-style titled dialog with a scrollable directory tree (sandbox-rooted, dirs only). `Move here` primary, disabled until a target dir is chosen. 409 → CollisionConfirmModal.
- **Delete (row action):** `DeleteConfirmModal`. File variant vs recursive-directory variant (the latter states the `{N}` file count — count fetched before opening). Destructive `Delete` button, `Cancel` default focus.
- **Upload (EDIT-10):** single + multi via the hidden input AND drag-and-drop. Drag-over the list shows `UploadDropOverlay` (`Drop files to upload here`, dashed `#7aa2f7` border + `ArrowUpTrayIcon`). On drop/select → `UploadQueuePanel` with one row per file showing a determinate `N%` progress bar + status glyph. Per-file 409 → inline `Replace?` prompt within the queue row (does not block other files). Over-cap (>50 MiB) → skip that file with the over-cap copy; other files proceed.

### 6. Large-file + binary guards (EDIT-11, EDIT-03)

- Opening a file >500KB for edit shows `LargeFileNotice` (warn-then-proceed, dismissible inline banner inside the editor — NOT a blocking modal): `This is a large file ({N} MB). Edits may be slow.`
- Files near the 5MB cap mount CM6 in plain-text mode (no language pack) and show `Syntax highlighting disabled for large files.` as a persistent caption in the editor header.
- Binary files (`entry.isBinary`) never render an Edit affordance anywhere (row or preview) — they keep the v3.4 download-only path.

### 7. Cross-surface parity (release-blocking)

Every affordance, modal, copy string, and keyboard shortcut above is identical on the desktop (Wails) and web-share surfaces. The only difference is transport (local daemon socket vs webserver+cap / daemon proxy) — invisible to the UI. Parity is a release-blocking UAT: GUI-local ⇔ web-share must show byte-identical UX. Wails-specific watch item (RESEARCH gap): verify Tab inserts indentation (not focus change) and Cmd-V does not double-paste inside CM6 in the WebView; conditionally suppress the Phase 49 app.go Cmd-V handler when CM6 has focus if a conflict surfaces.
