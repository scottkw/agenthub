<objective>
Implement the `$EDITOR` shell-out edit flow: press `e` → resolve editor → fetch file bytes to a host-local temp file → suspend the TUI and spawn the editor → on exit, write edited bytes back and refresh the listing.

Purpose: TUI users edit files in their real `$EDITOR` with full local AND remote parity (TUIW-02, TUIW-03, TUIW-04). Resolves Open Q1 via the read-to-temp + WriteFile-back design (ARCHITECTURE.md §5.3/§7.3).
Output: `resolveEditor()`, the `e` key branch, `editFetchCmd`/`editWriteBackCmd` async commands, and the `editorExitMsg` resume handler that always issues `tea.ClearScreen` + unconditional `loadDirCmd`.

NOTE ON SC#1 ("sandbox-absolute path"): satisfied via a temp-file round-trip, NOT a literal local absolute path. The TUI has no client method to obtain a session's absolute work dir (server-side only, api.go:85), and a literal abs path breaks remote parity. The verifier MUST check the BEHAVIOR — edit → WriteFile-back → refresh works for local AND remote — not a literal local path string. (RESEARCH Open Q1 / Assumption A1.)
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env ($EDITOR/$VISUAL) → process spawn | Editor binary resolved from user env, then executed |
| filename → exec argv | The temp file path passed to the editor |
| temp file → /tmp | Edited bytes transit a host-local temp file |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-126-04 | Elevation/Tampering | $EDITOR shell-out | mitigate | Editor resolved via `exec.LookPath` (binary must exist on PATH); file passed as a separate argv element to `exec.Command(editor, tmpPath)`, NOT a shell string — no shell interpolation, no command injection via filename. |
| T-126-05 | Information Disclosure | editor temp file in /tmp | mitigate | `os.CreateTemp` creates mode-0600 in the user temp dir; `defer os.Remove(tmpPath)` always runs in editWriteBackCmd so bytes do not linger. Acceptable trust level for a local single-operator tool (same as the editor reading the file). |
| T-126-06 | Tampering | write-back overwriting wrong path | mitigate | WriteFile targets the original sandbox-RELATIVE `relPath` carried through the msg chain (never recomputed from the temp path); server-side `validateAndClean` enforces the sandbox boundary. |
| T-126-07 | Denial of Service | synchronous FS/network in Update | mitigate | All temp-file I/O + WriteFile run inside tea.Cmd closures (async); Update only sets flags and returns cmds — never blocks the render loop. Verified by the no-sync gate (Plan 04). |
</threat_model>
