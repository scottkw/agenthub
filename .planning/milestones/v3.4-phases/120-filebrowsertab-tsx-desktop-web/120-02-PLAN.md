FileEntry JSON shape (from internal/files/types.go):
```
{ "name": string, "size": number, "mtime": string (RFC3339 or ""), "mode": number, "isDir": boolean, "isSymlink": boolean, "isBinary": boolean, "mime"?: string }
```
List leaves size=0 and mtime="" (Phase 118 design — lazy-stat per CONTEXT D-03).

FileListResponse JSON shape:
```
{ "entries": FileEntry[], "truncated": boolean }
```

HTTP status contract (Phase 119 TestFilesRoutes_* verifies all of these):
- 200 — owner cap with files.read OR daemon-loopback no-auth path
- 401 — missing `?cap=` (route exists but unauthorized; never 404)
- 403 with body containing literal "files.read" — viewer cap without files.read
- 403 with other body — per-directory chmod denial OR per-file 403 on /read
- 404 — unknown session
- 405 — POST/PUT/DELETE
- 413 — file size > 5 MiB on /read
- 416 NEVER returned (FS-07 0-byte short-circuit)

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser→/api/files/* | All requests flow through FilesApiClient — single point of construction concentrates input encoding |
| user-supplied path string→URL query | URLSearchParams must encode `+`, `&`, `=`, space, non-ASCII correctly |
| 403 response body→UI dispatch | FilesApiError.isMissingFilesReadPerm relies on substring match — must be case-insensitive and tolerant of whitespace/JSON wrapping |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-120-07 | Tampering | URL parameter injection via crafted filename containing `&`/`=`/`?` | mitigate | URLSearchParams.toString() handles encoding; tested in filesApi.test.ts case 3 |
| T-120-08 | Information Disclosure | cap token logged via fetch error message | accept | FilesApiError.message embeds `bodyText` not the URL; existing AgentHub pattern logs cap in URLs (Pitfall 7 acceptance) |
| T-120-09 | Elevation of Privilege | viewer treated as owner by buggy substring match | mitigate | `body.toLowerCase().includes('files.read')` — checked in test case 10; whole-token match enforced server-side (Phase 118 HasPerm) |
| T-120-SC | Tampering | react-markdown / remark-gfm supply chain | mitigate | Task 1 checkpoint:human-verify before pnpm add (slopcheck gate from RESEARCH Package Legitimacy Audit) |
