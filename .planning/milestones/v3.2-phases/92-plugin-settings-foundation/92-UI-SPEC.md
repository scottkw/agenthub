# Phase 92 — UI Design Contract

> Visual and interaction contract for the **Plugin Settings Foundation** phase.
> A new `Plugins` h3 section is appended to the existing scrollable Settings tab
> (Phase 69 single-page layout precedent). Eight rows: name + short description
> + a fully-functional enable/disable toggle. Toggles persist via existing
> `daemonSettings`, propagate via a `settings:plugins` Wails runtime event into
> a `pluginConfig` prop on every open `TerminalPanel`, but **no addon code
> consumes the prop in this phase** — the propagation pipeline exists end-to-end
> with no addon side effects. All polish (per-plugin captions, BannerStack
> confirmations, advanced disclosures, per-plugin config sub-panels) is
> intentionally deferred to Phase 99.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase Scope (read this first)

**In scope (Phase 92):**

- A single new h3 section "Plugins" appended to `SettingsTab.tsx` after the existing Paths section
- Eight plugin rows in a fixed vertical order: WebGL → Unicode 11 → Search → Web Links → Inline Images → Serialize → Clipboard → Progress
- Each row: plugin name (toggle label) + one-sentence description + functional enable/disable toggle (existing `settings-panel__toggle-row` pattern)
- A dedicated three-state Save button at the bottom of the Plugins section (`Save Plugins` → `Saving…` → `Saved!` 1.5s) mirroring the existing `Save Paths` pattern — no new save infrastructure
- All toggles look like normal operational toggles (TokyoNight palette, full opacity, no greyed-out / "coming soon" treatment) because they ARE functional at the persistence + propagation layer
- WCAG-AA keyboard / focus / ARIA contract carried over from existing toggle pattern

**Explicitly deferred to Phase 99 (do NOT design here):**

- Inline italic captions like "Applies to new sessions you create" under non-hot-swap toggles (Unicode 11, Inline Images) — Phase 99 / PUI-02
- One-shot post-toggle BannerStack confirmation toasts for non-hot-swap plugins — Phase 99 / PUI-02
- Per-plugin advanced `<details>` disclosures (Search regex/case/word defaults, Web-Links click modifier, Inline Images storageLimit) — Phase 99 / PUI-03
- Per-plugin config sub-panels (`PluginConfigSearch.tsx`, `PluginConfigWebLinks.tsx`) — Phase 99 / PUI-03
- Tooltips beyond browser-default `title=` (e.g. Serialize secrets-warning copy) — Phase 97 / SER-02
- Per-plugin info icons / "learn more" affordances

**Anti-goal:** any UI affordance that hints "this toggle does not yet do anything." The toggles ARE wired through to TerminalPanel via the new prop; the absence is *consumption inside the addon load path*, which is invisible to the user. A v3.1 returning user upgrading to v3.2 sees a Plugins section that responds, persists, and survives restart — exactly as PUI-01 / PLUG-01 / PLUG-02 / PLUG-03 require.

## Copywriting Contract

### Section heading

| Element | Copy |
|---------|------|
| Section heading (h3) | `Plugins` |

**Decision rationale:** "Plugins" matches the project-internal vocabulary already used in ROADMAP / REQUIREMENTS / RESEARCH ("Plugin Settings Foundation", "Plugin Suite", "PUI-01"). "Terminal Plugins" was considered but redundant in the Settings tab context (everything in this Settings tab is terminal-related). "Plugin Suite" (the milestone name) was rejected as marketing-flavored for an inline section heading. **Single bare word `Plugins`.**

### Section subtitle / lead description

**No section-level lead `<p>` in Phase 92.** A one-sentence section-level intro ("Toggle which xterm.js addons to load on new and existing terminals") was considered but **explicitly rejected** for Phase 92 because (a) Phase 99's polish phase will add per-plugin captions where the live-vs-new-session distinction lives, making a section-level lead premature, and (b) the section needs no priming — each row's per-plugin description is self-evident.

### Per-plugin one-sentence descriptions

| # | Toggle label (plugin name) | Description (`.settings-panel__description`) |
|---|----------------------------|-----------------------------------------------|
| 1 | `WebGL renderer` | `GPU-accelerated terminal rendering with automatic DOM fallback if the GPU context is lost.` |
| 2 | `Unicode 11 widths` | `Correct cell widths for emoji and CJK characters using the Unicode 11 width tables.` |
| 3 | `Find in scrollback` | `Open a find bar with Cmd-F to search the terminal scrollback buffer.` |
| 4 | `Clickable web links` | `Detect URLs in terminal output and make them clickable with Cmd-click (macOS) or Ctrl-click.` |
| 5 | `Inline images` | `Render images sent via sixel or the iTerm2 inline image protocol directly inside the terminal.` |
| 6 | `Save terminal as text` | `Right-click a tab to export the visible scrollback as a text file.` |
| 7 | `Clipboard (OSC 52)` | `Allow the running CLI to place text on the system clipboard via the OSC 52 escape sequence.` |
| 8 | `Progress (OSC 9;4)` | `Show a per-tab progress underline when the running CLI emits OSC 9;4 progress updates.` |

**Rules these descriptions follow:**

- Exactly one sentence. Ends with a period.
- Plain English; no marketing adjectives ("powerful", "seamless", "blazing").
- Concrete user-observable behavior or trigger ("Cmd-F", "right-click a tab", "running CLI emits OSC 9;4") — not implementation jargon ("ESM bundle", "addon-search@0.16.0").
- One technical term acceptable when it's the load-bearing identifier (`OSC 52`, `OSC 9;4`, `sixel`, `iTerm2 inline image protocol`) — these are the searchable terms a returning user wants.
- Does NOT mention "applies to new sessions you create" — that affordance belongs to Phase 99.
- Does NOT include warnings ("includes secrets!" for Save terminal) — Phase 97 / SER-02.

### Toggle on-state vs off-state

The toggle's checked/unchecked state is communicated **visually only** (track color + thumb position) — there is no "On" / "Off" text. This matches the existing Behavior / Session Behavior precedent.

### Save button (three-state)

| State | Copy | Background |
|-------|------|------------|
| Idle | `Save Plugins` | `#7aa2f7` |
| Pending (disabled) | `Saving…` (U+2026 horizontal ellipsis, single character — matches existing `'Saving…'` pattern) | `#7aa2f7` (opacity 0.6) |
| Confirmed (1500ms) | `Saved!` | `#9ece6a` |

After 1500ms in the Confirmed state, the button returns to Idle.

### Error state copy

| Element | Copy |
|---------|------|
| Save error (rendered as `<p class="settings-panel__error">` below the Save button) | `Could not save plugin settings — {message}` |

The `{message}` slot is the underlying error string from the Wails RPC (existing pattern, e.g. `toggleError` in `handleToggleMinimized`).

### Empty / loading state

**Plugins section never renders an empty state** — the eight plugins are a fixed, hard-coded list (not dynamically discovered). On first GUI launch, before `GetPluginSettings()` resolves, the section follows the existing `toggleLoaded` precedent: each toggle row is **hidden** (not rendered) until the daemon responds, identical to the `{toggleLoaded && (...)}` guard around the Behavior toggle. The hidden `<input type="checkbox">` is always present (so test selectors find it). This prevents the "checkbox flashes off, then on" flicker that motivated the existing `toggleLoaded` pattern.

If `GetPluginSettings()` rejects, no toggles render and an inline error `Could not load plugin settings — {message}` appears above the (still-rendered) Save button. User can retry by clicking Save (which will re-attempt the round-trip — same recovery shape as the existing Paths section).

### Destructive actions

**None in this phase.** Toggling a plugin off does not delete data, does not require confirmation, and does not interact with any modal. The only destructive surface in `SettingsTab.tsx` is `Regenerate Signing Key` (Phase 87) which is unmodified.

## Interaction Contract

### Click / keyboard

- Clicking anywhere on the `<label class="settings-panel__toggle-row">` toggles the hidden `<input type="checkbox">` (existing behavior — `<label htmlFor="...">` association). The full row including the description text label is the click target (44px+ tall), satisfying WCAG 2.5.5.
- The hidden `<input type="checkbox" class="settings-panel__toggle-input">` is keyboard-focusable. `Space` / `Enter` toggle it. (Existing pattern.)
- `Tab` order: WebGL → Unicode 11 → Search → Web Links → Inline Images → Serialize → Clipboard → Progress → Save Plugins button. (DOM order matches the visual order.)
- Focus ring on the focused `<input>` is provided by browser default focus-visible (existing precedent — settings-tab elsewhere does not custom-style `:focus-visible` for these inputs; the focus styling is on the visible parent label via the existing `:focus-within` if any). **Action item for executor:** verify the visually-hidden input still receives a visible focus indicator on the parent label. If not, add `.settings-panel__toggle-row:has(.settings-panel__toggle-input:focus-visible) { outline: 2px solid #7aa2f7; outline-offset: 2px; }` — but DO NOT count this as "new design"; it's a WCAG remediation that should be confirmed by the checker, not invented here.

### Toggle state semantics

- Toggling a row **does not auto-save**. The change is held in component state (mirrors existing Paths-section behavior). User must click `Save Plugins` to persist.
- The Save button is enabled iff (a) at least one toggle differs from the last-saved value, or (b) a save attempt has not yet been made and the section just loaded.
- After clicking `Save Plugins`:
  1. Button transitions Idle → Pending (`Saving…`, opacity 0.6)
  2. `SetPluginSettings(state)` Wails call dispatches
  3. On success: button transitions Pending → Confirmed (`Saved!`, `#9ece6a`); a `setTimeout(1500)` returns it to Idle
  4. On failure: button returns to Idle; `<p class="settings-panel__error">Could not save plugin settings — {message}</p>` renders below the button
- On the daemon side, a successful `SetPluginSettings` MUST emit `runtime.EventsEmit(ctx, "settings:plugins", newConfig)`. `App.tsx` listens for this event and updates its `pluginConfig` state, which propagates to every open `TerminalPanel` as a prop.
- **In Phase 92, the prop is unconsumed by TerminalPanel.** A unit test asserts the event fires, the app-state updates, and the prop is threaded — but no addon code reacts. This proves the pipeline end-to-end without addon work.

### Decision: NO auto-save / NO debounce

Auto-saving on toggle was considered and **rejected**. PUI-04 explicitly mandates reuse of the three-state Save button pattern. Auto-save would force the introduction of a different feedback pattern (inline saving spinner per row) — which is precisely the "new save infrastructure" PUI-04 forbids. Save-on-button matches Paths.

### Decision: NO confirmation modal on toggle

Toggling a plugin off (even Inline Images, even WebGL) does not require confirmation. The user has not committed to anything until they press Save. If they Save with all plugins off, the app remains fully functional (terminals run with the v1.0 baseline xterm.js core). The inert-but-functional pipeline in Phase 92 means OFF is observably the same as ON anyway — no addon code runs in either case. By Phase 99 / 93, the addon-side polish lives elsewhere and Phase 92's interaction contract carries forward unchanged.

### BannerStack

**Phase 92 does not surface any BannerStack toast.** The post-toggle BannerStack confirmation for non-hot-swap plugins (Unicode 11, Inline Images) is a Phase 99 / PUI-02 polish item. Adding it in Phase 92 would be premature — the addon code that makes the confirmation meaningful does not exist yet.

## Acceptance Snapshot (what the Phase 92 implementation looks like when done)

A returning v3.1 user opens v3.2 for the first time and:

1. Existing Behavior, Session Behavior, Appearance, Web Server, Security, Paths sections look IDENTICAL to v3.1 (no visual regression).
2. Below `Save Paths`, a new `Plugins` h3 appears.
3. Eight toggle rows render (no flicker — `toggleLoaded`-style guard) with 7 ON and Progress OFF (the migration default).
4. Each row shows a one-sentence description below.
5. Toggling any row's switch animates the thumb (200ms) — same feel as Behavior toggle.
6. The `Save Plugins` button is `#7aa2f7` blue.
7. Pressing `Save Plugins`: button briefly shows `Saving…` (opacity 0.6), then `Saved!` (`#9ece6a` green) for 1.5s, then back to blue.
8. Quitting the GUI, restarting the daemon, and re-opening the GUI: Plugins section reflects the saved state. `~/.config/agenthub/settings.json` (or platform-equivalent) has a `plugins` block with `schemaVersion: 2`.
9. Running terminals continue to function exactly as in v3.1 — webgl + unicode11 + addon-fit are still loaded the old way (Phase 93 migration territory). Toggling Plugins off does not affect them. **This is the inert-but-functional contract.**
