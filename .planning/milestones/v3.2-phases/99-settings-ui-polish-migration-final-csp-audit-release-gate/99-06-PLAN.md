<objective>
Close the two Phase-99 UAT gaps from 99-UAT.md (Tests 5 and 6) that are blocking v3.2 release:

- Gap 1 (Test 5 — Search disclosure): three checkbox controls render as label-only text; the <input> elements are present but invisible (1×1px, opacity 0).
- Gap 2 (Test 6 — Web Links disclosure): three confirmation checkboxes render as label-only text; the modifier <select> in the same disclosure renders correctly because it does not carry the same className.

Both gaps share one root cause (see `.planning/debug/99-disclosure-checkboxes-missing.md`): the 6 disclosure checkbox inputs reuse `className="settings-panel__toggle-input"`, a Phase-82 iOS-toggle-switch-anchor class that is hidden globally by `style.css:586-592` and intended to be paired with visible `.settings-panel__toggle-track` + `.settings-panel__toggle-thumb` spans (as in `renderRow`). The disclosure helpers copied the hidden-input class but omitted the visible track/thumb counterparts, so the inputs collapse invisibly with no visible substitute.

Fix direction (option (a) from the debug session — RECOMMENDED): drop `className="settings-panel__toggle-input"` from the 6 disclosure checkboxes so they fall back to native browser checkbox rendering. Native checkboxes inside a config <details> block are appropriate UX — they are not status indicators like the main row toggles, so the iOS-pill visual is unnecessary. Smallest possible diff (6 className attributes deleted, nothing else moved).

Also close the test-strategy gap that allowed this regression to pass 33/33: the existing `PluginsSection.disclosure.test.tsx` uses `import raw from '../PluginsSection.tsx?raw'` + `expect(raw).toContain(...)`, which grep the literal "checkbox" in source but never exercise the render path or computed DOM. Add a real-DOM render test that mounts the component under jsdom and asserts the disclosure checkbox inputs no longer carry the hidden-toggle class.

Purpose: unblock v3.2 release gate by flipping Tests 5 and 6 in 99-UAT.md from `issue` to `pass`, and add a class-level regression guard so the same CSS-driven visual bug cannot pass tests again.
Output: 6-attribute source patch in `PluginsSection.tsx` + one new vitest file (`PluginsSection.disclosure.render.test.tsx`) that fails on the broken code and passes on the fix.
</objective>
