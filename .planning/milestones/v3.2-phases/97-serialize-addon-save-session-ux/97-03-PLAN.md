<objective>
Wire the App.tsx saver pipeline that connects TabBar's right-click "Save Terminal As…" gesture to TerminalPanel's SerializeAddon and the new (*App).SaveTerminalSession Wails RPC. This plan introduces THE structurally-novel shape in Phase 97 — the saver-registry callback chain — per 97-PATTERNS.md "the only Phase 97 file with a structurally-new shape." Every other Phase 97 file is a near-verbatim copy of an existing analog; App.tsx is where the new wiring lives.

The chain works as follows:
1. **TerminalPanel** (modified in Plan 97-04) constructs SerializeAddon in its hot-swap useEffect; on attach, it calls `onRegisterSaver?.(sessionId, () => addon.serialize({ excludeModes: true }))` registering a closure into App.tsx's registry. On detach (toggle OFF or unmount), it calls `onRegisterSaver?.(sessionId, null)` to flush the entry.
2. **App.tsx** (this plan) holds the registry as React state, receives register/unregister calls via `handleRegisterSaver`, and exposes `handleRequestSave(tabId)` as a callback prop to TabBar.
3. **TabBar** (modified in Plan 97-04) extends its existing context menu (lines 152-170) with a "Save Terminal As…" `<button role="menuitem">` whose onClick invokes `onRequestSave?.(contextMenu.tabId)`.
4. **handleRequestSave** looks up the closure for the tab's session, runs it through `stripAnsi() + sanitizeFilename()`, then calls the new `SaveTerminalSession(defaultDir, defaultFilename, plainText)` Wails RPC (added in Plan 97-05).
5. If the registry is empty (Serialize toggled OFF), `handleRequestSave` shows a one-shot banner ("Enable the Serialize plugin in Settings to save sessions") instead of calling the dialog. This avoids the discoverability anti-pattern of hiding context-menu items based on settings state.

Purpose: TabBar is structurally above TerminalPanel in the React tree; TerminalPanel cannot directly handle right-click events on tabs. The closure-registry pattern lifts the addon's `serialize()` method into App.tsx via callback-prop registration, where TabBar's right-click handler can reach it. This is React-idiomatic; the antipattern alternative (`useImperativeHandle` + ref-forwarding) would require cross-tree imperative refs and break the existing one-direction data flow. The registry is keyed by `sessionId` (not `tabId`) because the closure captures the SerializeAddon ref bound to a specific terminal session — the welcome tab and any future non-session tabs do not register, and `handleRequestSave` looks up by `tabs.find(t => t.id === tabId).sessionId`.

The new callback contracts:
```typescript
const handleRegisterSaver = useCallback(
  (sessionId: string, fn: (() => string) | null) => {
    setSerializerRegistry((prev) => ({ ...prev, [sessionId]: fn }))
  },
  []
)

const handleRequestSave = useCallback(
  async (tabId: string) => {
    const tab = tabs.find((t) => t.id === tabId)
    if (!tab || !tab.sessionId) {
      setSaveBanner({ kind: 'info', text: 'Open a terminal session to save its scrollback.' })
      return
    }
    const fn = serializerRegistry[tab.sessionId]
    if (!fn) {
      setSaveBanner({ kind: 'info', text: 'Enable the Serialize plugin in Settings to save sessions.' })
      return
    }
    const plainText = stripAnsi(fn())
    const stamp = new Date().toISOString().replace(/[:T]/g, '-').replace(/\..+/, '')
    const fname = sanitizeFilename(tab.name) + '-' + stamp + '.txt'
    try {
      await SaveTerminalSession('', fname, plainText)
    } catch (err) {
      setSaveBanner({ kind: 'error', text: 'Could not save terminal: ' + String(err) })
    }
  },
  [tabs, serializerRegistry]
)
```
