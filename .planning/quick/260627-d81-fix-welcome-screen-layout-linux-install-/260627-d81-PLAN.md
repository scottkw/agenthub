Root cause (locked — do not re-derive):
Each install row is `display:flex` with a right-aligned label (min-width:64px) plus
`.welcome-tab__code { flex:1 }`. A flex item defaults to `min-width:auto`, so it cannot
shrink below its content's min-content width. The Linux command is a single unbreakable
URL token with no spaces, so its min-content width is large; the Linux code box refuses
to shrink and forces its row (and the centered 520px column) wider than the macOS/Windows
rows, which contain spaces and wrap normally. Setting `min-width:0` lets the flex item
shrink to its track, and `overflow-wrap:anywhere` lets the long URL wrap inside the box.
</context>

  <action>
In the `.welcome-tab__code` rule (currently around lines 2017-2026, the block beginning
`flex: 1;`), add these declarations so the flex item can shrink to its track and the long
unbreakable Linux URL wraps inside the box rather than forcing its row wider:

- `min-width: 0;` — overrides the flex default of `min-width: auto`, allowing the
  `flex: 1` box to shrink below its content's min-content width so all three boxes settle
  at the same width.
- `overflow-wrap: anywhere;` — permits the space-free curl URL to break and wrap inside
  the box.
- `white-space: normal;` — explicit, defensive; ensures no inherited/ancestor `nowrap`
  prevents wrapping (the rule sets no white-space today, so this only hardens intent).

Do NOT touch WelcomeTab.tsx or any install command string — strings are correct and gated
by WelcomeTab.install.test.tsx. This is a geometry/alignment fix only (no color is used to
convey it; appropriate given the owner is colorblind).

`.welcome-tab__install-label` to baseline-align the label with the first wrapped line. Keep
it minimal — the three `.welcome-tab__code` declarations above are the core fix; skip the
