## Broken E2E Flow

**Linux build → standalone deployment (BUILD-02)**

`build.sh build_linux()` runs `go build -tags production` inside a Docker container instead of `wails build`. The `wailsassets` build tag is never set, so `assets_stub.go` activates and the binary serves frontend from `os.DirFS(".")` instead of the embedded `frontend/dist`. The binary compiles and produces a valid ELF executable, but it cannot serve the web UI when deployed outside the source tree.

**Fix options:**
1. Install Wails CLI in the Docker container and use `wails build -platform linux/amd64`
2. Use `ghcr.io/abjrcode/cross-wails:v2.6.0` image (as originally planned in SUMMARY) which has Wails pre-installed
3. Add `-tags wailsassets` to the `go build` command and ensure `frontend/dist` is available in the build context for `//go:embed`
