## Critical Gap: SERVE-02 Frontend Integration

**Requirement:** New sessions have web serving enabled automatically when the web server is running

**Backend:** Working correctly. `api.go:handleCreateSession` calls `ws.EnableSession(id)` when webServer is set.

**Frontend:** Broken. Three separate breaks in the seeding chain:

1. **`app.go:ListSessions()`** — Maps `daemon.SessionInfo` to local `SessionInfo` but drops `WebEnabled` field
2. **`App.d.ts`** — `SessionInfo` TypeScript interface has no `webEnabled` field
3. **`App.tsx:createTab()`** — Does not call `setWebEnabled` after `CreateSession` succeeds; missing `webServerRunning` dependency
4. **`App.tsx:init()`** — Session restoration does not seed `webEnabled` map from session list

**Root cause:** Quick task 260409-vop executor rewrote App.tsx to remove HealthModal/SettingsPanel, and lost the Phase 59 webEnabled seeding code in the process.

**User impact:** StatusBar shows web toggle as "disabled" for sessions that are actually web-enabled on the backend. User can manually re-toggle to fix, but the displayed state is incorrect on session create and window restore.
